## 3. 新候选必须满足的五条（可机检）

- **C1 目标是输入，不是标签**：目标必须以向量形式参与每一步，而不是只在 prompt 里当字符串；
- **C2 组合算子**：存在一个把**两个**检索结果组合成一个输出的算子（现有候选只有单跳 copy）；
- **C3 动作读出是因子化的**：`score(动作) = f(对象因子, 位置因子)`，因子由描述词**逐个解析**得到，禁止把整句目标映射到整句动作的平坦查表（10.16 的 100% 正是平坦查表）；
- **C4 公平夹具**：目标不点名实体、描述首字异于实体首字、词表只走 records、切分留出**实体**而非局面（10.9／10.15／10.17 的规则）；
- **C5 小预算可判**：先用不训练的探针证明 C2／C3 的中间量确实会变（如 10.12 的做法），再谈训练。

## 4. 最小架构提议（供下一轮立合同）

在现有候选之上加一个**两槽组合头**，不替换底座：

1. **槽 A（对象）**：以对象描述词为查询，对 records 做一次读（复用 `EpisodicRead` 的读通路，不重造），得到一个"对象实体"向量；
2. **槽 B（位置）**：同上，以位置描述词为查询，得到"位置实体"向量；
3. **打分**：`score(动作) = match(槽A, 动作.对象) + match(槽B, 动作.位置)`，两项各自是低秩双线性；
4. **为什么它能过 C3**：两个槽是**按描述词**算的，不依赖"见过这个目标整句"；没见过的对象走的是同一条槽 A 路径；
5. **参数量**：两槽各约 1k，合计 < 4k，远小于主体现有 3.3M。

**预注册判据（若立合同）**：在 10.15 宽夹具上，按对象留出；留出 top-1 ≥40%（机会 5%）、置换词表对照 ≤10%、主体逐位冻结；预算 ≤600 CPU 秒。

## 5. 什么算失败

- C2 的中间量（两槽向量）在真/置换词表下**不变** ⇒ 组合头接的仍是字符串，直接判负；
- 留出 top-1 ≤ 最佳常量 ⇒ 仍是无组合；
- 只有"见过的对象"对、没见过的错 ⇒ 平坦查表，判负（10.16 的老毛病）。

**不声称**这份设计一定可行；它只把"下一候选该长什么样"写成可证伪的样子。训练仍需在新合同下重新授权。

## 6. 重审后的设计要求（未批准）

1. 先让成功门有可达oracle和坏策略动态范围，重发生成复核时存raw字节及EOS/截断原因；不覆盖10.19，不因修量尺就签模型正结果。
2. 两槽是一个归纳偏置候选，不是由旧0/6证明的必要组件。完整目标应由模型形成角色查询；宿主切好的描述词可作上界，不能被计为已学会目标解析。
3. 验读取是否把质量分给正确来源，使用同records只换相关目标、真/置换/无记录与无关干预；整表变化使槽向量变化仅说明通道活，不证明选择性。
4. 原冻结EpisodicRead＋投影头保留为特征可用性对照。主候选需任务误差到负责查询/读取/绑定参数的实际路径；联合可塑、仅训头、前向不变的停信用及必要oracle分账。不要把read_slot的no_grad冻结条件继承为唯一训练方式。
5. 全合法动作、未见实体/组合/映射与全部应答轮计分；旧能力真实损伤和对称漂移分开。旧≤4k/300步/600CPU只是原方案约束，新范围未定价/批准前不实现或训练。
