# PLAN-N5-24 `generated` 的奖励「回读」判据（DEBT-G121 的修法形状；十裁⑵ 批准动产品码）

冻结时刻：2026-10-13（㊵-778）。**判据先冻，实施排在重复臂两臂退出之后**（`PLAN-N5-23` 的 `G-N5v-1` 要求两臂与批次 C 同跑器码版，窗口内不许提交 `taiji/`）。
批准出处＝本会话 owner 弹窗十裁⑵ 选项原文「G121 奖励累加器」。

## §0 现状（全是现读，可复算）

1. `taiji/model.py:2660`——generated 那条路把奖励**写死** `0.0` 后交给 `settle_action(...)`；`record_generated_prediction`（`:2667`）的签名里没有 reward 参数。
2. `taiji/contracts.py:1968-1971`——`EpisodicMemoryRecord.__post_init__` 对 `provenance == "generated"` 且奖励非零者在**构造期**就拒（VISION §19.6）。这才是「零奖励」的真正保证所在。
3. `taiji/memory.py:474` 的 `write(...)` 要求显式 `reward: float`，`:490` 只验有限性——它不是累加器，也不按来源汇总。
4. 因此批次 C 件里的 `generated_reward_sum=0.0` 是**构造性字面量**（跑器自己按构造写出），不是测量；并排仪已把它降级为披露面（`reports/taiji_batch_c_arm_parity_20261013.json` 里两臂同缺 `generated_reward_sum_basis`，㊵-775 ②）。

## §1 形状选择：回读，不是第二条写路径

原案（DEBT-G121 修法）写的是「累加器」。本轮改选**按来源回读**：从情节场把 `provenance=="generated"` 的那些行的奖励求和，出版 `generated_reward_sum_readback`。
理由：累加器要在写入侧加一条记账通路，与「只有一条写链」（`G-N5r-1`：跑器内不许出现第二条 `memory.write(`）撞形；回读只读不写，且**它能覆盖历史上已写入的行**，累加器只覆盖新写的。
这一选择是**修实现形状，不是放宽判据**：`PLAN-N5-20` §1 第 3 句「出版 `generated_reward_sum` 且必须恰为 `0.0`」原文一字不动，新键是加性披露。

## §2 判据（冻四条，每条写明「什么情况下它为假」）

* **J-N5w-1 回读必须与分母同出版**：件里要同时有 `generated_write_count` 与 `generated_reward_sum_readback`，且当计数 `> 0` 时后者不许是 `null`。
  为假的情形＝计数为正而回读为 `null`（说明那一格没被走到或回读口径不认得它）⇒ 整档不发表，只报「回读不可用」。
* **J-N5w-2 区分「无行」与「和为零」**：计数为 0 时回读必须出版 `null`（或 `no_rows` 标记），**不许**出版 `0.0`。
  为假的情形＝把「一行都没有」求和成 `0.0` 再被引用成「奖励都是零」——那是把缺席读成观察（本仓反复记过的失效方式）。
* **J-N5w-3 构造期保证仍须能为假**：负对照一支——给 `provenance="generated"` 的记录塞非零奖励，必须 `ValueError`；同一支在 `provenance="experienced"` 上必须不抛（否则这条测退化成恒真）。
* **J-N5w-4 两枚键不许互换引用**：`generated_reward_sum`（字面量，跑器按构造写）与 `generated_reward_sum_readback`（本次实测）必须各自带一句身份自述；
  引用「零奖励已被实测证实」这句时**只许**引回读那一枚。为假的情形＝件里只有一枚键、或两枚键值相同但其中一枚是构造字面量而文档把它当测量。

## §3 守卫

* **G-N5w-1 不许第二条写链**：新代码不得新增任何 `memory.write(` 调用点（AST 数，形状同 `G-N5r-1`）；负对照＝喂一段含 `model.memory.write(...)` 的合成源码，计数必须为 1。
* **G-N5w-2 新键不进冻结块**：回读键只许加在 `run_report.json` 的自述块与披露面，不许塞进既有必需键的冻结集合（否则历史件全部读成缺键，㊵-700 那族的「扩必需键＝追认历史缺失」）。

## §4 落笔即钉的三行

* **预期绿**：`J-N5w-2`／`J-N5w-3`（形状性断言）；`J-N5w-1` 在批次 C 的治疗臂上应为绿（`generated_write_count=178000`），在对照臂上应为 `null`（计数 0）。
* **仍红时收回哪句**：`J-N5w-1` 红 ⇒ 当场收回「generated 的零奖励已被实测证实」这句，并点名回读失败的那一格；`J-N5w-2` 红 ⇒ 收回「区分了无行与零和」，把两枚键合成一枚较弱披露。
* **发表资格前置**：本件全绿之前，「零奖励已被测量」不许说；全绿之后，说的也只是「按来源回读到的奖励和为 0（或无行）」，**不是**「自生成内容没有价值信号」——后者是能力主张，要另立判据。
