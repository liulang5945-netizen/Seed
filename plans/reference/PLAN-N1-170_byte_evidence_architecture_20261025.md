## 1. VISION 条款对账

- VISION §68：TaskCore 的原始 byte 与来源引用必须无损保留，「关系内容不能先压成 mean/std 再交消费者」。v1 的证据只保留每 32 byte 一个 GRU 摘要，语言 decoder 读不到逐字节内容。
- VISION §70：16 工作槽是**标定起点，不是长期容量上限**；允许在读取 query 前修订并冻结配置，但**不因结果不好自动加槽**。本包**不加槽**，只把同一证据改为逐字节可寻址；参数增量 +32,768（512×64 位置表），总 970,945，仍 ≤100 万。
- 默认模型、旧 native、旧失败与已消费 dev 面均不变；本包是同一 N/VX 切片内的候选修订，不新增第二套模型或预算体系。

## 2. 证据：为什么改这一处

对 N1-169 final checkpoint 的**只读**注意力诊断（4 个 train 题）显示：

| 题 | 工作槽 | 自由生成用到的不同槽 | TF 用到的不同槽 | 自由匹配 |
|---|---:|---:|---:|---:|
| 50fdf402 | 7 | 2 | 2 | 0 |
| e888c23e | 7 | 3 | 3 | .039 |
| 5da96e59 | 16 | 3 | 3 | 0 |
| e794a47e | 8 | 2 | 2 | 0 |

即便在教师强制下，decoder 也只用 2–3 个槽，把证据当成**固定话题向量**而非可逐位读取的源序列；这解释了「TF 0.66–0.70、自由 0–3.9%、输出循环」的组合。v1 的证据粒度与无位置内容寻址是当前最早失效点，因此本包只改这一处。

## 3. 结构变更（单一变量）

| 层 | v1 | v2 |
|---|---|---|
| 证据记忆 | 每 32 byte 一个 GRU 摘要，最多 16 槽 | **逐 byte 的编码状态**（最多 512 byte），16 槽工作空间仍保留给共享状态 |
| 位置 | 无显式位置 | 512×64 共享位置表：key 加 byte 位置，query 加已生成步数位置 |
| 读取 | keys/values 对 16 槽 | keys/values 对每个源 byte，softmax 在 ≤512 位置上 |
| decoder | GRU(64+256→256)，输出 Linear(512→257) | 不变 |
| 参数 | 938,177 | **970,945**（+32,768 位置表，仍 ≤100 万） |
| checkpoint | `task-state-v1` / trainer v1 | `task-state-v2` / trainer v2；v1 存档显式拒绝，不伪装兼容 |

- 训练与生成仍共用同一个 `next_logits`；无 renderer 补答案；原始 byte 仍保存在 `observations`。
- 证据超 512 byte 时按固定滚动窗口，不静默改原文；来源跨度仍逐 byte 记录。
