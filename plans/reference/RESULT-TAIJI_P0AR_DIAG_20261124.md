# 结果卡：P0-AR 巩固目标对比（MLP 冻结 vs 线性共训）＋未见颜色对泛化（`p0ar_not_consolidated`）

> [结果卡·探索诊断] — 2026-11-24（D-20261124-379）。脚本 [diag_p0ar_20261123.py](../../scripts/training/diag_p0ar_20261123.py)；回执 [report](../../reports/taiji_p0ar_seed20261120.json)。**1 seed、209.31 CPU、零 check；探索诊断。**

## 1. 设计（按 owner 第 3 步）

同一翻转训练后的主体复制成两个巩固臂，均 1500 步：
- **ARM-MLP**：冻结已训练的 MLP 读出，只训单元＋适配器（P0-AQ 基线）；
- **ARM-LIN**：轻柔线性共训——冻结闭式线性读出，每 200 步用当前状态重拟合 $w$，lr 2e-3（P0-AO 的修正版）。
- 验收用**冻结框架**：闭式线性、logistic 回归（不同读出，防循环论证）、16 步 MLP 迁移、**未见颜色对（HOLDOUT）泛化**；并保留休眠/适配器因果与旧中文保持。

## 2. 读数

## 3. 判定

best_arm = MLP；G3 线性 0.937 ✅、G4 logreg 0.997 ✅、**G5 mlp16 0.734 ❌（差 0.016）**、**G6 未见对 0.557 ❌** ⇒ **`p0ar_not_consolidated`**。

## 4. 判读（两个关键结论）

1. **线性共训（粗版）仍然不行**：logreg 0.465、mlp16 0.365、适配器因果消失（drop −0.015）⇒ 用「冻结旧 $w$＋定期重拟合」的简单方案会破坏映射；owner 建议的**可微 ridge 元学习（support/query）**需要按标准实现，不能用手工闭式近似。
2. **真正的泛化缺口暴露**：MLP 基线在**已见颜色对**上线性 0.937/logreg 0.997，但在**未见颜色对（HOLDOUT）**上只有 **0.557/0.537（≈机会）** ⇒ 当前「翻转能力」是**按颜色对记忆**而非可泛化的条件变换。这与 objective 的「学习新能力」要求直接冲突，是比「巩固 0.006 之差」更本质的问题。
3. mlp16 0.734 再次落在 0.75 边界（与 P0-AQ 弱 seed 0.747 一致），说明该判据对单 seed 偏紧。
4. 休眠/唤醒/旧中文保持均稳定。

## 5. 下一轮

1. **可微 ridge 元学习巩固（MetaOptNet/R2-D2 式）**：每 batch 分 support/query，support 上闭式 ridge 解出读出，query 上算损失反传到单元；直接优化「线性可读且可泛化」；
2. 验收改用**不同读出（logreg）＋未见颜色对**为主判据，另报已见对与 mlp16（避免循环论证）；
3. 至少 2–3 个 seed 后再下结论；保留休眠/适配器因果与旧中文保持。
