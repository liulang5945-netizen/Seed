## 1. 层级时间常数：解决"长程信用"的候选解 A（`priority` · 时间维度）

> 与 §2 的关系：§1 与 §2 是**同一问题**（长程时间信用不足，delay probe distance≥32 ≈ 0）的两个正交候选解，不是两个独立问题。§1 = 时间维度（慢层缓冲早期信息，`τ` 逐层指数排布），§2 = 检索维度（内容寻址读出 `φ(q)ᵀS`）。可单独、可组合；执行时互为对照臂，不重复计为独立目标。唯一下一步仍由执行计划唯一决定，本文不自行排序。

**设想**：把 taiji fabric 的"所有区域同样快"改为"逐层指数变慢"——浅层 τ 小（逐符号、即时反应），深层 τ 大（早期信息天然停留），用慢结构缓冲早期线索，弥补 delay probe 的长程信用缺口（distance≥32 ≈ 0）。

**为何升格为重点**：P4.7 已关闭容量假设（`capacity_hypothesis_closed`），主线收束为"表示合同重设计"（P4.8 解耦选择学习与行为保持的空间维度）。层级时间常数是表示问题的**时间维度**——两者正交，是"表示路线"的直接延伸候选，与主线的因果衔接比其余条目更紧。

**已有基础**（代码实证）：
- [neuron_region.py L30-31](file:///e:/Seed/taiji/neuron_region.py#L30-L31)：`membrane_decay=0.65`、`trace_decay=0.82` 是**全局统一标量**——所有区域共用同一时间尺度，这正是"层级时间常数缺失"的直接证据。
- 膜电位积分器已存在（[L237](file:///e:/Seed/taiji/neuron_region.py#L237) `membrane.mul_(decay).add_(drive)`），即一阶 leaky integrator；τ 与 decay 的关系为 `decay = e^(−1/τ)`。**改动只需把标量改为逐区域向量，不新增结构。**
- 生物学依据：脑皮层沿感官→前额叶时间常数逐级变长（sensory fast → PFC slow），是脑"不显式存长程、靠慢结构留信息"的方式。

**为什么现在不做**：
- P4.8 预注册已冻结，是单一变量（约束形式 + 架构拆分）对照——插入 τ 分层会污染归因，违反"同一时间只推进一个研究问题"（[03_CURRENT_EXECUTION.md L50](file:///e:/Seed/plans/active/roadmap/03_CURRENT_EXECUTION.md#L50)）。
- 它解决的是 delay probe（时间信用），不是 P4.8 的保持/新任务互斥（空间表示）——不在本轮任何 Gate 的验收范围内。

**触发条件**：P4.8 三臂（functional-13 / invariant-13 / residual-26）收束后任意结局——无论 `representation_redesign_supported` 还是 `invariant_constraint_insufficient`，时间维度都可作为表示重设计的下一个候选进入 CPU smoke（不待特定结局）。

**若重开时的候选形态**：`RegionDynamics` 增加 `time_constant: float`（或 fabric 层索引的 τ 列表），`membrane_decay = 1 − 1/τ`；τ 按层指数排布（τᵢ = τ₀·growth^i，如 1→3→10→32→100）。验收：delay probe distance=32 从 ≈0 恢复 >0.5；单 tick FLOPs 增加 <10%（τ 是常数乘法）；逐层 τ 进 checkpoint 与 digest 往返一致；B2/B3/B4 原指标不回退；与 replay/资格迹正交不互扰。

## 2. 长程信用 / 注意力外挂（fetch-weights 家族）候选——候选解 B（`deferred` · 检索维度）

> 与 §1 的关系：同属"长程时间信用不足"问题的两个正交候选解——§1（时间维度，priority）压慢层缓冲早期线索，§2（检索维度）提供 `φ(q)ᵀS` 内容寻址读出。可单独、可组合；执行时互为对照臂。

**设想**：taiji 长程依赖（delay probe distance≥32 = 0）不足时，引入内容寻址读出作为注意力载体。

**已有基础**：
- taiji 已有三套"无名注意力"：惊讶度门控可塑性（local_update = delta-rule fast-weights 的稀疏化）、内容寻址循环检索（记忆场 recall = 现代 Hopfield ≈ 一层注意力）、任务线索快照（fabric M1-65）。
- 线性注意力/fast-weights 家族（Schmidhuber 1992 → Katharopoulos 2020；RetNet/GLA/DeltaNet）在数学上与 taiji 的可塑性规则同族（写入端 δ 规则 + 衰减 + 外积联想）。
- 线性注意力天然带 chunked parallel scan：**训练并行 + O(1)/步推理**——它同时回应"长程信用"与"GPU 利用率"两个问题，但两者都不在本轮。

**为什么现在不做**：
- M2.R2.R1 gated temporal 候选已试败（distance≥32 仍 0），按纪律不重开；M4.R10 的巩固方向未完成前，不把时间信用列为瓶颈。
- fabric/recall 的非线性动力学无法精确跨时间并行（数学事实），只允许"新的状态载体"走并行化，不允许改 fabric 本质。

**触发条件（候选闸门原文，全部满足才评估）**：
1. M4.R10 及巩固方向完成且 retention 仍失败；
2. 归因明确指向"时间信用"而非容量/更新干扰；
3. 候选保持本地、稀疏、可审计、可整体移除（含梯度对照与移除后行为证据）。

**若重开时的候选形态**：读出端 `φ(q)ᵀS` 内容寻址（taiji 目前完全缺失），写入端沿用 delta-rule 家族；delay probe 作验收。

## 3. 并行训练方案空间（`idea` · 未定方向）

> 2026-09-13 讨论链收束：由"RNN 时间标号并行能否移植到 taiji"发端，经"多流并行 / 分工≠并行 / 人脑学习效率"三轮收敛为方案空间。核心判别：**并行分两级——样本级受课程顺序语义约束，序列级受状态依赖非线性门约束**。本条登记方案空间与触发条件，不改变主线（唯一执行项仍是 P4.8）。

**先决判别（讨论链已收敛，防再发现）**：
- "并行输入 + 时间标号"即 positional encoding = Transformer 化（架构迁移，非 RNN 修复）；taiji 不引入。
- "神经元分组各学一段" = 分工/专精（MoE 路线），**不是并行**——它把"保持/新任务互斥（表示耦合）"转移成专家间接口；P4 证据（13→22 参数扩容无效）表明容量不解决耦合。
- "多时间流共享权重"被隔离实验证伪（隔离 active 分支 ~1 MiB 饱和、C' 增益 −0.070~−0.090）；独立权重流合并撞表示饱和（P4.12/4.13 的求解器机制是单模型内，不是流间合并）。
- 人脑数据效率（暴露 ~10⁸ 词级、~20 W）远高于 LLM（10¹³ token）；"人脑学习效率低"是把**模拟媒介吞吐**（全局同步 tick + 把 86B 条异步时间流压成 288 单元共享状态张量）误当成大脑效率。大脑三性质（空间独立流、权重长在位上、异步无全局时钟）正是审计契约（全局 tick 对齐）主动放弃的东西。

**方案空间**：

| # | 方案 | 机制 | 上界 | 代价 | 触发 |
|---|---|---|---|---|---|
| 1 | 课程段内 micro-batch | 同课程段内 episode 各走独立状态链、同步点聚合更新；课程段边界严格串行 | ~min(B, 内存) × 单流 | 内存 ×B；batch 化语义需对照（P4.11 投影求解器当前逐样本确定） | M8：语料百 MiB / 任务矩阵 / 容量放大 |
| 2 | 线性主干 parallel scan | 膜/迹线性递推 + delta-rule 权重线性累加（[sparse.py L178-183](file:///e:/Seed/taiji/sparse.py#L178-L183)）→ scan 把 O(L) 压到 O(串行门深度) | 取决于串行门占比 | 架构级改动 + scan 算子；受 P4.8 表示合同约束 | 只读 profile 出串行门占比 + P4.8 收束后 |
| 3 | 事件驱动 / 去全局 tick | 只算活跃子集（target_activity=0.12）+ 区域异步步进，事件时间戳替代全局同步 | 节点更新 ~−88% + 区域流水 | 最大：checkpoint/digest/审计契约全量重写（契约假定 tick 对齐） | 审计契约变更评审批准 |
| 4 | kernel fusion + device 移植 | 整条 tick 算子链 fuse 成少量 kernel，再搬 device | 常数 2–10× | 无语义风险；代码已 device 无关（[local_learning.py L23](file:///e:/Seed/taiji/local_learning.py#L23)） | M8 同款 |
| 5 | organ 级实例池（流内分离） | 状态 + 局部权重按 organ 实例分离、各走时间链、仅在读出/Gate 仲裁点汇聚 | 直通脑式空间并行 | 合并接口 = P4.8 表示合同 | P4.8 结局 = `representation_redesign_supported` |

**为什么现在不做**：唯一执行项仍是 P4.8 三臂；方案 2/5 依赖 P4.8 表示合同，方案 3 依赖审计契约变更，方案 1/4 依赖 M8 触发条件（当前 CPU 分钟级，吞吐非瓶颈——加速不改变任何 Gate 结论）。

**触发条件（任一，经 Gate 评审后打开）**：
1. 只读 profile 完成：每 tick 串行门占 FLOPs 占比、门控"输入依赖 vs 状态依赖"的量化——决定方案 2（scan）的上限是否值得架构级投入；
2. P4.8 收束后任意结局 → 方案 2/5 进入 CPU smoke；
3. 语料百 MiB / 任务矩阵 / 容量放大 → 方案 1/4；
4. 审计契约变更评审批准 → 方案 3。

## 4. 核心目标边界的自我界定（`deferred`，已形成决策）

**设想/结论**：taiji 的衡量尺子是"在线认知 agent"（边交互边学、可审计、可终身），**不是**"静态语料序列压缩冠军"。

- transformer 的强项（全局任意两两关系）与 taiji 的强项（因果在线 + 器官级隔离审计）在机制上是互斥的（全局稠密反传 ⇄ 局部稀疏可塑），不存在免费两头通吃。
- 因此在 agent 场景里，token 间全局关系不是主要需求；若未来实证仍需要，走 §2 的本地稀疏注意力算子，而非把 taiji 改成缩小版 transformer。
- **此条已作为从业界讨论中收敛的策略判断记录，不改变任何主线执行。**

## 5. 自主唤醒：让模型"自己决定醒来学习"（`idea`）

**设想**：不依赖外部显式调用 `learn=True`，模型在运行时基于内部信号自己进入"学习态"——相当于打盹/起身的内部仲裁。

**已有基础**（代码实证，不是空想）：
- `taiji/adapter.py` 在感知路径中已计算 `novelty = max(percept.prediction_error, 1.0 - recall.confidence)`，并已存在 `mode="wake"` 的调用形态（homeostatic controller）。**"醒"的信号和模式位已经在了。**
- 缺少的是：一个"消费这些信号 → 决定是否打开学习循环 → 记录为何醒/学了什么/为何回睡"的内部状态机。

**为什么现在不做**：
- 主线在 P0→P2（固定容量持续学习基线）。基线成立之前，让模型"自主决定何时学"会让"学到了什么"无法归因——会重复 M4 系列"fast≈C-replay / update 碰撞"这类审计教训。
- 全时/自主学习若没有可审计触发事件，就退回"黑箱全时学习"。

**触发条件（至少满足其一才重开）**：
- P2 之后仍有独立证据表明"固定容量基线下，外部触发的学习能过 Gate"；
- 计划 M4 第 7 条"自主选择干预（基于校准的失败/不确定性选择继续学/重放/申请增长）"拿到其前置能力。

**若重开时的候选形态**：novelty 阈值 → 连续 N tick 超标才醒 → 每次醒来是一次显式事件（reason/learned/result）→ CPU canary 证明"高 novelty 触发、低 novelty 不触发"。

## 7. 加载即活的快照 / 跨设备迁移

**设想**：任何设备加载一份 taiji checkpoint，即恢复为"活的"（可继续学、可继续成长），而不是冻结标本。

**已有基础**（代码实证）：
- `Taiji.checkpoint()` 不仅存参数，还存 `rng_state`（随机流续上）、`_identity_growth_history`（成长史）、active 分支与元数据、记忆场、结构增长 payload——**是"活的快照"**。
- `from_checkpoint` 带完整性校验与 fresh-process digest 往返一致；checkpoint 是纯数据（无硬件/绝对路径绑定）。**代码层面已可迁移。**

**为什么现在不做**：
- "快照可恢复"已成立；缺的是"加载后自动接入实时感知/行动循环"和"跨设备实际验证流程"（P3 中断续训在接近，但未覆盖真实设备迁移）。
- "自主行动"更依赖 §5 与 M4 第 7 条。

**触发条件**：P3 中断/续训流程 m4v2 稳定通过，且出现真实的多设备/多宿主需求。

## 8. 多流并行 / GPU 利用率（`deferred`）

> 2026-09-13：方案空间已由 [§3 并行训练方案空间](#3-并行训练方案空间idea--未定方向) 细化接管；本条保留原触发条件与逐位一致性验收要求。

**设想**：语料 ≥ 百 MiB、seed/任务矩阵膨胀或容量放大时，评估"多记录/多实例并行"调度（不改单实例逐 tick 学习语义），从而让 GPU 喂得饱。

**为什么现在不做**：当前 CPU 分钟级（1 MiB ≈ 20 分钟、峰值 ~370 MiB），吞吐非瓶颈；逐符号小算子（~60K FLOPs/tick）喂不饱 GPU kernel 启动开销，单一实例并行化反而更慢。顺序性在单实例内是本质（每步依赖前一步状态）。

**触发条件**：任一——语料到百 MiB、seed/任务矩阵膨胀、容量放大。并行后必须以同一 checkpoint 复跑固定输出 canary + A/B/C 指定 owner 分数，digest 与逐位输出一致方可替代逐符号路径。

## 9. AMD/DirectML 后端（`deferred`，决策记录）

**设想**：在 Windows 上用 AMD GPU 训练 taiji。

**现状（决策记录 2026-09-08）**：Windows 无成熟训练路径——ROCm 实验性、DirectML 对 taiji 依赖的稀疏算子（index_select/scatter_add/randperm/multinomial）有覆盖风险。本轮不装卡、训练主链保持 CPU。

**触发条件**：仅当 §8 或容量放大给出"GPU 可兑现加速"的实测证据后，再评估 Linux+ROCm 或 DirectML 核心算子冒烟。

## 10. 前端主流化（P5 队列项）（`deferred`）

**设想/结论**：把 taiji 客户端前端的成品感提升到主流产品水平——用户判定目前"视觉/样式不精致" + "交互/性能卡顿"两层均未达标。

**现状（2026-09-11 核实）**：
