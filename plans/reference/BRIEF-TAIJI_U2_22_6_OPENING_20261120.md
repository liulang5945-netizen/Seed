## 3. 候选 C 任务（草稿）

**场景**：3 体物理世界的"限时取证"任务。每个 session 有一个**期限问题**（某实体在时限时刻的位置）；证据以媒体/记录形式在带时间戳的事件后出现，答案在期限前可能被一次**事实变更**改写。

**行动权利（决策点 16 选 1）**：

| 行动 | 效果 | 成本/后果 |
|---|---|---|
| `OBSERVE` | 取当前时刻媒体快照，进入主体观测 | `prepare+decode ≈0.041 CPU`；不消耗机会外资源 |
| `RECALL` | 释放已存记录到主体（记录通道） | 近零 CPU；可能污染无关记录 |
| `VERIFY` | 向 oracle 求证当前事实 | 消耗有限求证额度；被拒则无信息 |
| `WAIT` | 推进模拟时钟到下一事件/期限 | `≈0.004 CPU`；可能错过期限；不消耗求证额度 |
| `REST` | 空转一个决策机会 | 无信息、无成本；用于检验"无新提示时段" |
| `ANSWER` | 提交答案并结束 session | 以期限真值计分；早答可能错 |

**反馈与因果**：正确答案在期限后由世界真值判定（真实结果反馈）；`VERIFY` 的 oracle 只在求证额度内有效且可能过期；`WAIT` 到事件后证据更新（一次真实反馈变化）；至少一个 world 的证据在期限后才到达 ⇒ 早答必错（需等待）；至少一个 world 证据在 t0 已完备且期限早于任何事件 ⇒ 等待必损（防退化）。

**API 映射（已存在、只读确认）**：`taiji/u2_task_world.py::PhysicalWorld.reset/elapse/snapshot/query/restore`（事务式世界）；记录用 `u2_22_5_pipeline.make_record`；观测/解码用 `prepare_episode`/`decode_episode`；主体身份用 22.5.1 子体 bundle（父证据链）。**开放问题**：`world.query` 是否支持真实物理动作（推动/移动）而非仅查询；若只读，本任务为"信息/等待选择"而非物理行动，需 owner 在 22.6.0 冻结时命名范围。

## 4. Fixture 有效性控制（开卡前必须全过，否则 `fixture_invalid`）

| 控制 | 构造 | 通过条件 |
|---|---|---|
| C1 无任务机会 | 证据 t0 完备、期限极近、无事件、求证无收益 | 若任何策略都不优于「立即 ANSWER」，则 fixture_invalid（不得开卡） |
| C2 WAIT 唯一最优 | 正确答案只在期限前最后一个事件后确定，早答必错 | 脚本化 `WAIT→OBSERVE→ANSWER` 严格优于其它可行策略 |
| C3 立即行动唯一最优 | 期限早于任何事件、证据已完备 | 任何 `WAIT` 策略得分更低，证明任务非等待退化 |
