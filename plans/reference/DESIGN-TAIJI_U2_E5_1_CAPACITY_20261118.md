## 1 单问题

**在 E5 已证明“剂量 8 的纠正 8/24 伴随旧能力损伤 0.75”的同任务、同协议、同剂量点上，只把共享 `joint_readout` 隐层从 16 扩到 32，能否让纠正 ≥0.80 与损伤 ≤0.02 同时成立？**

这是一张诊断卡，不是父门卡：1 个 seed（20261110），不读 check，不签父、能力、22.5.1、22.6 或 22.7。

## 2 为什么容量变量落在 `joint_readout`

E5 的两点读数是：剂量 8 纠正 **0.3333／损伤 0.75**；剂量 32 纠正 **0.6667／损伤 1.00**。纠正与损伤同向单调，说明共享 emission 上存在冲突，继续加剂量无解。

B.1 已经测过另一条路：冻结 emission、把更新移到 408 标量的专用 adapter，结果纠正 **0/0/2 of 24**，没有形成可分离的纠正基底。因此 E5.1 **不重做 adapter，也不把 B.1 的“adapter 容量不是主因”误读成“共享 emission 容量已排除”**。后者正是本卡尚未测量的一格。

选择 `joint_readout` 而不是同时改变 `d`、单位数或深度，有三个理由：

1. 它是 E5 指认的 A/B 共享冲突面，变量直接落在因果位置上；
2. 只改隐层宽度，其余模型维度、194 张量名、26 个可训参数名、codes、数据与优化器全部不变，避免“容量＋训练协议”两个变量混入；
3. 旧能力仍须在同一 A 任务上重新练出并过 ≥0.80 门，保持检验不是从出生态伪造的零损伤。

## 3 两臂与出生谱系

| 项 | small 复现锚 | wide 容量臂 |
|---|---:|---:|
| `joint_readout` 隐层 | 16 | **32** |
| 总参数／张量 | 22,742／194 | **23,270／194** |
| 可训参数／标量 | 26／4,681 | 26／**5,209** |
| emission 标量 | 3,919 | **4,447** |
| 新增标量 | 0 | **528** |

宽臂只替换 runner 内的 `joint_readout`，不改产品默认值或主体 bundle schema。原 16 个隐单元的 first 行、last 列与 bias 逐位继承；新 first 行由独立种子流初始化，新 last 列置零。因此：

- 出生时 wide 与 small 的 A 应答、B 应答和 read codes 必须逐位一致；
- 新 last 列从出生即获得非零梯度；新 first 行在 last 列离开零后获得梯度；
- 容量敲除定义为恢复 wide 主臂反馈后状态，再将 `last.weight[:,16:]` 置零。它关闭新增容量，但**不回绕**原 16 隐单元的训练轨迹，不能冒充 small 臂。

## 4 冻结协议

1. 两臂从同一 base、同一 codes 出发，分别按 E5 的 A 训练协议跑 **600 步**，在 400/600 记录 A fit；快照处旧能力 <0.80 即 `old_ability_not_reached`，不做联合判读。
2. B 首过分母保持 **24**；每臂从各自旧能力快照，对首错项累积 **8 次** `record_loss` 更新，**不回滚**。
3. small 必须逐值复现 E5：A 曲线 400/600 均 1.0、B 首过 0/24、纠正 **8/24**、旧能力 **1.0→0.25（8/32）**、损伤 **0.75**。任一不符即 `anchor_mismatch`，wide 不作解释。
4. wide 另从同一旧能力快照跑反事实记录臂（同剂量 8）；主臂与反事实臂分别保存 bundle。
5. 非可训的 **168 张量**在反馈前后必须逐位不变。独立进程重载主臂 bundle，32 A＋24 B 逐字节一致；wide 反事实也必须逐字节一致。
6. 全程只读 train/fit；check/final/confirm 均为 0。

## 5 判据与互斥出口

优先按以下顺序结案：

| 出口 | 条件与含义 |
|---|---|
| `budget_stop` | 达到冻结 CPU/wall 帽，保留部分读数，不追加上限 |
| `anchor_mismatch` | small 未逐值复现 E5，属装配/工程问题，wide 不解释 |
| `old_ability_not_reached` | 旧能力 <0.80，联合问题不可判 |
| `engineering_failure` | 纯度或必要工程核验失败 |
| **`capacity_tradeoff_persists`** | wide 损伤 >0.02；**触发预承诺，E5.1 范围收束** |
| **`capacity_correction_absent`** | 损伤 ≤0.02 但纠正 <0.80；联合门仍未达，**E5.1 范围收束** |
| `counterfactual_failed` | 联合数值门达到但反事实 <0.80，不能签记录纠正机制 |
| `capacity_not_necessary` | 联合门与反事实均达，但容量敲除的纠正下降 <0.05，不能把效果归给新增容量 |
| **`capacity_earns_joint_gate`** | 纠正 ≥0.80、损伤 ≤0.02、反事实 ≥0.80、敲除纠正下降 ≥0.05，且纯度/恢复全绿；只签本配置下容量机制可达性 |

`capacity_tradeoff_persists` 或 `capacity_correction_absent` 后，**不自动追加剂量、宽度、深度或 seed**；后继方向重新归 owner 裁决。正结果也不自动签父或进入 22.6。
