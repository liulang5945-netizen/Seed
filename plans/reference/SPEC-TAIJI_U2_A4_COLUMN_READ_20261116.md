## 1 这张卡问什么

A.3 的结论是：**主体在答题前的 x 不携带场景读**（前缀 0 读类 0.4375 对零假设 0.34375；被涂列颜色探针 0.0154，背景 0.963）。A/B 两个选项只能让**管线**答出答案，主体自己不读；C（读作教师）被关掉。

A.4 只问一件事：**把这条读做进主体的读出位置，主体自己能不能在答题前就读出来，并且把答案写进字节。**

## 2 结构

新增读模块 `column-read-v1`（[`taiji/u2_column_read.py`](../../taiji/u2_column_read.py)）：

| 环节 | 做法 |
|---|---|
| query | 主体自己的请求嵌入（文本编码器输出取均值，8 维） |
| key/value | 主体自己的**列 token**：同一编码器作用于列重排（16×8） |
| 注意力 | 16 列打分后 softmax，值池化 |
| 特征 | 注意力列坐标 x̄、峰值强度、熵、池化内容（11 维） |
| 读类 | 四类头：左／中／右／未知（**要挣来的类，不是自由槽**） |
| 注入 | 读出头输出**加法**注入 `joint_readout`，经**零初始化**投影 |

**参数量 476 标量**（query/key/value 各 72、头 132、输出投影 96），远低于 A.3 定的 ≤8k 设计帽。

### 2.1 三条旧教训直接写进结构

1. **位置必须离开整场摘要**（P3.21／P3.22）：注意力列坐标 x̄ 作为**独立特征**携带，因为池化值说不出"在哪"。
2. **不给自由弃权槽**（P3.22／P3.26）："未知"是四类之一，必须从特征里挣；没有任何参数能白推答案到未知。
3. **初值即无回归**（P3.25 撤回的教训）：输出投影零初始化 ⇒ 训练第一步的字节通路与"无读的主体"**逐字节相同**，不是扰动。

### 2.2 "体内"的准确含义（须说清）

模块参数**不进主体的 state_dict**（主体仍是注册的 22,742 标量／194 张量，旧 bundle 逐位不变）；但读**在主体的读出位置产生**，并**进入前缀 0 的主体状态 x**——A.3 的可测标准因此可以在这张卡上重跑并判定。若 owner 要求读模块成为 `U2Subject` 的成员（即新候选身份、旧 bundle 不再兼容），那是另一个变体（成本另计），本卡不采用。

### 2.3 契约测试抓到的一处设计缺陷（已修）

初版把**特征**（11 维）注入读出头，四类分布没有进注入向量——那意味着**类头不在字节损失的梯度路径上**：它永远学不到，而任何基于它测出的读准确率都会是偶然。契约测试 `test_class_head_is_on_the_byte_path` 抓到了这一点。

修复：注入向量改为 **15 维（11 特征＋4 类概率）**，类头因此由字节损失训练；参数量 444→**476**。零初始化残差的副作用一并声明：**首步类头梯度恰为 0**（只有投影能动），第二步起非零——这是声明性质，不是缺陷，由 `test_zero_initialised_residual_defers_the_head_gradient_by_one_step` 钉住。定价因此重做（帽 383.79→**443.63**），设计卡、台账与队首的数字同步更正。

## 3 门（读数前冻结）

**门 R（读，前缀 0）**：fit32 四类读准确率 ≥0.80，**且** 相对打乱零假设的差 ≥0.20，**且** 被涂列颜色探针 ≥0.50，**只允许前缀 0**（前缀 ≥1 一律标泄漏，不进判定）。这三条直接来自 A.3 登记的判据缺陷修正。

**门 B（字节，22.5.1 口径）**：全应答轮精确成功 ≥0.80、纠正率 ≥0.80、真实反馈增益 ≥0.05（world 配对 95% 下界 >0、3 seed 同向）、旧能力下降 ≤0.02、独立进程恢复逐字节一致。

**纠正率的可辨识性（读数前声明）**：A.2 的首过已是 32/32，**没有任何错误可纠正**，纠正门按设计不可辨识。A.4 因此把纠正门**声明在一次故意降级的首过上**——A.1b 未校准读（fit 25/32）——并要求反馈后纠正到 ≥0.80。这是读数前的设计决定，不是事后调参。

**能签与不能签**：本卡最多签 `read_in_body_confirmed`；**A 父不在这张卡的范围内**——22.5.1 的父门要真实反馈回合、world 配对区间、3 seed 与保持对照，需要一张完整协议的卡。0 能力声称、0 check/final/confirm 读取。

## 4 定价（实测，不是估计）

A.2 的教训是固定阶段没定价、结果越帽 10.9%。这次**每个阶段单独实测**：

| 单位 | CPU |
|---|---:|
| 字节回合／例（读已缓存） | 0.2520 |
| 字节回合／例（每位重算读，最坏情形） | 0.2695 |
| 训练步代理／例（前向＋反向，**不建优化器**） | 0.0781 |
| 前缀 0 采集（fit32 全量） | 1.1875 |
| 恢复重放（fit8） | 1.9531（逐字节稳定 ✓） |

列重排与读前向本身**低于 0.0156 s 计时刻度**（读数 0.0），因此不单独计价，只计入回合成本——如实说明，不把 0.0 当"免费"。

预算模型（3 seed × 600 更新 × 3 剂量点）：

| 项 | CPU |
|---|---:|
| 训练 | 46.88／seed |
| 评测（3 剂量 × fit32+train64 回合） | 72.56／seed |
| 前缀 0 探针 | 1.19／seed |
