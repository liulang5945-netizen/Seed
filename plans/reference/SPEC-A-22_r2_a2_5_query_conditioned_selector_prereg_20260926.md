## 1. 现状为什么挑错（机制诊断，不是猜测）

`taiji/copy_circuit.py` 的 `ToldContentStore.best_match(cue)` 是**归一化点积 top-1、无阈值**，
且查询侧喂的是**当前皮质态**：

1. **提问不参与**：cue 是"告知结束那一刻"的状态，查询是"现在这一刻"的状态——**问题里说了什么
   完全没进打分**，所以"我住哪？"和"我表哥住在无锡。"之间没有任何比较依据；
2. **逐步漂移**：每发一个字节就换一次查询，实测同一批题**32.2% 的答案步**挑的是另一条告知，
   而"提问喂完那一刻"的静态错率只有 22.9%（§14）⇒ 挑对一次不难，**每步都挑对**难；
3. **分辨率低于扰动尺度**：正确题也是贴边赢（margin 中位 0.025，最瘦 0.0003，§9）⇒ 任何噪声都翻。

## 2. 要装什么（设计冻结）

**选择分数**（在提问喂完时算**一次**，整轮固定）：

```
q      = 提问喂完那一刻的皮质 cue
score(e) = cosine(q, e.cue) + ⟨ q_state, W · content_repr(e) ⟩ / scale
picked = argmax_e score(e)          # 该轮内不变；W 零初始化
```

* 第一项是**现状那条 cue 余弦**，第二项是可学加分 ⇒ **W＝0 时逐位等于现状行为**
  （挂载位级不变这条老规矩守得住，见 §5 的守卫）；
* `content_repr(e)` 由事件字节经**已存在的固定随机基** `content_embed` 查表后按位置平均得到
  （不引入第二个 embedding 面，也不改 `content_embed` 是否可训——那是**内容表征案**，另案需签字）；
* 选定结果缓存到本轮生成结束，**不随解码步变化**（消灭 §1.2 的漂移）；
* 位置寻址（同一条告知内部看哪个字节）**本件不动**——那是 §23 之后剩下的"表征"那一支。

**训练信号**：selector 头与 A2.3 的局部更新同族（无 autograd）：正例＝含可复制答案词的那条告知，
负例＝该轮其余事件；交叉熵 over events，学习率与 `lr_address` 同档，advantage 沿用 ±2 clamp。
标签来自题面（`expected_contains` 逐字命中哪条告知），**不来自模型自己的输出**（否则会把
§13 那种分布差写进目标）。

## 3. 评测协议（先立后跑，跑完不改）

* **两条制度性要求来自 §20**：① 评测必须**在自己走出来的轨迹**上（`run_arm` 形态：模型自己的答复
  滚进历史，本来就是 on-policy）；② 主指标必须是**整句**结果——**严格真命中**（实体词逐字出现在
  更早的用户轮里、且出现在最终答复里），不用"每步指对率"当结论指标。
* **题集**：`v1`（软干扰，基线 seed-A 23／seed-B 22／对照 0）与 `v2`（同谓语难干扰，基线两臂均 16、
  天花板 43／39）各跑一遍，**分开报数不合并**（v1 偏易是已登记事实，`SPEC-A-21` §6）。
* **两电路同向规则沿用**：两个独立初始化电路（换 `--circuit-seed`，§11 的位级不变守卫已落地）
  各自与基线比，**同向且差 ≥3 题**才判改善；否则记 `not_resolved`（**不等于无收益**）。
* **回归门复用立项 §4.3**：装上新选择器后 CAP A 维 9 项不掉、C 维不降、表层 §4.3b 不劣于基线；
  B 维无机检就一直记 `unverified`（不许被代理信号点亮）。
* **基座不变**：只写电路 payload，`checkpoints/*.pt` 跑前后 sha256 逐位相同（既有硬门槛）。
* **止损**：smoke ≤20 分钟、判读 ≤90 分钟；超时按 `not_resolved` 归档，不追加时长后改判据。

## 4. 预登记的读法（三分支，都不许回头改口径）

1. **v2 提升 ≥3 且两电路同向** ⇒ 机制确认。此时**才**谈"默认挂载是否开"（所有者决定）；
   并把 §16 那个天花板 43 变成新的靶线，讨论剩余 61 题（键/续接那一支）。
2. **只在一个题集升**（v1 升 v2 不升，或反之）⇒ 如实报"**只在这个分布有效**"，不合并总分；
   若升的是 v1 而不升 v2 ⇒ 说明它学到的还是字面重叠那一套，按 §9 的老规矩再来一轮难干扰检验。
3. **两集都不升** ⇒ 学习式选择器**也被否证**。那选择侧就只能记为"已定价但装不上"，
   全线的下一个待裁事项自动变成**内容表征**那一条（需签字），本件如实归档不追加口径。

任何分支都**不许**拿 CAP 那 16 题（多数只有一条告知）当反证或正证——§16 已限定它的适用范围。

## 6. 现成件核查（2026-09-26）：`ContentSelector` **不是**可复用件，只是形状先例

`SPEC-A-17` §7.3 曾记"若要装学习器，现成件见 `ContentSelector`（零初始化 `Linear(6→1)`＋argmax＋
无图局部更新，已进 checkpoint 面）"。逐行读过之后：它服务的是**另一件事**——

* 特征是 `goal_signal / world_signal / information_gain / confidence / uncertainty / resource_cost`
  （`taiji/content_selection.py:24-31`），由 `ContentSelectionContext.from_state(goals, world)` 派生；
* 消费点在语言器官的内容计划路径上（`taiji/adapter.py:7811`，attach 见 P6 那批 eval/test 件）；
* **它的六个特征里没有一个是"提问与某条告知是否相关"** ⇒ 直接套用会把"选内容计划"当成"选记忆条目"，
  是类别错误，不是省事。

**能迁移的只有形状**：零初始化 `Linear(k→1)`＋argmax＋无图局部更新＋`to/from_checkpoint` payload 面
（这套管道可以照抄，参数与特征要新写）。⇒ 本件 §2 的特征表按此**具体化**，实现清单里
`taiji/content_selection.py` **不改**、不共用；新头放在 `taiji/copy_circuit.py` 内（与复制器官同生命周期）。

**per-event 特征（`k=5`，全部无参数可算，训练时才学权重）**：

| # | 特征 | 为什么需要它 |
|---|---|---|
| 1 | `cosine(提问皮质 cue, 事件 cue)` | 现状那条——保留 ⇒ 头零初始化时**逐位等于现状** |
| 2 | `cosine(提问运动语境 f1, 事件内容池化键)` | 提问条件化的"内容侧"匹配（现状完全缺） |
| 3 | 提问与事件文本的**共享字符比** | v2 上它单独不够（15<16），但作为**特征**给学习器用是合理的 |
| 4 | 事件在库中的**相对新度** | §13 的漂移/近因偏置需要一个可学的对抗项 |
| 5 | 事件长度的 `log`（归一） | 长告知天然占更多位置，与 §23 的聚合发现同源 |

分数 `score(e) = 特征1 + head(全部 5 个特征)`，`head` 零初始化 ⇒ **挂载与未训练时位级不变**；
选定结果在该轮生成结束前**固定**（消灭 §14 的逐步漂移）。位置寻址（同一条告知内看哪个字节）本件不动。
