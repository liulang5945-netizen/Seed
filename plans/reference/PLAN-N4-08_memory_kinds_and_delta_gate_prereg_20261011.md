# PLAN-N4-08 三类记忆职责与关联记忆 delta 门控的实现设计展开（V-15／V-16 的承载件；判据先冻、本件不开跑，2026-10-11）

## §0 为什么是这一件，以及它结的是哪一条债

`plans/active/roadmap/09_NEXT_MAINLINE_PLAN.md` §1.3 的对账规则写着"每个 N 项落 PLAN-Nxx 时，
必须消化表中归属该 N 项的全部条款（逐条在 PLAN 内展开为实现设计，**缺条即不完整**）"。
㊵-674 的普查（`scripts/training/audit_taiji_vision_clause_traceability.py`，读数件
`reports/taiji_vision_clause_traceability_20261011_after_v41.json`）量出归属 N4 的两条今天
**既无条款号引用也无章节锚引用**，且逐句核对确认是**确未展开**（不是"展开了没登记"）：

* **V-15（VISION §5.1 三类记忆职责分工）**——归属 N4，此前最接近的承载只有
  [PLAN-N4-03](PLAN-N4-03_s4_sparse_coding_prereg_20261009.md) 的稀疏编码，它动的是写入端编码，
  没有回答"哪一类记忆负责什么、谁不许负责什么"；
* **V-16（VISION §5.2 关联记忆门控 delta 机制）**——归属 N4，此前无承载件。

本件把这两条**展开成实现设计并冻住验收判据**。本件**不开跑、不动产品码**：§4 的实施批次里
凡动 `taiji/`／`seed/` 的格子都要 owner 批文（形状同 PLAN-N5-05：判据先冻、后动码）。

## §1 V-15 的展开：三类记忆在仓内的实际对象与职责边界（逐条给代码锚）

| 类别 | 仓内实际对象（现读存在） | 负责什么 | **不许**负责什么（缺这一列就是假展开） |
|---|---|---|---|
| 情节（episodic） | `EpisodicMemoryStore`（`seed`／挂载见 [PLAN-N4-09_episodic_mount](PLAN-N4-09_episodic_mount_prereg_20261009.md)），读回走 `MemoryRecall`（`taiji/state.py:369`） | 原样存"这一段发生过"：cue→payload，可回读、可逐条淘汰 | 不得被当成"能力"来源：容量有限、会淘汰，任何跨会话结论都不许只由它承担 |
| 语义（semantic） | `SemanticMemoryLearner`（`taiji/semantic_memory.py:18`） | 跨经历的规律（权重里的可迁移部分），是"会了"的承载 | 不得声称记得**具体一次**事件；它没有逐条回读口，所以任何"我记得那次"的读数不能记在它头上 |
| 程序（procedural） | `ProceduralMemoryLearner`（`taiji/procedural_memory.py:28`）、`NativeProceduralMemoryTrainer`（`taiji/procedural_evolution.py:89`） | 怎么做（输出侧的持久改） | 不得代替前两类参与寻址验收：寻址失败率是**读取通路**的量，不是执行能力的量 |

**职责分工的可核验形式**＝写入端自述"这一次动了哪一类"。今天没有这个自述 ⇒ §3 的 `J-N4g-1`
把它写成判据而不是散文。

## §2 V-16 的展开：门控 delta 用现成机制，不新造张量

关联记忆要的是"按预测误差定向更新、并被门控限制范围"。仓内**已有**这套零件，本件只做接线与
验收，**不新增参数面**（新增张量要另走"参数面加新张量的三件配套事"那条流程）：

* 误差信号＝`eligibility`（资格迹）× 全局标量误差——发育 F1 通路已在用（`developmental_f1/*eligibility`
  与 `fast_delta`，㊵-636 落地时逐枚命名过槽位）；
* 门控＝**变化量上限**：`fast_delta` 的幅度就是天然的门（`PLAN-N5-07` 的守卫臂已证明它可以为 0
  也可以非 0，具备动态范围）；
* 遗忘＝只作用于**可逆层**（`fast_delta` 可清），持久项不许被门控顺带抹掉（这正是
  DEBT-G76 那条"位置列不进 fast/slow 可逆层"的教训反向应用）。
* **不照抄示意式**（09 §2 N4 原话）：方向、归一化、门的取值一律由 §3 的判据在真面上现取，
  本件不预设数值。

## §3 判据（冻；跑面时生效。全部沿用已冻公式，不新增阈值字面量）

* **J-N4g-1 写入端职责自述在场**：每次写入必须落一条 `touched_memory_kinds ⊆ {episodic, semantic,
  procedural}`；三类的并集必须非空、且**不许是全集自动为真**——同一条经历在只动情节的装配下
  必须出版 `{episodic}` 单元素。缺自述键 ⇒ 记 `unverified_self_report_absent`，不得读成"没动"。
* **J-N4g-2 重命名不变性**：同一事件把对象标识符换成未出现过的新符号，寻址顶位命中必须不变
  （取 `measure_taiji_n4_addressing_surface.py` 的 `wrong_top1_rate`，两侧差 `== 0`）。
* **J-N4g-3 属性交换跟随性**：两条记忆的**可读属性**互换后，寻址结果必须跟着互换（成对判定）；
  若顶位仍指向原对象 ⇒ 判 `name_or_position_shortcut`（"记的是名字/位置不是属性"），
  与 [PLAN-N4-06](PLAN-N4-06_perturbation_strength_and_ruler_prereg_20261009.md) 那族捷径诊断同形。
* **J-N4g-4 干扰与占满分开判**：(a) 加入 K 条干扰后的差值必须 **> 该档自取噪声带**才许出结论，
  否则整条记 `ruler_unusable`（沿用 `adjudicate_taiji_n5_shadow_gate.py:295 〔2026-10-11 ㊵-685 行号更正：现行行号＝299。㊵-673 那次提交 `240b20210` 给该文件 +28/−10，把 `ruler_usable` 那行从 295 推到 299；口径未变，引用前按现行行号回查。〕` 的 `ruler_usable` 式，
  **不新造阈值**）；(b) 库满时读取端必须**响亮拒绝或记录淘汰**，不许返回空——空库与寻址失败在
  34.6% 那次读数里就是被混成一谈的（DEBT-G65 同族）。
* **J-N4g-5 门控真的在门**：门的开与关必须造成 `fast_delta` 幅度**可分**（复用 PLAN-N5-07 的
  `mode_readings`／幅度现读形状）；两档逐位相同 ⇒ 判 `gate_inert`，本件结论全部收回。
