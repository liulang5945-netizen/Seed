## 3. 资源配平的四个允差

### 3.1 先分清两类"同"

- **同信息权利＝离散项，逐条相等，无容差。** 六类权利（可见输入、反馈通道、禁止写入项、可见历史长度、可用编码/表达接口、评分 oracle 不回流）见 §5 第 5 项。差任何一条即 `baseline_information_rights_differ_from_u2`——"差一点也算同"在本卡不存在。
- **同量级＝四个连续资源量各带一个技术容差**，且必须**同时**满足。任一越带即 `baseline_resource_imbalance`。

### 3.2 参数量：`|N − 22742| / 22742 ≤ 10.0%`（带 [20,467, 25,016]）

**依据（步长算术，均为 0-step 构造可算）**：在 22.7k 这个尺度上，两个候选的**单个整数步**就把参数量挪动 3%–5%——
- `gru_sequence`（前端宽 89＝rgb 48＋audio 33＋proprio 8、单层、逐字头共用 257 词表）：每 +1 隐藏单元 `ΔN = 3·(89+2h+2) + 257 ≈ 746`（h≈36 处）= **3.28%**。
- `transformer_sequence`（单块、ffn=4d、共用 257 词表）：每 +1 `d_model`，`ΔN ≈ 12·(2d+1) + 2·257`，d=24 处 **4.85%**。

**为什么这个量级算"同量级"**：10% 带内至少容纳 **2 个**不同整数配置，说明这个带不是靠"正好凑出来"才能满足；同时 ±10% 折算成宽度差 ≤8%，递归核的矩阵乘工作量 ∝ h² 因此差 ≤17%——两臂仍在同一个容量档。

**取大一档（20%，±4,548）差在哪**：等于 6.1 个 GRU 隐藏单元（递归核宽 17%，矩阵乘约 +36%）或 4.1 个 `d_model` 步（宽 17%）。到这个跨度，"两臂共用一张价目表"在构造上就不成立，"按实际资源配平"退化成"每臂单记一笔"。

**取小一档（5%，±1,137）差在哪**：等于 1.5 个 GRU 单元 / 1.03 个 `d_model` 步。Transformer 一侧带内只能容下**一个**整数点，且当最近步落在 4.9% 处时**一个都容不下** → 该架构会因"取整不巧"被排除（`baseline_parity_infeasible` 误触发），这是拿粒度排除架构，不是拿能力排除架构。

### 3.3 峰值内存：`ΔRSS(base) ≤ 1.20 × ΔRSS(U2)`

定义：`ΔRSS = 一次前向+反向的进程峰值 RSS − 同进程 import 完、构造模型前的 RSS`；同设备（cpu）、同 dtype（float32）、同 batch、同序列长、同测量点、同线程数（`torch.set_num_threads`/`interop` 显式钉住）；取 3 次独立进程测量的**中位**。

**依据**：先扣掉解释器与 torch 的固定基线，容差才作用在"模型真正占的内存"上，否则百分比会被固定基线稀释成空门。**当前 `measured=false`**：ΔRSS 预计为个位数 MB 量级，冻结时按上述定义实测填入。

**取大一档（+50%）差在哪**：等于放行"两倍激活足迹"——例如把各层激活多留一份、注意力中间量存两遍、或片段里混进 batch=2。那是**另一种测量体制**，不是同体制下的另一种实现。

**取小一档（+10%）差在哪**：ΔRSS 与页粒度、allocator arena 抖动同量级，10% 会被噪声反复打穿，变成随机失败的假门；本卡宁可留 20% 并规定"3 次中位"，也不设一个分辨不出来的门。

### 3.4 CPU：`片段 CPU(base) ≤ 2.0 × 片段 CPU(U2)`，且**整段 update ≤ 120 CPU**

片段定义同上（同 batch/同序列长/同观测数/同前向反向次数/同线程数），3 次中位。120 为 22.4.1 的单次执行帽，本卡沿用同口径以保持可比。

**依据**：我们自己的 CPU 记账是**推定上界**（`cpu_upper_bound_derived`=12 s/attempt、`measured=false`），比实测斜率 s≈1.9 大约 6 倍（见 [D-20261111-14](DECISION-LEDGER_20261109.md)）。用一个比测量仪器更细的容差去判违规，等于用噪声定罪。2.0× 正好一个二进档，也是本账能分辨的最小倍率。

**取大一档（3.0×）差在哪**：最强基线一步到 s≈5.7 CPU，10 步整段 ≈ 8.6+57=65.6 CPU，而 U2 同口径 27.6 CPU——2.4 倍。一张价目表覆盖不了两臂，22.5 的三臂配对就失去共同价格尺度。

**取小一档（1.5×）差在哪**：会把 Transformer 在冻结序列长上的注意力常数（预计 1.6–1.9×）判成违规。那是实现常数差，不是容量差；用资源门排除架构，与 §1 的"本卡不判强弱"直接冲突。

### 3.5 wall：`片段 wall(base) ≤ 2.0 × 片段 wall(U2)`，且**整段 update ≤ 240 wall**

口径与 §3.4 相同，理由相同（wall 比 CPU 噪声更大——调度、IO、页错误——所以同样取 3 次中位）。

**取大一档（3.0×）**：慢三倍的臂仍可"配对"，但同一片段的 wall 与价格表不共享，测量本身失去可比性。
**取小一档（1.5×）**：噪声即可打穿（同上；wall 的抖动幅度大于 CPU）。

### 3.6 四个数合起来叫什么

> **同量级 = 参数量差 ≤10%（同容量档）∧ 峰值增量内存差 ≤20%（不换内存体制）∧ 同片段 CPU 与 wall 各 ≤2×（可共用一张价目表）∧ 绝对帽 120/240 不破（同预算体制）。** 四个条件**全部**满足才算配平；信息权利另行逐条相等，不参与任何百分比。

## 4. 确定性载体选择规则（唯一选中一个常规基线）

### 4.1 候选集（冻结自 22.4.4 原文，非本卡新增）

| `architecture_id`（冻结字面量） | 结构 | 唯一自由量 | 其余维度 |
|---|---|---|---|
| `gru_sequence` | 单层 `nn.GRU` 序列编码器 + 与 U2 同宽输出头 | 隐藏宽 h ∈ ℕ∩[8,128] | 全部由 U2 冻结的输入/输出接口决定 |
| `transformer_sequence` | 单块、多头注意力、因果掩码、ffn=4·d、无 dropout | d_model ∈ ℕ∩[8,64]（heads=4） | 同上 |

两候选**必须**复用 U2 的输入编码与多模态前端（不新造前端），否则"同信息权利"不成立。基线模块必须放在 `taiji/` **之外**：`taiji/*.py` 受"U2 自足"契约扫描（[test_architecture_contract.py](file:///e:/Seed/tests/taiji_native/test_architecture_contract.py) 与 `verify_taiji_native_v7` 都把 `TransformerEncoder`/`TransformerBlock`/`MultiheadAttention` 列为禁止符号）。

### 4.2 构造规则（保证参数量可判，且不能人为挑小）

1. 在各自网格上**逐点构造**（0 step），读出标量参数量 N 与命名张量数。
2. **选点**：取使 `|N − 22742|` 最小的整数点；同距取 **N 较小**者；仍并列取**宽度较小**者。
3. **资格**：选点后仍 `|N − 22742|/22742 > 10%` → 该候选记 `excluded_by_parity_band`，四项偏离量照实记账（§4.3 E2），**不得改网格放行**；是否停卡由 §4.3 的 E3 判定。
4. 两候选同前端、同输出头、同 dtype（float32）、同设备（cpu）。
5. 测量结果与逐参数 `(name, shape, dtype)` 清单当场落盘，作为 §5 的输入。

### 4.3 资格闸门（四条可判真假的检查）

记 `Q = {c : d_N(c) ≤ 0.10}`，`d_N(c) = |N(c) − 22742| / 22742`，`N(c)` 由 §4.2 第 2 步唯一确定。四条按序执行：

| # | 检查（写成可判真假） | 满足时 | 违反时 |
|---|---|---|---|
| **E1** | `\|Q\| == 1` | 唯一合格者**直接当选**：`selection_path="single_qualified"`、`tie_break_level=null`，**不执行 L1–L5** | 交 E3 / E4 |
| **E2** | 对每个 `c ∉ Q`：`status="excluded_by_parity_band"`，且 `param_delta_pct`、`rss_delta_pct`、`cpu_ratio`、`wall_ratio` **四项都存在且为数值** | 记账完成，留 22.5 | 任一缺项或非数值 → 本卡不通过（`exclusion_record_incomplete`），不得写身份清单 |
| **E3** | `\|Q\| == 0` | 判 `baseline_parity_infeasible`，**停卡报 owner**；不写身份清单、C09 保持假 | 本检查不触发 |
| **E4** | `\|Q\| == 2` | 执行 §4.4 的 L1–L5，必须产出唯一胜者并记录 `selection_path="tie_break"`、`tie_break_level∈{L1..L5}` | 选不出（L5 保证全序，理论上不可能）→ 按实现缺陷停卡，**不得手填** |

**E2 与 E1/E4 不互斥**：只要存在 `c ∉ Q` 且 `|Q| ≥ 1`，就必须执行 E2（`|Q|==1` 时同样要测落选臂的四项）。`|Q|==0` 时整卡已判停，只记两个候选的 `param_delta_pct`（构造即得、零成本），其余三项标 `not_measured_because_infeasible`，**不得编数**。

E2 的四项与 §3 同口径（同片段、3 次中位、`ΔRSS` 同定义），被排除臂的测量**计入** §6 的 250 CPU；若 250 不够，停卡报 `pricing_over_budget`，**不得少测一项来凑**。

**为什么不要"两个都合格"**：落选者**不参与 u2 的身份**——u2 只需要一个主强基线，§7 的三槽回填也只对它做；落选者只是 22.5 的对照臂。为一条只作参照的臂把整卡停摆，代价是：只要某条臂取整不巧（例如最近整数步落在 4.9%），整卡就停，而停的理由是**粒度**而不是**能力**——这反过来会逼人改网格去通过，而"改网格放行"正是 §4.2 第 3 条明令禁止的。故资格门只对**当选者**是硬的，对落选者是**如实记账**。

**代价与处置（写明，免得后来人以为漏了）**：22.5 的三臂价格表可能缺一条臂的完整价目。处置：落选臂四项偏离量照实入账；22.5 若要用它当对照臂，必须先按其偏离量判定它是"同量级对照"还是"仅作参考上界"，**不得默认进同一张价格表**。

### 4.4 选择链（仅在 `|Q| == 2` 时执行；全序、逐级可判、无并列）

按下表从上到下比较，**第一个不同处即胜负**：

| 级 | 判据 | 取值来源 | 可判性 |
|---|---|---|---|
| **L1** | 参数量 N **更小**者胜 | §4.2 第 2 步唯一确定 | 整数比较 |
| **L2** | `state_tensors` **更小**者胜 | 结构常量，身份清单声明：单层 GRU=**1**、单块因果 Transformer=**0** | 整数比较，不依赖测量 |
| **L3** | 峰值增量内存 ΔRSS **更小**者胜 | 3 次中位 | 整数（KB）比较 |
| **L4** | 同片段单步 CPU **更小**者胜 | 3 次中位 | 浮点，按 `round(x, 6)` 比较 |
| **L5** | `architecture_id` 字面量的 **Unicode 码位字典序更小**者胜 | 本文件冻结的两字面量 | `'g'`(U+0067) < `'t'`(U+0074) → `gru_sequence` 胜 |

L5 是**绝对可判**的一级：比较对象是本文件冻结的字面量，不是实现里的类名，因此**改名不能改变结果**。两字面量必然不同，故全序不可能并列。

> **L2 的定义**（避免"状态重建更简单"落成口号）：两次 update 之间**必须**由 bundle 显式持久化、且**不能**由参数与当步输入重建的在线张量个数。GRU 的 h 必须存；因果 Transformer 的 KV 在单片段内由输入重算即可，故记 0。

### 4.5 落选臂的处置

落选臂（`|Q|==1` 时的那一条，或 `|Q|==2` 时 L1–L5 输掉的那一条）**不在本卡冻结身份**，但仍留在 22.4.4 的三臂里（原文第 309 行），供 22.5 作对照臂。它的身份由**同一 §4.2 构造规则唯一确定**（因此不是"未定"，而是"待抄录"）；其 digest 必须在 22.5 开卡前按其首次进入价格或评测的时刻，按 §5 同一清单填实，**不得另行调参、换网格或另选初始化**。

若落选臂同时 `∉ Q`，抄录时必须带 `excluded_by_parity_band` 标记与 E2 的四项偏离量；22.5 **不得**把它当作"配平合格"的对照臂使用（只能作参考上界），也不得默认它与 U2 共用一张价格表。

## 5. 身份要件清单（缺任一项 → C09 假）

|---|---|---|---|
| 1 | **架构** | 模块路径（在 `taiji/` 外）+ 文件 `sha256` + 类名 + `architecture_id` 字面量 + 层数 + 自由量取值 + 归一化（有/无、类型、eps）+ 残差（有/无、位置）+ 激活 + 注意力头数 + 掩码类型 + 是否双向（GRU 必须单向）+ dropout=0 + 复用的 U2 前端/输出头组件名与其 `sha256` | C09 假：`baseline_identity_incomplete` |
| 2 | **参数量** | 标量总数 + 命名参数张量数（两个整数）+ 有序 `(name, shape, dtype)` 清单及其 `sha256` + dtype/device。0-step 构造后直接读出，**不得手算** | 同上 |
| 3 | **初始化** | 逐张量的初始化分布与参数；若用框架默认，须写明 torch 版本 + 函数名 + 默认值；初始化 RNG 的消费顺序；初始化 seed；初始化后 `state_dict` 逐张量 `sha256` 的汇总 digest。判据：**同 seed 两次构造 digest 必须相同** | 同上 |
| 4 | **训练配方** | optimizer 每字段（lr/betas/eps/weight_decay/amsgrad）+ batch + 序列长/窗口 + clip + warmup + 步数 + 损失项与权重 + 数据 recipe digest（片段生成器版本、seed、dt、每段观测数、反馈通道 red）+ 与 U2 臂**逐项点名相同**的项。凡与 U2 不同者必须写进 `recipe_delta` 并给理由；**未列入 `recipe_delta` 的差异视为违约** | 同上 |
