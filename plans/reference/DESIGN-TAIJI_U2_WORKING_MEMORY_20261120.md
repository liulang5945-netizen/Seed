# 设计草案：工作记忆写回（22.X，零训练设计稿）

> 状态：[设计草案/待实现] — 2026-11-20。依据 D-20261119-108：顺序递归在**状态已携带**的情况下仍无法组合（tick2 ≈ 机会），推断缺的是**显式把中间结果写回为下一步输入**（工作记忆），而不只是隐状态携带。

## 1. 机制定义

两步动作对（同 D-108）：tick1 看 r1 预测 `bin1`；tick2 看 r2 **并且**看「tick1 的预测桶」写回特征（one-hot 写入 48 维特征的 39–41 维；该区在动作数据上为空闲维度，已核对 `build_row` 布局 0–36 感知、37 方向、38 位置代理）。

写回两种模式：
- **自写回**：`bin1_hat = argmax(tick1 logits)`（detach），训练与评估都用模型自己的预测；
- **oracle 写回**：用真实 `bin1`（上限参考）；
- **对照**：零写回（39–41 全 0）、shuffled 写回（随机桶）。

## 2. 门（预注册）

1. **组合增益**：自写回 tick2 `≥0.55` 且比零写回高 `≥0.10`；
2. **写回必要性**：评估时把 39–41 清零（等价零写回）使 tick2 下降 `≥0.10`；
3. **oracle 参考**：oracle 写回 tick2 `≥0.65`（证明任务在写回下可学，排除任务本身不可学）；
4. **控制**：shuffled 写回 tick2 `≤0.45`。
四门全过 ⇒ `working_memory_writeback_ready`（有界：单主体、两步任务、显式写回通道）；否则按失败子条件记 partial/negative。

## 3. 实现与预算

- 复用 `UnitScan`（D-107 已验证）逐样本 tick1→tick2；写回特征在 tick2 输入前注入；
- 训练：tick1 CE(bin1) + tick2 CE(bin2)，1500 步；自写回用当前预测（detach，不反传到 tick1 标签路径）；
- 3 seed、零 check、**价 ≤200 CPU**；四门阈值不调。

## 4. 与既有负结果区别

| 形态 | 中间结果去向 | 结果 |
|---|---|---|
| D-102 重复输入 | 无中间结果 | negative（无深度收益） |
| D-108 状态携带 | 隐状态 `z/a` 携带，读出无法组合 | negative（tick2≈机会） |
| **本设计** | **显式写回为下一步输入特征** | 待测 |

## 5. 风险与出口

- 风险 1：写回桶在 tick2 前被忽略（读出仍只用 r2）→ 门 2 必要性检验暴露。
- 风险 2：自写回早期噪声导致训练不稳 → 记录 tick1 准确率与写回桶分布；若必要可预热 tick1 再开写回（须预注册）。
- 风险 3：oracle 也不过 0.65 → 任务本身不可学，记 `task_not_learnable` 并停止。
- 判读边界：即使通过也只是「显式工作记忆写回」有界成立，不等于一般递归推理；不改任务轴/check②。
