## 0. 一句话边界

这套系统的全部能力是：**把一段字节记录按“2 字节词集合”放进一个表，用一个在表内只出现一次的詞做锚点，读的时候只在这个锚点唯一时回答；回答的内容是写入时的 `fast` 快照；写的时候先扩容量再生效，整批要么全进要么全退。**

它现在**不具备**的能力，本文逐条标成“空接”或“未接”，不藏在代码里：
1. 读到的值还没有进入 `fast`（旧版 `_sc_sfk_read` 只返回判定，不改状态）；
2. 读没有成为下一笔写的依据（写入是调用方显式发起的，不读表）；
3. 没有修剪（prune）动作，死地址只增不减；
4. 地址层是闭式统计、0 参数，**不能被训练塑形**。

## 1. 状态清单

“生命周期”指谁创建、谁改变、谁销毁；“关闭态”指 `sc_sfk_enabled=False` 时该状态是否存在。

### 1.1 图内张量（参数）

| 状态 | 形状/量 | 生命周期 | 谁能改 | 关闭态 |
|---|---|---|---|---|
| encoder / read / write / world / readout 等全部 `nn.Parameter` | 135 个张量、3,311,259 个元素 | 构造时创建，随 subject 存活 | **只有优化器**；地址层任何动作都不碰 | 存在，字节不变 |
| `W, U, V, P, R, tau_logit, nu_projection` 等 | 同上 | 同上 | 同上 | 存在 |
| `candidate_sha_v2` | 摘要 | 由 `graph_identity` 计算 | 只读 | 不变 |

地址系统对参数的态度是**只读**：写入不产生梯度，读取不产生梯度，容量增长只改 Python 状态。这是“地址是本体缺件而不是阈值问题”的前提，也是“它还不能被训练塑形”的原因。

### 1.4 词频统计

`document_frequency` / `idf_table` / `unique_features` 都是**派生量**，每次读或自检时从 `addresses` 重算，不单独存。这是有意的：没有增量维护就没有增量漂移。代价是自检 O(n²)。

DF 的口径：一个地址的 `count` 是“这条记录被观测了几次”，DF 按次数累加。所以**重复写同一条记录会把它的词从“唯一”抬成“共享载体”**。这不是 bug，是夹具里 8 条基础记录合并成 1 个地址、其词变成载体的原因。

### 1.5 会话态 / 容量

- 会话边界由调用方调用 `attach_store` / `clear_store` 表达；`clear_store` **换一张新表**，旧表的值与历史整体丢弃（没有跨会话墓碑）。
- `growth_wire` 的 `generation` 目前**不在 state 里**，是函数参数传进传出；这是“接不上”的一项，第二步把它统一到 `expansions`。
- 容量没有硬上限（`slot_cap=None`），只有倍增。

## 3. 出口清单（必须由结构条件触发）

### 3.1 SC-SFK 读出口

| 出口 | 触发条件（结构） | 状态变化 | 旧版是否满足 |
|---|---|---|---|
| `no_store` | `state.sc_sfk is None` | 不动 | ✓ |
| `no_match`（未知词） | `∃w∈Q: DF(w)=0` | 不动 | ✓ |
| `no_match`（无唯一词） | `Q∩U(T)=∅` | 不动 | ✓ |
| `matched` | `|Anchors(Q)| = 1` | `fast ← (1−α)fast + α·value`（第二步） | 旧版是 `|anchors|=1 ∨ margin≥0.02`，**第二项是阈值** ✗ |
| `ambiguous_multiple_anchors` | `|Anchors(Q)| ≥ 2` | 不动 | 旧版是 else 分支，带阈值 ✗ |

其中 `U(T)={w:DF(w)=1}`，`Anchors(Q)={i : A_i ∩ (Q∩U(T)) ≠ ∅}`。修法：删掉 `ANCHOR_MARGIN`，`matched` 只由 `|Anchors|=1` 决定。

### 3.2 SC-SFK 写出口

| 出口 | 触发条件（结构） | 状态变化 |
|---|---|---|
| `appended_after_growth` | 表内无**完全相同**的特征集 | 先倍增容量，再追加 |
| `merged_duplicate` | 同特征集且值逐字节相等 | `count+1`，`values` 追加 |
| `replaced_at_same_address` | 同特征集且值不同 | 旧值进 `history`，当前值换新 |
| `rejected_batch_address_collision` | 批内两条同特征集、不同值 | 整批回滚，表不动 |
| `rolled_back_global_check_failed` | 写后自检失败 | 整批回滚，表不动 |

旧版写入口用 `COPY_OVERLAP=0.85` 的加权 Jaccard 判定“同址”，这是**为夹具调出来的阈值**；第二步改成**特征集逐项相等**（结构条件），`COPY_OVERLAP` 退役。代价：不同措辞（不同 2 字节集合）不再合并成同一地址；收益：写入身份不再依赖任何数值阈值。

### 3.3 全局自检（A11）的结构判据

旧版 `check_global` 的两条：
1. `self_read = ∀i: similarity(A_i,A_i) ≥ 1−1e-12` —— **恒真**：加权 Jaccard 的自相似度按定义等于 1（分子分母是同一个求和）。它不检验“能不能被锚定”，只检验“集合等于自己”。这是闭环里的一处**假接线**。
2. 两两 `similarity(A_i,A_j) ≥ 0.85` —— 阈值判据；而且两个地址能在写入时合并（同阈值），只在 IDF 漂移后才可能重新越过阈值，所以它抓到的是“漂移”，不是“身份冲突”。

第二步替换为两条结构判据：
- **G-A 无错指**：`∀i: read(A_i).address ∈ {None, i}`。任何地址的自身特征集，要么读回自己，要么说“不知道”，绝不能读到别的地址。
- **G-B 无附带损失**：记写前可锚定集合 `U_before = {i: A_i ∩ U(T_before) ≠ ∅}`，本批触及的目标集合 `Touched`。要求 `U_before \ Touched ⊆ U_after`。即：**一次写可以把自己的地址降级为载体（重复观测），但不能把别的地址的唯一词抢走。** 违反则整批回滚。
- **G-C 身份唯一**：所有 `A_i` 两两不相等（由“逐项相等才合并”在构造上保证，仍显式断言）。

这三条都是集合/计数条件，不含调出来的常数。

## 4. 闭环图

### 4.1 旧版真实回路（含三处空接）

```
写：raw ──features──► 相似度≥0.85 找同址 ──是──► merge / replace(value=raw.hex())
                              │否
                              ▼
                       先倍增容量 ─► append
                              │
                              ▼
                     DF/IDF 全表重算
                              │
                              ▼
              全局自检：自相似度=1（恒真） ∧ 两两<0.85
                     │通过                 │失败
                     ▼                     ▼
                  提交                  snapshot 回滚
                     │
                     │ value = 记录字节（不是 fast）
                     ▼
读：raw ──features──► 唯一锚点 ──0──► no_match ──► fast 不动 ──┐
                          ├──1──► matched ──► 只返回判定，不返回值 ◄── [空接1]
                          └─≥2──► ambiguous ──► fast 不动 ──────┘
                                                                  │
                                                    ┌─────────────┘
                                                    ▼
                                       下一笔写不读表 ── [空接2]
                                       纠正只能靠调用方显式再写 ── [空接3]
```

- **空接 1**：读命中了，但 `_sc_sfk_read` 不改 `fast`；即使改了，`value=raw.hex()` 也不是可混合的向量。接不上的原因：写入时没有把“当时的 fast 快照”存进去。
- **空接 2**：写入完全由调用方发起，读的结果不进入下一笔写的输入；没有“读→写”的回授。
- **空接 3**：没有“反馈→写→再读→再纠”的自动环；纠正只有同址不同值的 replace，且必须由外部显式触发。
- **假接线**：全局自检的 `self_read` 恒真，回滚分支实际上只能被 0.85 阈值触发。
- **未接**：修剪不存在；跨会话历史不存在；`growth_gate` 离线存在但未接入。

### 4.2 第二步落位后的目标回路

```
写：raw ──features──► 特征集逐项相等? ──是──► 同值 merge / 异值 replace(旧值进 history)
                              │否
                              ▼
                       先倍增容量 ─► append(value = 当前 fast 快照)
                              │
                              ▼
                     DF/IDF 全表重算（派生，不增量维护）
                              │
                              ▼
        全局自检 G-A 无错指 ∧ G-B 无附带损失 ∧ G-C 身份唯一
                     │通过                         │失败
                     ▼                             ▼
                  提交                       snapshot 整批回滚
                     │
                     ▼
读：raw ──features──► 唯一锚点 ──0──► no_match（fast 不动，显式“不知道”）
                          ├──1──► matched ──► value 快照 ──► fast ← (1−α)fast + α·value
                          └─≥2──► ambiguous（fast 不动，显式“说不准”）
                                              │
                                              ▼
                              新的 fast 成为下一笔写的 value ──► 反馈环闭合
                                              │
                                              ▼
                              再读同一地址 ──► 值覆盖/幂等 ──► 纠正环闭合
```

闭合后的三段回路：
1. **局部写 → 全局统计 → 自检 → 通过/回滚**：`write_batch_checked` 内完成，判据是 §3.3 的 G-A/G-B/G-C。
2. **读 → 是否进 fast**：`matched` 才混合，`ambiguous/no_match` 明确不动。
3. **反馈 → 写 → 再读 → 再纠**：读后的 `fast` 是下一笔写的值；同址不同值走 replace，旧值进 history。

仍然接不上、但已显式占位的两段：
- **修剪**：没有安全的删除判据（删值会破坏旧值守恒），所以不接；见 §6.4。
- **跨会话**：`clear_store` 丢弃整表，没有墓碑/回放；跨会话连续性是另一个系统，不在这套里假装有。

## 8. 第三步：形式化（定义、定理、证明、反例边界）

> 本节只覆盖第二步落位后的 SC-SFK 系统。符号与 §1–§3 一致：`A_i` 是地址 `i` 的特征集合，`c_i` 是观测数，`v_i` 是当前值，`H_i` 是旧值历史，`T` 是表，`U(T)={w:DF(w)=1}`。
> 不引用 U1 勘误中标为 INVALID EVIDENCE 的结论；不用实测数据代替证明。

### 8.1 定义（全部可计算）

**D1 地址.** 记录 `x∈{0,1}^{8*}` 的特征集 `φ(x) = { hex(x[2k:2k+2]) : 0 ≤ k < ⌊len(x)/2⌋ }`（奇数尾字节丢弃），去重。表 `T` 的地址是序列 `(A_1,…,A_n)`，`A_i=φ(x_i)` 非空；地址 `i` 的身份就是 `A_i` 本身（不是向量，不是哈希）。

**D2 文档频率.** `DF_T(w) = Σ_{i: w∈A_i} c_i`；`N_T = Σ_i c_i`；未出现记 0。

**D3 唯一特征集.** `U(T) = { w : DF_T(w) = 1 }`。`U` 只依赖计数，不依赖 idf。

**D4 锚点.** 对查询 `q`，`Q=φ(q)`，
`Anchors_T(q) = { i : A_i ∩ (Q ∩ U(T)) ≠ ∅ }`。

**D5 读判定.**
- `no_match` 若 `∃w∈Q: DF_T(w)=0` 或 `Q∩U(T)=∅`；
- `matched(i)` 若 `Anchors_T(q)={i}`；
- `ambiguous` 若 `|Anchors_T(q)|≥2`。

**D6 写目标.** `target_T(A) = i` 若 `A_i = A`（逐项相等），否则 `⊥`。写动作：`⊥→append`；`i` 且 `v∈values_i→merge`；`i` 且 `v∉values_i→replace`。

**D7 可锚定.** `Addr(T) = { i : A_i ∩ U(T) ≠ ∅ }`。

**D8 容量.** `C_0=2`；写前若 `n ≥ C` 则 `C←2C`，`expansions+1`。`C` 是声明上界，append 不复制。

**D9 全局自检.** 对写前表 `T`、写后表 `T'`、本批目标集合 `Touched`：
- G-A：`∀i: read_{T'}(A_i).address ∈ {None, i}`；
- G-B：`Addr(T) \ Touched ⊆ Addr(T')`；
- G-C：`i≠j ⇒ A_i ≠ A_j`。
三条全过才提交，否则 `restore` 到写前快照（内容逐项复原；事件计数不回滚）。

**D10 读混合.** `matched(i)` 时 `F' = (1−α)F + α v_i`，`α=ADDRESSED_ALPHA=0.5`；`no_match/ambiguous` 时 `F'=F`（逐字相等）。

**D11 相似度（只作读数，不参与判定）.** 加权 Jaccard
`sim(A,B) = Σ_{w∈A∩B} idf(w) / Σ_{w∈A∪B} idf(w)`，
`idf(w)=log(1+N_T/(1+DF_T(w)))`，`w∉T` 时取 `log(1+N_T)`。它的唯一用途是报告 `top1/top2/margin`；**没有任何出口读它**。

### 8.2 定理

**定理 1（唯一锚定的充分条件 / 不会错指）**
*假设*：`q` 的每个特征都在 `T` 中出现（`∀w∈Q: DF_T(w)≥1`）。
*结论*：`Anchors_T(q) ⊆ { i : A_i ⊇ Q∩U(T) }`；特别地，若 `q` 是某条已存记录的特征集 `A_i`，则 `Anchors_T(A_i) ⊆ {i}`，于是读 `A_i` 只能得到 `matched(i)` 或 `no_match`，**不可能读到别的地址**。
*证明*：取 `i∈Anchors`，存在 `w∈Q∩U` 且 `w∈A_i`。`DF(w)=1` 意味着全表恰有一个地址含 `w`（按次数计，`c_j≥1` 的任何地址都算），所以含 `w` 的地址唯一，只能是 `i`；若 `j∈Anchors` 也由同一个 `w` 锚定，则 `j=i`。对 `q=A_i`：任何 `w∈A_i∩U` 都满足 `DF(w)=1` 且 `w∈A_i`，故其唯一含者就是 `i`；若 `Q∩U=∅` 则 `no_match`；若 `A_i` 有特征 `DF=0` 则不可能（`A_i` 是已存集合）。∎
*退化*：A1 不成立（`Q∩U=∅`）时结论退化为“只能说不知道”，不会给出错误地址。

**推论 1（充分条件的可检验形式）**
若存在 `w∈Q` 使 `DF(w)=1`，且所有这样的 `w` 都属于同一个地址 `i`，则 `matched(i)`。这是构造地址时的充要判据；代码用 `|Anchors|=1` 直接检验，不需要先求“所有唯一词的主”。

**定理 2（词频漂移的界）**
*假设*：一批写入 `B={x_1,…,x_m}`，写前表 `T`，写后 `T'`；`Δ = Σ_j |φ(x_j) ∩ U(T)|`（本批带进来的、写前唯一的特征出现次数，按记录计）。
*结论*：
1. 只有含 `w∈U(T)` 的地址可能失去可锚定性；具体地，`i∈Addr(T)\Addr(T')` 仅当 `A_i ∩ U(T) ≠ ∅` 且 `A_i` 的某个唯一特征在 `B` 中出现。
2. 失去可锚定性的地址数 `|Addr(T)\Addr(T')| ≤ Δ`。
3. 若 `B` 的特征与 `U(T)` 不交（`Δ=0`），则 `Addr(T') ⊇ Addr(T)`，一个旧地址也不会掉。
*证明*：`DF` 只在 `B` 的特征上增加。对 `w∉⋃φ(x_j)`，`DF_{T'}(w)=DF_T(w)`，故 `U(T)` 中未被 `B` 触及的特征仍是唯一，其所属地址保持可锚定。若 `i` 掉出 `Addr`，它写前必有一个唯一特征 `w`（否则写前就不可锚定），而写后 `w` 不再唯一，只能是 `DF` 在 `w` 上增加，即 `w∈⋃φ(x_j)`；每个这样的 `(j,w)` 贡献一次计数，故失去的地址数不超过 `Δ`。`Δ=0` 时没有 `w` 的 `DF` 变化，`U(T')=U(T)`，结论 3 成立。∎
*说明*：`Δ` 是本批“抢锚”的代价上界；G-B 在 `Δ` 落到别的地址时整批拒绝，所以系统实际保证的是 `Addr(T)\Touched ⊆ Addr(T')`，比定理 2 的计数界更强。

**定理 3（容量倍增的摊销代价）**
*假设*：从 `C_0=2` 开始，只追加、不删除，第 `n` 次追加前按 D8 倍增。
*结论*：
1. `expansions(n) = max(0, ⌈log_2(n/C_0)⌉)`（`n` 为追加后的地址数上界意义下），且 `C(n) ≤ 2·max(C_0,n)`。
2. 若 append 需要复制整表（定长数组实现），总复制代价 `Σ_k C_k ≤ 2C(n) = O(n)`，单次摊销 `O(1)`。
3. 本实现 append 是 Python list 追加、容量只是标记，复制代价为 0；单次写的实际主项是全局自检的 `O(n²·f)`（`f` 为平均特征数），容量倍增不改变这一项。
*证明*：倍增序列 `2,4,8,…` 的几何和 `< 2·末项`；每两个容量级之间至少发生一次追加，故级数与 `log n` 同阶。列表追加的均摊复制由 CPython 的 over-allocation 承担，与本模块的 `capacity` 无关；自检对每对地址做集合交并，`n(n−1)/2` 对，每对 `O(f)`。∎
*边界*：`n` 大时写变慢的是自检，不是扩容量；若要 `O(n)` 写，应把 G-C 改成哈希集合（当前不做，因为 `n` 很小且要保留逐项可审计性）。

**定理 4（合并/取代的幂等性与旧值守恒）**
*假设*：同一个地址 `A_i`，写入序列 `(A_i,v_1),(A_i,v_2),…`；值比较是逐字节相等。
*结论*：
1. **地址幂等**：任何次数的同址写都不改变 `A_i`，也不改变 `i`。
2. **值幂等**：重复写同一个 `v` 是 merge，`values_i` 的当前值仍是 `v`，读回的值不变（只有 `c_i` 增加）；因此“读到的值”对重复观测幂等。
3. **旧值守恒**：任何 replace 都把被取代的当前值追加到 `H_i`，再把 `values_i` 的当前值换成新值；`values_i` 与 `H_i` 不重叠，二者的多重集合并等于全部观测值的日志，旧值永不丢失。
4. **取代的收敛**：连续两次 replace 到同一个 `v'`，第二次是 merge（因为 `values_i[-1]=v'`），值固定；replace 序列的当前值等于最后一个写入的值。
*证明*：(1) 由 D6，`target` 只由 `A_i` 决定；(2) merge 只 `count+1`，`values_i` 不变；(3) replace 在改 `values_i` 之前执行 `H_i.append(values_i[-1])`，之后执行 `values_i[-1]=v'`，故被取代的值只进不出且不与当前值重复；(4) 第二次写时 `values_i[-1]=v'`，走 merge。∎
*注意*：`count` 不是幂等的（每次观测 +1，merge 和 replace 都算一次观测），这是有意的“观测次数”语义；它影响 `DF`，进而影响可锚定性（定理 2），所以重复写同一条记录会把它的词降级为载体。`values` 只保留当前值，`history` 只保留被取代的值，两者不重叠，内存 O(观测数)。

**定理 5（整批拒绝的原子性）**
*假设*：`write_batch_checked` 在一次调用内完成；表内容 `Content(T) = (addresses 的 features/values/history/count, capacity)`；`snapshot` 深拷贝这些字段。
*结论*：
1. 批内冲突（同址不同值）时，`Content` 与调用前逐项相等；`rejected_batches` 单调 +1。
2. 写后自检失败时，`Content` 与调用前逐项相等；`rollbacks` 单调 +1。
3. 任何“部分写入后失败”的中间态不会暴露给调用方（函数返回前已 `restore`）。
*证明*：冲突路径在返回前执行 `restore(snapshot)`；自检失败路径在同一函数内 `restore(snapshot)` 后才返回。`snapshot` 含 `features/values/history/count/capacity/peak_capacity`，`restore` 逐字段写回。事件计数（`rejected_batches/rollbacks/global_checks`）不在 `Content` 内，是审计量，不回滚。∎
*边界*：`peak_capacity` 不回滚（它记录曾经达到的最大值），所以回滚后 `capacity` 可以变小而 `peak_capacity` 不变；这是有意的，容量是声明上界，不是内容。

**定理 6（读不到锚点时必须能说“不知道”）**
*假设*：读入口只有 D5 的三个分支；没有其他路径能返回值。
*结论*：若 `Q∩U(T)=∅` 或存在 `DF=0` 的特征，则 `read` 返回 `no_match`，`fast` 逐字不变；系统**不可被强迫作答**。
*证明*：D5 的第一个条件先于锚点计算返回；`Q∩U=∅` 时 `Anchors=∅`，走 `no_match`；D10 规定只有 `matched` 才混合，其余分支 `F'=F`。值只通过 `matched` 分支的 `v_i` 进入状态，空锚点集没有 `i` 可取。∎
*边界*：legacy dense store 不满足这条（softmax 总给权重）；这是本文不把 legacy 计入结论的原因之一。

**定理 7（读入 fast 的可逆性与二次稀释的界）**
*假设*：`F∈R^d`，`V=v_i` 是唯一锚定地址的当前值，`α∈(0,1)`，一次读 `R_V(F)=(1−α)F+αV`。
*结论*：
1. **幂等点**：`R_V(V)=V`；若 `F=V`，读不动。
2. **收缩**：`‖R_V(F)−V‖=(1−α)‖F−V‖`；连续 `k` 次读同一 `V`（中间无其他更新）后，`‖F_k−V‖=(1−α)^k‖F_0−V‖→0`。
3. **二次稀释**：`R_V(R_V(F))=(1−α)²F+α(2−α)V`；原始分量权重 `(1−α)²`，`α=1/2` 时为 `1/4`。
4. **可逆性**：`R_V` 是仿射双射（`α<1`），逆为 `F=(F'−αV)/(1−α)`；在唯一锚定下 `V` 可从表里取回，所以**单次读可逆**。但连续读不同的 `V_1,…,V_k` 后，`F_k` 是 `k+1` 个向量的凸组合，仅凭 `F_k` 无法唯一分解；可逆性只对“已知 `V` 的单次读”成立。
5. **不回答时零扰动**：`no_match/ambiguous` 下 `F'=F`，逐字相等（不是近似）。
*证明*：(1)(2)(3) 直接代入；(4) `α<1` 时 `1−α>0`，仿射映射可逆，逆式代入即得；不同 `V_j` 的复合是 `(1−α)^k F_0 + αΣ_{j=1}^k (1−α)^{k−j} V_j`，`k+1` 个未知量一个方程，不唯一；(5) 由 D10。∎
*注*：读的“可逆”不意味着“无损”：单次读丢掉的是 `F` 在 `V` 方向之外的分量的一部分，逆式需要已知 `V`；系统不保存读前的 `F`，所以工程上不提供回滚读。定理只给代数可逆性与稀释界。

## 13. 定义 A：内容决定切分＋保护带＋序列包含（2026-11-08）

### 13.1 验收哲学的改变

本轮不再用“说不准／不知道”过门。**每一次读都必须给出一条 top-1 实际输出**（选中记录的一段连续字节切片＋出处），弃答只作读数（`no_anchor`、`ambiguous_candidates`、覆盖分布），不进通过条件。评分改为三层，全部按输出判：L1 机械（有没有编造字节、切片是否合法）、L2 内容（是否逐字来自它声称的记录）、L3 选择（指的那条是不是正确的那条）；错误分三类：错人／编造／空输出。

### 13.2 冻结定义

- **切分**：gear 哈希（`rolling = ((rolling << 1) + gear[byte]) & (2^64-1)`，gear 由 `sha256("taiji-gear-v1" + byte)` 确定性生成）；窗口 16（低 6 位只看最后 6 字节）、掩码 `0x3F`、最短 16、最长 128（强制切）。块指纹 `sha256(chunk)[:16].hex()`。
- **身份**：`S(r)` ＝ 丢弃覆盖首 16／尾 16 字节的块之后，剩余块的指纹**有序序列**；剩余不足 2 块即无身份。
- **锚定**：`S(r)` 是查询全部块指纹序列 `C(Q)` 的**连续子序列**。0／1／≥2 个锚分别记 `no_anchor`／`matched`／`ambiguous_multiple_anchors`，**只作读数**。
- **结构保证**：任何前缀、后缀、套语或别的记录里的一段文字，都无法为一条查询制造出指向他人的锚点——锚点要求目标记录的**整个内部**按序连续出现。中间改动按不匹配处理，不加容差参数。
- **写侧**：0 回滚／0 驱逐／0 静默覆盖；单条拒收条件 (a) 剩余块 < 2、(b) 同身份异值、(c) 与已有身份互为连续子序列（包含冲突）。DF／唯一词／G-A／G-B／G-C 随旧定义删除。
- **输出**：按覆盖块数降序 → 覆盖比例降序 → 地址序升序取 top-1；包含时输出整条记录，否则输出最长连续匹配段的字节区间；零覆盖也输出首条记录完整字节。出处＝地址、区间、覆盖、身份块数。

## 14. 局部谓词切分（2026-11-08，§13.5 的唯一后继已执行）

### 14.1 改动（写死，其余不动）

- **切点只依赖局部字节窗口**：对缓冲区的每个绝对位置 `i`，`h_i = (h_{i-1} << 1) + gear[x_i] (mod 2^64)`，在 `(h_i & 0x3F) == 0` 处切。滚动哈希**从不重置**，没有“距上一刀至少 16 字节”，也没有 128 字节上限。
- 低 6 位只由**最后 6 个字节**决定（`h_i = Σ gear[x_j]·2^(i-j)` 中 `i-j ≥ 6` 的项模 64 为 0），所以切点判定确实只看一个固定局部窗口。
- **短块不进身份**：切点集确定之后才看长度，长度 `< 16` 的块直接丢弃（不合并、不延长、不回头改切点）。保护带仍丢首尾 16 字节；`S(r)` 仍是剩余块的有序指纹序列；锚定仍是“`S(r)` 是查询全块序列的连续子序列”；写侧规则、确定性 top-1 规则、出口一律不动。

### 14.2 平移不变：可检验的陈述

> **命题**：对任意字节串 `r` 与任意前缀 `p`，`S(p + r) ⊇ S(r)`（指纹多重集与顺序都相同），且 `S(r)` 在 `C(p + r)` 中连续出现。

证明（可逐条检查）：

1. 下标 `i` 处的谓词只读 `x[i-5..i]`（14.1 第二条）。因此 `K(p + r) ∩ [|p| + 5, |p| + |r|] = {|p| + k : k ∈ K(r), k ≥ 5}`，早于 `|p| + 5` 的切点只可能落在 `p` 内或接缝处。
2. `S(r)` 只保留 `start ≥ 16` 且 `end ≤ |r| - 16` 的块，两个端点都 `≥ 16 > 5`，所以每个被保留块的左右切点都在上面的等式范围内，块内容与指纹逐字节相同。
3. 被保留的块在 `r` 内两两相邻（中间没有别的切点），平移后在 `p + r` 内也两两相邻；因此它们构成 `C(p + r)` 的一段连续子序列。
4. 后缀同理：谓词是**因果**的（只看左边），追加后缀不改变 `r` 内任何切点；唯一影响是最后一个块变长，而它落在尾部保护带内，不进 `S(r)`。

**失效构造（必须能指出）**：

- 把保护带设为 0（`PROTECT = 0`）：1 字节前缀就会让首块内容改变，`S(r)` 的第一个指纹不再出现，命题立即失败。现有 `PROTECT = 16 > 5` 是这条证明成立的实际条件。
- 任何“距上一刀至少 `m` 字节”的谓词：长度 1…`m-1` 的前缀会移动“最早可切位置”，首刀移动后每一刀的绝对位置都被非恒定地改写，体内块内容随之改变——这正是 §13 的 8 条错人。
- 任何“最长 `M` 字节强制切”的规则：强制切点由“距上一刀”决定，前缀会移动上一刀，从而移动强制切点。

## 15. 短条目可寻址＋有信息的回退（2026-11-08，§14.5 的唯一后继已执行）

### 15.1 改动（两件一起做，其余不动）

- **保护带收到谓词的真实依赖宽度**：`PROTECT = WINDOW = 6`。偏移 `a` 处的切点只读 `r[a-6:a]`，所以前缀只能扰动 `a < 6` 的切点；6 是使 15.3 的等式成立的最小带宽，不是调出来的经验值。
- **只丢末块**：身份保留所有满足 `start >= PROTECT` 且 `end < len(r)` 的块。`end == len(r)` 的块右端是缓冲区末尾，任何后缀都会改写它，因此只有它必须出局；其余块的右端是真实切点，后缀碰不到。
- **块数下限 2 → 1**：一条记录只要还剩 1 个身份块就有地址；空身份仍被拒绝（空身份是任何查询的子序列，会锚定一切）。
- **回退规则换掉**：见 15.4。切分谓词、块指纹、序列包含的锚定规则、写侧三条拒收、top-1 规则一律未动。

### 15.2 最短可寻址长度（写死的量）

> **`MIN_ADDRESSABLE = MIN_CHUNK + PROTECT + 1 = 16 + 6 + 1 = 23` 字节。**

推导：一个身份块 `[a, b)` 需要同时满足 `a >= 6`、`b - a >= 16`、`b <= len(r) - 1`，故 `len(r) >= a + 16 + 1 >= 23`。它由三者共同决定——**块长下限**（`MIN_CHUNK`）、**保护带**（`PROTECT`，即谓词窗口）、**末块右端必须严格在缓冲区内部**（`+1`）——不是单独由保护带决定。

**必要非充分**：`a` 与 `b` 是否真的是切点由内容决定，所以 23 字节以上的记录仍可能没有身份；23 字节以下则**结构上不可能**有身份。本轮语料 58 条长度 **156–1072 B**，观测到的最短可寻址记录 **156 B**；`unaddressable_records = []`、`structurally_unaddressable_below = []`，即这批语料里没有落在“不可寻址”区间的记录。

### 15.3 平移不变：前提、等式、失效构造

**前提**：偏移 `i` 的切点谓词为 `pred(r, i) = ((h_i & 0x3F) == 0)`，其中 `h_i = Σ_{k<i} G[r[k]] · 2^{i-1-k} mod 2^64`；模 64 只剩最后六项，故 `pred(r, i)` 只依赖 `r[i-6:i]`。身份保留每个满足 `a >= 6`、`b - a >= 16`、`b < len(r)` 的块 `[a, b)`。

**等式**：对任意前缀 `p` 与后缀 `s`，`S(r)` 是 `C(p + r + s)` 的**连续子序列**。

证明（逐条可查）：

1. **前缀**：对所有 `6 <= i <= len(r)`，`pred(p + r, |p| + i) = pred(r, i)`，因为结束于 `|p| + i` 的六字节窗口正是 `r[i-6:i]`。于是 `r` 的每个 `a >= 6` 的块 `[a, b)` 就是 `p + r` 的块 `[a + |p|, b + |p|)`，字节与指纹都相同。
2. **后缀**：对所有 `i <= len(r)`，`pred(r + s, i) = pred(r, i)`（窗口仍在 `r` 内结束）。于是每个 `b <= len(r) - 1` 的块逐字节存活；只有右端贴缓冲末尾的末块会变，而它不在身份里。
3. **两者同时**：被保留的块顺序不变、指纹不变、相邻块之间没有插入任何块；`p + r + s` 的两端只可能贡献 `S(r)` 之外的块。故 `S(r)` 连续出现。

**失效构造**（每条都是一个把常量写错就立刻破的反例）：

- `PROTECT < 6`：取 `r` 在偏移 4 有切点、块 `[4, 20)`；前插 1 字节后，结束于 4 的窗口变成 `p + r[0:4]`，该切点可能消失，`[4, 20)` 并入首块，指纹消失。6 是能排除它的最小带宽。
- 不丢末块：给 `r` 追加 1 字节，末块变成 `[last_cut, len(r)+1)`，指纹改变，含它的身份失去锚点。
- 短块合并（而不是丢弃）：合并会改变下一块的起点，其字节与之后所有指纹重新依赖前缀。
- 保留首块（`a >= 0`）：15 字节引导语让首块吸收前缀，指纹改变，该记录不再被锚定。
- 允许**空身份**：`S(r) = ()` 是任何 `C(Q)` 的连续子序列，于是每个查询都锚定这条记录——正是“1 块下限”要禁止的错指。

本轮实测：**1102 条构造**（前缀 0/1/5/6/15 × 后缀 0/1/3/7，以及两者组合）在 58 条记录上**0 失败**；`records_keeping_first_chunk = []`、`records_keeping_final_chunk = []`（首块与末块从不进入身份）；`identity_empty_records = []`。

### 15.4 回退：只决定“输出谁”，不决定“是否输出”

无锚点时（一个记录的 `S(r)` 都不连续出现在 `C(Q)` 里），按**块级重合度**排序：

> `overlap(r, Q) = shared / (|S(r)| + |C(Q)| - shared)`，`shared` = 查询块与该记录身份块的**多重集**交集（同指纹计次数）。

三条约束：

1. **标注是读数，不影响是否输出**：无论 `fallback` 还是 `matched`，top-1 一律输出。
2. **不引入通过/拒绝阈值**：重合度只用于排序，没有“低于某值就拒答”。
3. **旧规则被删除**：旧实现“按覆盖块数最多、覆盖为 0 时退到地址序最小”等于对一切零覆盖查询恒指记录 0，不携带查询信息；本轮删除该分支。

## 16. 输出单元：输出必须是一个可用的答案（2026-11-08）

### 16.1 判定口径的更换

§15 的 L1 只问“字节是否可从那块内存里取出来”，因此一个跨 UTF-8 字符的字节片段也算“合法切片”。这是把**出处**当成了**答案**。§16 把判定改成：

> 输出必须是**完整可解码的文本单元**，逐字来自它声称的记录，并且指向**该给的那条**记录。

三层重定义（跑前冻结在 manifest 里）：

| 层 | 问什么 | 冻结口径 |
|---|---|---|
| L1 机械 | 有没有编造、有没有非法切片 | 编造字节 = 0；非法切片 = 0；**UTF-8 可解码 = 100%**；**边界合法 = 100%** |
| L2 内容 | 是不是逐字来自它声称的记录 | `output == record.bytes[start:end]`，忠实率 ≥ 0.95 |
| L3 可用与选择 | 给的是不是该给的、是不是一个完整回答 | 三列分开计：`usable_and_correct`／`usable_but_wrong`／`unusable`；另报“该给答案却被 L1 挡掉”的条数与样本 |

### 16.2 输出单元（写死）

1. **锚定读**（`S(r)` 连续出现在 `C(Q)` 中）：输出**整条记录**，`unit = record`，`span = [0, len(record))`。
2. **回退读**（无锚点／覆盖不足）：仍按块级重合度（多重集 Jaccard）选记录，但输出该记录中**块重合度最高的一整句**，`unit = sentence`；同分取句序在前。回退依据 `fallback_basis ∈ {record_overlap, address_order}`。
3. **句界**只落在句末标点（`。！？；…`）、换行或记录末尾；`sentences()` 先按 UTF-8 解码再按字符推进偏移，因此返回的 span **一定落在字符边界**上。记录没有任何终止符时，整条记录就是唯一一句。
4. **碎片路径已删除**：`_output_span`（旧回退取最长连续覆盖的字节区间）被 `_sentence_span` 取代；任何输出都不再从半个汉字或半个词处切开。
5. **每条输出带出处读数**：`unit`、`unit_index`、`start`／`end`、`fallback`、`fallback_reason`、`fallback_basis`；全量落盘并附 `boundary_before`／`boundary_after` 前后文，便于逐条检查边界。

### 16.3 不变式

- **I-16-1（字符边界）**：任何输出 span 的起点是记录起点或终止符/换行之后，终点是记录末尾或终止符/换行；因此 `record.bytes[start:end]` 必然可解码。
- **I-16-2（出处）**：输出永远是某条已存记录的连续字节区间，绝不拼接、不补全、不生成。
- **I-16-3（无新增容差）**：`sentences`／`_sentence_span` 的数值字面量只有 span 下标/列表偏移/元组位置（0–3）；终止符集是**分类字符集**，不是数值阈值。模块大写数值常量与上轮全等。
- **I-16-4（回退不改“是否输出”）**：回退只决定输出谁、输出哪一句，不引入通过/拒绝阈值。
- **I-16-5（不变式 I-15-x 保持）**：切分、身份、锚定、平移不变、写侧单条拒收全部未动。

## 18. 定义替换：身份＝全部 16 字节窗口指纹集合（2026-11-08，§17.8 的唯一后继已执行）

### 18.1 定义（先写死，再跑）

**身份**：对条目 `r`，`I(r) = { H(r[i:i+16]) : 0 ≤ i ≤ len(r)−16 }`，其中 `H(b) = sha256(b).hexdigest()[:16]`；每个偏移出一个 token，**重数保留**（重复窗口按出现次数计）。

**覆盖判定选“按重数”（多重集覆盖）**，写死理由：`count_q(t) ≥ count_r(t)` 对所有不同窗口 `t` 成立。去重集合会让**一次**查询出现同时“付清”条目里出现两次的窗口（重复表格行、重复分隔线就是这样漏的）；计数只多一次字典查找，**不引入任何数值常量**。多重集覆盖蕴含集合包含，反之不成立。

**锚定**：查询 `q` 取同一窗口集合 `W(q)`；条目 `i` 进入锚点集 ⇔ `I(r_i) ⊆ W(q)`（按重数）。恒定规则不变：0 锚点 → 回退但仍输出；1 → `matched`；≥2 → `ambiguous_multiple_anchors`，仍输出 top-1 并标注。读数是读数，不是退出口。

**取消保护带，且不再保留**：每个身份窗口**完全落在条目内部**，任何前缀/后缀只把 `r[i:i+16]` 平移到 `(|p|+i, |p|+i+16)`，成员一个不变。旧的 `PROTECT = 6` 属于**切点谓词**（切点要读它左边 6 字节才有定义），窗口身份里没有这个依赖，保留它只会把真实可寻址的条目挡在外面。**不保留。**

**最短可寻址长度重算 = 16 B**（上轮 23 B 作废）：`MIN_ADDRESSABLE = WINDOW_BYTES = 16`；长度本身决定身份是否非空，故**必要且充分**（不再有“长度够但内容无切点”的中间态）。<16 B 条目身份为空，单条拒收（`window_identity_empty`）——空身份会被**任何**查询覆盖，不设此下限则任何短条目都会被所有查询锚定。

**回退必须有信息**：无锚点时按 `|set(I(r_i)) ∩ set(W(q))| / |set(I(r_i))|` 降序、地址序兜底；`fallback_basis = window_overlap`（有共享窗口）/ `address_order`（零共享）。无任何通过/拒绝阈值。

**输出单元不变**：锚定出整条记录（`unit=record`）；回退出所选记录中窗口重合度最高的一整句（`unit=sentence`，句界来自 `sentences()`）。

**写策略**：只追加；**只有空身份拒收**。身份包含**不是**拒收理由——窗口身份下标题、表行天然是长条目的子串，按包含拒收正好会筛掉这套定义要救的短条目。

**实现隔离**：新层 `taiji/sc_windows.py`（sha `5ffb2935…`），`taiji/sc_sfk.py` 未改动（sha `476eb5f4…`，历史 runner 与关闭态电池出处不变）。新常量只有 `WINDOW_BYTES = 16`、`FINGERPRINT_HEX = 16`；删除 `MASK`／`MASK64`／`MIN_CHUNK`／`PROTECT`／`WINDOW`，`MIN_ADDRESSABLE` 由 23 改为 16。

### 18.2 三条一句话证明（可逐条检查）

1. **平移不变（成立）**：对任意前缀 `p`、后缀 `s`，`W(p + r + s) ⊇ I(r)`——窗口 `(i, i+16)` 在 `p+r+s` 中是 `(|p|+i, |p|+i+16)`，其字节逐位等于 `r[i:i+16]`；窗口不跨条目边界读取，故后缀也不改任何成员。`I(r)` 的**每个成员**与重数都不变。
2. **冒充成本（推不出“必须几乎逐字复现”）**：`I(r) ⊆ W(q)` 只能推出 `q` 必须**包含 `r` 的每一个 16 字节窗口**（且重数够），**推不出** `q` 连续包含 `r`，也推不出近似逐字。构造：`q = r[0:16] + r[1:17] + r[2:18] + …`——覆盖全部窗口、没有任何两段重叠，`r` 在其中**不连续出现**（顺序丢失）。故“几乎逐字复现”**不成立，如实记“推不出”**。
3. **性质失效的构造**：① 保留空身份 → 每条 <16 B 条目被任何查询锚定（已用下限堵住）；② 用集合包含代替重数 → 重复窗口被一次付清（本条选多重集）；③ **低熵窗口**：16 个空格之类被任何含该串的查询共享，本轮实测未知集 1/550 被误锚定，按 `usable_but_wrong` 如实计入、不隐藏；④ **丢序**：窗口覆盖不是连续性（见第 2 条）。

## 19. 顺序恢复：身份＝全部 16 字节窗口的指纹**序列**（2026-11-09，0 训练／0 优化器步／0 Adam／0 confirm／0 新容差）

上一轮（§18，提交 `2db6274b5`）把身份换成**集合**，用“覆盖”锚定，代价是**顺序丢失**：`q = r[0:16] + r[1:17] + …` 这种重组串能锚定却从不包含 `r`。本轮只改这一处，并修正回退记账分母。

### 19.1 冻结定义（跑前写死，manifest `freeze_revision 2`；rev 3 只做一次语义等价的 lint 修改并重取读数）

| 项 | 定义 |
|---|---|
| 身份 | `I(r) = ( H(r[i:i+W]) : 0 ≤ i ≤ len(r)−W )`，`W = 16`，`H(b) = sha256(b).hexdigest()[:16]`。**有序元组**，每个偏移一个 token；重数由序列本身保留（不再需要单独的计数表） |
| 锚定 | 存在 `j` 使 `W(q)[j : j+len(I(r))] == I(r)`，且 `I(r)` 非空。**偏移差恒为 1、顺序一致** |
| 保护带 | 无，也不保留。每个身份窗口完全落在条目内部，前后缀只平移窗口、不改成员；旧 `PROTECT=6` 属于切点谓词，在窗口身份下没有定义来源 |
| 最短可寻址 | `MIN_ADDRESSABLE = 16 B`，**必要且充分**（长度本身决定身份是否非空）；<16 B 身份为空，单条拒收 `window_identity_empty` |
| 出口 | 0 锚点 → 回退但仍输出（标 `no_anchor`）；1 → `matched`；≥2 → `ambiguous_multiple_anchors`，仍出 top-1 并标注。锚点是读数，不是出口 |
| 回退排序 | **不变**：`|set(I(r)) ∩ set(W(q))| / |set(I(r))|` 降序、地址序兜底；`fallback_basis` 为 `window_overlap`／`address_order`；无通过/拒绝阈值 |
| 回退分母 | **修正**：相关性只在“库内有答案”的查询上计算（写入集自读 + 并集集）；未知集、无关集只报输出形态与是否误锚，不进中位数 |

### 19.2 连续性定理（双向推理，可逐条检查）

记 `W(x)[i] = H(x[i:i+16]) = sha256(x[i:i+16])[:8]`（64 bit 指纹）。令 `n = len(I(r)) = len(r) − 15`。

**（⇒）若 `W(q)[j : j+n] == I(r)`，则 `q[j : j+len(r)] == r`。**
对任意 `i ∈ [0, n)`，有 `W(q)[j+i] = H(q[j+i : j+i+16])`，而 `I(r)[i] = H(r[i : i+16])`。两边相等 ⇒ `sha256(q[j+i : j+i+16])[:8] == sha256(r[i : i+16])[:8]`；在 64 bit 指纹无碰撞的前提下，`q[j+i : j+i+16] == r[i : i+16]`。取 `i = 0` 得 `q[j : j+16] == r[0:16]`；取 `i = 1` 得 `q[j+1 : j+17] == r[1:17]`；逐字节递推覆盖 `i = 0 … len(r)−16`，合起来就是 `q[j : j+len(r)] == r` 的每一个字节（`r` 的每个字节至少落在其中一个窗口里，且首尾窗口分别覆盖开头 16 B 与结尾 16 B）。

**（⇐）若 `q[j : j+len(r)] == r`，则 `W(q)[j : j+n] == I(r)`。**
对每个 `i`，`q[j+i : j+i+16] == r[i : i+16]`，同一函数 `H` 施加后必然相等，故 `W(q)[j+i] == I(r)[i]`，长度也相同，即连续出现。

**唯一缺口＝指纹碰撞**：两个不同的 16 B 块共享同一 64 bit 指纹时，等价性在那一处断开。本轮在 550 条语料的 **98,032 个窗口**、**1,092 条锚定行**上用**原始字节**逐条复核（不经指纹），`independent_containment_violations = 0`。该检查是独立于定理的算术对照。

**结论**：连续锚定 ⇔ `r` 在 `q` 中逐字出现（模指纹碰撞）。顺序恢复后，上一轮的重组逃逸被关闭：手测 `q = r[0:16]+r[1:17]+r[2:18]+r[3:19]` **不再锚定**，落回退，窗口重合度 **0.267**。

### 19.3 冒充成本（买到什么、没买到什么，不掩盖）

- **买到**：要锚到 `r`，`q` 必须在某个偏移处**原样写出 `r`**。锚定不再是“凑齐零件”，而是“逐字引用”。
- **没买到**：`q` 不必**只有** `r`——引用可以嵌在任意文本里；也不能区分“引用”与“同义改写”。
- **对 1 个窗口（16 B）的短条目**：身份只有 1 个 token，`q` 中任意一处出现那 16 B 就买下锚点，**证据量下界＝16 B**。这是本定义能给出的最低冒充成本，如实报出：短条目的保护强度就是“复述这 16 字节”，不能再高。

## 21. 表示层：同内容异说法 vs 无关内容（2026-11-09，**0 训练／0 优化器步／0 Adam／0 confirm／0 新参数**；§20 的唯一后继已执行）

**21.1 问题**。§20 收口后，字节级锚定线只剩一句话：**锚定当且仅当原样出现**。它没有可训练自由度，也不证明语义匹配。要让地址层接进训练图，先得回答：**项目现有的文本表示，能不能把“同一内容的不同说法”从“无关内容”里分出来？** 这一节只测这一件事，不训练、不加参数。

**它不能证明什么**：R3 是冻结通用编码器、只作上界，**不能升级 `representation_not_supported`**（R1／R2／B 三臂判定不变）；R3 的 1-NN 0.75 也不能当成“项目自身表示达到 0.75”。

**它不能证明什么**：oracle 桥用夹具自带词典，**不声称任何检索／归一能力**；`bridge_insufficient` 也不升级、不降级 `representation_not_supported`（三臂判定不动）。

## 21.21 R12 键单位对照：码位键清掉“拆字伪 token”，但共享单字仍漏；offset 只治位置漂移（2026-11-09）

**结论（结构事实）**：① 同一个值可以只存一份，但**键数不会因此下降**；② 同值包含删长键是**无阈值**操作，且能救回“压缩前因同起点而弃答”的长说法；③ 守卫只能看到“完全落在长键内部”的残差键，看不到**跨边界**的键，所以删除不是查询级安全；④ 跨值包含必须排除，否则会把长说法的值答成短键的值。**因此默认仍是“每说法一键”；任何键级压缩都必须由外部限定查询集或给出“可安全删除”的标注，不能由桥自行决定。**

**边界（与读数一起引用）**：① “安全嵌套”只证该几何下删长键不丢读，**不得**推广为“同值即可压缩”；② 边界泄漏例中多出的值不是“答错”，而是**压缩改变了可见性**——不得据单个反例说桥有语义；③ 跨值不压缩是本轮规则，不是从数据学出来的；④ 默认表 0 删除只说明这 18 条键里没有同值包含对，不说明真实语料也没有；⑤ 桥**仍不得**接进默认图。

**下一步（已于 §21.27 执行）**：R18“显式纠正协议”闸——R15 的先写者保留使**第一次写错就永久错**。R18 只测一种不恢复“后写者赢”的纠正方式：调用方给出显式纠正凭据，旧值被**可审计地**撤回；普通冲突写仍必须整批拒绝。判据同样读数前冻结。

## 21.27 R18 显式纠正协议：普通冲突写仍拒、CAS 纠正可审计（2026-11-09）

**一句话**：R15 的“先写者保留”让第一次写错就永久错。R18 增加的不是第二条写冲突规则，而是一个**独立的比较并交换（CAS）操作**：调用方必须出示“当前绑定的值”作为凭据，整批校验通过后才改写，旧值进**只增不改的审计日志**；普通 `write` 写冲突仍然整批拒绝。结果是：**盲写者仍不能改地址，知道当前值的调用方可以一步纠正，且每一步有账可查**。

| 例 | 操作 | 结果 |

**判定与成本**：`plain_conflict_still_rejected`／`cas_correction_applied`／`stale_credential_rejected`／`unknown_address_rejected`／`correction_batch_collision_rejected`／`correction_chain_audited`／`round_trip_clean`／`closed_state_equal`／`anchors_complete` ⇒ 总判 **`explicit_correction_available`**；成本 **1.703 CPU／2.541 wall**（估 30、上限 200、`threads=1`）。0 训练／0 优化器步／0 Adam／0 confirm；`count` 不因纠正而增加（纠正不是一次观测）。

**边界（与读数一起引用）**：① 凭据是“当前值”本身——**知道当前值的调用方就能纠正**，桥不判断谁有权限；② 协议**不能识别错误的核对器**：若外部给出一个错误的新值，CAS 仍会通过；③ 旧值只进日志、不再可读为当前值，日志只增不改；④ 普通冲突写仍拒绝，不恢复“后写者赢”；⑤ 纠正不改变键数（承接 U52）、不产生语义；⑥ 桥**仍不得**接进默认图；⑦ 只在 18 键表与 1 键算例上测过，真实语料未测。

## 21.28 R19 读—核验—纠正闭环：单键闭环可用，但核对器本身不可校验（2026-11-09）

**一句话**：R18 的 `correct` 可以被一个“读→比对→纠正”的循环使用：读出错值、与冻结核对器比对、用**刚读到的值**作凭据纠正，一步后读回新值；读已正确时不做任何写入；基于过期读的凭据被拒；普通冲突写仍拒。**但协议只校验“旧值是否当前值”，不校验“新值是否正确”**——核对器给错时，循环会照样接受。这不是实现缺陷，是这条协议的能力边界。

**A 单键闭环（每例先冻结）**

| 例 | 操作 | 结果 |
|---|---|---|
| 一步纠正 | 表 `蓝色杯子`，核对器 `红色印章` | 读出 `蓝色杯子` → `corrected` → 读出 `红色印章`，日志 1 条 |
| 用读到的值作凭据 | 表 `红色印章`，核对器 `绿色瓶子` | 读出 `红色印章` → `corrected` → 读出 `绿色瓶子`，日志 `红→绿`（不是硬编码的 `蓝→绿`） |
| 已经一致 | 表 `蓝色杯子`，核对器 `蓝色杯子` | `agreed`，**不写**，日志 0，内容摘要不变 |
| 过期读 | 先读到 `蓝色杯子`，另一调用方改成 `红色印章`，再用旧读纠正 | `rejected_batch_correction_mismatch`，读回仍 `红色印章`，日志仍 1 条 |
| 核对器给错 | 表 `蓝色杯子`（真值），核对器 `绿色瓶子` | `corrected`，读回 `绿色瓶子`；`verifier_error_accepted=true`、`final_matches_ground_truth=false`——**边界如实登记** |

**B 默认表往返**：18 键表上别名 `喝水的杯子` 由 `蓝色杯子` 纠正为 `红色印章`、再纠正回 `蓝色杯子` ⇒ `content_digest` **前后相等**、读回原值、日志 2 条；R15 的 20 句仍 **40/40**、12 未写候选 **0**、18 条碎片 **0**、关闭态**九项全等**。

**判定与成本**：`one_step_correction`／`read_value_used_as_credential`／`no_op_when_agree`／`stale_read_rejected`／`verifier_error_accepted`／`plain_write_still_rejected`／`loop_converges`／`default_table_unchanged`／`closed_state_equal` ⇒ 总判 **`read_verify_correct_loop_available`**；成本 **1.766 CPU／2.592 wall**（估 30、上限 200、`threads=1`）。0 训练／0 优化器步／0 Adam／0 confirm；本轮未改 `taiji/address_bridge.py`。

**边界（与读数一起引用）**：① 协议只校验旧值，**不校验新值**；核对器给错时循环会接受——`verifier_error_accepted` 是已声明的边界，不得写成“循环能判断对错”；② 凭据是读到的值，读已过期即被拒；③ 只在单键上测，句级双实体的纠正组合未测；④ 不判断权限、不记录“谁纠正/为什么纠正”；⑤ 纠正不改变键数、不产生语义；⑥ 桥**仍不得**接进默认图。

## 21.29 R20 句级双实体纠正：单槽/双槽/原子子集（2026-11-09）

**一句话**：一句两实体读出的两个值可以按槽位分别核对、并用**各自读到的值**作凭据纠正。单槽错只动那一槽；两槽都错在同一批里改两个键；**过期子集**（一槽有效、一槽过期）整批拒绝，有效那一槽也不落盘。**批量原子性**在这里第一次被当作能力来测，而不是只当作写冲突的副作用。
