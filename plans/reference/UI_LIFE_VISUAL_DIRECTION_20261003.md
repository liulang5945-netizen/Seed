# Seed「生命」页视觉方向

更新：2026-10-25。现行风格：**Seed 认知观测台**。本版补齐审美构图、颜色、排印、组件和状态样式；信息/数据职责及VX6子包仍以[生命页实施设计](UI_LIFE_UX_SPEC_20261003.md)为准。旧六卡/CSS整片模板从`c97d74d00:plans/reference/UI_LIFE_VISUAL_DIRECTION_20261003.md`恢复。本文件是待实施的视觉规格，不代表产品页面已经改成下述样式。

## 1. 方向与保留项

页面的主角是“一个模型正在完成什么，以及有什么证据”，面向持续观察和开发Taiji的用户。整体感觉应当安静、清楚、有生长感：白色或墨蓝灰的工作表面、明确的中文排印、少量Seed绿、舒展的事件脉络；温度来自内容、节奏和柔和边界。

| 风格选择 | 有利之处与实际代价 | 本轮决定 |
|---|---|---|
| 情绪/生物拟态界面 | 容易表达生命感；数值和动画容易让人误把原型状态理解成主观感受或已获能力 | 不采用为主视图 |
| 密集监控仪表盘 | 适合并发进程排障；大量同权指标、曲线和卡片会掩盖目标、结果及未知 | 技术明细按需展开 |
| **认知观测台** | 以当前重点与真实事件建立模型的连续性，同时能诚实容纳缺失能力和独立研究任务 | **唯一推荐，按本页落地** |

继承当前DSH/Seed外壳、明暗主题、静止Seed标志和已交付的未知/空闲语义。生命页通过构图获得自己的身份，不另外换品牌或建立局部全屏应用。普通页面不使用背景插画、装饰渐变、大型百分比、毛玻璃或无来源的持续呼吸动画。

### 1.1 标志性元素：证据脉络

把“承诺→选择→真实结果→学习”的事件联系做成页面记忆点：一条细的竖向轨道，主节点旁是可读事件，右侧是时间/来源，展开可看关联依据。轨道表示实际事件先后和关联，节点类型来自真实事件；没有学习回执时止于结果，并写明“学习尚未验证”。

总览最多露出最近3条；完整事件在目标与选择/训练与证据里展开。它不是流程进度条，不预画虚线终点、四个永远点亮的图标或连续发光连线。仅有研究记录时显示真实训练/保存/评价事件，不硬套原生目标链。

## 2. 颜色与排印

### 2.1 调色板与现有token

生产样式引用`packages/client/ui-theme/src/styles/design-platform.css`，字体引用`base.css/brand-font.css`。下表是2026-10-25源码的解析值，便于样稿准确着色；实现引用token，用户切换主题后继续正确解析。

| 角色 | 浅色 / 深色 | 现有token与使用方式 |
|---|---|---|
| 页面底色 | `#FFFFFF` / `#151517` | `--dsw-alias-bg-base`；保持页面大面积安静 |
| 重点表面 | `#FFFFFF` / `#232324` | `--dsw-alias-bg-layer-1`；仅一个重点块，浅色靠边界/留白分层 |
| 次级表面 | `#F5F6F7` / `#353638` | `--dsw-alias-bg-module-platform`；页签、技术摘要，不铺满全页 |
| 主文字 | `#0F1115` / `#F9FAFB` | `--dsw-alias-label-primary`；目标、状态和关键结果 |
| 次文字 | `#61666B` / `#CFD3D6` | `--dsw-alias-label-secondary`；说明、来源、单位 |
| Seed品牌强调 | `#569E58` / `#7CBB67` | `--dsw-alias-state-business-primary`；选中标记、轨道活节点、焦点和少量实心图形 |

这是白/墨蓝灰与Seed绿的双色体系；琥珀、红、成功绿只承担状态，不构成第二套装饰主题。边线取`--dsw-alias-border-l2`（浅黑10%/深白12%），hover取`--dsw-alias-interactive-bg-hover`，已验证成功/需关注/失败分别使用现有`state-success/warn/error`图形token并附文字。

小字对比单独处理：浅色Seed500对白对比约3.27:1，不能直接承载12–14px关键正文。拟在LifePanel局部将`--life-accent-ink`映射到已有`--dsw-static-seed-600`（`#42814D`，对白约4.69:1），深色映射到`--dsw-static-seed-400`；它是拟局部别名，不是已有全局token。警告/成功正文仍用主文字，色点/图标负责辅助识别。关键值不取caption/tertiary，也不以低对比白字绿底作为唯一主动作。

### 2.2 字体与字阶

| 角色 | 字体与排印 | 范围 |
|---|---|---|
| 中文页面名/重点 | `--dsw-font-family`，22/30、600；重点结论20/28、500 | 系统栈含Segoe UI、PingFang SC、Microsoft YaHei，确保中文清楚；页面内只出现一个最大层级 |
| 少量英文识别字 | 本地`Montserrat`，11/16、500，字距0.06em | 仅用于`TAIJI / DEVELOPMENT`等既有主体识别；不替代中文标签，不为了装饰新增一排英文标题 |
| 分区标题 | 系统栈，16/24、600 | 当前视图内标题，避免每一行都加标题 |
| 正文/操作 | 系统栈，13/20、400；短结论500 | 保持现有全局内容字号轴；信息密度靠留白分组，长说明不缩小 |
| 辅助来源 | 系统栈，12/18、400 | 最近读取、范围和单位，仍用secondary；不能藏必须理解的结论 |
| 数值/身份 | `--ds-font-family-code`，12/18或13/20，`tabular-nums` | 费用、时间、run/bundle短ID；完整路径在展开详情中 |

`Montserrat`的300/400/500本地WOFF2已随ui-theme打包；不增加外网字体请求。系统代码栈包含Consolas等及中文回退；用户字体/缩放设置仍生效，不固定整页像素字号绕过全局设置。

### 2.3 间距、边界与材质

采用4px基准：同一值与说明4–8px，同一组行12px，组内16px，重点块内24px，段落间24–32px。桌面左右32px、窄列16px。重点块12px圆角、内部局部表面8px，状态标签沿用现有Tag，按钮/选择器沿用ui-primitives自己的圆角，不把所有控件强制改成同一形状。

普通内容无投影；用1px边界、背景层和空白分组。仅浮层复用现有`--dsw-elevation-panel/prominent`，不为每张摘要加阴影。事件轨道1px，节点6px；选中的当前节点8px并配文字。图标统一16px，重要恢复/确认动作可20px，复用现有图标族，不混用emoji与线性图标。

## 3. 布局

标题区由页面名、观察对象、来源/最近读取和刷新构成。标题与页签属于同一页头，但不堆成三层悬浮工具栏。主体上限1100px，正常阅读内容在其中保持可扫读的行长；只有已经出现的警告才在标题下占一条恢复带。

### 3.1 总览构图

桌面采用“一个重点＋事件/资源2:1双栏”。重点块以一句实际状态为主，下面是一句目的或等待条件和一项详情入口；数字服务状态，不以一个巨大的CPU秒数取代主叙事。双栏是两个平面区域，不再套一层大卡后各塞一排小卡。

```text
生命                        [观察对象 ▾] [刷新]
TAIJI / DEVELOPMENT        范围 · 连接情况 · 最近读取
总览  目标与选择  训练与证据  资源与权限  兼容工具
─────────────────────────────────────────
当前重点                                      [查看依据]
一句真实结论 / 下一完成条件
主体身份 · 已采用/研究候选 · 状态来源
─────────────────────────────────────────
最近事件与结果（2份宽）        资源与保持（1份宽）
● 真实事件：一句结论          实耗 / 预留 / 未知尾账
│ 来源、时间与详情            实际约束、保持是否已测
● 已发生的后继事件           需要用户处理（有事项才显示）
─────────────────────────────────────────
```

总览在首屏交代“哪个对象、正在做什么、结果是否已知”；原始日志和完整配置退到详情。重点块不是营销hero，不强行占满屏幕，也不增加“生命活力/综合成长分”。

### 3.2 五视图的视觉分工

| 视图 | 构图与阅读重点 | 避免同质化 |
|---|---|---|
| 总览 | 单重点＋左事件/右资源，先结论后证据 | 不重复五个详情页的整表 |
| 目标与选择 | 左侧简洁目标列表，右侧所选目标的承诺、候选、实际选择与事件；窄列顺排 | 不把每个候选做成一张宣传卡；分数带估计标签 |
| 训练与证据 | 按观察对象列研究任务行/三臂进度；展开后显示阶段、保存、恢复、评价与保持依据 | “训练完成”“评价中”“能力通过”用不同文案，不用一整片绿色宣布成功 |
| 资源与权限 | 对齐的定义列表/费用表，上方摘要、下方授权和未知项 | 不把预算、内存、时间做成三个同样的圆环 |
| 兼容工具 | 次级表面、清楚的小标题与现有文件/动作控件 | 全部保留来源和范围，视觉优先级低于原生任务 |

### 3.3 宽度与主题

- **1100px内容列**：总览2:1，栏间24px；目标列表/详情允许240px＋余宽；页签单行，避免内容被装饰挤窄。
- **640px内容列**：主内容单列；目标列表在详情前，用紧凑选中项展开；重点块内20px，页头操作可换行。
- **320px内容列**：页边16px、块内16px；五视图改为有明确标签的同一“视图”选择器，按钮整行/换行，费用与单位不拆散；身份可换行并保留复制/展开入口。

布局按可用内容列宽而非屏幕设备名响应；不足560px强制单列，640px也不勉强塞双栏。长表只在自身`.tableScroll`内滚动，页面无横向溢出。深色依靠层次、边线和文字区分区域，不给浅色稿整体套滤镜，也不把Seed绿提高到霓虹亮度。

## 4. 来源与证据的可见性

| 典型状态 | 视觉表达 | 恢复/阅读路径 |
|---|---|---|
| 原生字段尚未实现 | 普通文字“此模型尚未提供原生发展观测”，一个短说明，无空仪表 | 已有健康来源继续显示；未实现按钮不做占位主操作 |
| 运行时离线、研究源健康 | 页头一条中性/警告恢复带；研究区照常显示，范围和最后读取清楚 | “重新连接”只针对运行时，不把研究结果染灰或清空 |
| 研究三臂完成、评价未结 | 完成图标只落在训练阶段；当前重点写实际的“待评价/评价中/待判读” | 查看评价记录；不展示能力增长百分比 |
| 原生等待/目标完成 | 安静的文字结论与真实理由，已核验项才使用成功图标 | 给出恢复条件或结果依据，不为等待添加旋转动画 |
| stale/结果未知 | 保留最后读数，旁注“旧读数/结果尚未核验”和时间；不将未知写成0 | 展开读取原因与关联回执，禁止重复执行相同外部动作 |
| 单run失败/执行失败 | 对应行显示错误图标和具体失败范围；详情保留原始依据 | 其他对象继续正常，整页不变成大面积红色 |

估计、模型预测、已发送、执行中、已核验、证据不足是不同文字状态，不构成从红到绿的成长等级。能力/学习摘要展示parent/child和声明范围；没有独立行为读数就写“尚未验证”。原型curiosity/fatigue/stress仅在详情显示方法/来源与“原型”标签。

## 5. 动作与危险确认

每个动作和对应对象同组，使用“刷新研究任务”“取消此目标”“暂停自主窗口”等具体名称。当前只读观察阶段以查看/刷新为主，不放高饱和的大“开始成长”按钮。页头最多一个主要操作；局部查看/筛选使用文字或次级按钮。

删除、强制解锁、checkpoint采用保留既有确认与影响列表；确认使用现有Modal/Drawer/原地流程，不另写通用弹层。不可用动作在旁说明原因，不以浅到难辨的按钮代替解释；运行时控制和研究观察不能共用含混“停止”。

## 6. 交互与可达性

旧`life`入口及`#life-*`深链继续定位。观察对象切换先换身份和来源，再呈现新内容，未完成操作仍绑定原subject。键盘依次可到观察对象、视图、详情、动作及返回；focus ring复用现有token，并确保不被sticky遮挡。

状态切换采用100–150ms轻微淡入/位置替换，只有真实变化才播报；不做整页错峰入场、持续呼吸或每5秒轮询播报。减少动效时全部非必要过渡关闭。骨架屏对应真实读取中的结构，已知不支持时直接说明；错误详情折叠，但恢复动作始终可见。

## 7. CSS和组件落地范围

现有`LifePanel.module.css`仍是已实现样式源。先在VX6.0交付研究任务行和真实来源状态；VX6.2再按本风格重组页头、视图、重点块、事件和资源区。VX6.1/3/4按真实生产者增加内容，不能等完整模型自主性后才做必要的阅读改善。

复用ui-primitives的SegmentedTabs/选择器、Tag、按钮、Drawer/Modal、图标和全局字体；必要新样式只在LifePanel组件范围。`--life-accent-ink`等拟局部角色明确在主题下映射，不能散落字面hex、复制全局CSS或引入第二套主题。

实施顺序固定为：**来源/身份与当前重点→单列阅读与双栏比例→字阶/留白/颜色→真实事件脉络→明暗/窄列/键盘修整**。每步有实际数据fixture装配，不能先做装饰动画再补状态。避免用`nth-child`、中文文本或固定DOM相邻关系区分业务状态，状态tone由显式类/数据属性表达。

## 8. 视觉验收

有限布局面仍为五视图×三种内容列宽（320/640/1100）×明暗两主题，共30个；使用明确标记的设计fixture，能力/自主性是否成立由VISION验收。样稿可用于评审美感，不能算产品实现或真实发展日志。

审美与可用性一起核验：首屏能定位观察对象和唯一当前重点；文字/边界层级清楚、相邻内容有节奏；无同权卡片墙和重复指标；页内只有一个最高字阶、品牌强调服务焦点；窄列无溢出、单位不断裂、焦点不被遮挡；关键正文对比至少4.5:1，非文字控件/焦点至少3:1。关键状态有文字，不依靠颜色。

另以键盘和减少动效走通观察对象切换及一条完整详情路径。离线、已完成但未评价、未知和单run失败四种fixture各验证一次来源/动作；测试中读取/写入断言仍按VX6合同，不因视觉通过放宽。用户验收记录“能否快速理解当前情况、视觉是否舒适、是否像Seed同一个产品”，只修受影响组件后结束本包，不因审美追求无限增加模型前置。
