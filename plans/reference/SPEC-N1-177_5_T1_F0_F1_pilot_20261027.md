# N177.5 T1 F0/F1 入门课程与资源合同（冻结草案）

日期：2026-10-27。状态：训练授权前的固定合同草案；未生成正式数据、未训练、未读sealed。

本包在[N177计划](PLAN-N1-177_joint_cognition_slice_20261026.md)中的N177.4A原生T1 producer上测基础中文和单对象事实更正。课程按“短对话→对象属性→纠正旧事实”逐级增加，使用自然中文原文和byte-span标签；推理不接Gold WorldObject/Goal/答案。T2记忆检索与T3自然Goal/行动解析不属于本次训练包。

## 1. 候选和父权重

- V4语言父模型固定为N176 `curriculum_v4/batch_02560.pt`，SHA-256 `6df85a28edbb18b9c8638289ea8bcfaa868eb6b3e384344b12fc7ec2d0e69a71`。所有模式用同一父文件的独立克隆，不覆盖N176原checkpoint。
- 输入producer从零初始化；正式使用3个parser seeds `0/1/2`。同一seed的所有模式共享逐参数相同的V4父状态、parser初态、训练顺序与episode曝光。
- 训练文件生成新N177 family，禁止复用N176训练episode、N175匿名留出题/key或任何sealed答案。N176未消费面不被读取。

## 2. 课程和隔离

每个split均按family整体隔离。一个F1 family固定相同的实体、属性、取值组合及改写模板；它包含初始陈述、简单属性查询、更正、更新后查询以及无关实体干扰。所有相关改写留在同一split。

| Level | Train | Support | Query | Holdout | 目标 |
|---|---:|---:|---:|---:|---|
| F0 | 320 episodes / 64 families | 64 / 16 | 128 / 32 | 128 / 32 | 日常问候、确认、请求、短回答与结束标记 |
| F1 | 320 episodes / 64 families | 64 / 16 | 128 / 32 | 128 / 32 | 一个对象、一个属性、两个普通取值；陈述、查询、更正、追问及无关对象保持 |

总计640 train、128 support、256 query、256 holdout episodes。每个family的脚本全部同split。F1使用简单日常表述，避免AI、技术、政策等专业题。实体/属性/值的UTF-8 byte-span和act标签只属于监督训练/评分输入；train manifest外的支持/查询/holdout标签在训练期间不可由runner访问。语料构造后，先校验无family、脚本、答案或span-label跨split重复，再固化manifest及SHA。

## 3. 一次固定的训练臂和责任控制

Formal update package有5个更新模式×3个parser seeds，共15个arm；另从正确臂终点派生3个state-only分支，不作为新训练run。

| Mode | Producer parser | V4 language parameters | CognitiveState write |
|---|---|---|---|
| Correct | 正确slot/act labels | 完整允许组 | 允许模型自产parse提交 |
| Permuted | 同attribute/取值、长度可配的预注册错误slot/answer配对 | 完整允许组；输入与目标错误配对 | 允许模型自产parse提交 |
| No update | 冻结 | 冻结 | 不做学习期状态写入 |
| Readout only | 冻结 | 仅`language_candidate.output` | 冻结事实写入 |
| Responsible owner frozen | 冻结`input_semantic_producer`；语言分支保持完整更新 | 完整允许组 | 允许模型自产parse提交 |
| State-only diagnostic | 用Correct终点parser推理，不更新producer | 全冻结 | 允许提交parse并写状态 |

F0前640 updates只使用F0；其后1920 updates按固定混合顺序复习F0并纳入F1。每个训练arm使用batch4、固定2560 updates，完整课程顺序预先SHA绑定；No-update也按同批次做forward以给出匹配计算基线。每臂零checkpoint、每256步、F0/F1边界和终点保存。标签置换由manifest预先生成，不能现场抽签或按结果改动。

N177.5还需实现`JointT1TrainerV1`：span/act loss只回`JointInputProducerV1`参数，answer loss回对应V4参数组；inference/predict/commit签名不接gold标签。现有`supervised_loss`只证明梯度通路，未运行optimizer update。

## 4. Joint checkpoint和恢复

单个NativeCheckpoint必须包含：TSK kernel/perception组件、canonical CognitiveState、JointTaskState及source ledger、V4权重/Adam/RNG、producer权重/optimizer/RNG、联合update计数、training mode、family/split manifest SHA、seed、shuffle order SHA、下一episode cursor、六类credit policy和parse ledger。不得把producer、语言候选、Adapter和联合状态拆成互相独立的sidecars。

每个arm在正式第一个更新前保存zero并由新进程恢复。第一批2步canary计入2560步：保存→新进程恢复→下一步输出与不中断克隆一致；随后沿恢复checkpoint继续。终点再次新进程恢复，并重现同一输入parse/answer。任一恢复差异、源绑定失配或optimizer参数组偏离立即停留证，保留partial；不清账重跑。

## 5. 固定验收和有限收官

逐臂分别报告parser span exact/F1、CognitiveState属性正确/更正、F0自由生成有效UTF-8与结束标记、F1原值/相关翻转/更正后查询/无关对象保持、Ambiguous/negative不误写率、F0旧级保持和真实成本。

- F0有效UTF-8≥99%、结束标记≥95%、规范化简单答复exact≥85%。
- F1 entity/attribute/value span exact和post-correction状态准确率各≥90%；正确更正后答复≥90%；无关事实改变时保持≥95%；否定/歧义写成确定事实≤5%。
- Correct比No-update及Permuted的F1 holdout状态/query exact至少高10个百分点；否则如实记为未观察到正确监督的学习增益。Readout-only、owner-frozen、state-only用于区分语言参数、事实producer与状态写入贡献。
- F0相对各自零checkpoint下降不超过3个百分点。任何阈值未过仍到固定终点结案；不自动扩样、加轮、重抽seed或以另一个runner结果补洞。

能力范围上限：即使本包通过，也只支持“一对象/一属性的基础中文事实/更正切片”。不表示开放中文理解、T2跨经历记忆、T3自然目标理解、规划、外部行动、持续成长或自主性。

## 6. 资源估算和训练授权
