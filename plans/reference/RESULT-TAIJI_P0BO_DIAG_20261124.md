## 1. 设计

在 P0-BN 末态（两能力齐备、决策 2 = wait）之后，加**唤醒监视器**跑 3 个 tick：
- 信号：新能力需求 demand∈{0,1}、预算占比 budget、证据漂移 drift；
- **唤醒规则（读前写死）**：`wake = (demand > 0) or (budget >= 0.30) or (drift >= 0.20)`；
- 唤醒 → 「回忆＋核验」两能力 → 重跑效用决策 → 若无可做动作则回到等待；
- 预注册期望：tick0 不唤醒、tick1 唤醒（有需求）、tick2 回等待。

## 3. 判定

**`p0bo_wake_condition_failed`**：G22「唤醒序列 == [False, True, False]」不过——实际为 **[False, True, True]**。

## 4. 判读（诚实归因）

1. **机制按规则工作**：tick2 的 budget=0.45≥0.30 也满足唤醒规则 ⇒ 唤醒，属**规则定义**的结果，不是硬件/实现错误。
2. **预注册期望与规则不一致**：期望 [False,True,False] 假设「预算充足不单独触发唤醒」，与写死的规则矛盾——这是**判据设计错误**（我方），不能算负结果；按纪律：如实记失败、不改旧卡，下一卡预注册修正规则与期望。
3. **唤醒—回忆—核验—回等待**闭环已可运行：唤醒后两能力被成功回忆（0.99–1.00）并回到等待终态。
4. 规则本身也值得改：budget 高立即唤醒会让系统「一直醒着」，应把 budget 仅作为**使能条件**（能行动才唤醒），demand/drift 作为**触发条件**——下一卡预注册。
