# E5 零训练判定：纠正内容本来就有，卡在终止

> 日期：2026-11-18｜性质：**零训练**（0 optimizer step）｜0 check｜判据未改

## 1 读数（8 个 task-B 项，同一事件，只多一条合法释放的记录）

| 项 | 值 |
|---|---|
| 首字节答案**改变**（有记录 vs 无记录） | **8/8** |
| copy 通路有质量（`log_copy` 非空且质量 >1e-6） | **8/8**（≈0.468） |
| 完整应答**完全正确**（与目标逐字节相等） | **0/8** |
| 应答**语义正确**（含正确的实体与位置词） | **8/8** |

例（`fit-1`，目标「右边」）：输出 `在在右边的是紫色圆片。现在在右边的是紫色圆m…` —— 实体对、位置对、**不终止**，打满 64 字节帽。

## 2 三条结论

1. **copy 通路是活的**，不是惰性的（此前 A.2 时代"copy gate inert"的印象在这里不成立）。
2. **纠正不需要写权重**：一条合法释放的记录，在 **0 次更新**下就把内容改对了。A.5／E5／E5.1 三轮都在测"用梯度把事实写进共享参数"，而事实本来可以从记录读出来——**那三轮的 `纠正率 0` 测的是错机制**。
3. **真正的卡点是终止**：`cap = max_output_bytes + 1 = 65` 步内从不发 EOS，于是"完全正确"永远为假。

## 3 对 E5 口径的影响

- A.5 的 `0.0`、E5 的 `8/24 = 0.3333`、E5.1 的 `2/24`，都受同一个终止缺陷污染：即使内容正确，只要不终止就算错。
- 因此"纠正与保持单调权衡"这个结论**必须先复检**：权衡是"写权重"造成的，而写权重可能根本没必要。损伤 0.75／1.00 是真读数，但它属于**一条本可以不用的路径**。
- 不能据此签"纠正已成立"：`完全正确 0/8` 是硬读数。

## 4 唯一后继

**修终止，再重测纠正率**（零训练优先）：

1. 诊断：在 copy 段结束时，`cursor` 的 valid 位置是否耗尽、`log_copy` 是否退化为空、EOS 的 logit 是否被 `byte_head` 压住；
2. 修法候选（按上限排序）：① 发射端在"copy 段耗尽且生成端无话可说"时给 EOS 加成（结构规则，不是调参）；② 让 `byte_head` 的 EOS 行读 `cursor` 的耗尽信号（新增一条连接，出生中性）；
3. 重测：同样 8 项，要求 **完全正确 ≥6/8 且 0 更新**，再谈"纠正在 0 损伤下成立"。

**不签**：纠正已成立、父、能力、check（仍 1/2 used）、22.5.1／22.6／22.7。
