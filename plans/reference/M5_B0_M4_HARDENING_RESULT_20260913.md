## §1 一句话结论

M4 的 `+2.000` 同参照增益在 **12 个 context / 6 个结构变体 / 5 个种子偏移**下**全部成立**，
冻结规则在同一面上 **0/6 变体为正、零交错**；**但本轮暴露出一个必须写清的界限**：
六个变体只在**表面**（扩展名、目标语言、内容形状）上不同，**共享同一种组合结构**
（创建文件 + 显式改语言），因此本轮**只排除"增益依赖 `.py`/python 这一偶然表面"，
不排除"增益依赖 create+override 这一结构"**。

## §2 风险 3（规模）：数字达标，但达标方式改了

审计要求「扩到 ≥12 个 context 并报告区分面」。原候选面是
`dual_200`..`dual_203` —— 四个只差索引后缀的 context，按本项目自己的规矩
（**同一结构事实的多个实例不算独立样本**）那是**一个结构事实测四次**。

本轮改成 **6 个变体 × 2 个 context = 12 个 context**：

| 变体 | 扩展名 | 语言 | 内容形状 |
|---|---|---|---|
| `py_python_fn` | `.py` | python | `def run_N()` 函数体 |
| `txt_python_plain` | `.txt` | python | 纯文本 `value N` |
| `py_python_single_line` | `.py` | python | 单行 `x = N` |
| `h_cpp_header` | `.h` | cpp | C 头文件声明 |
| `py_python_two_lines` | `.py` | python | 函数 + 注释行 |
| `js_javascript_const` | `.js` | javascript | `const value_N` |

**有效样本量按变体计，不按 context 计**（报告里两个数都给出）。

三种参照在本面上**全部 feasible**，且最严参照的缺口首次有了余量：

| 参照 | 要求 | 需要 k | 可用 k | feasible |
|---|---|---|---|---|
| 全体单体 oracle（1.5 + 0.15） | 1.65 | 10 | **12** | ✅ |
| 最佳固定单体（0.5 + 0.15） | 0.65 | 4 | **12** | ✅ |
| 最佳已观测固定 pair（1.0 + 0.15） | 1.15 | 7 | **12** | ✅ |

## §3 六个变体逐一复现，冻结规则一个都不成立

| 规则 | 池化最佳 pair | 增益 | 正增益变体数 | 交错 context | 干预真实性 |
|---|---|---|---|---|---|
| 冻结（`chosen = bindable[0]`） | `a+b` | **+0.000** | **0 / 6** | **0** | ✅ |
| `m4_failure_handoff` | `a+c` | **+2.000** | **6 / 6** | **12** | ✅ |

逐变体：六个变体**各自** `best_pair_gain = +2.000`、`combination_only = 2`、`interleaved = 2`。
四单体在**每个**变体上 mean outcome 均为 `−1.0`（全败），
即增益仍同时需要**交接**与**两个成员** ⇒ 审计 §4 的机制 lesion 在扩面上保持。

## §4 本轮最重要的自我批评：表面可分 ≠ 结构可分

`variant_outcome_distinctness` 诊断实测：**6 个变体只有 1 个不同的结果指纹**
（最佳 pair、增益、组合专属数、交错数、停止原因分布全部逐位相同）。

这条不是坏消息，而是**把结论的边界钉准**：

- ✅ **排除**：增益来自 `.py` 扩展名、python 语言、某个特定内容形状、或某个特定索引；
- ❌ **不排除**：增益来自 `create + override` 这一**组合结构**本身。

**六个表面不同的同一结构事实，仍然是一个结构事实。**
这正是审计批评"四个后缀 context"时用的同一条尺子，本轮把它先量在自己身上。

⇒ 真正的结构独立性要靠[机制续篇](M5_B0_MECHANISM_AND_TASK_PRECHECK_20260913.md) §5 的
**T1（串联交接）/ T2（纠错交接）/ T3（共享状态约束）**——三者组合需求不同，
才是三个独立结构事实。**已登记为 D5 之后的必做项（见 §8）。**

## §5 风险 2（新停止原因语义）：给出清单，并排除一项混淆

M4 引入 `all_members_blocked`（能绑定但都刚失败过），语义不同于冻结的
`all_members_exhausted`（无成员可绑定）。门禁审查需要的是**具体清单**而不是猜测：

- 扫描 `scripts / seed_platform / taiji / tests` 下所有读 `stop_reason` 的文件：
  **11 个**（含 P5.2a/P5.2b/P5.2c 系列 gate 与契约测试）；
- `all_members_blocked` 目前**已被引用**（反事实与审计脚本自身），
  但**没有任何既有门禁把它当作判定值**——须逐个确认后才是安全结论，扫描只界定审查面；
- **排除一项混淆**：`contract_intercepted:preview_ValueError` 在冻结规则与 M4 下
  **计数完全相同**（各 72），来自单体在自己专长外行动，**不是 M4 引入的**
  ⇒ 增益对比未被合同拦截差异污染；
- 逐变体停止原因归属已写入报告（每个变体：`blocked 24 / exhausted 4 / intercepted 12 / reached 4`）。

⇒ **落地 M4 前仍须单独预注册 `all_members_blocked` 的门禁语义**（哪些门消费 `stop_reason`、
是否影响"安全拒绝"判定）。本轮**不改任何门禁**。

## §6 合同层预期被证据推翻一次（并已改判 + 加守卫）

脚本原判：`.h` + `cpp` "预期被合同拦截"（类比冻结 block-3 的
`language_evidence_ambiguous`）。**实测否决**：`.h`/`cpp` 可被合同层接受。

**根因**：block-3 的歧义来自**缺少**语言证据；本变体集每个任务都带**显式
`user_override`** 且扩展名唯一可解析 ⇒ 无歧义可拦。六个变体在
**与规则无关的脚本化参考步骤**下全部 `goal_reached=True`、无失败步骤。

处置（不是悄悄删掉错误预期）：

1. 预期改判为 `expect_contract_ok=True`，并在源码注释里**保留这条被推翻的推理**；
2. 新增 **fail-closed 校验**：任一 `expect_contract_ok` 与脚本化观测不符即
   `SystemExit` **拒绝出报告**（沿用 B0 测量字典审计 `cross_check` 的同一规矩）；
3. 回归测试 `test_corrected_cpp_prediction_stays_corrected` 钉住改判结果，防止退回。

**`.h` 保留在扫描内**：一条"提出→检验→被推翻"的预期比一条从未被检验的预期更有信息量。

## §7 风险 4（种子）与可复现性

- 种子偏移 **5 个**（`0/101/202/303/404`，审计为 3 个）：池化增益
  **恒 +2.000**，`min_positive_variants = 6`，每个种子的干预真实性均为真；
- 全量重跑**两次，输出 JSON 字节完全相同**（`79302dc0503dbbe4…`，30558 B，约 80 s）
  ⇒ 扫描与测量均无隐藏随机性；
- 反事实仍在冻结模块命名空间的**副本**中 `exec`，`frozen._member_episode is` 恒等性
  由脚本断言并写入报告（`frozen_attribute_intact=true`）。
