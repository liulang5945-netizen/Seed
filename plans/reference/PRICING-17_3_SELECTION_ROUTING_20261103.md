## 1. 定价方法与两处必须说明的偏差

**方法**：在 17.0 真实图上做组件分解——同一 batch8 样本分别测 forward-only、forward+backward（含 BPTT）、一次 joint Adam step，再按 stage×arm 组合成每次更新单价。生成、评价、选择探针、restore、bundle 各自实测。外推口径：2 seeds × 每臂 300 更新（100 selection + 100 copy + 100 joint）、240 dev × 2 endpoints 的生成/评价/探针、10% 超时余量 + 60 CPU 启动、wall = CPU×1.15。

**偏差 1（方法替换，需 owner 知悉）**：17.3 合同原写“三臂×三阶段各 1 次工程更新，共 9 次 Adam”。本轮改成组件分解，只花 **1 次** Adam 就把 9 个 stage×arm 格与 Adam 本身分开测出，价格更细，且满足“train/forward/bptt/adam 单列”的要求。代价是它不验证“端到端一次更新”的整体耗时，端到端总耗时留待 17.4 预检核对。

**偏差 2（Adam 超支，如实登记）**：首次端到端定价实现在 evaluation 处崩溃，已烧 **12 次工程 Adam**，CPU/wall 未留存；随后改用组件法又花 **1 次**。本轮工程 Adam 合计 **13 次**：超 17.3 卡（≤9）4 次，超 17.2 卡（≤12）1 次；正式训练更新 **0**。这不是剂量变更，也不改判据，但成本账不清零。

## 5. R1 阈值标定与冻结

**判据公式**（20 对 = 10 个 dev 目标 × 两种重排 reversed/sorted）：

```text
h(g)   = OrderedSelectionHead 的 pooled 表示（576 维有序编码后的池化）
repr   = ||h(g) − h(g')||₂ / max(||h(g)||₂, ||h(g')||₂, 1e-12)   # 相对 L2（DESIGN §10）
score  = max_i | s_i(g) − s_i(g') |,  i∈{0..N-1, null}    # 最大绝对差
通过 ⇔ repr ≥ θ_repr 且 score ≥ θ_score
θ_repr = 1e-2, θ_score = 1e-3   # SPEC §9.1 预注册值，17.3 冻结；20 对只作余量证据
```

| 冻结量 | 数值 |
|---|---|
| θ_repr / θ_score | **0.01 / 0.001**（SPEC §9.1 预注册，候选输出前已写入） |
| 20 对中位 / 最小（repr） | 0.499264 / 0.428526 |
| 20 对中位 / 最小（score） | 0.131360 / 0.052838 |
| 预注册分布检查（DESIGN §10） | 中位 repr 0.4993 ≥1e-6 ✔；20/20 对 >1e-8 ✔；中位 score 0.1314 ≥1e-6 ✔ |
| 噪声底（16.1 旧头 float64 旧读数） | repr 1.67e-16、score 8.88e-16 |
| 本轮旧头对照（换序见证句） | **repr 0.0、score 0.0**（完全序盲） |

**通过/失败样例**：

| 样例 | repr | score | 判定 |
|---|---|---|---|
| 换序见证句「把甲从乙搬到丙」↔「把乙从甲搬到丙」 | 0.198238 | 0.111321 | pass（≥θ，余量 19.8×/111×） |
| 只改一字节的对照句 | 0.301262 | 0.099991 | pass（≥θ） |
| 旧头（均值字节嵌入）同见证句 | 0.000000 | 0.000000 | fail（序盲，正确拒绝） |
| 同一输入重复两次（数值噪声） | 0.000000 | 0.000000 | fail（正确拒绝） |

**为什么能区分“真分辨”与“数值噪声”**：θ 距噪声底（≤8.88e-16）有 **13–14 个数量级**，旧头与同输入都严格为 0.0，不可能误过；反向，最小的真序敏感差（0.4285/0.0528）仍是 θ 的 43×/53×，不会被“刚好过线”误判。因此该阈值对“真分辨/序盲”是数量级分离，不依赖 0.1 倍的余量假设。

**D17-1（自纠偏差，已修）**：首次标定用了 `θ=max(1e-6, 0.1×中位实测差)`（得 0.049926/0.013136），但该规则从未预注册，且与 DESIGN §10“禁止按候选差异的 0.1 倍回填阈值”冲突。已撤回该规则，改用 SPEC §9.1 已写明的 1e-2/1e-3 重跑验证（0 更新、19.94 CPU）；20 对数据改作“余量证据”而非阈值来源。判据没有被改动，改的是我把标定方法写错又纠正。

该阈值由 `taiji/selection_routing.py::load_thresholds` 直接读取上述 manifest，**0b 的 T2 与 17.2 复用同一份标定，不按候选自身差异回填**。

## 7. step150 分段预算（先跑到 step150，过闸门再续 step300）

**两段结构**（每段 150 更新）：

| 段 | 阶段切分 | 三臂每 run CPU | 三臂合计 CPU | 二臂每 run | 二臂合计 |
|---|---|---|---|---|---|
| seg1（step0→150） | selection 100 + copy 50 | 859.06 | **5,154.38** | 850.31 | **3,401.25** |
| seg2（step150→300） | copy 50 + joint 100 | 1,245.60 | **7,473.59** | 1,250.47 | **5,001.88** |
| 两段合计（含余量） | — | — | **13,950.77** | — | **9,303.44** |

**出口定义**：
- **seg1 出口 = 早期闸门（readiness/budget gate）**：selection 教师前缀 top-1 ≥0.90、R1 见证通过、位置监督后 gold 跨度 object_exact ≥0.8。不过 → `early_gate_failed`，**不构成任务判定**，不进入续跑，也不再花 seg2。
- **seg2 出口 = 冻结任务门（唯一任务裁决）**：object_exact ≥0.8 且 A−C 选择差 ≥0.10（两 seed 各自 world 配对 bootstrap 下界 >0）。step150 的读数只用于决定是否花钱，不用于签任务结论。

**提前终止时已烧成本分布**（三臂）：

| 停止点 | 已烧合计 CPU | 占两段全量 |
|---|---|---|
| 只跑完 selection 100 更新就停 | 2,244.84 | 16.1% |
| 跑完 seg1（step150 闸门失败） | 5,154.38 | 36.9% |
| 跑完两段（step300 任务门） | 13,950.77 | 100% |

二臂对应 1,479.06（15.9%）、3,401.25（36.6%）、9,303.44（100%）。

**分段是否稀释判定效力**：**会稀释，但只稀释“早期停止”的解释，不稀释最终判定**。分段后 step150 的读数出现在“只有 50 次复制/span 更新”的中间态，若把它当失败证据，会把“剂量未到”误读成“机制不成立”。因此协议固定：step150 只允许记 `early_gate_failed`（准备度/预算出口），**任务门只在 step300 判**；一旦提前停，该 run 只能记“未完成”，不能记任务负结果，也不得用剩余臂的结果替代。这样做的代价是：一次失败可能只买到 37% 的信息，但换来的是“不在中途改判据”。

## 8. 我的臂范围建议（唯一一条）

**建议三臂 A/B/C，不建议二臂 A/B。**

数字权衡：三臂比二臂多 **4,341.91 CPU（+49.6%）、600 Adam、165.0 MiB 峰值产物**；换来的是唯一能判主命题的对照组 C。

理由（判定效力 vs 成本，具体到本项目的判据）：
- 17 的主命题是“**路线锁定**（最终 Q 用选择结果锁定复制分布）是否带来任务增益”，对应判据是 **A−C ≥0.10**。二臂 A/B 里没有 C，**主命题根本不可判**；二臂只能判 A−B（ST 任务信用这一支），而 A−B 在主合同里只是次要机制对比。
- 反过来，若砍掉 A 只留 B/C，则失去“ST 信用”对照，A−B 不可判；若砍掉 B，则 A−C 与 A−B 共享 A，仍可判主命题，但少一个“锁定但停梯度”的中间对照，机制归因会退化为单因子，无法区分“锁定本身”与“锁定+代理梯度”。
- 成本侧：13,092 vs 8,750 CPU 的差额只占 17 整包 30,000 CPU 硬上限的 14.5%，而 17 整包的观察线 20,000 CPU 在三臂下也只到 65%。**以 +49.6% 的单价换主命题可判，是把钱花在唯一不能省的地方**；要省，宁可把 step300 的任务门一次判完（本协议已经如此），也不该省掉 C。
- 唯一例外（留给 owner）：若资源合同硬性压到 9,000 CPU 以下，则二臂 A/C 比 A/B 更值（A/C 可判主命题），但那等于修改“三臂同期对照”的机制归因范围，需要另立合同，不在本建议内。

**最终决定权在 owner；本文件不据此启动训练。**
