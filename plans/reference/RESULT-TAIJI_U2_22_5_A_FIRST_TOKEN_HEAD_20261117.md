# 22.5.0.A 首 token 选择头设计：冻结表示上不可行

> 卡号：`22.5.0.A`｜日期：2026-11-17｜状态：**`head_not_feasible_with_frozen_u2_representation`**｜性质：**fit-only 设计验证**，0 check、0 final、无正式 A 门。
> 报告：[状态/read/H 头](../../reports/taiji_u2_22_5_a_first_token_head_20261117.json)、[编码 token 头](../../reports/taiji_u2_22_5_a_first_token_attention_20261117.json)、[768/192 分区头](../../reports/taiji_u2_22_5_a_first_token_partition_20261117.json)。

## 1 设计尝试

在**冻结 U2**上尝试三类首 token 选择头，训练只读 train，评估 fit：

1. **状态线性头**：`context[16]`、`read_h[16]`、`H[32]`、`context+H[48]`；64/32 first-A 预检。
2. **编码 token 头**：U2 `encode` 的 rgb/audio/proprio/outcome 共 **25×8** token + request goal[8]；线性拍平、均值、单查询 attention；64/32。
3. **全分区头**：同样 token 头，改用 **22.4.3 的 768 train／192 fit** world；这是正式分母。

## 2 读数

| 设计 | train | fit | 结论 |
|---|---:|---:|---|
| 状态 `read_h` 线性（64/32） | 0.516 | **0.438** | 不可行 |
| 状态 `context` 线性（64/32） | 0.484 | 0.281 | 不可行 |
| 状态 `H` 线性（64/32） | 0.563 | 0.375 | 不可行 |
| 编码 token 线性拍平（64/32） | **0.906** | **0.469** | 过拟合，不可行 |
| 编码 token 均值（64/32） | 0.344 | 0.219 | 不可行 |
| 编码 token attention（64/32） | 0.25 | 0.25 | 不可行 |
| **768/192 线性均值** | **0.293** | **0.302** | 不学到，不可行 |
| **768/192 attention** | **0.293** | **0.302** | 不学到，不可行 |

- 64/32 的线性拍平能把 train 拟合到 0.906，但 fit 只有 0.469——**过拟合**。
- 换到正式 768/192 后，均值和 attention **连 train 都只有 0.293**（4 类机会线 0.25），fit 0.302；**没有可泛化/可拟合的类选择信号**。
- 因此：**不是头容量不够、不是只差 loss 权重**；冻结的 U2 token/状态没有把"请求指名的实体→该实体位置→4 类"这条绑定暴露给任何简单/注意力头。

## 3 归因（2026-11-17 修订）

> 本节早先写作"实体表示缺口、需要每实体槽位"，**该归因已撤回**。核对代码后的实际原因是查询通路，不是表示缺槽位。

- 不是 EOS/UTF-8/恢复（前一卡已分离）。
- 不是首 token 权重（1 和 7 都 0.25）。
- 不是单纯头容量：768/192 上连 train 都学不到。
- 真正原因：探针的查询取 `model.language_goal(state)`，它经 [u2_subject.py 的 `goal()`](../../taiji/u2_subject.py#L739-L747) 把整句文本用**随机初始化**的注意力权重压成 **8 维**；本轮 U2 的优化步数为 0，这套权重未经训练。六个实体名只差第一个字（红/蓝/绿/黄/紫/青），其余"圆片现在在哪里？"完全相同，随机 8 维压缩后几乎撞在一起。头拿到的 query 基本不含"找谁"，所以 train 只能停到类别先验（`未知` 占 25%）。
- 因此"train 0.293"的含义是**查询信号在压缩时被抹掉**，不是"观测里没有实体信息"。当前 16 个 rgb patch 带绝对 x/y 坐标（[u2_task_sensors.py](../../taiji/u2_task_sensors.py#L91-L96)），颜色信息在 48 维里，信息层面并未被证否。
- **不能写成"U2 架构被证否"**；这只是本轮读出探针的查询接口缺陷。

## 4 唯一后继（已替换）

不做实体槽位。槽位等于把"3 实体／6 色／3 档位置"写进架构，换场景就要重设计重冻，属于封闭世界标定，上限低。

改为**查询自编码的绑定头**：头自己编码 request 原始字节（字符级 Embedding + 位置 + 均值/峰值池化），与 patch token 集合做单次 cross-attention，输出 4 类。该表示随字符组合扩展，不枚举实体。

判据在跑之前声明（对 `raw` patch 源、三个头种子的中位数）：

- `raw` median train ≥ 0.95 且 median fit ≥ 0.80 → `head_feasible`，再考虑搬进 U2 读出并申请身份。
- `raw` median train ≥ 0.95 但 fit < 0.80 → `query_pathway_fixed_generalization_gap`，是数据多样性/样本量问题。
- `raw` median train < 0.95 → `perception_not_separable`，才说明 16×16 图、4×4 像素一块的感知分辨率不够，那时升级感知前端（仍然不加槽位）。

同时用同一头跑冻结 U2 的 25×8 token，用来分离"世界可解性"与"U2 编码压缩是否丢信息"。

始终：0 U2 optimizer、0 check、0 final；fit 未过 0.80 不读 check。

## 6 修订后的归因与判词

- **查询通路是主因**：同样冻结特征，旧探针用随机初始化的 8 维 `goal()` 池化，train 只有 0.293；把头改成自编码 request 字节后，raw train 升到 **0.788**。这条差异是干净的对照。
- **“感知不可分”不能成立**：`左` 已到 **96.9%**，说明颜色→位置的证据确实在 patch 里。缺口集中在 `中`（74%，正好是两列 patch 的析取）与 `未知`（64%，58 例错答成 `右`）。这是**头容量与优化**的形态，不是输入信息缺失。
- 预先声明的判据“raw train < 0.95 ⇒ `perception_not_separable`”在本轮**不成立为结论**：它缺少一个容量对照就能翻案。按纪律记为“判据设计不足”，不据此写感知结论，也不据此写架构证否。
- **冻结 U2 token 明显更差**（0.438 对 0.788）。原因是 `encode` 的 48→8 是**未训练的随机线性投影**再加 `bounded`，不是训练后的编码器。因此这个差值**不能推论到正式 A 门**（门内编码器会被训练），只能说明“冻结随机编码不可读”。

## 7 唯一后继

先做**一次头容量上限对照**（不作判据，只定位）：缓存 `raw` 特征，把宽度 32／单层／600 步提到 64／两层／2000 步，看 train 能否过 0.95。

- 过了 0.95 → 剩余是对照不足，A 门读出应按“查询绑定头 + 联合训练”设计，另立读出身份。
- 仍不过 0.95 且`中`/`未知`仍低 → 才回到任务本身：检查遮挡/同列实体造成的答案歧义，先修 fixture 再谈任何头。

在此之前：不改 U2 观测/读出身份、不重冻、不跑正式 A 门、不读剩余 1/2 check。

## 5 纪律

- **0 U2 optimizer 步**、0 check、0 final；check 曝光保持 **1/2 used、1/2 remaining**。
- 正式 A 门未跑、A 父未得、B 未进；22.5.1／22.6／22.7 锁定。
- 本组探针 CPU 未单独记账（只做 U2 前向/编码与头训练）；不冒充预算读数。
