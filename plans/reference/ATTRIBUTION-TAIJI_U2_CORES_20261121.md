# 失败归因：新旧两核的差异与不可推进原因（2026-11-21）

> 文档状态：[归因] — 2026-11-21（D-20261121-243）。**零 check/final；不新增能力结论。** 本文回答两个问题：① 新核与旧核的结构差异；② 两核为何都无法推进 joint。

## 1. 两核的结构差异（逐条对照代码）

| 维度 | 旧核 [u2_neural_units.py](../../taiji/u2_neural_units.py) | 新核 [u2_selective_units.py](../../taiji/u2_selective_units.py) |
|---|---|---|
| **状态形状** | `z/a` 为 `[N]`，**全批共享**；`inputs [T,G,D]` 把 batch 当时间步 | `z/a` 为 `[B,N]`，**按样本独立** |
| **状态更新** | `z = c·z + (1−c)·tanh(v)`，`a = (1−η)a + ηz`；`c/η` 为每单位标量，**无输入依赖写门** | `candidate = tanh(v)`；`g = σ(write_in(x) + write_state(z) + bias)`（bias 初始 −2）；`z = (1−g)z + g·candidate`；**学习式写保护** |
| **输入混合** | `drive = r·x`；无跨通道混合 | `drive = r·x` ＋ `cross_channel_mix`（6 合法通道→组上下文） |
| **读出** | 每 tick 的 `p @ (mix·activity + mix·a)` → 直接查询/读出；**不读末态**，配合外部历史/池化 | **只读末步** `[z_T, a_T]`，再乘 `read_gate = σ(read_gate(final raw channels))`，MLP 读出；**无 tick 平均** |
| **跨步记忆能力** | 无写保护 → 每 tick 被输入覆盖；D-217 实测 batch=1 序列中 `z` 在 t1 即回落机会（0.382），`a` 仅 t1–t3 弱残留 | 写门＋末步读出 → M1 无外部历史 T=5/10/20 **1.0/1.0/1.0**；M2 覆盖 1.0；M3 容量 0.456/0.706/1.0 |
| **补偿机制** | 只能靠**外部历史＋位置注意力**（D-205 读出工程），不改变状态本身 | `step_mask` 填充冻结、`capsule_v2`、cohort 双生发育、生命周期/生长代际 |
| **生长** | `with_neutral_birth`：新单位 `r/p/c/b/w=0`（中性但零功能路径） | `grow_units_neutral_`（随机新生儿＋读出零列）与 `grow_antithetic_cohort_`（冻结锚点＋immature 辅助信号） |
| **恢复** | capsule v1（state_dict＋registries＋digest） | capsule v2（v1＋selective spec/state/cohort/generation） |
| **读出工程地位** | 旧线中文语序 0.472→0.967 **靠外部历史读出**，不证单位状态 | 新核中文 0.9979/0.9823 与 M1 **在单位状态读出下**成立 |

**一句话差异**：旧核是「**共享状态＋外部历史读出**」；新核是「**按样本持久状态＋写门＋末步读出**」。新核补上了旧核缺失的记忆基底，但没有补上「多任务容量分配」。

## 2. 旧核为什么不能推进

1. **记忆基底缺失（结构性）**：`z/a` 按批共享、无写门，序列中 t≥1 即被输入覆盖（D-217：z 0.903→0.382→0.306…）。任何需要跨步保持的 joint 任务（P24/P26/P27 及 S1）在**输入层**就失败，不是训练不够；
2. **读出升级只救序列任务**：位置注意力读出把中文语序从 0.472 抬到 0.967、把「外置历史可读」抬到 0.74–0.92（D-205/213/217），但**状态本身仍不保持**；因此旧核的「能力」实为**外部历史读取器**；
3. **动作/结构同样卡在表示**：旧核 A2 动作先验 replay 0.784<0.80（D-215）；22.7 等 FLOPs 生长收益 absent；旧核新单位零路径。

⇒ 旧核不是「差一点」，而是**缺少按样本持久状态这一整个层**；继续在旧核上调读出/生长只会重复「外部历史可读」的结论。

## 3. 新核为什么仍不能推进 joint

新核的 per-axis 证据是真实的（M1/M2/M3、中文 0.9979/0.9823、P24 专用 0.85–1.0、P26 +0.38～+0.49、P27 0.885、capsule 0.0/重连 1.0、中性生长 birth 0），但 joint 失败可归为**三条相互锁死的机制**：

1. **共享单位顺序训练 → 干扰/覆盖**：同一 48 单元被 P-A/P-B/P-D 依次更新；S1-R2 中 P-B 升至 0.875，但 P-D 掉到 0.781、旧损伤 0.051；23-S.0b 中 P-B 达 1.0，P-D 崩到 0.623、旧损伤 0.484。**任务专用读出 head 不解决问题**，因为被覆盖的是单位状态/权重本身；
2. **冻结单位 → 表征不足**：23-S.0c 中 P-A 后冻结全部单位，P-B/P-D 只训适配头 → P-B 0.294/0.363/0.425、P-D 0.425–0.494。说明 P-A 中文训练出的 48 单元表征**不含**实体映射/物理动力学所需变量；不能靠「冻结＋换头」通用化；
3. **生长 → 中性但无功能**：S1-G 证明 48→56→64 出生中性/旧技能 0/胶囊 0；S1-G2（裸新生儿两阶段）lesion 0.031/0.055、S1-G3（cohort 发育）0.031/−0.008。增长只增加了**不被读出使用**的单元，没有 credit assignment/连接绑定。

**共同根因（两核共有、程度不同）**：缺少**任务条件化的容量分配与保护**——即「把哪些单位/连接绑定给哪类功能、并在学新任务时保护已绑定部分」的机制。旧核连按样本状态都没有；新核有状态但没有分配/保护，因此：
- 若共享 → 相互覆盖；
- 若冻结 → 表征不通用；
- 若增长 → 新增容量无功能绑定。

## 4. 一个未成立但值得注意的尝试（如实披露）

本轮尝试「按任务分区 16/16/16 单元（任务门控）」来直接验证根因，但实现后 CN 训练未起来（两条件均为机会水平），**该实验作废、不作为证据**；不能据此声称分区可行或不可行。根因结论仅基于第 1–3 节的代码差异与既有 S1/R2/23-S.0 读数。

## 5. 若要推进，需要补的机制（不是再调参）

1. **任务条件化路由**：按任务/目标激活单位子群（门控/专家混合），同时**保护已绑定子群**（冻结或低 LR），并让新任务只能使用未绑定容量；
2. **功能绑定与信用分配**：新增单位必须通过「其输出对任务损失有可测贡献」来获得读出头/连接，而不是仅出生中性（lesion 门就是检验此点）；
3. **继承式整合**：旧子群保留＋新子群加入后的联合读出，需要验证「联合 > 任一单独」而非简单拼接。

这三项属于**架构级新卡**，需预注册、预算与 owner 授权；不是继续在 S1/23-S.0 同范围调参。

## 6. 结论

- **旧核不可推进**：缺按样本持久状态（结构缺失，D-217 证）；
- **新核不可推进 joint**：有状态但缺任务条件化容量分配/保护；共享→覆盖、冻结→表征不足、生长→无功能绑定（D-231–240 证）；
- 两核的失败**不是同一原因**：旧核是「没有记忆」，新核是「有记忆但没有多任务组织」；后者才是当前真正的瓶颈。
