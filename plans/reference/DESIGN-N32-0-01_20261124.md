## 1. 要回答的问题

在 GRU＋read_gate 骨干上，按任务名外控路由的分列结构，能否在每列 24 或 48 个单元、每任务 1,200 或 2,400 步内，让 CN、P-B、P-D 都过格01 门？哪一个配置最便宜、又留有 +0.02 余量？本卡只选配置，不改任何格。

## 2. 骨干（`taiji-gru-rt-v1`，冻结）

| 项 | 值 |
|---|---|
| 路由 | 每个任务一列；`forward(ticks, task)`，任务名是显式参数（外控） |
| 列 | 若干 block；block k = `GRUCell(48＋前面各 block 单元数 → u)`，只读本列前面的 block（单向侧向） |
| read_gate | 每个 block 用末个有效时刻的输入算 `Linear(48→u)`，bias 初值 1.0（与 N31.4 `gru_gate`、N31.1.02 一致） |
| 读出 | 第一层是各 block 的线性项之和 → Tanh → 本任务输出（CN 8，P-B 4＋conflict 1，P-D 4） |
| 填充 | 全零时刻保持状态；read_gate 取最后一个有效时刻（修复 GRU72 问题 1） |
| 生命周期 | 每个单元有 `alive` 标记，每个时刻都乘上（修复 GRU72 问题 3）；可逆休眠 |
| 生长 | `grow_(task, u)` 追加 block，新 block 的读出权重为零 ⇒ 旧输出逐位不变（不变量02） |
| 保护 | 列互不相交，**构造保证**旧任务零损伤，不是学得的性质 |
| 范围标签 | `routing=external_task_id; protection=disjoint_columns(construction); heads=per_task; state=episode_reset; scenario=task_incremental` |

## 3. 协议（冻结）

- 数据、评测集、训练数据 seed 与 N31.1.02 完全相同（复用其 `make_batch`、`eval_sets`、`train_seed`）；B=48；Adam，lr 6e-3 / 7e-3 / 7e-3；每列单独一个优化器；梯度裁剪 1.0。
- 每个 seed、每个单元数（24、48）各训练一个主体：CN → P-B → P-D，**每列训练 2,400 步，在第 1,200 步和第 2,400 步各存一次快照并评测**。各列互不相交、优化器按列分开、学习率不衰减，所以第 1,200 步的快照**就等于**「1,200 步配置」，不需要另跑。
- 每个配置记录：四项分数、`g01_margin`（四项减门后取最小）、三任务均值、胶囊往返差、快照评测与训练时即时评测是否逐位相同；每个主体在训练完所有列后，再评测一次旧列，BWT 必须逐位为 0（`live_bwt_exact_zero`）。
- 格01 门：CN ≥0.85、P-B ≥0.75、conflict ≥0.85、P-D ≥0.70。
