## 0. 唯一问题

把「按颜色找到对象」与「读出它的位置」**拆成两个可学步骤**后，模型能否在同任务、同剂量下越过 0.80？若能训练集过而 fit 不过，瓶颈就转到任务切分（3 对象 vs 1–2 对象）；若训练集也过不了，说明这个结构仍不足以表达合取。

## 1. 为什么是结构而不是再调配方

P3.10–P3.16 已把剂量、步规则、上下文监督、聚合方式、监督接点逐个排除；剩下的事实是：**32 维池化编码要把「哪种颜色在哪一列」压进同一向量**，0.39 的天花板与容量/结构一致。本卡把合取拆开，各由一小块承担。

## 2. 结构（最小改动，零初始化，先隔离测表达力）

在同一 194 张量底座上新增一个**查询条件的 patch 注意力**模块，但**本卡不把它接进字节路径**——先隔离回答「这个结构能否表达合取」，接线留给 P3.18（接线要改模型内部，风险和成本都更高，先证结构值得接）：

1. **patch 编码**：沿用现有 `encoder.rgb` 输出 `[16, 8]`（不新建编码器）。
2. **查询**：用现有请求文本嵌入（`text_units` 的均值，8 维）作查询 `q`；不引入外部语义解析器。
3. **打分**：`s_i = (W_q q) · (W_p h_i) / sqrt(8)`，16 个 patch 上 softmax 得 `a_i`。
4. **读出**：`z = Σ_i a_i h_i`；`logits = W_o [z ; q]`（四类）。
5. **训练范围**：只训 `encoder.rgb` ＋ 本模块（约 600 参数），其余冻结；损失＝四类 CE。**字节路径不参与、不评估为能力**。

新增参数：`W_q`(8×8)、`W_p`(8×8)、`W_o`(16×4) ≈ **192 参数**；连同可训编码器构成新候选身份 `native + patch-attention v1`（仅诊断用，不产出父）。

## 6. 风险与前提

1. **查询质量**：已在 1844 bundle 上做零成本核验——六个颜色名的请求嵌入**确实可分**：两两平均距离 **0.0229**，逐维 std 均值 **0.0069**（最大 0.0159）。信号存在但弱（约为 8 维尺度的 3%），足以给注意力一个可学的查询，但不能假定它强。若实现后注意力 top-1 仍贴机会，先修请求编码，不怪结构。
2. **任务切分**：fit 是 3 对象、train 是 1–2 对象，D2 触发时属预期，不是结构失败。
3. **不扩容**：本卡只加约 200 参数的结构模块，不拓宽编码器、不加层；扩容留到结构被证明能表达之后。
4. 不读 check／final／confirm，0 能力声称。
