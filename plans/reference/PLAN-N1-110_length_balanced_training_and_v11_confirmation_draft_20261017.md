# PLAN-N1-110 · length-balanced material training and v11 confirmation · DRAFT · 2026-10-17

**Status: proposal only. Not frozen, implemented, trained, or authorized for v11 face generation. Owner approval is required because this changes the training schedule and adds a new confirmation face.**

## Evidence and question

The run100 train-derived schedule contains only six-character known `lookup`/`revision` answers (1,536/1,536). The consumed v10 diagnostic crossed six- and seven-character answers. In the position arm, seed11 has one seven-character lookup template that always abstains; seed12 has one seven-character lookup and one revision template with one-character errors; seed13 fails every lookup/revision template at both lengths, with two-to-seven-character edit distance. Stored `teacher_exact` and `free_exact` agree on all 2,232 v10 rows, so these errors also occur under gold-prefix scoring. The length gap may explain part of the seed11/12 pattern but does not explain seed13.

Question: does equal six/seven-character material exposure improve exact answer prediction under the same architecture and update budget, while preserving the original train and confirmation gates?

## Proposed matched comparison

- Keep the nine PLAN-N1-100 final checkpoints frozen as the six-character-only baseline. Train nine fresh candidates: seeds 11/12/13 × `position`/`terminal`/`cut`. Use the same model architecture, 24,576 updates per endpoint, optimizer, learning-rate schedule, five-group update limits, initialization lineage, source curriculum, paired-question objective, and recovery requirements as PLAN-N1-100. The only intended recipe change is material-value length exposure.
- Generate a train-only candidate schedule from the same 192 v3 train parents. For lookup/revision, produce matched six- and seven-character views per parent. In each 6,144-update cycle, keep 16 raw and 16 hard-view presentations per parent; assign eight raw presentations per length. For lookup/unknown hard views, preserve all four observation-count × Hamming-distance cells and split each cell's four slots 2/2 by material length. For revision, preserve both distance cells and split each cell's eight slots 4/4. Keep each revision's stale/current values the same selected length and preserve order. Balance the paired `second_question` answer to the selected length. Unknown targets remain absent and still answer literal `unknown`; balance their observed distractor-material lengths 6/7 so answer length is not an absence cue. Leave transition tasks and their direction values unchanged.
- Generate all seven-character known material values deterministically from a train-only seeded derivation; verify disjointness against v3 train, v5/v6, v7/v8 queried sacrifice, and the consumed v9/v10 diagnostic values. Do not read or decode dev/holdout content or v7/v8 confirmation payloads. Validate source split, task semantics, row order, answer length, exact per-parent/cell balance, paired-question validity, and full source hashes before the first optimizer update.
- Before training, save and independently restore all nine fresh zero checkpoints with full optimizer/RNG/history verification. Train exactly 24,576 updates per candidate (221,184 total), with no continuation or post-failure retry. Preserve the current six-character schedule's nine frozen checkpoints and report as the matched baseline. Use the PLAN-N1-100 CPU ceiling of 18,000 seconds for preflight, training, recovery, face construction, range check, confirmation, and closeout.
- Only after all nine candidates pass checkpoint/source guards and the original training sufficiency gates, build one new v11 face with seed 111: 40 new items, 10 per kind, 12 observations, d=1, 20 sacrifice and 20 confirm. For lookup/revision, balance five six- and five seven-character answers across each kind; split the five/ five between sacrifice and confirm as 2/3 and 3/2. Use fresh entities/materials disjoint from all frozen train, v5/v6, v7/v8 sacrifice, v9, and v10 sources. Run the original ≥6/9 sacrifice range gate on the nine new candidates only. If it fails, do not query confirm.
- If range passes, run the v11 confirm subset exactly once on both the nine frozen PLAN-N1-100 baseline endpoints and nine new candidates (360 item-endpoint queries total). Compute the original PLAN-N1-94 four gates separately for each nine-endpoint cohort without changing thresholds: each position seed ≥10/20; each position seed/kind ≥2/5; aggregate position advantage over terminal ≥12/60 and over cut ≥12/60. Keep the original training sufficiency gates unchanged for the candidate cohort. The old cohort is a same-face descriptive control; no model is promoted by this proposal.
- Refuse any extra training, second face draw, threshold change, or checkpoint overwrite after a failed gate. Preserve `can_promote=false` unless an existing promotion contract is separately satisfied and reviewed.

## Interpretation and limits

This tests a length-exposure change against frozen same-protocol endpoints. It does not presume length is the sole cause: seed13's v10 errors at both lengths remain a central falsifier. A candidate that only improves seven-character items but leaves seed13 broad failures would not satisfy the multi-seed confirmation gate. Training success, range success, and confirmation success remain separate decisions.
