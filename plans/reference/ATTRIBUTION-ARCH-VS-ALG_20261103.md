# 架构 vs 算法：N16.1 失败的只读归因分析（2026-11-03）

> 文档状态：[只读归因·已交付]。日期 2026-11-03。范围：0 训练更新、0 训练前向；仅消费既有报告/manifest/档案，并对已存 bundle 做 0 更新只读探针（80 次推理生成，两次运行合计 74.14 CPU / 78.95 wall，如实计费）。不改变任何已冻结判据与剂量；不启动训练；不物化父候选。实际调度见 [MAINLINE](../MAINLINE.md)。

## 1. 结论（白话版）

1. **这次失败不是单一原因：算法层的问题已经被 N16.1 修掉了，剩下的是两个更深的架构层断点。** N16.1 相对 15.1 的大改（给选择头配监督信号、锁 α、γ 下限、按准确率触发课程）确实修好了三件事：选择从"完全没接线"（0/240）变成"已见内容能选对一半多"（0.38）；γ 从"死门"（≈0）变成活门（0.82/0.75）；课程触发机制真的会触发了。这些是算法问题的证据——改算法就见效。
2. **但有两个症状从 10.21（2026-11-01）到 16.1（2026-11-03）换了四套算法都没消失：未见过的内容选不对（≈0），以及错误总是先出现在"实体名字"的第一个字节上。** 同一症状＋不同算法＋同一切点，这是架构不变式的标准证据，不是训练不足。
3. **只读探针给了两个硬证据：** ① 现在的选择头把句子读成"字节袋"（只数字节种类、不管顺序），对 goal 做任意字节重排，打分变化 < 9e-16——这在数学上证明该函数类无法区分换序句，训练多久都没用；② 就算把"正确记录＋名字在记录里的起始位置"每一步都喂给模型（gold 探针），40 例里完成数从实际的 2 例只升到 3 例，逐字节强制复制甚至 0/40——说明"复制通路不知道往哪儿对"不是缺一个起点，而是整个"记录内定位"机制从没被训练过。
4. **对 17 号候选的裁决：保留为主选，但必须加一条早期探针闸门。** 17 号恰好修的是被证明的两个架构断点（换序盲＋整句一次性选择），方向正确；但探针 P4 显示"记录内定位锐度"是比 17 号设计预期更硬的墙——若不在 17 的图阶段就用同样的 gold 探针预检，17 号有可能在实体字节上撞同一堵墙。详见 §7。

**时间线要点**：
- "未见内容 ≈0" 一栏在五个版本里**全部为 0 或贴地**，而算法换了四套（EpisodicRead → query_binding → R0 记录寻址 → R1 跨度复制 → 显式头＋锁定）。
- "首次偏差在实体/对象字节" 在 14.6（123/133）与 16.1（50%/63%）两次独立出现，中间隔着一次算法大改。
- 每一版的自诊断都指向"选择/绑定接口"，但每次改动修好的都是上一层，露出下一层。

## 3. 四层归因（对 N16.1.1，逐条给证据）

### 3.1 架构层（表示与接口）——主因

| 断点 | 证据 | 判定 |
|---|---|---|
| A1 选择头是"字节袋"：`encode=字节嵌入取均值`，对换序/重排不变 | **探针 P1**：8 例 goal 的 reversed/sorted 重排，选择打分最大差 8.9e-16；换序见证句"把甲从乙搬到丙"/"把乙从甲搬到丙"编码差 1.7e-16（字节多重集相同⇒编码相同）；新描述选择 0/60（两 seed、两臂、同一个头） | **架构不变式**：该函数类在数学上无法区分字节顺序，训练不能修复 |
| A2 单次整句选择：整句锁死一条记录，地点字节只能靠生成支路 | 16.1 接口在输出循环外选一次；A 臂 place_exact 仅 0.21/0.07；**探针 P4** 显示即便对象字节被 gold 强制，地点/模板段仍 derail | 架构：任务需要"对象段→对象记录、地点段→地点记录"的阶段切换，单次选择表达不了 |
| A3 记录内定位（β/transport）没有位置级监督 | **探针 P4**：逐字节 gold 强制（正确记录＋正确偏移＋γ=0）完成 0/40、object_exact 0/40；20 例在第一个强制字节（byte 3）就偏掉——one-hot β 经 transport 后复制质量被摊开，argmax 不落在目标字节；**探针 P3**：只强制首步也仅 3/40（实际 2/40） | 架构/接口：15.1 引入的 transport 把"位置指针"变软了，但从未加位置级训练信号；对照 14.4 的 R0 接口强制记录/位置复制概率为 1.0（锐利），本探针证明 R1 接口在 gold 条件下也不锐利 |
| A4 选择→解码的信用形态：argmax 阻断回答损失到头 | 16.1 的头只从 CE 学习（已见 0.61/0.43、train 0.5729）；回答 NLL 对头参数无梯度 | 架构/算法交界：17 号以 ST 代理信用处理 |

### 3.2 算法层（目标/课程/信用/剂量）——部分成立、部分已被修掉

| 项 | 证据 | 判定 |

| 选择无监督→有监督 | 15.1 α 0/240（无 CE、无信用）→ 16.1 已见 0.61/0.43、train 0.5729 | **算法问题，已修**（监督一接上就会学） |

### 3.3 数据/标签层——不是主因

- 键片段＝描述、标签逐例断言唯一；新描述按构造未见，不是标错。

### 3.4 仪器层——已修、不改判

- D16-1 分母（240→60/60/15/36/108）、D16-2 局部 index 缓存（内容/反事实 true 侧、反序配对撤回）、D16-3 γ 语义（生成权重、复制权重 1−γ）均已只读修正并登记；总体/选择/γ/rescue 主读数不受影响。

## 4. 三个问题的回答

### a) 哪些症状在算法大改前后都存在？（架构不变式）

| 症状 | 大改前（15.1 及更早） | 大改后（16.1） | 结论 |
|---|---|---|---|
| 未见内容选择/完成 ≈0 | 10.21.4 未见组合 0–0.0417、未见实体 0.075–0.100；14.6 未见名字 0/40；15.1 未见名字/新描述 0 | 未见名字 0/60；新描述选择 0/60 | **同一症状＋四套算法＋同一切点（未见串的绑定）⇒ 架构不变式** |
| 首次偏差在实体字节 | 14.6：123/133 | 16.1：50%/63%（byte 3） | 同上（实体起点定位） |
| 记忆/复读捷径满足训练 | 10.21.1 复读记录子串；15.1 loss 2e-5 软混合＋模板 | B 臂 loss 0.003→1.1、总体 0.34 全靠记忆（未见 0） | 目标函数未强制"内容必须被用到输出"——跨版本持续 |
| 查询/选择不随内容变 | 10.21.1 五个描述词全选 glossary-1 | 16.1 新描述 0/60（但已见 0.61，程度不同） | 同族，程度被监督修复了一部分 |

### b) 哪些症状被那次算法改动修掉了？（证明另一部分是算法问题）

1. **选择接线**：0/240 → 0.38（已见 0.61）。给选择配监督就见效 ⇒ 15.1 的"选择为 0"是算法（信用/目标）问题，不是表示问题。
2. **γ 死门**：γ≈0 → 0.82/0.75，下限抬升步只占 14.6%/23.0%，移除下限差 0.0/+0.0167 ⇒ 门控崩溃是算法/接口问题，已修且下限不背成绩。
3. **课程触发**：固定位置（失效）→ 准确率触发（B 臂 127/121 次生效）⇒ 触发机制修好；剩下的 D16-4 是标签合同缺陷。
4. **字节合法性/终止**：10.21.1 的 0 EOS、64 字节截断、UTF-8 全败 → 14.6 起 utf8≥0.9875、16.1 eos=1.0 ⇒ 表达/评分接口问题，已修。

**不要把两者混为一谈**：修掉的都是"信号没接上"类（监督、梯度、触发、评分口径）；修不掉的都是"表示/接口表达不了任务"类（换序盲、单次选择、位置无监督）。

### c) 有没有"看起来相同、其实不同因"？

1. **15.1 选择 0/240 ≠ 16.1 新描述 0/60**：前者是接线/信用失败（无监督⇒α 没理由对齐），已被显式 CE 修复（0→0.38）；后者是表示不变式（字节袋无法组合匹配未见串），CE 修不动。这是**两个独立断点被顺序揭开**：先修接线，才露出表示。
2. **15.1 "γ≈0 复制未用" ≠ 16.1 "复制权重低"**：前者是门死掉（复制支路根本没跑）；后者 γ 高（0.82＝生成主导）是因为复制内容对不齐、模型"宁愿生成"。同是"复制不重要"的表象，一为门控崩溃、一为定位失败。
3. **14.6 反序配对 320/320 ≠ 16.1 反序配对**：前者是真实模型性质（字节级一致），后者因 true_raw 缓存缺陷撤回、不可判。同一指标名，一个是行为、一个是仪器。
4. **10.21.1 "查询不改变选择" ≠ 16.1 "新描述 0/60"**：前者是状态/内容压过查询（路径被淹没），后者是表示换序盲。都表现为"选择不随内容变"，但机制不同，且前者连已见都不行、后者已见 0.61。

## 7. 对 17 号候选的裁决：**保留（附强制修订）**

**17 号修的是架构层还是算法层？** 修的是架构层，且恰好对准被证明的两个断点：有序共享编码对 A1（换序盲，P1 证明）、逐步对象/地点/null 路由对 A2（单次整句选择）、最终 Q 锁定＋平滑下限对 γ 死区、输入/标签分离对 D16-4、ST 信用对 A4。算法层的问题（选择监督、课程触发）在 16.1 已修，17 号继承。

**它会不会撞同一堵墙？会，有一处明确的墙**：P4 证明"记录内定位锐度"在 gold 条件下都不成立，而 17 号的记录内位置分布（η=Q 的记录内归一）仍是学的、仍只吃稀释 NLL——17 号设计文本没有为"位置锐度"准备专门监督。若不做预检，17 号可能在实体字节上重演 P4。

因此裁决为**保留主选、附加两条设计/预算说明**（不改机制、不启动训练）：
1. **强制早期闸门**：17.0b/17.1 必须复跑 P1 式换序探针（证有序编码真的有序）与 P4 式 gold 跨度探针（证最终 Q 锁定后定位锐利）；两者不过则图阶段不通过。
2. **条件追加项**：若 P4 式探针在新图上仍 ≤0.1，最小充分集必须追加"实体跨度位置监督"（由冻结模板导出的名字字节跨度做辅助指针目标）再进 1.1——即"只补实体对齐"单独不够（F3 已证），但作为 17 的追加件是必要的。
