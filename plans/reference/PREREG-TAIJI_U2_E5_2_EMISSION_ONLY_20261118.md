# 预注册：E5.2 只训发射端能否在记录状态下答对而不伤旧能力

> 冻结于 2026-11-18，**开跑前**。目的是把 E5 的"纠正 vs 保持"从"写共享权重"换成"用记录＋训发射端"，看权衡是否消失。

## 1 问题

已定位（推断级）：释放的记录进入了 cursor，copy 有 0.34–0.85 质量，但指针 argmax 落在控制字节上——指针从未被训练。本卡检验：**只训发射端（记录/指针族参数），能否让 B 任务答对、同时 A 任务不掉。**

## 2 主体与协议（冻结）

| 项 | 值 |
|---|---|
| 主体 | `a5-pre-seed20261110`（注册表键，sha256 见登记表） |
| 可训参数 | A.5 合约声明的 `emission_parameters + record_parameters`（其余冻结） |
| 损失 | `record_loss`（A.5 原生：记录存在＋合法释放，对答案做逐字节损失） |
| 数据 | task B 的 24 项（A.5 首过全错的那 24 项），记录为**新位置** |
| 更新 | 24 项 × 25 轮 = **600** 次（与 A.5 的 A 训练同档） |
| 优化器 | A.5 合约的 `feedback_optimizer` |
| 评估 | A：`data["fit"]` 32 例逐字节完全正确；B：24 项逐字节完全正确（有记录） |

## 3 判据（冻结，唯一出口）

- **通过**：B 完全正确 **≥20/24（0.833）** 且 A 掉分 **≤0.02**（相对基线 32/32）。
- **权衡复现**：B ≥0.833 但 A 掉分 >0.02 ⇒ 记录 `tradeoff_with_emission_only`。
- **指针仍不可用**：B <0.833 ⇒ 记录 `pointer_training_insufficient`，不再加轮次。

任何出口都**不读 check**（仍 1/2 used）、不签父、不解锁 22.5.1／22.6／22.7。

## 4 与 A.5／E5／E5.1 的差异

| 项 | A.5／E5／E5.1 | 本卡 |
|---|---|---|
| 纠正来源 | 一次更新即可，随后回滚 | **600 次累积更新** |
| 可训范围 | 合约声明（含记录族） | **同上，不动共享主体其余部分** |
| 记录用法 | 更新时用一次 | **每个样本都带记录**（学会用指针） |
| 判据 | 纠正率 ≥0.80 | **A 不掉 + B ≥0.833 同时成立** |

## 5 风险

- 600 更新可能仍不足以让指针从控制字节转到合法字节；若 B <0.833，按出口 3 结案，不加轮次；
- 若 A 掉分，说明"发射端"本身与旧能力共享参数（`byte_head` 共用），那就是结构性权衡，需登记为架构结论而不是训练不足。
