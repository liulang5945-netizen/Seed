## 0. 为什么是这一步（不是又一次换头）

- 10.7 族的选择读数已被 14.1／14.2 判为**建在有语义泄漏的夹具上**：目标 `把X放到Y` 与正确动作串逐字节相同，14.2 的公平切分留出 6/6 全部来自复读目标串（状态置零 6/6、状态错位 6/6 ⇒ `state_contributes=false`）。⇒ 10.7 面既不能证明也不能否证参数化，**不在 10.7 夹具上继续换参数化**。
- 仓库中唯一无泄漏的选择夹具是 10.21（目标不点名实体、词汇只从 records 给）。它已经判过两次，都在同一处失败：
  - 10.21.1（冻结主体、手给描述词、零训练）：目标 top-1 真 **1/5**、置换 **1/5**，五个描述词在全部条件下都选 `glossary-1` ⇒ 读侧 `absent`；
  - 10.21.4（训练后的 `QueryBindingCandidate`，双臂两种子）：`reader_mean_source_top1` **0.1125／0.096875**，对 chance 0.05 约两倍，但门槛 `COMPARE_READER_BAR = 0.40`（`scripts/training/verify_taiji_composition_10_21.py:201`）未过 ⇒ `reader_selection_absent`。
- 两次的共同形状是"读源不被查询选择"。这是**机制归属问题**，不是样本量、不是头容量、不是学习率。再训一次不会告诉我们是哪一环坏了。
- 前驱 10.21a-2 的 rev2 卡已把这个形状量化（[卡](../../reports/taiji_core_slot_descriptor_10_21a2_20261101.json)）：五行词表下**描述词因子只占方差 0.40%、词表因子 99.59%**（F(4,16)=184.571、尾部 p≈0 ⇒ 查询信号真实存在但被极度衰减，残余交互 0.0086%）；把表缩成单行后描述词因子升到 **51.40%**。⇒ "查询没信息"与"信息被多行平均淹掉"这两种成因必须分开测，这正是本包把 D2 与 D3 拆成两个环节的依据。
- 因此 14.3 的唯一主问题是**把"读源条件化"拆成三个可分别否证的环节**，全部只读、零参数改动，用与 10.21.4 同一条取数链、同一货币（per-record 注意力质量 ⇒ source top-1）报数，使读数可以直接并回在册卡片。

## 1. 四件套

### 1.1 任务范围（一个主问题）

主体自己的读通路（`taiji/living_core.py` 的 `EpisodicRead`，经 10.21.2 已交付的 `taiji/query_binding.py` 源读取装配）在 10.21 无泄漏夹具上，**是否由目标决定它读哪一条记录**。三个环节各自有独立签名：

| 环节 | 命题 | 只读签名 | 判负形状 |
| --- | --- | --- | --- |
| **D1 查询侧** | 目标描述词进入读通路时携带可分的实体信息 | 同一 records 下换 descriptor：`goal_vector` 两两相对距离、注意力分布 L1 位移 | 位移≈0 ⇒ 查询根本没进式子（接线／编码问题） |
| **D2 选择侧** | 注意力把查询差异变成"读哪条"的差异 | **按组**（`model.config.groups`，本候选＝4）逐条记录的注意力质量、每组 source top-1（null 参与竞争）、每组归一化熵 `H_group / log(P+1)`（均匀＝1）、slot 与"整表均值向量"的相对距离 | top-1 低 **且** 各组归一化熵≈1 **且** slot≈表平均 ⇒ 读＝对表求平均 |
| **D3 值侧可达性** | 只把该条记录摆在读通路面前时，值侧能否带出它的实体身份 | **内容受限**上界探针：records 只放目标那一行（不训任何参数、不patch任何权重），量跨记录 slot 的相对距离中位数；同时按组报记录质量与 null 质量 | 受限下仍不分离（或分离只来自 null 竞争） ⇒ 值／编码器不可承载，任何读出头都救不了 |

D3 用**内容受限**而不是"把注意力置成 one-hot"，是有代码依据的设计选择而不是省事：`EpisodicRead.forward` 的 `values` 是模块内部量（[taiji/living_core.py](../../taiji/living_core.py)，`:168-178`），要在外部造 one-hot 加权和就必须自己重算 `self.value(positions) + self.value_meta(metadata)`——那等于新造一条读通路，测的就不是主体的读了（本仓规矩：不许在新仪器里重抄生成链）。内容受限则整条 `目标→查询→key/value` 全是主体自己的。

同理，**D1／D2／D3 一律按组报，不许只报跨组均值**：`state.h` 是 (groups, width)，`self.h(state_normalize(h))[:, None]` 使每组各做一次 softmax，所以"某一组在选、其余组在平均"这种形状在均值里是隐形的。顺带更正一处已入库的取法：10.21a-2 rev2 卡的 `attention_rows.normalized_entropy` 除以的是 `log(groups×(P+1))`，而每组是独立 softmax，正确的均匀上限是 `log(P+1)`（即该列被系统性抬高约 groups 倍）。它**没有**进入该卡的状态判据（判据只用方差分解），但引用那一列时必须按此换算，且 14.3 的卡不得再用这个分母。

### 1.3 资源预算

- **≤90 CPU 秒／≤240 墙钟秒**，单线程，`torch.set_num_threads(1)`。
- 单价同链实测（不外推）：本轮 10.21a-2 rev2 卡在**同一候选、同一载入路径**上跑 75 次读用 1.297 CPU 秒 ⇒ **≈0.017 CPU 秒／次读**（模型载入约 0.9 秒是大头，单次读约 17 毫秒）；10.21.4 的特征缓存是 29.61 秒／352 例（那条链含编码与状态装配，比裸读贵一个量级，不用来给本包定价）。本包面规模 **8 world × 5 描述词 × 3 条件（真／域内置换／反序）＝120 次读 ＋ 40 次单行受限读 ＋ 20 次实体／描述词单项替换对照 ＋ 空 records 下界 ＋ 锚点复算 15 次 ≈ 200 次**，按实测单价 ≈3.4 秒，取 **×10 保守上界 ≈34 秒**，在 60 秒工作额度内（90 − 30 reserve）。
- 14.3.0 的锚点复算必须**先现场重测单价**并在卡里报 `cpu_per_read`；若实测 >0.17 CPU 秒／次（即上界 10 倍），本包自动按 world 缩面（8→4 world，缩掉哪几个 world 逐格点名）而不是加预算。
- 收尾 reserve 写死：停止判据 `elapsed_cpu >= 90 - 30`，超限走 `budget_stop`，不许中途换小任务。
- 磁盘：不写权重、不写检查点；只写 1 份 JSON 卡（<2 MB）。

## 2. 预注册阈值（能翻）

机会水平一律点名分母。全部用 dev 面、每格 1 次读、tie 记错（容差 `1e-12`，沿用 10.21.1 的 `tie_tolerance`）。

1. **D1**：5 个描述词的 `goal_vector` 两两相对距离中位数 **> 1e-3**，且同 records 下换描述词的注意力 L1 位移中位数 **> 1e-3**；两项同向才记过。
2. **D2**：**每组**的 per-record source top-1（跨 40 格＝8 world × 5 描述词）**≥ 0.40** 记"条件化在场"（与 10.21.4 同货币同门槛，`null` 参与竞争、tie 记错）；任一组 **≤ 0.10** 记"该组缺席"；组间结论不一致时**按组分别记**，不许取均值糊过去，并整体记 `not_resolved`。同时按组报归一化熵（均匀＝1，分母 `log(P+1)`）与 slot 对"整表均值向量"的相对距离，作为"读＝平均"的直接证据。
3. **D3**：单行受限读下，跨记录 slot 相对距离中位数 **≥ 0.50** 记"值侧可达"；**≤ 0.20** 记"不可达"；中间 `not_resolved`。两个必做的分离对照（都只改一个成分）：**实体单项**（`圆口的器皿是木桌。` vs `圆口的器皿是窗台。`，前缀逐字节相同）与**描述词单项**（`圆口的器皿是木桌。` vs `带纹路的方块是木桌。`，后缀相同）。若实体单项对照不分离，则 D3 只测到字符串差异而非**映射到的实体** ⇒ 记 `not_resolved`，不得声称值侧承载词义。每条受限读都必须同时报该组的 `null` 质量；若分离主要由 null 竞争贡献（记录质量 < null 质量），同样记 `not_resolved`。
4. **对照必须是真置换**（同一条实体集合换映射，不是重排措辞），且**冻结性**：父参数逐位不变、`optimizer_calls = 0`。
5. **配对性**：14.3.0 的锚点复算必须逐位重现 10.21.1 的 15 行 `selected_source` 与 top-1（真 1/5、置换 1/5）；重现不了就 `engineering_failure`，本包不产结论。
6. 预算／异常出口按 §1.4。

## 4. 到"同一主体的最小中文连续任务"的衔接

## 6. 风险与不做的代价

- 最可能的读数形状：D1 过、D2 不过、D3 过 ⇒ `selection_bottleneck`。这会把"要不要更多训练/更大头"这个花预算的问题**永久关掉**，把下一步变量收敛到选择机制本身。
