## 4. 归因与不得夸大

- 直接原因：12 题整批平均梯度在 64 次更新内未拟合。与 N1-170 相比，每个训练题获得的梯度次数相同（64），但每步梯度是 12 题的平均方向，且没有更多更新；N1-170 的 4 题 batch 在同一步数已到 0.301 nats，本包仍在 1.6 nats 且继续下降。
- 因此本包**不能**判「v2 不能泛化」，也**不能**判「题-答绑定失败」；只能判「在 64 次整批更新下训练侧未拟合，留出读数处于机会水平」。
- 同折不同 prompt 的自由输出几乎相同，是当前训练阶段的描述性事实；它不推翻 N1-170 的「TF 读取 104–121 个源 byte 位置」，也不构成 J1 信息消费判定。
- 0 dev、0 reference、0 N1-166；`can_promote=false`；不称语言能力、L2 或未见泛化。

## 7. 唯一后继建议

**N1-172：fit-first 曝光探针**。沿用同一 16 题与折分配，不改选择、不改判据；只改一个变量——把「64 次 12 题整批更新」换成「最多 192 次整批更新，并在训练 TF 中位数首次 ≥0.90 时提前停止」，先确保训练侧拟合，再读留出。为留在 CC-2 剩余 932 CPU 内，只跑折 0 与折 1（8 个留出题，主判据等比例 ≥4/8 且比 A/B 各高 ≥0.15），上限 750 CPU；若 192 步仍不拟合，则把「曝光/优化预算不足」作为独立瓶颈记录，并只在明确批准的新预算下讨论扩大规模。
