# 训练系统精简记录

2026-10-23，用户要求梳理训练系统并删除繁琐流程。当前处理范围为 R2 continuation 的实际启动与运行路径。

## 结论

唯一活动入口为 `scripts/training/run_taiji_r2_resume.py`。直接复用 checkpoint 存储与训练执行器，不再调用 V1→V2→V3 manifest 构建链，不再为运行源码绑定测试文件哈希。旧文件不再出现在活动操作指令中；它们被已有不可变 launch 引用，保留原字节作为历史证据。没有删 checkpoint、账本、语料或失败记录。

| 原流程 | 精简后的实际行为 |
|---|---|
| 每条 start intent 都扫描六万多账本文件，恢复函数再执行一次 | 已记录结算按序号直接寻址并校验 SHA；活动 token 不扫描；缺失旧记录时单次扫描共用结果 |
| V3 经 V2/V1 构建 manifest，临时切换全局预算 | 一个入口直接生成来源、预算、起始 checkpoint 与账本 manifest |
| 加载新额度前按旧额度验证实耗，导致永久拒绝续训 | 先验证已有 amendment/source SHA，再采用该额度读取账本；失败恢复旧运行常量 |
| 每个保存周期读取三臂训练历史，预测任何缺口都停机 | 删除剩余全程预测否决；定期只读实际账本余量，每个 work unit 仍受原子硬预算约束 |
| 启动两次 CPU 采样，高负载即拒绝 | 删除整机 CPU 采样否决；CPU 使用量继续真实记账 |
| 启动 7 GiB，循环 8 GiB | warm_start 全程统一 7 GiB |
| 启动无可见阶段输出 | 输出预检、恢复、已结算 resumed、耐久 commit 和完成节点 |

## 保留的必要保护

同臂 writer lock；原 parent 与 receipt 祖先链；bundle/source SHA；固定 NTFS 原子耐久发布；新进程恢复验证；每步 CPU reservation/settlement、聚合与单臂上限、停止 reserve。未知中断尾账仍保守累计，未改账或缩减费用。终点评测前仍要完整审计。

## 验证与现状

20 项聚焦测试通过，覆盖直接寻址的工作量边界、事件篡改拒绝、旧记录单次扫描、活动 token、统一内存门槛、停止 reserve、旧额度以上的新预算采用，以及账本尾链。真实 `--check-only` 已通过 checkpoint 祖先链、存储、来源和账本检查；ruff 通过。该命令不训练、不消费评测数据。

上次实际训练日志截至 24,998 episodes，耐久点仍 24,992；不把无效句柄或旧锁视为正在运行。v1.4 当前累计 1.55M/臂、4.4M 总额，上轮已落盘；本次不再提高额度。

## 后继与限制

下一步使用单入口续训 warm_start，观察耐久 checkpoint。新简化 manifest 的 endpoint 审计接线在最终评测前完成；已有 V3 历史 manifest 也需被终态校验器识别，不得跳过。原三臂配对评测与整模型能力门不因流程精简而改写。
