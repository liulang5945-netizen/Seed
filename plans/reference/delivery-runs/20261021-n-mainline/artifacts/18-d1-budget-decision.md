# D1 预算裁决材料：三臂到完整终点的缺口与唯一推荐

日期：2026-10-23，Asia/Shanghai。状态：**证据与推荐已备，等待 owner 裁决**。本材料不启动训练、不消费保留题面、不改冻结协议。

## 结论

**唯一推荐：批准 v1.5 补额，把每臂上限从 1,550,000 提到 1,590,000 CPU 秒、总计从 4,400,000 提到 4,560,000 CPU 秒，按原范围完成三臂 final，再执行冻结 W5b 配对评价。**

理由：三臂已分别完成 56.3%／91.6%／83.3% 的预训练更新，合计已花 4,369,799 CPU 秒；按耐久游标补完剩余更新只需约 **118,303 CPU 秒**（约为已花成本的 2.7%）。不补额则三臂都无法同时完成，W5b 继续阻断，已花成本无法转化为任何语言能力结论。

## 两个选择

### A. 补额完成原实验（推荐）

- 能回答：冻结 W5b 的 parent＋三臂 39×4＝156 次生成、固定前 12 个 family 人工判读；在同一可恢复版本上比较原生中文连续对话表现；给 CC-2 提供完整端点而不是 partial 混淆。
- 放弃/成本：新增约 16 万 CPU 秒额度；仍需按原纪律逐臂恢复、单臂串行、失败即停；评价另计 CPU/wall 各 14,400 秒上限。
- 风险：未知尾账仍可能消耗缓冲；本推荐已预留约 7.2 万总计缓冲（与 v1.4 当时留约 7 万的口径一致），并把 warm 单臂缓冲留到约 2.9 万。

### B. 封存 partial，转 CC-2 归因

- 能回答：训练充分性、工程/资源约束、部分错误切片；可较早开始归因设计。
- 放弃：不能产出 W5b 的四端配对证据，不能给语言能力胜负结论；partial 与“训练未完成”混淆，CC-2 很可能仍要回到训练。已花 4.37M CPU 秒只差 2.7% 就能转化为完整端点，选择 B 等于放弃这部分已投入。
- 现实约束：即使只想跑单臂，当前总计余量 30,201 也只够 fresh_same_capacity 单独完成（约 25,884）；仍无法形成 W5b。
