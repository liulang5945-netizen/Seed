# 评价资格消费边界修订 v2（待裁决）

## 1. 要解决的问题与唯一推荐

两次正式attempt都在题面选择前因工程接线失败，0条行为输出。其修复与98项回归、真实Job/token/NTFS授权探针已完成，见[恢复v1结案](../../../PLAN-R2-EVALUATION-RECOVERY-V1_execution_closeout_20261025.md)。仅调整资格边界不能代替工程修复，也不能保证后续模型通过。

| 资格何时消费 | 优点与问题 | 本稿裁决建议 |
|---|---|---|
| 进程attempt形成时 | 容易实现；启动、路径和恢复故障都会消耗科学试验资格，工程修复反复变成人工特批 | 旧合同保持；后继不沿用 |
| 第一条成功输出时 | 工程容错较宽；但读题、失败生成、部分输出都可能已经提供反馈，之后重跑会造成选择偏差 | 不采用 |
| **首次真实题面读取之前** | 把预算受控的工程准入与不可逆信息消费分开；需要耐久marker、统一读取入口和完整失败记录 | **唯一推荐** |

一次采纳v2即可授权后继包按固定候选/评价范围完成工程准入及一次正式题面消费；不再对同范围内每次工程修复、重启或文件提交逐次申请。该授权不能追溯性重开旧v1。

## 2. 两阶段、一总账、一份正式消费标记

| 阶段 | 可以做什么 | 结束及失败处理 |
|---|---|---|
| 工程准入 | 元数据/来源/资源检查、真实Job/IPC/token/claim、只读四端点恢复、合成完整生成链 | 每个工程尝试有独立ID和耐久记录；未触达题面且退出/费用可核验时，可在同一剩余额度内修复并重新准入。没有模型行为评分，不消耗新正式资格 |
| 正式消费 | 所有端点恢复receipt齐备、同一模型/decoder/源码冻结后，先耐久发布唯一`face_access_started`，成功后才运行真实selector、解析开发面正文或复用其缓存 | marker发布即消费一次，selector本身失败、零输出、半条输出或后续生成失败都不能重试；固定156条完整输出后只做原定48回答判读与结案 |

合成完整生成链只使用合成模型/语料；工程阶段不在真实候选上新增行为查询或按输出调参。进入正式阶段前按冻结恢复语义复核四端模型和初始状态，不把工程诊断残留带入比较。

工程尝试ID与科学资格ID分开，但都归同一个evaluation_window_id。不得按新进程、新prefix、新协议号、客户端重启或新日期清账。最多一个正式消费marker；已消费后换名/改seed/补题/续最后一条均拒绝。

marker发布失败、发布返回不明或无法确认旧marker是否存在，按资格可能已消费停止；不能仅因“没有face文件/没有输出”就删除marker重开。发布后即使尚未读到一个字，也不退款。

## 3. 哪些访问触发消费

- 明确允许且不触发：对既定文件做不可解释的字节哈希、原有仅提取`split`字段的扫描、仅解析train记录并按原合同恢复模型。这些操作不能输出/保存dev正文或将其送入模型。
- 必须先消费：进入真实dev selector（包括其family/episode选择）、读取/解析真实题目与历史、打开已选face内容、将已有题面缓存交给模型或审阅者。缓存命中同样是信息访问，不能成为旁路。
- 当前`_load_assistant_train_corpus()`与selector访问同一混合split JSONL：前者仅扫描split、跳过非train记录，后者读取dev身份/正文。v2必须在统一面访问入口区分这两种权限；不能只给`_select_dev_prompts()`外面包一层后便宣称没有其他入口。
- 无法判断某异常前是否已暴露题面、是否有部分生成、是否有未经记账的其他消费者时，停止并记录不明；不以“输出0”反证未消费。

该证据边界只覆盖受监督执行链，不冒称审计整台机器全部历史访问；原39-family仍是开发面，不升级为全新独立确认集。N1-166、reference及其他未授权封存面继续不可读。

## 4. 不变的研究问题与预算

复用已训parent＋full_turn_1m/warm_start/fresh_same_capacity，同一checkpoint SHA、decoder、39-family开发面，固定156生成、48回答及四维判读；0参数/优化器更新，`can_promote=false`。不通过换模型、删难题、降分母或事后改判据获得成功。

承接用户既有额度：原评价CPU/wall各14400秒为外层上限；v1已批CPU14140秒、wall13480秒分配是更紧的现有边界。v2不自动提高任何额度。旧3400历史预留、准备费用、两次失败、实际probe/恢复/发布以及未知尾账全部进入同一累计账；已知实耗、条件上界与未知分别列明，不重复漏计或把预留当实耗。

wall按各实际运行区间累计，不重置；进程树已确认停止后的人工等待/代码编辑不冒称运行wall，退出未核验的空档则按未知尾账保守处理。

**不是每个工程重启再获得10500秒。** 每次操作前，用同一账本核对剩余量，保留尚未完成的四端恢复、固定156生成、selector/发布和失败退出所需完整reserve。无足够余量就不开始下一动作；工程故障可修复不等于可以无限运行。未知成本没有可审计上界时停止，不能先重跑再补账。

本稿不宣称剩余量一定够用。落地时先对现有失败和探针结算/条件预留做只读对账；未覆盖的费用或资源缺口必须作为具体阻塞记录，不能通过重置包编号解决，也不反复小额提额。只有实际改变总预算、候选、题面权限或声明范围才重新进入决策。

## 5. 采纳后直接实施的最小改动

1. 保留冻结evaluator及v1原件，新增一个明确的v2上下文，统一拥有路径、source/endpoint snapshot、window账和face权限；parent、worker、token授权、readiness、face读取全部消费它。避免散落的固定路径和多处可独立失配的默认值。
2. 在同一parent监督链内完成工程准入，再发布上述一次marker；没有marker时真实selector/face/cache读取均拒绝。恢复成功后不得换模型/decoder再进入正式阶段；工程修复版本需重新准入并冻结，但不问新的科学问题。
3. 保留真实Job/token/NTFS与全合成4恢复/156生成集成。再用合成故障证明：marker前工程失败不消耗正式资格但费用增加；marker存在后即使0输出也拒绝再次读题；发布不明、缓存旁路、异面/异namespace、源码漂移、余额不足均停止。
4. 先提交可复核实现和合成/真实工程证据；在v2明确获准后，按既有固定范围自动推进至一次评价、固定判读和有限结案，不再逐文件申请。

当前只交付规则修订，不执行v2、不修改已批准机器合同、不改旧失败/费用、不读取题面或加载新模型。采纳的是后继规则与其固定范围授权，而不是宣告历史两次资格未消费。
