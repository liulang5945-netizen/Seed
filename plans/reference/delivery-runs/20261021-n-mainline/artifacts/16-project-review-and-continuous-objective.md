# 项目改进评审与持续目标建议

日期：2026-10-23，Asia/Shanghai。评审基线提交：`4c1ba7f730`。

本次由主理人核对根需求、架构/交付计划、运行与产品代码，执行审阅子代理独立核对训练、评测和CI。这里只记录已完成的审阅，不补写未完成的独立架构审查。用户请求是提出改进意见和最合适的持续目标；下述目标为建议，未创建或替换Goal，未据此改变预算、默认模型或冻结评价协议。

## 1. 核心判断

项目根需求与高上限方向已较清楚。当前最重要的差距，是同一个真实模型版本中的表示、记忆、预测、选择和反馈，尚未形成已验证的联合能力与学习信用链。这个差距在[核心需求](../../../../active/TAIJI_CORE_REQUIREMENTS.md)第38行已有明确表述。

当前应把研发进展的主要单位改为“同一模型版本新增了什么真实能力、保持了什么旧能力、花了多少资源”，并让每项机制研究服务于这个单位。局部实验、静态合同、训练步数和可恢复性继续作为支撑证据。

### 已核对的事实与边界

- [README](../../../../../README.zh-CN.md)明确区分态极认知模型、Seed运行时、Harness界面；完整架构和通用对话仍属待验证目标。
- [旧R2对话结案](../../../../reference/PLAN-R2-DAILY-DIALOGUE-ARCHITECTURE-AUDIT_20261021_execution_closeout.md)的12个人工样例为0/12连贯贴题。该负结果属于旧配方，不能套到尚未完成评测的新checkpoint。
- 新单入口精简已经实际生效，不能再次把“合并入口、消除重复对账”列成尚未做的工作。15:24快照：warm进度25,402 episodes / 12,273,366 updates；最近耐久点25,376 / 12,263,243。训练未形成完整终点和新语言能力结论。
- 同时点账本序号62,010，warm charges约1,541,629.857 CPU秒，活动reserve252秒；在1.55M单臂上限下可用余量约8.1k秒。15:19按近期实际更新速率粗估，剩余预训练仍约需12.7k–14.8k CPU秒，另有SFT与终态发布；这提示完整终点与额度尚未闭合。估计用于沟通和排期，不恢复预测否决门，也不是新预算授权。
- [当前队首](../../../../active/roadmap/03_CURRENT_EXECUTION.md)承认新简化manifest的终点审计待接线；[endpoint准备器](../../../../../scripts/training/prepare_taiji_r2_continuation_endpoints.py)仍要求三臂终点。[旧评测入口](../../../../../scripts/training/evaluate_taiji_r2_daily_dialogue_recovery_v2.py)不能直接冒充extension评测。当前只跑warm不会自动改变原四端点评测合同。

## 2. 最值得改进的五处

| 优先事项 | 现存问题 | 建议的改进与可见结果 |
|---|---|---|
| 模型联合能力 | 机制/局部runner的通过尚不能拼成一个可用模型 | 围绕一个连续任务，让语言、状态/记忆、预测/行动产生可观察的共同贡献；以同bundle的未见实例、消融、真实结果和恢复后表现验收 |
| 学习有效性与上限 | 停止标记、合法UTF-8、复制、loss改善和延长训练，均不足以证明语义、历史消费和推理 | 分清“没学够、数据不支持、目标/信用分配错误、容量不足、结构失效”；完成当前配对证据后只选择一个主因推进。把新结构投入放在可学习的表示、记忆消费与反馈信用链；成熟编解码、优化器和工程设施可以复用 |
| 训练到评价到使用 | 新checkpoint已有，extension endpoint/provider/worker/manifest尚未贯通；产品默认加载链与研究候选分离 | 在隔离候选模式下共用加载与生成路径，固定代码、checkpoint、decoder和模式；保存原始输出与能力卡，证明研究收益能在实际入口复现。接入不自动切换默认模型 |
| 运行工程与资源规划 | 精简入口已修复即时阻断，但仍通过运行时替换挂接旧冻结执行器，额度/未知尾账/完整终点仍需统筹 | 保留当前在跑代码，后继受控版本把训练器、存储、预算、实验配置做成清晰接口；区分实际进程CPU和未知尾账上界，不擅自核销旧账。开跑前一次规划到可判定出口，运行时用廉价监测展示“在运行、预计能完成、触顶停止”三种事实 |
| 权威状态、CI与计划 | 部分入口文档保留旧额度/运行快照，CI历史判断与新workflow接线不同步 | 由run manifest、progress/receipt和CI提交身份生成当前摘要；一个活动队首、一个能力卡/候选身份、旧方案清楚退役。CI应针对对应提交定位失败，避免扩大成重跑全部研究 |

高上限来自可学习能力和可迁移的机制；研究时允许困难方案，不以多添模块或反复改文档代替能力证据。当前不能据此宣称需要立刻扩模、增加epoch或更换架构。

## 3. 唯一持续目标建议

> 持续把态极（Taiji）发展成一个由自身认知机制驱动、能通过自然中文可靠完成连续任务、跨会话积累和修正经验、从反馈中学会新能力并保持旧能力的原生认知模型。沿N主线迭代，以同一可恢复模型版本在未见任务上的真实表现、旧能力保持和实际资源成本决定下一步；先形成可用对话与一项真实认知闭环，再验证持续适应，逐步扩大能力范围。

这是一条目标的不同成熟阶段，不是并行启动多个方向，也不是在本轮同时实现全部长期CR。

### 沿用既有验收等级

1. **先到L2：基础对话真实可用。** 在声明范围内完成短问答、材料事实、多轮上下文与简单指令。固定模型/入口、保存原始回答、进行必要对照；新R2训练完成只是评价的输入条件。
2. **再到L3：同一模型可交付。** L2加至少一项项目代表能力，并有真实终态、来源/权限、恢复及资源证据；材料齐备后交用户实际验收。隔离集成原型可提前开发，不能用UI或不同模型的成绩拼装L3。
3. **继续到L4：新经历能带来持续收益。** 分开评价状态记忆、参数学习和结构变化；按在线协议先预测后释放反馈，证明新任务适应、旧能力保持、纠错与中断恢复。不能拿重放原题或全程平均分掩盖遗忘。

以上沿用[07整模型交付](../../../../active/roadmap/07_MINI_MODEL_DELIVERY.md)的L2/L3/L4，不另建等级。07中建议分数线仍须在正式评价前按原流程冻结，本次不采纳新数字、不降低已有门槛。多模态和开放式成长继续保留为上限方向，按能力证据依次准入。

## 4. 唯一下一步

**趁warm训练，补齐extension评测适配链：新旧launch manifest → endpoint/provider → 受监督generation worker → 原冻结W5b输出。** 先做不接触冻结题面的静态/合成验证，使训练完成或预算触顶后均有明确、可审阅的结案材料；不把partials改称final。其他两臂是否继续仍按实际费用与原配对合同裁决。

本次只做评审及计划更新，不据建议启动新的研究分支、训练配置或能力晋级。当前运行中的warm续训按原有效保护继续。
