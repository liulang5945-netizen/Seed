## 2. 保持门口径裁决

### 2.1 两句话的原文对照

- 纲领（`plans/MAINLINE.md:57`）："……学习新能力并**保持已核验且仍有效的旧能力**……"
- 现行门（`plans/MAINLINE.md:51` 自承 + `scripts/training/verify_taiji_fragment_horizon.py:76`）："当前保持门/回退使用**旧 NLL 绝对变化**，测**对称稳定性**，**不直接证明遗忘**。"
- 可执行形式：`abs(mean_nll_after(RETENTION) − mean_nll_before(RETENTION)) ≤ 0.030`

### 2.2 差在哪几步（逐步拆）

| 步 | 差在哪里 | 具体后果 |
|---|---|---|
| **S1 符号** | `abs(Δ)` 把"变好"与"变差"折成同一个数 | "旧能力退化 0.02 + 新能力大涨"与"旧能力改善 0.02"在门上**不可区分**；一侧的改善可以冲销另一侧的损伤，只要净值不越门。纲领关心的是**退化方向**。 |
| **S2 量纲** | NLL（teacher-forced 平均字节负对数似然）vs **正确性** | `native_development.py:32-35` 只做 `-log p(target_byte).mean()`，**没有正确率、没有任务分母、没有"这条任务能不能做成"**。NLL 不变差 ≠ 任务仍能做；NLL 变差也不必然是遗忘（概率质量可搬到等价表达上）。纲领的"仍有效"是可执行性，不是似然。 |
| **S3 前置** | 没有"**已在父版本达标**"这一条件 | 门只比 before/after。一个 before 时刻本来就 0/6 的任务，"保持"住了也过门 ⇒ **空集可以签通过**。纲领的"已核验"是一个**前置状态**，不是一个差值。 |
| **S4 能力集** | 没有"旧能力集"的定义（清单／分母／覆盖／有效期） | 全部证据只有 **RETENTION 一个合成生涯上的一个标量**。纲领说的是"旧能力"（复数、有在册清单、有核验状态、"仍有效"要能被判失效——被纠错/被替代/过期）。仓库里没有这张清单，也没有"哪些项在册、哪些已失效"的记账。09.6.9 自己也写明"RETENTION 仍只作保持探针，不当评估面"。 |
| **S5 语义** | §51 已自我降级 | "测对称稳定性，不直接证明遗忘"这句话本身就把该维度从"保持"移到了"稳定性"。因此**现行门不是保持门的弱版本，而是另一个量**。这一点必须在任何引用处显式写出，否则"门通过"会被读成"保持成立"。 |

> 一句话：四步里 S1/S3/S4 是**机制缺失**（可以补上，10.21 合同补了两步），S2 是**测量对象选错**（更贵），S5 是**已自承的口径偏差**（最便宜，只需改称呼）。最贵的是 S2——因为换正确性就要换夹具：现有 RETENTION 生涯根本没有"正确/错误"这一栏，只有字节标签。

### 2.3 10.21 §6.2 修好了哪一步

合同原文（`SPEC-TAIJI-CORE_COMPOSITION_10_21_20261101.md:151`、`:153`）：
> "仅有已在父版本达到预声明能力门、仍有效的旧任务，才可用于'旧能力保持'；若不存在，记 `not_supplied`，不让空集签保持通过或推动 11 准入。"
> "保护已有能力的未来门采用有符号损失/实际正确性：`D_old=max(0, L_old_after − L_old_before)`，对称 `abs(ΔL)` 另报为稳定性。"

- **修好了 S1（符号）。** `max(0, L_after − L_before)` 是**单侧**的：只罚退化、不给改善发钱（"变好"贡献恒 0），因此不能用新得分冲销旧损伤；同时把 `abs(ΔL)` 降级为"稳定性另报"。**这正是 §51 缺的那一刀**——两个量被分开命名了。
- **修好了 S3（前置）。** 要求"已在父版本达到预声明能力门且仍有效"，并把空集显式做成 `not_supplied` 而不是沉默通过，且明确 `not_supplied` 不推动 11 准入。

- **没修好 S2（量纲）。** 公式用的是 `L_old`，也就是**损失**；"实际正确性"只出现在**文字**里，没有成为公式的一个分支、也没有成为报告里的一个独立字段。⇒ 正确性面**仍未落地**。
- **没修好 S4 的另一半。** `not_supplied` 只判"有没有达标的旧任务"，**没有规定能力集怎么枚举、多少项在册、覆盖率多少、"仍有效"如何判定**。"纠错和过时事实不受保护"是原则，不是可执行字段。
- **而且是未来口径。** §6.2 写在 10.21 合同里，而 10.21.3–10.21.6 全部未准入。全仓 grep `not_supplied`：只出现在本合同文本与其他系列（`tests/taiji_native/test_cap0_baseline_contract.py`、`scripts/training/check_p3b_criteria.py`），**taiji-core N 线没有任何一份已执行报告携带 `D_old` 或 `not_supplied` 字段**。

- 10.21.3 → 纲领翻真之间还有**两道未批准的门**：10.21.4（1200 CPU）＋10.21.5（600 CPU 独立确认），合计 **≥1,980 CPU**，且 10.21.4 要求"两 seed × 两臂 × ≤300 步"。
- **即使 10.21.4 过门，纲领"未见任务表现"也只能翻到"夹具级正读数"**：§6.1 明写"40% 只是一份机制研究的最低有用效应提案，**不够宣称可靠中文或 P2/L3**"，10.21.5 的 40% 也"只作机制门"。
- ⇒ **把 10.21.3 说成"决定纲领某条能否翻真"的一步，是把它抬了两档。** 它决定的是**下一档预算是否可行**，不是能力是否存在。

### 4.3 一条必须一起看的算术（**不是新读数**，是两数相除；前提未定，故不当结论用）

已发布的唯一相关单价（`reports/taiji_core_10_21_graph_v2_20261101.json:cost`）：
`adam_calls_total=12`、`cpu_seconds=26.265625`、`worker_cpu_seconds=16.84375`、`recorded_bundle_bytes=1.41326e8`。

除法：`26.265625 / 12 = 2.189` CPU 秒／Adam 调用。
按这个单价外推 10.21.4（2 seed × 2 臂 × 300 步 ＝ **1,200 次调用**）⇒ **≈2,628 CPU 秒，是 1200 上限的 2.19 倍**。

**但这个数不能当结论用**，三个理由必须同时给出：
1. 26.27 秒里含 `worker_cpu_seconds=16.84`（spawn／恢复／replay）与四 profile 的 FD 检查，而 10.21.4 的 300 步是**连续训练、不含恢复**；
2. 10.21.2 的 profile 是 small/S 与 f32 对照，不是任务 profile；
3. 若真实训练步单价低一个量级，1,200 步可能只花 260–900 秒，**能落进上限**。

⇒ 结论：**区间横跨上限**，这正是定价该回答的问题。但它给出一条**硬要求**：**若 10.21.3 不把四类单价拆开报，180 秒买到的混合单价根本无法外推**（混合单价只能得出一个横跨上限的区间，与定价前的先验一样宽，等于没买）。

### 4.4 建议（三条，属建议不属批准；不含预算裁决）

- **S1（必要条件）单价四项分列。** `cpu_per_train_step` / `cpu_per_restore` / `cpu_per_eval_example` / `cpu_per_bundle_MiB`，并单独报有效游标与 `optimizer_calls`（§7.1 已要求两者分开记）。**不拆就不批**——理由见 §4.3。
