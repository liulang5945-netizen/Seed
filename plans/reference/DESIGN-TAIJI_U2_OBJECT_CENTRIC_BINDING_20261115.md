## 2 代码级归因：重复槽是当前前向的稳定解

这一节是本卡的核心。它回答“是不是架构问题”，并给出可检验的预测。

**先纠正一个容易说错的判断。** 现有绑定**已经有** token→槽位的竞争：`assignment = torch.cat([score, null], -1).softmax(-1)` 是对“3 个槽＋空”做归一，每个 token 的单位质量被分给槽（[u2_subject.py](../../taiji/u2_subject.py) 第 450 行）。它的内容也已经是**质量加权均值**：`content/(mass+0.01)` 展开后等于 `Σ α v /(Σ α + 0.01N)`（第 453–462 行）。所以“没有竞争”与“归一化写错”都不是准确的归因。

真正的缺口有三条，全部在结构里：

1. **槽位之间没有身份信号。** 三个槽的初始差异只来自 `initial_h`／`initial_p` 的随机初值（第 223–224 行）；之后所有功能通路对槽位是**对称的**——共享权重、共享 `object_z` 投影（第 305–306 行）、共享 corrector。对称的初值差异会随时间被拉平，而没有任何机制要求槽位保持不同。
2. **细化发生在共享状态里，不在绑定里。** `observe` 把 `binding` 放在 `for _ in range(2)` 里，每轮用 corrector 把 `obs` 写进 `h/p/v/s/l`（第 951–977 行）。当三个槽的 `obs` 接近（例如 α 接近 1/3 均匀），corrector 的输入就接近，输出也接近，写入后三个槽**再次变得相同**。也就是说，当前结构会把“重复槽”主动写回去，它是一个**固定点**。
3. **读层的惩罚到不了这条通路。** P4.4 的存在门与重复惩罚加在训练期读出上；它们只能通过梯度间接影响 `α`，而前向的固定点没有变。读数反而更差（0.436→0.218），与“惩罚在和配对匹配互相拉扯”一致。

**可检验的预测**：若在绑定内部加入①每槽身份锚、②绑定内迭代细化，则在同样的编码器、同样的列 token、同样的标签、同样的读出脚手架下，三个槽的内容会先分化再写入状态，set 准确率应从 0 抬起；若仍为 0，则“绑定结构是墙”这一判断需要改写为“这套监督不足以驱动任何绑定”，本路线按失败关闭。

## 3 设计方案：`binding-v2`

### 3.1 单位是什么（用平实的话说）

一个**对象槽**就是一个计算神经单位：

- **身份**：槽下标 `i` 加一个学习到的身份向量 `a_i`（8 维）。这是本卡新增的唯一“身份”参数。
- **持续状态**：`h_i`（外观）、`p_i`（位置）、`v_i`（速度）、`s_i`（尺度）、`l_i`（存在 logit），即现有 40 个状态字段里的 5 个，**不新增状态字段**。
- **可学习连接**：`bind_query`／`bind_key[m]`／`bind_value[m]`／`null_score[m]` 全部继承，新增一个共享的槽更新网络。
- **生命周期（本卡只做最轻的一层）**：空槽靠空 token 与 `l_i` 自然休眠（质量门 `mass/(mass+0.01)` 已经存在）；**出生、分化、合并、退役不在本卡范围**，留给后续单位生长卡。

### 3.2 数学定义

记号：`K=3` 个槽，`d=8`，某一模态有 `N` 个 token `y_n ∈ R^d` 与坐标 `x_n`。先验状态给出 `z_i^0 = object_z(prior)_i`、`p_i`、`s_i`、`l_i`。

对迭代 `t = 0,1`（绑定内 `T=2` 轮）：

```text
q_i      = W_q (z_i^t + a_i)                      # 身份锚只在查询侧
k_n      = W_k^m y_n ,  v_n = W_v^m y_n
ℓ_{n,i}  = <q_i, k_n>/√d + log σ(l_i)
           − ||x_n[:2] − p_i||² / (0.01 + mean(s_i[:2]))      # 仅 rgb
ℓ_{n,∅}  = 0
α_{n,:}  = softmax([ℓ_{n,0}, …, ℓ_{n,K−1}, 0])    # 每个 token 在 3 槽＋空之间分配
s_i      = Σ_n α_{n,i}                            # 总质量，用于内容归一
m_i      = s_i / N                                 # 平均质量，沿用 v1 的 corrector 门语义
u_i      = Σ_n α_{n,i} v_n / (s_i + ε)
z_i^{t+1}= LayerNorm( z_i^t + MLP([z_i^t, u_i, m_i, log σ(l_i)]) )
```

最终返回 `content_i = u_i`、`mass_i = m_i`（平均质量，≤1，保持 `mass/(mass+0.01)` 的休眠门不变），rgb 的 `spatial_mass = mass`；跨模态仍按现有 `reliability` 加权融合（第 435–461 行不变）。外层 `observe` 的 `for _ in range(2)` **保留**，所以一次观测总共 4 轮细化、2 次写入。

新增参数（实现时以实测为准，不用手算代签）：

| 张量 | 形状 | 标量 |
|---|---:|---:|
| `slot_anchor` | [3, 8] | 24 |
| `slot_update.first` | [16, 18] + [16] | 304 |
| `slot_update.last` | [8, 16] + [8] | 136 |
| `slot_norm` | LayerNorm(8)：w＋b | 16 |
| **合计** | **7 张量** | **480** |

输入 18 = `z`(8)＋`u`(8)＋`m`(1)＋`logσ(l)`(1)。设计预算 **≤560 新标量**；实现实测若超过，先停卡报告，不得自行扩大。

### 3.3 与 v1 的差异（只列真正改动的）

1. **身份锚 `a_i`**：查询侧加性偏置，每个槽天生不同。这是打破“对称初值被拉平”的结构手段，不是惩罚项。
2. **绑定内迭代 `T=2`**：`z_i^t` 在绑定内部用学习到的门控更新，不经过共享状态的 corrector 写入，因此细化不会被“三槽同一写入”抹平。
3. **内容直接取 `u_i`**：语义与 v1 的加权均值等价，只是不再经过两次除法；读出的量纲更稳定。
4. **不新增任何惩罚、门或损失权重**。P4.4 证明“加约束”不是修法；本卡的分化必须由前向自己产生。

**不动的部分**：编码器（冻结在 P4.1 B 臂）、列 token 布局 `column-observation-v1`（零新参数）、数据、读出脚手架（458 参数、6 排列精确匹配）、字节头、纠正协议。标签用 P4.4 的真值锚定可见子集（比 P4.3 的列均值分箱更干净），因此这是**「绑定结构＋标签质量」两项差异**，不是严格单变量；裁决按绝对门，不靠与 P4.3 的差值。这一点在读数前写明，避免把结果解释成只由结构造成。

### 3.4 被否方案（写明为什么不选）

| 方案 | 不选的理由 |
|---|---|
| 硬编码分割／连通域 | 绕过主体，无法签“学习到的对象单位”，上限最低；违反“单位可学习、可继承”的目标 |
| 继续在读层加惩罚／加剂量／换读出 | P4.3／P4.4 已实测，且 P4.4 更差；预注册已封存这条方向 |
| 加宽编码器 8→32 | P4.1 已证 8 维可承载颜色（0.906）；DEBT-OBS-1 已关闭为“不需要加宽” |
| 单独训练一个图像→（颜色,位置）集合的回归头 | 不经过主体单位，无法继承、无法回答“机制贡献”，也会重蹈脚手架覆盖主体的覆辙 |
| 自监督重建目标（slot attention 经典配方） | 上限高，但会同时改变结构与训练目标；本卡先做**单变量结构对照**。若本卡失败，重建目标是下一张卡的独立假设，而不是在本卡里混在一起 |

## 6 判据（预注册）

### 6.1 最小试点（3 臂 × 461 步，先于全剂量）

目的只是**检查机制活着、checkpoint 存得住**，不做能力裁决。三臂：

- A：完整 v2（锚＋T=2＋`u_i`）。
- B：去掉绑定内迭代（`T=1`，参数仍在，等价于“只加锚”）。
- C：去掉身份锚（查询侧 `a_i=0`，参数仍在但零梯度，守卫须如实报告）。

硬门（**只对 A 臂**；B／C 只作归因，不参与停走）：

1. 新张量梯度有限；checkpoint 独立进程重载逐位一致；工程 Adam 步可恢复。
2. 在 **≥一半** 的 3 对象 fit 场景上，至少两个槽的质量 ≥0.05（不是一槽独吞，也不是三槽全空）。
3. 槽内容两两余弦 **≤0.995**（允许接近，不允许字面同一）。
4. 后 50 步损失均值 < 前 50 步均值（有任何下降即可）。

试点只是止损门；通过后仍以 A 臂跑全剂量，**不因试点读数换臂**。

### 6.2 阶段 1：槽位形成（全剂量 1844／3688）

同一读出脚手架、同一 6 排列精确匹配；标签为 P4.4 的真值锚定可见子集：

- `pair ≥ 0.95` 且 `set ≥ 0.80`（与 P4.3／P4.4 同门，保证可比）。
- 重复颜色率 **≤ 0.0625（2/32）**。
- 槽数与真值数一致率 **≥ 0.75**。
- train set **≥ 0.85**（证明可学，不是只背 fit）。
- **槽位敲除诊断**（只评估、不训练）：把某个槽的 `object_z` 替换为批均值后重算，三对象场景中“恰好丢掉该槽匹配的那一对”的比例 ≥0.60；若全场景零变化，判 `read_ignores_slots`，**即使准确率过门也停**（防止读数没有使用槽身份）。

### 6.3 阶段 2（另一张卡，本卡只写门）

槽位形成过门后，才允许把诊断读出换成主体自己的 `read_o`＋`emission`／字节头，按 22.5.1 原门：全 32 fit 轮精确应答 ≥0.80、纠正 ≥0.80、反馈增益 ≥0.05、稳定损失 ≤max(1, 10% 首轮正确)、恢复逐字节一致、对照 0 更新；A 保持 `not_applicable_no_A_parent`、单 seed、check② 未读、`accepted_parent=false`。**阶段 2 的预算不在本卡内**，按当时实价另立。
