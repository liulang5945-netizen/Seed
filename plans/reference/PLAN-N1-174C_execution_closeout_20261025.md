## 4. 机制判读与不得夸大

- 与 N1-171/172/173 的 12 题结果相比，数据规模把「训练题自由滚动」从 0–11.7% 抬到了单 seed 的 .937；这支持「滚动能力需要数据规模」的假设，但跨 seed 不稳定（.937/.305/.294），尚不能称稳固能力。
- 留出题 0/48 且 own/错配 TF 无差异，说明模型没有学会「按未见问题选择回答」；这是**泛化/绑定缺口**，不是格式或解码问题。
- 500 题、97 万参数、40 epochs 的容量足以记住训练集，但远不足以覆盖自然中文问答分布；本包不据此断言架构上限。
- 0 dev、0 reference、0 N1-166；不称 L2/L3、不称未见任务能力。

## 7. 唯一后继建议

**N1-175：数据规模跃迁（先审计，再训练）**。这是目前唯一能同时解释「训练题已能自写、留出题零绑定」的下一杠杆。

1. **审计**（只读，几分钟）：从已冻结的 OASST2 原始档案（`data/conversation/OASST2/2023-11-05_oasst2_ready.messages.jsonl.gz`，SHA 已钉）统计可用中文 prompt→assistant 对；目标 ≥2,000 对，若可达 5,000 对优先用 5,000。
2. **建集**：按 family 隔离，留出 **64 个 family**（比本包 16 题更稳）；训练集用其余全部；不读 dev/已消费面。
3. **训练**：只保留 tf 臂（ss 在本包已证明同剂量更差），3 个 seed，40–60 epochs；按实测 1.2 ms/target byte 估算，2,000 对约 3.1 万 CPU、5,000 对约 7.8 万 CPU（3 seed），在用户「合理范围内给机时」的授权内。
4. **判据**：R（训练自由中位数 ≥0.50，≥2/3 seed）；G（64 留出中 ≥16 题自由匹配 ≥0.20 且比 A/B 各高 ≥0.15）；另加**人工可读/贴题判读**（16 条留出回答，描述性），因为逐字前缀匹配对「换一种说法」过严。
5. 若 5,000 对仍 0 绑定，则把瓶颈登记为「缺绑定/检索机制」，再讨论结构改造（如可寻址回答记忆或对比式目标），不再继续加数据。
