## §1 结论摘要

1. **评分参照确实混用，且已用算术复现。** 对象用 pair 内参照 `mean(P−max(S_i,S_j))`，对照 C2 用空白参照 `mean(max_i S_i−B)`，两者共用一个字段名后被同一 margin 判据相减。旧值复算 32/32 字段一致（§3）。
2. **当前任务面不存在任何"组合超过全体单体"的证据，也不存在这种可能性。** 六个 pair 在四个未见 context 上，**0 次**超过全体单体 oracle；连"可看结果的全 cell oracle"也只到 1.5，与单体 oracle 完全相同 ⇒ 矩阵里**没有任何隐藏的联合能力**（§4.2）。
3. **按现行任务，公平 oracle 也过不了门槛。** 三种候选参照**全部不可达**：oracle 参照缺口 2.15、可部署单体参照缺口 0.15、可部署 pair 参照缺口 1.15（§4.3）。
4. **最接近的那条参照，缺口恰好等于 margin 本身。** 用可部署固定单体作参照时，天花板 0.5、要求 0.65；即便把 margin 降为 0 也只是 0.5 vs 0.5，仍不满足严格大于 ⇒ 缺口不是"再调一点"能补的（§4.3）。
5. **路线 A 的"选中对象"由平局打破决定，不由排序决定。** 两个未见 pair 预测值逐位相同（`−0.1168032786885246`），选中 a+c 只是排序稳定性的副产物，且恰好选中了更差的那个（0.5 vs 1.0）（§4.4）。
6. **因此 B0 的出口判定是：目标当前不可达，禁止直接进入正式训练。** 必须先改任务定义与估计目标（§6），而不是继续加特征列（§4.5 停止点）。
7. 五类手算用例已落地为可执行断言（§5），统一字典 v1 草案已可用（§2）。
8. CI 阻塞已定位到**命令级**：本地 `ruff check .` 原有 1 项 `I001`（既有测试文件的导入顺序），已修复；当前全仓 Ruff 为 **All checks passed**（§10）。

## §2 统一测量字典 v1（草案，待审阅冻结）

字典以纯函数实现，位于[审计脚本](../../scripts/training/audit_taiji_b0_measurement_reachability.py)；
`MEASUREMENT_DICTIONARY_VERSION = b0-measurement-dictionary-v1-draft`。**在审阅通过前，仓库任何冻结门禁都不得绑定它。**

### 2.1 原始量（同一 context 内）

| 量 | 记号 | 含义 |
|---|---|---|
| 空白 | `B(ctx)` | `(F,F)` baseline cell 的实测结果 |
| 单体 | `S_i(ctx)` | 成员 i 单独执行的实测结果 |
| 组合 | `P_ij(ctx)` | pair cell 按**实际执行路径**（dual-predict-select）的实测结果 |

结果编码冻结为：成功 `+1`、失败 `−1`；重复次数已在上游池化，字典内不再二次平均。

### 2.2 估计目标（互不替代，必须分列）

| 估计目标 | 公式 | 参照 | 是否可部署 |
|---|---|---|---|
| 主任务表现 | `mean U(policy)` | 无 | 是 |
| 同参照增益 | `U(policy) − U(common reference)` | **所有策略同一参照** | 是 |
| pair 内参照增益 | `mean(P_ij − max(S_i,S_j))` | pair 内最强单体 | 是（历史对象口径） |
| 全体单体 oracle 增益 | `mean(P − max_i S_i)` | 全体最强单体 | **否**（诊断上界） |
| 因果 interaction | `P_ij − S_i − S_j + B` | 加性期望 | 是，但**不是任务效用** |
| 成本 | `calls / steps / wall / recovery` 分账 | — | 是 |

### 2.3 硬约束（写进代码，不靠自觉）

1. **同参照**：任何"增益"必须显式声明参照；不同参照的数值禁止相减、禁止共用一个字段名。
2. **oracle 不可冒充策略**：`all_singleton_oracle` / `oracle_all_cell` 标记为 `deployable=False`，回归测试断言该标记存在（`test_every_candidate_reference_is_self_consistently_reported`）。
3. **interaction 不自动等于效用**：负 interaction 配正增益是合法且真实的组合。
4. **成本权重必须事先冻结**：`policy_utility(cost_weight=...)` 默认 0.0，任何非零权重须先写进预注册；看到结果再定权重等于事后调参。
5. **参照强弱关系**：`max(S_i,S_j) ≤ max_i S_i`，故 pair 内参照**恒不严于**全体参照 ⇒ 旧字段 `−0.5` 与统一参照下的 `−1.0` 不是同一量的两次读数。
6. **每个公式都要有手算用例**（§5）与可执行断言；公式与断言不得只在文档里存在。

### 2.4 与旧口径的处置关系

旧 `1.65` 判据**不静默替换、也不无解释继承**。本文只做复算与诊断（§3、§4）；新判据的推导放在[路线 B 预注册草案](M5_B0_ROUTE_B_PREREGISTRATION_DRAFT_20260913.md)，且**必须经审阅后单独冻结**。

## §3 旧值复算（算术复现，非推理）

### 3.1 复算方法与可信度

从[路线 C 报告](../../reports/taiji_p5_2c_double_prime_unseen_combination_transfer_20260913.json)的
`success_matrix` 按 block 重建逐 context 结果表，再与[路线 A 报告](../../reports/taiji_p5_2c_triple_prime_representation_repair_20260913.json)
的逐 context 行逐字段对照：**32/32 字段一致**（`cross_check.all_match = true`，`mismatches = []`）。
若该对照失败，脚本直接 `SystemExit` 拒绝出报告——**不在此基础上给上界**。

重建口径：block 聚合值 = `2 × successes/attempts − 1`，且每个 block 的最后一个 context 即 holdout context（`contexts[8:]`）。前者由对照验证，后者由 `success_matrix.blocks` 顺序验证。

### 3.2 对象与对照的参照混用（复现）

| 字段 | 实际公式 | 复算值 | 报告值 |
|---|---|---|---|
| `object.mean_gain_vs_strongest_single`（a+c） | `mean(P − max(S_a,S_c))` | **−0.5** | −0.5 ✓ |
| `control.strongest_singleton.mean_gain_vs_strongest_single`（C2） | `mean(max_i S_i − B)` | **1.5** | 1.5 ✓ |
| `required = C2 + margin` | `1.5 + 0.15` | **1.65** | 1.65 ✓ |
| `object.mean_realized_interaction`（a+c） | `mean(P − S_a − S_c + B)` | −0.5 | −0.5 ✓ |

**换成同一参照（全体单体 oracle）后，对象不再是 −0.5：**

| 未见 pair | 报告（pair 内参照） | 统一参照（全体单体 oracle） | 空白参照（vs B） |
|---|---|---|---|
| `member-a+member-c` | −0.5 | **−1.0** | +0.5 |
| `member-b+member-d` | 0.0 | **−0.5** | +1.0 |

⇒ 参照不同使**同一个对象**的读数从 −1.0（同参照）变成 −0.5（pair 内参照），相差 0.5。
也就是说，报告里 1.65 − (−0.5) = 2.15 这个"缺口"中，有 0.5 来自**参照不一致**，不是来自表征或选择能力。这正是[复审](M5_POST_ROUTE_A_REVIEW_20260913.md) §2 指出的问题，此处给出算术证据。

### 3.3 全部 6 个 pair cell（统一参照）

| cell | 是否留出 | mean outcome | vs 空白 | vs pair 内 oracle | vs 全体 oracle | interaction | 超过 oracle 的 context 数 |
|---|---|---|---|---|---|---|---|
| `member-a+member-b` | 否 | −0.5 | +0.5 | −0.5 | −1.0 | −0.5 | **0** |
| `member-a+member-c` | **是** | −0.5 | +0.5 | −0.5 | −1.0 | −0.5 | **0** |
| `member-a+member-d` | 否 | −0.5 | +0.5 | 0.0 | −1.0 | −0.5 | **0** |
| `member-b+member-c` | 否 | 0.0 | **+1.0** | 0.0 | −0.5 | 0.0 | **0** |
| `member-b+member-d` | **是** | 0.0 | **+1.0** | 0.0 | −0.5 | 0.0 | **0** |
| `member-c+member-d` | 否 | −0.5 | +0.5 | −0.5 | −1.0 | −0.5 | **0** |

**"超过 oracle 的 context 数"全为 0**，即：没有任何组合在任何 context 上比"该 context 最强单体"更好。跨任务覆盖更广（+1.0 > 单体 +0.5）是**路由**事实；同任务协作增量在矩阵中**不存在**。

## §4 任务可达性上界

### 4.1 三种参照的天花板

| 参照 | 参照值 | margin | 要求 | 可达天花板 | 可达 | 缺口 |
|---|---|---|---|---|---|---|
| 全体单体 oracle（不可部署，历史 C2） | 1.5 | 0.15 | **1.65** | −0.5 | **否** | 2.15 |
| 最佳固定单体（可部署） | 0.5（`member-a`） | 0.15 | **0.65** | 0.5 | **否** | 0.15 |
| 最佳已观测固定 pair（可部署） | 1.0（`member-b+member-c`） | 0.15 | **1.15** | 0.0 | **否** | 1.15 |

三种参照**全部不可达**。第二行最接近：天花板 0.5 恰好等于参照 0.5，缺口 0.15 全部来自 margin；即便 margin 归零也是 0.5 vs 0.5，**严格大于仍不成立**。⇒ 缺口不是调参能补的。

### 4.2 三个结构性上界

| 上界 | 值 | 含义 |
|---|---|---|
| 当前矩阵的组合 slack 天花板 | **−0.5** | 无 cell 能超过 oracle；观察值严格为负，连 0 都达不到 |
| 全 cell oracle vs 空白 | **1.5** | 与单体 oracle 相同 ⇒ **矩阵内无隐藏联合能力**（给 outcome 也拿不到更多） |
| 若唯一全失败 context 变得可解 | **+0.5** | `p52a-validation-111` 是 4 个未见 context 中唯一"全体单体失败"的一个；组合若能在它上面成功，同参照增益至多 (0+0+0+2)/4 = 0.5 |

### 4.3 对"能不能过门"的判定

即使假设组合解决了那个全失败 context，上界 0.5 仍远低于 1.65（也低于 0.65 的严格不等式要求）。**公平 oracle 无法超过门槛 ⇒ 按推进方案 §5.2 的停止点，禁止正式训练，先讨论目标/任务修改。**

这不是"表征不够好"的结论：`oracle_all_cell = 1.5 = oracle_singleton` 说明**矩阵本身**没有可被任何表示捕获的联合信号。路线 A 的 rank 1→2 修复是真实且必要的，但它作用在一个**没有被测到的量**上。

### 4.4 排序主张的可测性边界

- 两个未见 pair 的预测值逐位相同 ⇒ 选中 a+c 由**平局打破**决定，不由排序决定。
- 两个未见 pair 的 vs 空白增益分别是 0.5 与 1.0 ⇒ **选择区分度只有 0.5**；完美选择器的上限就是这 0.5。
- 校准样本量：门 8 只有 2 个比较样本（A）/ 1 个（c′）。在 0.5 的区分度与 ≤2 的样本量下，"学会排序"与"抛硬币"不可区分。

⇒ B1 的验收必须包含**独立排序验证**（同一表示、不同 tie-break、成员重命名、任务编号置换），不能只看"预测非恒定"。

### 4.5 停止点（本轮触发）

> 公平 oracle 也无法超过门槛时，禁止正式训练，先讨论目标/任务修改。

**本轮触发该停止点。** 因此 B0 的出口不是"进入 B1 训练"，而是"交付任务与估计目标的修改方案供审阅"（§6）。

## §6 复合任务候选（**供审阅，未选定，未实施**）

### 6.1 任务必须满足的六条（先验可检验）

1. **非平凡**：存在 context 使所有单体在 tick 0 后仍需多步才能满足（沿用 P5.2b 的 `_assert_nontrivial_goals` 方向）。
2. **可满足**：至少一个 cell 在该 context 上成功；否则该 context 不计入区分面，也不判为能力不足。
3. **权限不放宽**：在现有 contract 层下合法。block-3 的 `contract_intercepted: language_evidence_ambiguous` 是**合同层合理拦截**，新任务不得通过放宽合同绕过。
4. **需真实交接**：组合必须依赖前一步产生的中间状态或失败证据，而不是"二选一"。
5. **lesion 使收益消失**：拆除任一成员或任一交接通道后，增益归零——这是"协作"而非"路由"的判别式。
6. **不被脚本补答案**：任务定义不得让 runner 直接构造目标终态（P5.2b 零步缺陷的教训）。

### 6.2 候选（按可解释性排序，均需先做上界预检）

| 候选 | 结构 | 为什么可能产生同参照增益 | lesion 判别 | 主要风险 |
|---|---|---|---|---|
| **T1 串联交接** | 目标需两个有序状态变更，第二步仅在第一步产生特定中间态时合法 | 单体各只能完成一步 ⇒ `P > max(S_i,S_j)` | 去掉任一成员或打乱顺序，增益消失 | 若第二步可独立完成，会退化成"路由" |
| **T2 纠错交接** | 成员 A 产出被合同拦截的候选，成员 B 必须读取 A 的失败证据才能修复 | 单体的失败证据不构成能力 ⇒ 联合才有解 | 断开失败证据通道，增益消失 | 需要可验证的证据通道，否则是脚本补答案 |
| **T3 共享状态约束** | 各成员可满足各自子目标，但组合违反全局不变量（如跨文件语言一致性） | 全局不变量是 joint-only 约束 ⇒ 对应"联合必需"手算用例 | 去掉不变量检查，收益消失（说明任务失效） | 不变量须由 contract 层强制，不能由 runner 断言 |

**T3 与"联合必需"手算用例一一对应**，是最容易做出可判定上界的候选；T1 最贴近现有 workbench 载体；T2 依赖证据通道，工程量最大。三者都必须在正式实施前完成 §6.3 的上界预检。

### 6.3 上界预检（新任务的强制前置，B0 出口条件之一）

对任何候选任务，在**训练之前**先用公平 oracle 复算：

1. 逐 context 计算 `max_i S_i`（全体单体 oracle）与 `max_all cell`（全 cell oracle）；
2. 要求 `oracle_all_cell − oracle_singleton` 在开发集上**显著大于**目标阈值，否则该任务**结构上不可达**，直接否决；
3. 同时报告"若 margin 归零是否可达"；若归零仍不可达，则任务无效，不允许用调 margin 解决；
4. 报告区分面（有多少 context 是"单体全失败但组合可解"），以及 block/模板先验的来源与可见性。

**未通过上界预检的任务，不进入 B1。**

## §7 条件化关系表示与对照（B1 输入，草案）

### 7.1 表示

推荐位置敏感、任务条件化的关系表示，目标是表达"**谁在当前观察下提供何种贡献、联合如何改变结果**"，而非"识别四类模板"。硬要求：

1. 条件化输入**只取预测时可见的 observation**；禁止从 context 编号推导隐藏目标，禁止用 holdout 构造 surface（A 的 `block = task_index % 4` 属模板先验，必须显式披露来源与可见性）。
2. 特征必须能区分**位置与身份**：A 的三列只计"覆盖多少"、不携带"哪些 block"，四个互补 pair 特征行全等 ⇒ 组内不可分。这是 A 的已知残余局限，B1 不得重复。
3. 复杂度增长必须带来额外的预测或任务收益；非零系数、秩改善**不是**完成条件。

### 7.2 对照（全部冻结，同一执行路径与评分口径）

| 编号 | 对照 | 作用 |
|---|---|---|
| C1 | 无学习（固定顺序 / 随机组合，种子冻结） | 下界 |
| C2 | 路线 A 计数表示（rank 2 版） | 保留基线，避免同时改所有环节 |
| C3 | train-only 简单模型（per-block 向量，可解释） | 复杂度增长的对照 |
| C4 | 特征 lesion（去掉位置/身份列） | 归因：收益是否真来自新特征 |
| C5 | 全体单体 oracle（不可部署，仅诊断） | 上界 |
| C6 | 最佳可部署固定单体 | 公平可部署对照 |
| C7 | 成员重命名 + 任务编号置换 | 防字典序 / 编号泄漏 |

### 7.3 验收（分主张，不得合并）
