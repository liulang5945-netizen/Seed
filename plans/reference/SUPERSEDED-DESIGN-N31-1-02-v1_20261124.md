# 预注册：N31.1.02 学得路由正式协议（格01–05 的第一个有效探索卡）

> [预注册·探索] — 2026-11-24（D-20261124-484）。**写于运行之前。** 依据 [N31.1 开线卡](DESIGN-N31-1-00_20261124.md)、[机制通过标准](../active/MECHANISM_ACCEPTANCE.md) §3–§4。零 check/final。

## 1. 为什么需要这张卡

- N31.1.01（D-480/482）= `engineering_failure`：复用的 R2-X 试点只有 300–400 步/任务、无 C5，共享臂在 CN/P24 上近随机，不能作为 N31.1 读数；
- N31.1 是必需线（格01–05），目前已无有效信号；本卡是**第一个有效探索卡**，需干净实现协议。

## 2. 协议（固定、读前冻结）

### 2.1 任务与数据

| 任务 | 生成器 | 类别 | ticks | 评测 |
|---|---|---|---|---|
| CN | `cn_split(n, seed, "seen")`（`verify_taiji_23s2a_gain_20261122`） | 8 | 48 | seen 集 1024 |
| P24（纠错四类） | `_make_p24_stream(n, seed)`（`verify_taiji_cognitive_loop_20261121`） | 4（val_labels） | 同生成器 | val 集 1024 |
| P27（物理/遮挡） | `_make_p27_physics_batch(n, seed)` | 4 | 同生成器 | 独立 seed 集 1024 |

### 2.2 训练

- 顺序课程 CN → P24 → P27；步数 **CN 1200 / P24 1000 / P27 1000**（R2-X 的 300/300/400 明显不足）；
- batch 48、lr 7e-3（沿用试点）、Adam；每个任务训练后立即记录其在**任务无关**前向下的准确率，不重训旧任务；
- **任务无关**：R2-A/R2-B/C1 的评测前向只给 ticks，不接收任务名或任务索引（单测断言签名）；
- C0 为 RT 参照臂（允许任务名），只作对照，不参与「任务无关」结论。

### 2.3 骨干

- 按 N31.4 终态（D-475）：**GRU＋read_gate**。本卡先实现最小 `GRU72` 骨干（72 个隐单元、每 tick 输入 48、末步 read_gate 读出），保留单位身份索引 0–71（名义槽位）与生命周期置零语义；若骨干实现有工程问题，**本卡作废并另开卡**，不得退回 Selective 骨干冒充 N31.1 读数；
- `GRU72` 需进 tests（不变量 01/05/09 的最小版）。

### 2.4 臂（3 个，控制成本）

| 臂 | 说明 |
|---|---|
| **R2-A** | 共享块（前 24 单元 always active）＋**学得输入条件路由**（在 24:48/48:72 两组上 top-1/soft，entropy 正则）＋L2 锚定 |
| **C5** | GRU＋read_gate，同协议、同步数、同预算（必选强基线；格04 的核心对照） |
| **C0** | RT 参照（任务名路由）；只作对照，允许任务名 |

（R2-B HAT 门与 C1 全共享列为后续卡，预算允许时再开。）

## 3. 读数与判定（映射格01–05）

| 格 | 本卡能否判 | 说明 |
|---|---|---|
| 格01 任务无关共存 | **可判（探索级）** | R2-A 在 CN/P24/P27 上的任务无关准确率：CN≥0.85、P-B≥0.75、P-D≥0.70（P24 的 conflict 子项另记） |
| 格02 路由学得 | 不能（需替换控制器，后续卡） | 本卡只记录路由器活跃分布与熵 |
| 格03 保持 | 不能（需 BWT 与梯度日志，后续卡） | 本卡记录每任务训练后即时读数与最终读数 |
| 格04 强基线 | **可判（探索级）** | R2-A vs C5 三任务平均差；门为确认运行口径，本卡只出信号 |
| 格05 共享块使用 | 不能（需休眠实验，后续卡） | — |

**代理指标**：R2-A 的**最弱任务准确率**（min over CN/P24/P27）。
**探索出口**：`signal_positive`（最弱任务 ≥ 门−0.02 且 ≥ C5−0.02）/ `signal_negative` / `inconclusive` / `engineering_failure`。

## 4. 预算

| 项 | 估计 |
|---|---|
| 每臂每 seed | CN 1200＋P24 1000＋P27 1000 步 ≈ **450–550 CPU**（试点 300–400 步约 150 CPU/臂） |
| 3 臂 × 3 探索 seed | ≈ **4,000–5,000 CPU** |
| N31.1 线现有余额 | **不足**（已消耗 1,834/2,000）⇒ **需 owner 追加约 +5,000 CPU 并修订 N31.1 线预算**；或由 owner 改判那 1,834 CPU 为工程诊断 |

## 5. 出口与失败处理

- 工程失败（骨干/协议 bug）：记 `engineering_failure`，修复后重开新卡号；
- 若 R2-A 最弱任务显著低于 C5（差 >0.05）：记 signal_negative，按 §4.3 预注册换路线条件准备「收缩声明」；
- 不读确认 seed；格状态不变，只有 N31.1.90 确认运行能改格。
