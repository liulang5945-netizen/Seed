# U2 22.4.1元数据读取与逐群结构

> 文档状态：[设计合同] — 2026-11-11。父为22.3工程初始化，当前实现范围CPU small float32/64，0optimizer更新。先冻结本设计，再按正常读取、生长与恢复入口验证。

## 1. 记录元数据

配置record_metadata控制候选图，旧配置默认false。新候选从父复制全部同名参数，再启用元数据分支。新参数在原参数初始化之后创建，旧参数值与各自dtype身份逐项核验。该操作构造新候选图，当前用于未训练初始化；已有状态的跨图热迁移需独立验证。

每条合法记录生成四个数值输入，分别为log1p(version)、signed_log1p(observed_at)、log1p(world_time−observed_at)、writable。source与scope经已有字节编码器池化。元数据向量为独立Linear(4,d)加Linear(d,d)来源投影，添加到该记录每个有效字节的表示。两个投影采用非零权重，偏置置0，任务信用可直接作用于新参数。

version非负整数、时间有限且不晚于当前world_time，来源/权限仍经正常输入门校验。元数据按原顺序传入读取，模型学习内容、目标和元数据之间的关系。record_id保留为协议引用；真实实体ID和正确记录选择留在环境评分器。当前source合法域仍为sensor/world，来源可信能力需另验。

验收含同H/F、同记录内容/顺序而version或时间变化的成对输入，检查记录表示、读取权重与任务梯度。随机初值的可辨性与有用学习分开裁决。所有常规基线取得同一合法元数据。

## 2. 真实逐群生长

保留native_r/native_p为既有共享宽度基座。group_extensions按群登记真实incoming[n_g,8d]、outgoing[d,n_g]参数。群g的残差为基座ΣP tanh(Rx)加该群扩展ΣP⁺ tanh(R⁺x)，各单元继承自己的内容门。

新生incoming为0，outgoing取该群信用矩阵的左奇异方向乘0.1。groups显式指定生长群，仅检验这些群的独立信用。非选中群保持实际单元数、参数和ID。新坐标moment置0，旧坐标及step保留。首次扩展继承基座R/P各自的optimizer组，传入optimizer却缺相应owner时拒绝该提案。

配置base_units记录基座宽度，group_units记录各群实际宽度，units记录最大群宽。参数与成本按真实参数量及sum(group_units)统计。旧默认groups=None且尚未进入逐群模式的调用沿原同步dense扩展路径，保存其原接口；逐群模式下后继生长继续扩展真实群参数。

每次出生原子更新config、IDs、内容门谱系、optimizer映射、history版本与结构schema。相同群可再次出生，其他群可随后加入。G/d/M/K及通信类型保持各自后继责任。

## 3. 保存与迁移

新增字段为可选配置，旧bundle可按默认值构造原图。新元数据/逐群图导出subject v3，保存实际扩展参数及group_units。正常runtime/history同步版本，先做构造、两代出生、参数/状态往返及独立进程后继。当前结构的历史重编码使用实际参数与门谱系，历史config兼容判据允许合法R/P群宽递增。

正式数据和训练尚待世界/价格合同。本轮零更新证明参数信用及接口，22.4余下4个工程更新额度继续按原分配保留，实际任务收益和旧能力保持由后继验收。
