# PLAN-N5-26 配置内散布（噪声地板）的第二把钥匙：混杂维度选哪个、什么必须先测（十三裁＝本窗口裁「乙」）

冻结时刻：2026-10-14（㊵-823）。批准出处＝本会话 owner 弹窗四裁原文：
①地板维度＝「乙：再跑一对只换混杂参数的臂（推荐）」；②G104 批次 B＝「等重复臂全套读数判读完成之后再起」；
③CAP 40 题＝「保持待回填，我继续别的格」；④N1 阶段 1＝「授权：先出实施预注册，再按它动码」。
本件只冻"乙怎么落地"的判据与前置，**不起臂、不动码**；机时尚未花费。

## §0 为什么需要本件（全是现取，可复算）

1. ㊵-822 实测：重复臂治疗档与批次 C 治疗档**逐位相同**——`cumulative_mean_surprise` 与
   `cumulative_online_accuracy` 末值 delta 都是 `0.0`；逐张量比较 188 枚槽位差异名集为空；两枚 `.pt` 的
   file sha 不同（`1c839f01…` 对 `09e18ae2…`）、两跑 `session.wall_seconds` 不同（36784.023 对 32120.932）
   ⇒ 真两跑，差只在非张量信封。同一趟治疗↔对照仍是 52 枚差异槽 ⇒ 比较器分辨力在同一趟内被证到。
2. ⇒ `PLAN-N5-23` 的地板按预注册必为 0，走「两支逐指标都落 `no_spread_unjudged`、不发表幅度句」那一支。
   地板要非零，必须让两跑之间只差一个**混杂参数**（不是处理、不是数据内容）。

## §1 候选旋钮的现读账（这一步不许靠设想）

| 旋钮 | 可达性（现读出处） | 判定 |
| --- | --- | --- |
| `--seed`（跑器 CLI） | 不存在：`train_taiji_r2_readout_retrain.py:407-431` 的 21 个 `add_argument` 里没有它 | **要用就得先动跑器**＝窗口硬约束解除（对照臂收口）之后的产品码变更，另案实施 |
| `TaijiConfig.seed` | 存在且被广泛消费（`taiji/model.py:116` `self._rng.manual_seed(self.config.seed)`、`taiji/fabric.py:60/:101`、`taiji/adapter.py:3774` 等） | **对本臂是否有效应未测**：本臂权重来自基座检查点、训练是读出头单点写入，若 RNG 只喂初始化则换 seed 可能**零效应** ⇒ 先做 §2 的秒级探针，不许先花 15 小时 |
| `--corpus` 文件次序 | 存在：`:419` `nargs="+"`，`:486-488` 按给出顺序读 | **与 `--skip-symbols` 混淆**：当前配方是 `--corpus 单文件 --skip-symbols 11199800`，把语料切两段反序 ⇒ 被跳过的 11,199,800 符号内容也变了 ⇒ 一次动两个变量。除非两对都从 `skip=0` 起跑（＝另建一条基线链，成本另计） |
| `--progress-every`／`--checkpoint-every`／`--device` | 存在 | 不改训练轨迹 ⇒ 造不出散布，只能改计时面（且本仓已禁止拿计时当散布尺） |

结论：**没有"零改动就能纯换混杂"的现成旋钮**。所以本件把「乙」拆成两道必须按序走的前置，
而不是一句"再跑一对"。

## §2 前置一（秒级、零预算）：seed 对本臂到底有没有效应

取数式：同一基座、同一语料、同一 `skip=0`、`--symbols 5000`，两跑只差 `TaijiConfig.seed`
（经一次性脚本注入，不落跑器旗标），比较两枚末值与两枚 `checkpoint.pt` 的张量差。
出口：差为 0 ⇒ seed 对本臂**无效应**，本件的前置二直接改走"次序对＋skip=0 新基线"，且明写
它测的是**另一条链**的地板；差非 0 ⇒ 才允许把 `--seed` 提上跑器旗标（新代码＋契约测，
`--seed` 缺省必须与今天逐位相同——这条中性测一起做）。

## §2bis 落地读数（2026-10-14 ㊵-824）：§2 的两条出口都没走到，走到了第三条「这一支跑不起来」

探针（仓外一次性脚本 `seed_structural_control_824.py`，**不是仪器**，按 `PLAN-G138` G-G138-2 的口径它不进门）
没跑 5,000 符号的训练，因为**装不上基座**就停了。三档隔离（同一段代码、只差注入与否）：

| 档 | 注入 | 结果（现读） |
| --- | --- | --- |
| untouched | 不碰信封 | `Seed.from_checkpoint` 载入成功；枚举到 6 枚 generator |
| identity | 两处种子都改成**信封自带**的 20260822 | 载入成功 ⇒ 证明"拒载"不是我的补丁形状造成的 |
| changed | 两处种子改成 999999／20260823 | **`ValueError: receptor channel map does not match architecture`** |

机制出处（逐条读码，非推断）：`SparseReceptorBank.__init__` 用 `torch.randperm(..., generator=generator)`
与 `torch.randint(..., generator=generator)` 画通道映射与极性（`taiji/organs.py:99-104`），这枚 generator 的
种子来自 `config.seed`（`taiji/model.py:115-119`）；`load_payload` 要求通道映射**逐位相等**否则拒绝
（`taiji/organs.py:162-165`）。种子在两处都参与：外层 `config["taiji"]["seed"]`（建架构，
`seed/model.py:256-257`）与 kernel 内嵌 `taiji["kernel"]["config"]`（`Taiji.restore` 拿它跟架构 config 做
相等比较，`taiji/model.py:3720-3722`）；另 `Taiji.restore:4056` 会把主 `_rng` 覆盖成信封里的 `rng_state`。
在档基座的受体面现读 **1152→96**，换两枚种子后与在档通道映射差 **1137／1152**、**1142／1152** 位
（极性差 575／548 位），同种子两次构造**逐位相同**（⇒ 它是种子的纯函数，不是时钟或竞态）。

**结论口径（此刻能声称什么，不能声称什么）**：
* 能写：`config.seed` 在本产品里是**结构身份的一部分**，改它会让现成基座检查点拒载 ⇒
  「再跑一对只换混杂参数的臂」这条 route 在现形态下**起不来**，不是"跑出来差为 0"。
* 不能写：「seed 对本臂无效应」——那是 §2 原文给"差为 0"那支的话，本轮**没有走到那一步**，
  一个都没训练过的臂不许发表任何效应方向。
* 因此噪声地板在本管线内的状态是 **不可测**（造不出只差混杂参数的第二档），不是"等于 0"；
  ㊵-822 那条"同配置逐位相同"仍然成立，但它的含义缩回"同档可复现"，抬不出幅度句。

**§2 原文自身两处落不了地**（记下，不改写原文）：① 出口只列了"差为 0／差非 0"两支，缺了"注入被产品守卫
拒绝"这第三支——本轮走到的正是它；② "同一 `skip=0`" 与跑器的 seen-prefix 守卫冲突
（`train_taiji_r2_readout_retrain.py:493-497`：`--skip-symbols` 小过 lineage 值即 `parser.error`），
在默认语料上今天不可能取到 skip=0（本轮未走到这步，是读码得到的）。
可红载体＝`tests/taiji_native/test_n5_39_seed_is_structural_identity_contract.py`（5 passed，小剖面，
不读在档 `.pt`；含"同种子必须接受"那一支，防守卫变成恒拒）；债表条目＝DEBT-G140。

## §3 前置二：对臂预算与排期（现取速率报价，带算法）

两臂各 8,900,000 符号（与批次 C／重复臂同额，不新申请预算；`--symbols` 帮助原文的批准上限是
16,000,000）。现取速率两枚都从各自末行的同一行内算：治疗档 `symbols_consumed／elapsed_seconds`＝
8,500,000／30706.76＝**276.8** 符号每秒 ⇒ 单臂 8,900,000／276.8 ≈ 32,154s ≈ **8.93 小时**；
对照档＝5,000,000／12710.323＝**393.38** 符号每秒 ⇒ 单臂 ≈ 22,624s ≈ **6.28 小时**；两臂串行 ≈ **15.2 小时**。
起跑窗口必须排在当前重复臂之后：对照臂现取（`2026-10-14T01:35:21Z`，5,000,000／8,900,000）余
**2.754 小时**（≈04:21Z）⇒ 本对最早 ≈04:30Z 起跑、≈19:45Z 收口（10-14）。期间同样适用「两臂之间不许提交
`taiji/`、`seed/`、`readout_retrain_spec.py`、跑器本体」这条硬约束。

**㊵-824 状态更新（不动上面的报价，只标此刻能否执行）**：本对的前提是 §2 出口里「差非 0 ⇒ 才允许把 `--seed`
提上跑器旗标」那一支，而探针走到的是第三支（换 seed 后基座**拒载**）⇒ 这 ≈15.2 小时今天**不该被执行**。
报价本身仍然有效——它量的是"两臂各 8,900,000 符号要多久"，与选哪条混杂维度无关；要花钱必须由 owner 另择一个
**能装上现成基座**的档（见 DEBT-G140 的三条候选与各自的代价）。


## §4 判据（冻四条，各写"什么情况下为假"）

* **J-N5y-1 单变量**：B 对与它要服务的 A 对之间，除该混杂维度外全部旗标逐位相同，且并排仪
  `config_face_identical` 为真、`runner_commit_per_arm` 同版。为假的情形＝顺手改了 skip／预算／基座（那是要另立一条链，不是地板）。
* **J-N5y-2 地板定义**：`floor_role(metric) = |A - B|`，两把尺（`cumulative_mean_surprise`／
  `cumulative_online_accuracy`）各一枚，**逐指标不合并**；`floor=0` 沿用 `PLAN-N5-23` 的
  `no_spread_unjudged` 出口，不许换成"更敏感的第三把尺"。
* **J-N5y-3 链绑定**：地板只能用于**测它的那条链**上的幅度句（同 base、同 skip、同预算、同跑器版）。
  为假的情形＝把 skip=0 链上测到的地板搬给批次 C（skip=11199800）——那是本仓已翻过车的"阈值跨链搬"。
* **J-N5y-4 一次为限**：本件只允许一对 B 臂。若 B 对的差仍为 0，结论是「该维度在本管线下不产生散布」，
  幅度句保持不可发表，**不许再花第三对**；要升级只能换成"多次小预算重复"这种不同问题，须另立冻件。

## §5 落笔即钉的三行

* **预期绿**：J-N5y-1（并排仪已有机检）、J-N5y-2 的取数式（同一枚地板仪现成，只是喂第二对件）。
* **仍红时收回哪句**：J-N5y-1 红 ⇒ 当场收回"这是配置内散布"，B 对降级为"另一条链的第一次跑"；
  J-N5y-3 红 ⇒ 收回幅度句，只保留"两链各自可复现"。
* **发表资格前置**：本件全绿之前，批次 C 的 `not_resolved` 不许被改写成任何方向的幅度结论；
  §2 探针出数之前，"seed 是可用混杂"这句话不许出现在任何计划或批文里（它今天是未证的）。
