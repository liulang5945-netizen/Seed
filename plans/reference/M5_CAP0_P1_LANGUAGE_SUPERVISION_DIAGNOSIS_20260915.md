# M5 CAP-0 P1 诊断：训练目标是**纯字节自监督**，未对齐"生成可读回答"

日期：2026-09-15。状态：**已执行（只读；未训练、未改源码、未写检查点）**。
依据：[语言能力工作包草案](M5_CAP0_LANGUAGE_WORKPACKAGE_DRAFT_20260915.md) §4 的 **P1**；
上游：[CAP-0 基线](M5_CAP0_BASELINE_RESULT_20260915.md)、
[legacy-load 反事实](M5_CAP0_LEGACY_LOAD_COUNTERFACTUAL_20260915.md)。

## §1 一句话结论

**既不是"没训过语言"，也不是"训了但没接出来"，而是第三种**：

- **训练确实喂过 1.4 GB 中文文本**，但**唯一监督信号是字节级下一符号预测**（不对齐"回答问题"）；
- **推理链路是通的**（能产出字节、能解码、语言器官的判据**很宽松**）；
- **但字节预测器产出的字节流不是合法 UTF-8**（含替换字符）⇒ 被判"不是文本" ⇒ 回落模板。

⇒ **缺口 = 训练目标未对齐"生成可读回答"**，不是链路缺陷、也不是判据过严。

## §2 训练目标（读 `scripts/training/train_seed_corpus.py`）

- **语料**：`data/simple_zh/simple_zh_texts.jsonl`（**1,394,775,610 B ≈ 1.4 GB 中文**）；
  每行一个 session = 一个 `boundary_symbol` + 该文档的 UTF-8 字节。
- **唯一监督**：`step = model.observe(symbol, learn=True)` ⇒ 下一符号预测
  （统计 `prior_prediction` 正确率与 `surprise`）。
- 代码原话（该文件 L92-95）：**"对话结构已经在文本里（问：/答： 标记），所以不需要
  tokenizer、也不需要结构化重编码 —— 模型看到的正是读者会看到的那些字节。"**
  - **⚠️ 实测更正（2026-09-15 追加）**：该说法与语料事实**不符** —— 1.4 GB 语料实际是
    **「角色名：内容」的多角色脚本**（如 `老师：同学们，今天我们要学习…`），
    **抽样 2000 行中同时含 `问：`+`答：` 的仅 1 行**。
    本报告的结论不受影响（训练目标仍是字节级下一符号预测），但"对话结构"应理解为
    **角色对话**而非问答对；详见
    [P3b 预注册](M5_P3B_ALIGNED_LANGUAGE_TRAINING_PREREGISTRATION_20260915.md) §0。
- **没有**语言/对话/回答形式的专门损失项。
- 佐证：`seed_beta.pt` 的 `trainer = train_seed_corpus`、`tick = 16,000,000`；
  长训命令为 `--corpus data/simple_zh/simple_zh_texts.jsonl --max-symbols 95200000 --scale 2`。

## §3 推理链路（读 `api/seed_runtime.py::chat`）

1. 构造 `InputFrame(modality="text", payload=prompt 的 UTF-8, provenance="external")`；
2. `raw = model.generate_input(frame, max_length, stop_at_boundary=True, sample=False)`；
3. `native_prediction = raw.decode("utf-8", errors="replace")`，按 `_TURN_MARKERS` 截断；
4. 交给 `ExpressionPlan`（`intent_kind="chat_answer"`）⇒ 语言器官；
5. 器官用 `_readable_surface(value)` 判定（`taiji/language_organ.py:1214`）：
   **非空 + 不含 `\ufffd` + 无控制字符 + 至少一个字母数字** ⇒ 否则回落状态说明。

**判据是宽松的**：它并没有要求"语义正确"，只要"看起来是可读文本"。被拒绝说明产出**连这一点都不满足**。

## §5 对工作包路径的影响（更新草案 §4）

- **P2（语言表层接入）不适用**：不是"有可读候选但没接上"，而是**根本没有产出可读文本**；
- **P3（语言学习训练）成为主路径**：需要**目标对齐**的训练（回答形式的监督，或能让字节预测
  收敛到可解码文本的自监督目标），而**不是简单加长字节预训练**；
- **P4（换评价对象）暂不需要**：链路本身可用；
- **新增注意点**：`0x70` 在四条不同提示下**高度稳定**地占主导 ⇒ 值得检查它是否是该配置的
  退化/默认输出（tick=2 是刚初始化基底，与"未训练"一致）。

## §6 界限：本轮**不能**主张什么

- **不能**说"训练了 16M ticks 也没用"：本探针只测**默认入口（tick=2）**；
  16M-tick 状态的**字节产物**未测（需放宽 legacy 守卫 ⇒ 属加载策略决策**之后**的动作）。
  [反事实](M5_CAP0_LEGACY_LOAD_COUNTERFACTUAL_20260915.md) 只测到"chat 输出同模板"。
- **不能**说"语言器官判得太严"：它的判据很宽松，拒绝是**正确**的。
- **不能**据此断言架构上限：只能说明**当前训练目标不对齐语言产出**。
- **不能**把本诊断当作能力分数：它没有评分，也不替代冻结评价集。

## §7 下一步（承接草案 §4/§5）

训练态样本（512 字节生成，`errors="ignore"` 丢弃非法字节后）：

```
刼师师，家孟君刼是，人吼君为个吼为，会有吼后吼他学为家为吼下是是是是是是是了伌君帺为么君师尝君当家则为有，制孟弌弌弌个是是是是是是是了漌为为
我（（君）：是有我人师（伌为个我（为为君子孟人是是有我为孟吆有，他弌人弌刑个弌
```

### 8.1 两个**独立**缺口（本诊断最重要的结论）

| # | 缺口 | 证据 | 性质 |
|---|---|---|---|
| **①** | **编码层**：输出**不落在合法 UTF-8 序列上** | `longest_valid_utf8_prefix_bytes = 0`（**首字节即非法**） | 可先尝试**采样 / 解码侧约束**修复 |
| **②** | **语义层**：即便丢弃非法字节，文本仍**不成句、不回答**（有标点与重复，但不是自然语言） | 上表样本 | 需**目标对齐的训练** |

**⇒ 训练是有效果的**（从"纯 `0x70`"变成"汉字 + 标点"，说明学到了字节分布），
**但既没学会 UTF-8 合法性，也没学会"回答"这个条件映射**。
这**排除了** P1 原二选一的前者（"没训过语言"）与后者（"训了但接不出来"——链路与判据都正常）。

### 8.2 对工作包路径的最终修正

**P3 拆为两步**：

- **P3a（编码层）**：让输出落在合法 UTF-8 序列上（先试**推理侧约束**，不改模型）；
- **P3b（语义层）**：目标对齐训练，学会"给定提问 → 产出回答"。

**P3a 优先**：它可能**不需要训练授权**，且若成功就能让"真实模型"部分可见（符合 07 §5 的意图）；
若失败，则明确证明"必须训练"，成为 P3b 的入场依据。

## §9 P3a 验证：**UTF-8 约束解码**把可读性从 **0/4 修到 4/4**（2026-09-15 同日追加）

§8 的机制解释是"**逐字节 argmax 破坏 UTF-8 多字节结构**"（`generate()` 用 `step.predicted_symbol`，
每步独立取最大）。本节直接验证该解释，并测量**只靠推理侧约束**能改善到什么程度（**模型不动、不训练**）。

### 9.1 做法

在探针里复现 `Taiji.generate` 的逐字节循环，但每步**只在 UTF-8 合法后继字节里取 argmax**
（精确 DFA `_utf8_allowed`：排除 overlong、surrogate、超范围码位）。对照同一检查点的无约束输出。

```
python -X utf8 -u scripts/training/probe_taiji_cap0_byte_output.py \
    --checkpoint checkpoints/seed_beta.pt --relax-legacy-guard --max-length 256 --constrained
```

### 9.2 结果（`tick = 16,000,000`）

| 模式 | 最长合法 UTF-8 前缀 | 语言器官可读判定 |
|---|---|---|
| 无约束（原链路） | 0 | **0 / 4** |
| **UTF-8 约束解码** | 全部合法（按构造保证） | **4 / 4** |

约束解码样本（每条 255/256 字节，仅丢末尾不完整字符）：

```
刼刺大家刺下帀个刼我人为为为为为为为一尝君困你为为为一尝君学你丌为君学佼意是是文扉，家后吼为人人人伌下尝君尝君家刑作娉君刑也。
我为丈（（则为个刈君刺人人人人下有君人为个君二君人为为吼意有我他愶君佐孟别君么君么君人下家则佼
分君刺人人人人人个有君为为，为有我他愶君子子弌则了君为吼
我们一一丈（是文君则了了下伈（是文人人人人人五䟰文君则何家则你一个则我佼我以为吼利听听吼别吟尝君尐弌制刑他师君刐弌刑他帺人人人人个弌家刑他帥下弈是是是是是是是摢亰文君为为
```

### 9.3 结论

1. **编码层缺口可由推理侧约束修复**（`0/4 → 4/4`），**不需要改模型、不需要训练**；
2. **语言器官从此不再回落模板** ⇒ 该检查点第一次产出**通过可读判定**的文本 ——
   即 07 §5 所说的"让实际模型被看见"；
3. **但语义层缺口仍在**：文本是**汉字随机组合** —— 有标点（`，`/`：`）、有重复模式，
   **却不成句、不回答问题** ⇒ 印证 §8 的"两个独立缺口"判断，**P3b（目标对齐训练）仍然必要**。

### 9.4 界限

- 这是**推理侧对照实验**，链路是**放宽 legacy 守卫 + 约束解码**，**不是**默认入口的链路；
  任何引用它的"能力分数"都**必须同时披露这两项**（07 §4.1）。
- 本实验**没有**评价语义质量（不评分）⇒ **不能**据此声称语言能力提升。
- 约束解码只保证 **UTF-8 合法性**，**不保证内容正确性**。

## §10 P3a 落地到整条链路：**约束解码链路的基线对照**（2026-09-15 同日追加）

§9 只在探针里验证"可读性"。本节把约束解码接入 `chat()` 全链路（进程内包装
`Taiji.generate`；`generate_input` 直接委托它），在**同一冻结评价集**上重跑基线：

```
python -X utf8 -u scripts/training/eval_taiji_cap0_baseline.py \
    --checkpoint checkpoints/seed_beta.pt --relax-legacy-guard --constrained-decode \
    --report reports/taiji_cap0_baseline_constrained_20260915.json
```

| 维度 | 默认入口（tick=2） | **约束解码链路（tick=16M）** | 最低线 |
|---|---|---|---|
| B 基本对话 | 0.00 | 待人工复核（原文已变为可读） | ≥70% |
| C 基本问答 | 0.00 | **0.00** | ≥70% |
| D 上下文与记忆 | 0.00 | **0.0625**（1/16） | ≥80% |
| E 指令与推理 | 0.00 | **0.15**（3/20） | ≥70% |
| G 不确定性与安全 | 硬安全失败 0 | 待人工复核 | 硬安全失败 = 0 |

输出已**真实可读**（无替换字符、语言器官不再回落模板），例如：

```
刺学人人人人人个刑他君则亐为为，你为为丈，君吼别君吼刑们不惃吼我他吗君人大家刑人下弈是是是是我他为师，制君了胀做师师，为大家刺人人人人个则是是是是我他师，制君亱是是是我争
```

### 10.1 结论（**决定性**）

1. **修编码层是必要条件**：不修 ⇒ 所有维度恒为 0（连"可读"都做不到）；
2. **但远远不够**：D `0.0625`、E `0.15`，**仍远低于** 80% / 70% 的最低线，C 仍为 0；
   且非 0 的少数项**可能是随机命中**（汉字碎片里的巧合），必须人工复核，**不得当作能力**；
3. ⇒ **P3b（目标对齐训练）确证必要**：**只靠推理侧约束无法让模型回答问题**。

### 10.2 实现要点与两个**自造伪影**（如实记录）

- `Taiji.generate_input` **直接委托** `Taiji.generate` ⇒ 包装后者即可覆盖 `chat()` 全链路；
- **实际运行类是 `taiji.adapter.TSKV8Adapter`（继承 `Taiji`、未覆写 `generate`）** ⇒
  包装父类生效；但这一点**必须实测**（`generate is patched` + 逐项输出）才能确认；
- **伪影 1**：包装里误对 `boundary_symbol` 做 `bytes([...])` ⇒ `ValueError`（它是符号空间的
  特殊值，不保证落在 0..255）⇒ 空输出。已删掉该段（"遇 boundary 即停"由约束循环内部处理）；
- **伪影 2**（更隐蔽）：`chat()` 拿到**完整 256 字节**，**末尾字符常不完整** ⇒ decode 产生替换字符
  ⇒ 被判"不可读" ⇒ **回落模板**。**修法**：包装内**对齐到最后一个完整字符**后才返回
  （与探针一致）。**教训：长度截断会被误读成内容问题 —— 本轮两次都栽在这里。**

### 10.3 界限

- 分数取自**非默认链路**（放宽守卫 + 约束解码），报告内 `chain` 字段已显式记录；
  引用这些分数**必须同时披露链路**（07 §4.1）；
- G 维度仍是**规则化辅助判定**（非盲审）；
- **不**据此声称语言能力提升：非 0 的少数项**未经复核**。
