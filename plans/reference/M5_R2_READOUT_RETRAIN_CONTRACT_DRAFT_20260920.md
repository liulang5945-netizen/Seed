## §1 为什么是这件事（前置事实，均已核实）

1. **P0-a′**：现行产品默认基座 `seed_beta.pt`（16M tick）的语言读出**从未独立训练过**——训练期修订
   `ac37c890` 的 `observe()` 只有 `motor.learn()` 一条写站，全文件无 `predictive_readout.learn()`；
   读出面是 v8 迁移时**从运动面权重重建的副本**（`load_legacy_motor_payload`）。
2. **P1/P2 否证了解释一**：解码参数不能补救——贪心成句率 0.2326 已是四臂最好，
   top-k/temperature 均 0.0 且显著更差（p=0.00195）。⇒ "换个解码设置就会说话"这条路已用数据关掉。
3. **D/E 脱离 0 但仍远未达线**（1/16、3/20），且表层形态**依 checkpoint 而定**（旧默认是模板回声）。
4. 历史负结果约束本件：内容绑定 v1–v6 全部判停，v6 结论是"**同架构放大已无依据**"；
   字节图族五条变体线已按预承诺关闭；字级粒度（D7）是唯一留有正向证据的表示层。
   ⇒ 本件**不是**"再放大一次"，而是"把一个从未被写入的面第一次写入"，这属于新的自变量。

## §2 主张与不主张

主张（若门通过才允许说）：在固定符号预算下，**把语言读出纳入训练**相对同等训练量的非读出路，
能否在**同一批未见题面**上带来可归因的改善。
不主张：不声称语言能力形成；不把成句率提升当回答能力；不以本件解除 R2 的 M5 排除状态。

## §3 设计（双臂 + 一个反事实，缺臂即作废配对）

| 臂 | 处理 | 它隔离什么 |
|---|---|---|
| **A 读出头** | 固定符号预算 N，仅开放 `predictive_readout` 学习，运动面冻结 | 自变量本身 |
| **B 多训一遍** | 同样 N 个符号，走原运动面路径，读出冻结 | "只是更多训练"这一替代解释（P3b 已证它是真混淆） |
| **C 出生即冻结对照** | N 个符号流过但两处都冻结 | 权重变化之外的漂移：episode 计数、动态状态、随机流 |

**重放纪律**：训练符号按**检查点血缘**计算，绝不重放该检查点已见过的数据——否则"改善"可以纯靠
记忆伪造（这条在 P3b 双臂里实测过代价）。未见评价集**先建先封**，训练前落 digest，训练后不得换题。

**两处我自己的缺陷（都在 2026-09-22 被抓到，如实记账）**：

1. **"重跑同一命令即幂等"是假的。** 原实现对"已跑满的臂"`raise SystemExit`，于是多臂 campaign 会
   **在第一个跑完的臂上中止**——A/B 早已完成，C 却停在 12.25M 且没有任何 driver 去接它。

   回归测试 `test_a_finished_arm_is_skipped_so_a_campaign_can_be_re_run`：同一条命令复跑后
   `arms_status == {B: already_complete, C: already_complete}`、`failed_arms == []`，
   且 C 的 `session_id` **逐字不变**（证明没被偷偷重跑）。
2. **`--fresh` 在 Windows 上必崩。** 归档旧报告的文件名用了 `_utc_now()`，含 `:` ⇒
   `OSError [WinError 123]`。**是上面那条新写的测试当场抓到的**（此前 `--fresh` 路径从未被执行过）。
   修法：新增 `_stamp_for_filename()`（`:` → `-`），JSON 字段仍用 `_utc_now()`。

**教训（可复用，已入 MEMORY）**：

- 「幂等重跑」这类承诺必须**用测试证明**，而且要证**多臂**情形——单臂测试全绿挡不住 campaign 层中止。
- **把时刻写进文件名**要换安全字符集（`:` 在 Windows 非法）。
- 长跑的 driver 要**分开记每臂状态**（`arms_status`），否则"哪一臂停了"只能靠翻进度流猜。
