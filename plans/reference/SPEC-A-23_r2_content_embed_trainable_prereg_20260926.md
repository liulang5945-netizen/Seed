## 0. 这份案要解决的、已被量出来的那件事

`taiji/copy_circuit.py` 的 `content_embed` 是**固定随机基、永不更新**（`learn()` 的更新名单里就没有它）。
它同时是两处信号的来源：寻址的键（`keys = embed[c] @ query_content`）与选择头特征 2
（`content_cosine`＝提问运动语境 vs 事件内容池化键）。

| 事实 | 出处 |
|---|---|
| 寻址分数对 `M` 线性 ⇒ "离线好解"能做到 94.5%，但装回发射链反而掉分，on-policy 只剩 23.8% | `SPEC-A-17` §18–§20 |
| 字节聚合方式（求和→取最大／按位置数归一）不是限制 | `SPEC-A-17` §23 |
| 提问条件化选择头：v1 上 +5/+5 过线，但**配对换位后 0/104**（对照 0）⇒ 装的是位置先验 | `SPEC-A-22` §16/§18 |
| 头权重两电路同形：`recency` 独大，两个内容侧特征小一个数量级、重叠项恰好为 0 | `SPEC-A-22` §17 |
| v1 **与 v2** 都规定"含答案词的告知必为第一轮" ⇒ 位置捷径两边满分 | `SPEC-A-22` §12 |

⇒ 排除法走到这里，剩下的候选解释是：**"提问与该告知内容相关"这个信号在当前表征下拿不到**。
本件测它：把 `content_embed` 交给训练。

## 1. 主判据必须是 v3（先钉题集，再谈机制）

v1/v2 已被本案自己判为"给位置捷径发满分卷"，**不再充当判据**。
`plans/manifests/r2_copy_surface_extension_v3_position_random.json`（提交 `712dd97f`）：
答案告知落第 1／第 2 轮由**均衡牌堆**严格 52/52、八个 kind 内部两种落位都有、
提问与判分词逐题不变、与 v2 逐题配对。
⇒ 在这份题集上，"挑最旧／挑最新"两条位置规则的期望都退回 chance，答题只能靠内容相关性。

**读法（本件全部结论的前提）**：同一臂在 v2 与 v3 上的差 ＝ 它吃了多少位置红利。
`乙／丙` 在 v3 上的读数正在跑（`reports/taiji_r2_a25_{lock_only,selector}_surface_v3_20260926.json`），
它们是 丁（本件的臂）的**先决对照**——若 丙 在 v3 上就已经塌到对照附近，
本件要修的"内容表征"这一维才有可归因的空间。

## 2. 要动什么（设计冻结）

**唯一变量**：把 `content_embed` 加进 `learn()` 的更新面，走**已有的**寻址交叉熵梯度
（`delta` 已在算，键侧梯度 `(delta[:, None] * embed).T @ query / scale` 现成——
把它打到 `embed` 自身的行上，即"这一字节被指对/指错 ⇒ 它的表征行往键方向挪"）。

* **不动**参数面形状（不新增张量 ⇒ 旧 payload 仍可载、digest 不外扩）、
  **不动** gate 零初始化 ⇒ **挂载位级不变**这条老规矩不受影响；
* 新增 `--lr-embed`（默认与 `lr_address` 同档），**只影响 丁 臂**；
* `content_embed` 一旦可训，它同时改动寻址键、`pooled`、选择头特征 2 ——
  这是**有意的**（本件测的就是"表征变了对内容相关性够不够"），
  但因此**不许**把 丁 的任何读数单因归给"表征"，须并列这三处都变了（见 §4 的限定）。

**公平性前置（A2.5 留下的直接教训，`SPEC-A-22` §13）**：训练按 **episode 数**钉，不按墙钟——
`--episodes 2189`（丙 seed-A）与 `--episodes 1985`（丙 seed-B），`--max-minutes` 只作保险上限。
否则"丁 不如 丙"可能只是"丁 少训了三成"。

## 3. 评测协议（先立后跑）

* **主判据**：v3（位置随机），严格真命中、整句、on-policy（§20 两条制度性要求）；
* **配对旁证**：v2 与 v1 同臂并报（用于算"位置红利"这一列），**不合并总分**；
* **两电路同向且差 ≥3** 才判（沿用 §3 规则）；否则 `not_resolved`（不等于无代价）；
* **回归门**：CAP 16 题两臂并报，方向不一致就记 `not_resolved`；B 维无机检 ⇒ 恒 `unverified`；
* **基座不变**：`checkpoints/*.pt` 只读，跑前后 sha256 逐位相同（仪器自带硬门槛）；
* **payload 自证**：丁 的两枚 payload 与对照臂的 payload 一律**新目录**输出
  （A2.5 曾因 `nohup` 残留进程与 `run_in_background` 同时写一个 out-dir 而污染来源，`SPEC-A-22` §17）；
* **止损**：判读 ≤90 分钟／臂，超时按 `not_resolved` 归档。

## 4. 预登记的三分支读法

1. **v3 上升（对 丙 同向 ≥3）且 v2 不降** ⇒ 内容表征确有限制性，机制确认。
   此时才谈"默认挂载是否开"（owner），并把靶线换到"续接/发射"那一支（§21/§23 剩余的 68–74 题）。
2. **v3 升而 v2 降** ⇒ 它学会了内容匹配、丢掉了位置先验。如实分开报，不判"总体改善"——
   这条尤其要防：只报 v3 会夸大，只报总分变化会掩盖。
3. **v3 不升** ⇒ 内容表征**也不是**限制。那么 A2 这条旁路剪贴板在 2026-09-26 一天里被
   五条独立修法轮翻否证（幅度、聚合方式、离线移植、提问条件化选择头、内容表征），
   本件如实按"已定价但装不上"结案，交 owner 裁定：
   要么接受"chat 形态严格真命中 6–7/16"这一档为当前上界，要么换机制路线（不再在剪贴板上加部件）。

任何分支都**不许**拿 CAP 那 16 题（多数只有一条告知）当反证或正证（`SPEC-A-22` §16 已限定）。
