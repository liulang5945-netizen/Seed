补证前写定的判据是：「**2/2 复现（含 917 即 3/3）⇒ 系统性**；0/2 ⇒ 偶发」。

## §4 与 v3 的规模-稳定性边界

- **v1**（174 行）→ **v3**（1278 行，7.34×）：同类门 **1/3**、可判抖动、matched 正常完成；
- **v3** → **v4**（4862 行，再 3.8× = **28× v1**）：同类门 **3/3**、且出现机制退化。

⇒ **在固定 lr=0.01、固定配方下，存在一个规模上限，v3 之内稳定、v4 之外不稳。**

## §5 裁决选项

**(i) 承认"固定配方下的规模上限"，v4 判为超参域外的负结果。**
⇒ 结合 v3 已有结论（**K1 主门过、M4/flip 全零**），R2 的机制地图**已完整**：
「复制链在 v3 规模上建成，而"绑定/取反"未随规模出现」。
⇒ 转入合同所言的**阶段收束 / 入口转换评审**（第三、四行路由的共同归宿）。

**(ii) 把"规模适配的学习率"立为新变量。**
⇒ 但必须**新预注册**：同时变"规模"与"lr"会让 v4 失去与 v3 的归因力，
需要**分别**检验（例如先固定 v4 规模、只扫 lr，确认"是 lr 而非规模"）。

**(iii) 只修 wall_cap、不修 loss 门，仍放行 matched。**
⇒ **不推荐**：seed 918 已显示机制读数在 3.8× 规模下会掉（`copy_M1` 0.847），
在**训练本身不稳定**的前提下跑 matched，得到的读数无法归因到机制。

**助手建议：(i)。**
理由：v4 的目的本是检验「绑定 = per-item 率连续函数」——
但**该假说的检验前提是"训练稳定"**，而这个前提在 3.8× 规模上**已被证否**；
继续在 (ii)/(iii) 上投入，只会让"规模"这一变量与"优化稳定性"纠缠不清。
且 v3 的 matched 已经把可答的问题答完了（复制站稳、flip 未出现）。
