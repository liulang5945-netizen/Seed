## §2 执行范围与口径

- 模型：默认入口 `seed_corpus.pt`（tick=2）；**未训练**（`learn=False`），未写任何检查点。
- 规模：B/C/D/E/G **各 20 项 = 100 项**；A/F/H **未在本 runner 内执行** ⇒ 记 `not_executed`。
- 每项**独立会话**（新建 runtime 实例 + 空 history）；题面 `__RESET__` 触发会话重置。
- 计分：C/D/E 用 `expected_contains` 规则判分（全或无）；B/G 一律待人工复核。

## §3 **一次被自己抓住的无效测量（重要）**

首版 runner 直接把回答与 `expected_contains` 匹配，得到 C 4/14、D 1/16、E 9/20。
逐条回看发现**全部 14 个“正确”都是回显假阳性**：该入口的回答是固定模板

```
我已收到你的问题：“<PROMPT>”。当前原生语言表层正在形成稳定表达。
```

它把提问**逐字抄回**，而 `expected_contains` 的词（`5` / `苹果` / `A` / `冷` / `3` / `小明` /
`a,b,c` / `是` …）恰好就在提问里 ⇒ 命中的是**回显**，不是答案。

**修法**：判分前删除回答中逐字回显的提问（`_strip_prompt_echo`），并在报告里保留
`raw_last_output` 与 `verdict_text` 两个字段、记录 `prompt_echo_stripped`，
使“去掉什么、依据什么判分”都可复核。修正后 C/D/E **全部归零**。
受污染首版报告**留档为物证，不删**。
