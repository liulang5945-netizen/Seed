## 3. 怎么读

- **接点确实有影响**：接在编码器输出上，头能在训练集上拟合到 25/64（0.391）；接在读出上下文上则完全不动。⇒ 编码器不是"冻死"的，它可被梯度推动。
- **但推不到门**：0.391 距 0.80 很远；fit 只有 0.344（8/32 外 3 例），即**没有泛化**，只是记住了部分训练样本。
- **字节路径完全不受影响**：四个点仍是常量、train 16/64。⇒ 即便编码器被推动，字节读出也没有消费它。
- 统计口径：64 样本下 0.25 的标准误约 0.054，0.391 约 2.6 SE，属于"勉强离开噪声"，不构成能力。

## 5. 下一张机制卡（P3.17，待设计）

把合取拆开，而不是要求池化向量一次表达：

- **查询条件的逐 patch 检测**：`score = (W_q · 查询嵌入) · (W_p · patch 编码)`，对 16 个 patch 归一化；目标＝该 patch 是否属于被问对象（来自合法输入，不引入新反馈通道）。
- **位置由 patch 索引给出**（坐标已在 metadata 里），于是「找对象」与「读位置」分开，各自由可学的部分承担。
- 这是**结构改动**（新读出模块），需新身份、对照与定价；先写设计卡，再定价，不直接开跑。
- 若该结构下 train 能过 0.80 而 fit 不过，问题回到任务的 train/fit 分布（3 对象 vs 1–2 对象）；届时应先修任务切分，而不是继续改结构。
