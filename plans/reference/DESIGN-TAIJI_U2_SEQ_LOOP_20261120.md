# 设计草案：显式循环＋工作记忆写回的序列推理（22.X，零训练设计稿）

> 状态：[设计草案/待实现] — 2026-11-20。依据：D-102（重复输入无深度收益）、D-108（隐状态携带但读出不可组合）、D-115（**显式工作记忆写回有界 verified**）。本设计把已验证的写回机制接到**多步序列**上，检验「显式循环＋写回」能否产生**深度收益**。

## 1. 任务（多步、需要跨步记忆）

- 动作序列 `r1,r2,r3`，每步方向 `d_i ∈ {+1,−1}`；
- 标签：`same13 = (d1 == d3)`——**必须记住第 1 步方向**才能与第 3 步比较；单步模型（只看 r3）无解；
- 深度分级：`k=1`（只看 r3，预测多数类）、`k=3`（循环三步、写回方向）；
- 数据：动作对扩展为三元组（用 `build_partition` 行，方向字段已有）；平衡 1:1；每类 ≥300 评估样本。

## 2. 显式循环与写回

新模块 `taiji/u2_loop.py`（不改核心）：

```
run_loop(scan, graph, features[B,S,48], memory_dim=39..40, invalid=41)
```

- 逐步：tick t 编码 `r_t`＋**上一步写回的预测方向**（首步 invalid=1）→ `UnitScan.run(T=1, 状态携带)` → 预测本步方向 → 写回；
- 损失：每步方向 CE（t=1..S）＋最终一致标签 CE；
- 对照：零写回（每步 invalid=1）、shuffled 写回（滚动置换）、oracle 写回（真实上一步方向）、k=1 单步基线。

## 3. 门（预注册）

1. **深度收益**：`acc(k=3) ≥ acc(k=1) + 0.10`；
2. **写回必要性**：零写回 `acc(k=3)` 比自写回低 ≥0.10；
3. **顺序依赖**：shuffled 顺序（r3,r2,r1）`acc` 比正确顺序低 ≥0.10；
4. **oracle 参考**：oracle 写回 `acc(k=3) ≥ 0.85`（任务可学）。
四门全过 ⇒ `sequential_loop_ready`（有界：单主体、三步、显式循环＋写回）；否则按失败子条件 partial/negative。

## 4. 预算与出口

- 复用 `UnitScan`（D-107 已验证）与 `probe_s2_accessible` 数据构造；
- 训练 1,200 步、3 seed、零 check、**价 ≤300 CPU**、阈值不调；
- 出口：全过记有界 verified；仅 1/3 过记 partial；全负停止该设计方向并记录失败子条件（深度/写回/顺序）。

## 5. 与既有负结果的区别

| 形态 | 中间结果去向 | 结果 |
|---|---|---|
| D-102 重复输入 | 无中间结果 | negative |
| D-108 顺序两步 | 隐状态携带，读出不可组合 | negative |
| D-115 两步写回 | 显式写回（2 步） | **有界 verified** |
| **本设计** | **显式循环＋逐步写回（3 步）** | 待测（检验深度收益） |

## 6. 判读边界

即使通过也只证明「3 步显式写回循环」有界成立，不等于一般多步推理/递归发展；不改变任务轴/check②。
