## §2 拟改动 + 可复用资产 + 为何可能改善（03 §5.2）

### 2.1 假设 H-GEN

**F3 与 F4 是同一个模式，出现在两条不同的链路上**：

> **teacher-forced 分布持续改善（surprise↓ / TF-acc↑），而自主生成的 `exact` 恒为 0。**

这正是经典的 **exposure bias / train-test mismatch** 特征：
训练时每一步的输入都是**真实前缀**（teacher forcing），
而推理时每一步的输入是**模型自己上一步的输出**。
⇒ 模型只需学会"给定正确前缀，预测下一字节"，**从未被训练过"给定自己写错的前缀，如何恢复"**。

**H-GEN**：在**生成态**（自回归、以自身输出为前缀）下施加同一份 response-only 信用，
能改善 `exact_response`；若不能，则 exposure bias 不是充分根因，**本候选否决**。

### 2.2 拟改动（**最小、可回退**）

| 项 | 现状 | 拟改为 |
|---|---|---|
| 训练时前缀来源 | 全部用真实前缀（teacher forcing） | **按比例 φ 的 episode 步改用模型自身生成的前缀**（scheduled sampling）；φ 从 0 线性升到 φ_max |
| 目标/信用 | response-only 字节信用（0.75/0.25 混合） | **不变** |
| 表示 / 架构 | 现有 prefix 编码 + factorized response plan | **不变** |
| 推理 | 贪心、`--sequence-*` 不变 | **不变** |

⇒ **只改"误差是在哪种前缀状态上被施加的"**，不改目标、不改表示、不改架构。

### 2.3 为什么它可能改善条件内容与自由生成

- **条件内容**：生成态下前缀包含模型自身的错误，迫使模型学会在"信息已有偏差"时仍然把回答收敛到 `required_terms` 上；
- **自由生成**：不再依赖"上一步恰好正确"这一训练期特权，缩短 train/inference 差距。

### 2.4 可复用资产（不重建）

`LanguageAlignmentTrainer`（含 H3.7B 的 prior/credit 修复）、`LanguageEpisodeCorpus`、
P3b-v2 的 80 行语料（digest `4d199747…`）、逐 episode 进度钩子（`--progress-file`，本轮已加）、
评价与报告链路、isolated sequence 原型、恢复/血缘协议。

## §3 状态如何进入训练、误差如何分配、覆盖与评价如何匹配（03 §5.3）

### 3.1 进入与误差分配

- **问题 + 材料 + 上下文** → 现有 `LanguageEpisode.prompt_bytes`（`context` + `user_input` 拼接）；**不变**；
- **接收回答误差的参数** → **与 H3.7B 相同的那组**（response-only 信用路径、0.75/0.25 混合）；
  **本候选只改变误差被施加时前缀的"来源"**，不改变"谁接收"。

### 3.2 **必须区分的四层**（03 §5.3 明确要求）

| 层次 | 判据 | 本候选的预期 |
|---|---|---|
| **① 梯度可达** | 目标参数获得有限非零梯度（数值差分） | 与现状相同（已由既有 gate 覆盖） |
| **② 训练可拟合** | train `exact` / train surprise | **train `exact` 可能首次转正**（若 H-GEN 成立） |
| **③ 未见回答** | dev `exact`（**J6**） | **本候选的主判据** |
| **④ 自由生成** | 无参考的生成质量（人读 / 语义判据） | 只做描述，不作晋级依据 |

⇒ **禁止把 ② 当作 ③**：这正是 F3/F4 已经踩过的坑。

### 3.3 训练覆盖与评价的匹配

- 训练覆盖：P3b-v2 语料 train split（40 条），**不扩规模**（避免与"数据规模"因素混淆）；
- 评价：**同一冻结集**（dev 20 条），**同链路**（P3a 的 `relax_legacy_guard + constrained_decode`），
  `trained_during_eval=false`，final 不读。

### 3.4 评估入口的附注（必须显式声明）

`exact_response` 要求**整段逐字节相等**。在只有 80 行合成语料、2 epochs 预算下，
它可能**过于严格**而掩盖真实改善。
⇒ 本候选**同时报告**：`exact` / `required_term_coverage` / `sequence_valid` / 人读样本，
**但主判据仍用 `exact`**（不因结果不好而换指标 —— 那是 07 §4.2 禁止的）。

## §4 公平基线、主效应、保持/恢复、预算与停止线（03 §5.4）

- **公平基线**：**同一语料、同一预算、同一起点方式（从零构建）、只关掉 φ 的对照臂**；
  ⇒ 差异只能归因于"生成态训练"本身（**不是**与历史 H3.7B/H3.8 数字比较）。
- **主效应**：dev `exact_response`（③层）。
- **保持/恢复**：沿用 `checkpoint_roundtrip_preflight`；每臂零步→训练→新进程恢复→一步续训一致性。
- **预算**（先 pilot，放大需另批）：seed 20260917；两臂各 **2 epochs × 12 episodes**（与 P3b-v2 可比）；
  CPU 单线程；300k 参数；wall cap 每臂 30 min。
- **停止线**（任一触发即停，不扩预算）：
  1. 非有限值 / 参数预算超限 / 更新预算不匹配；
  2. **两臂 dev `exact` 均为 0** ⇒ H-GEN 否决（exposure bias 非充分根因）；
  3. **对照臂 dev `exact` ≥ 处理臂** ⇒ 生成态训练无优势；
  4. 退化（A/H 或恢复一致性）⇒ 回滚；
  5. wall cap 超限。

**出口**：一份可评审的对比报告，**决定该候选采用或否决**（不是刷一个玩具分数）。

## §5 与已停止 H3.8 机制族的**实质区别**（03 §5.5）

| 维度 | H3.7 / H3.8 | **本候选** |
|---|---|---|
| 改动对象 | **计算图 / 机制**（内容寻址工作空间、单一前缀通道、参数匹配） | **训练时的前缀来源**（不动机制） |
| 失败形态 | `workspace_unused`：机制未被承担 | 若失败 ⇒ **目标声明本身被否决**（不是"机制没用好"） |
| 新假设 | "加一条内容通道就会承载内容" | **"teacher-forced 分布对齐 ≠ 自主生成"这一 gap 有独立机制** |
| 是否换名追加预算 | — | **不是**：假设、判据、失败含义都不同，且**只跑 pilot 不申请长训** |

**若 H-GEN 被否决**，结论将是「**exposure bias 不是充分根因**」——
这本身是对 §1.2 未分离因素表的一次**实质性排除**，仍有决策价值。
