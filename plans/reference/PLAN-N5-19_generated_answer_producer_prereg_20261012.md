# PLAN-N5-19 自生成答案的情节写回（producer）：批次 C 的前置冻结件（判据先冻，五裁⑴ 已批产品码）

冻结时刻：2026-10-12（㊵-735）。执行体＝`tests/taiji_native/test_n5_30_generated_producer_contract.py`（号现取：
`test_n5_*` 目前用到 29，30 未占用）。本件冻的是**producer 的最短形状与其判据**，不是长跑预算——长跑的定价要等本件
落地后按实测重报（DEBT-G116 修法③）。

## §0 本件要拆掉的两道墙（都是 ㊵-734 当场量出来的，不是回忆）

1. **产品里没有把来源写成 `generated` 的赋值点**：对 `taiji/`、`seed/`、`api/` 全量搜 `"generated"` 字面量命中 **2 处**＝
   `taiji/config.py:24`（枚数定义）与 `taiji/contracts.py:1960-1967`（§19.6 拒载：带非零奖励的 generated 记录构造期即抛）。
   枚数到位（DEBT-G100 已结清）**不等于有人赋值**。
2. **候选长跑器不碰情节**：`scripts/training/train_taiji_r2_readout_retrain.py` 对 `provenance`、`settle_action`、
   `memory.write`、`episodic` 四个关键词命中数＝**0**。

一条现成的好消息，它决定了本件的最小半径：`Taiji.settle_action` 已经**校验并接收**任意 `PROVENANCE_KINDS` 里的取值
（`taiji/model.py:2612-2613` 拒绝表外值，`model.py:2102` 把 `pending_experience.provenance` 透传给 `memory.write`）
⇒ producer **不需要新 API 语义**，需要的是**一个明确的调用点**与一条"被走到"的读数。

## §1 设计（四句，第三句是本件的地基）

1. **入口形状**：在持有 `self.memory` 的那一层（`Taiji`）新增一条**显式**写回入口，只做一件事——把模型自己生成的答案
   作为一条经验写入情节场，来源固定 `generated`、奖励固定 `0.0`。入口名字在本格实施时定，但**必须是动词式单一步骤**，
   不接受"顺手在别处多写一个参数"。
2. **不放在 decoder 里**：`taiji/language_alignment.py` 对 `self.memory` 的命中数＝**0**，它拿不到 `EpisodicField`；
   硬塞进去要么新造一条跨对象引用、要么重抄生成链（两者都被 DEBT-G99 那类"两条链"教训禁止）。
3. **不改动现有调用点的标签**：`taiji/adapter.py:8128`「Execute a generated call and feed its outcome back into Taiji」
   那条路径现在写 `provenance="experienced"`（`adapter.py:8161-8166`）。**本件不改它**——那里的受事是**外部工具执行回来的
   观测**，它是真的外部经验；把它改标成 `generated` 会把"外部世界给的回执"误标成"自我产物"，方向与 §19.6 相反。
   需要新写的入口与需要改标签的对象是两件事，本件只做前者。
4. **默认零调用者**：新入口在产品链里**不接任何自动触发点**；批次 C 的长跑语义因此变成"由跑器**显式**喂自生成答案"，
   而不是"重跑现有长跑然后期待某处自己长出来"。

## §2 判据（冻四条，每条写明"什么情况下它为假"）

* **J-N5q-1 赋值被走到**：调用新入口一次之后，情节场里必须出现一条来源索引＝`PROVENANCE_KINDS.index("generated")`
  的记录，且 `EpisodicField` 的来源读出该位从 **0.0 变为正**（继承 `J-N5o-5` 的活槽位性质）。
  为假的情形＝写入发生但来源位仍为 0.0（说明标签没进读出链），或索引不等于该位（说明默认标签泄漏）。
* **J-N5q-2 §19.6 的零奖励不变量**：经新入口写入的记录，奖励必须为 `0.0`；传非零即抛，且抛点在**构造期**
  （`contracts.py:1960-1967` 已在，本件要求新入口**不许绕过**它——不许自己拼 payload 再塞）。
  为假的情形＝非零奖励的 generated 记录成功进入，或新入口用绕过合同对象的旁路写入。
* **J-N5q-3 默认中性**：不调用新入口时，现有链必须**逐位不变**——同一份配置跑一段固定回合，前后两次（加入口前／后）
  的情节场摘要与整模型摘要必须相等。为假的情形＝任何一位不等，那说明入口被接到了自动路径上（违反 §1.4），
  本件必须回退而不是"把不等说成近似"。
* **J-N5q-4 计数出版**：一个只读计数器（`generated_write_count`）必须随写入递增并出现在**载荷自述**里（走披露键，
  不进冻结必需键集合，遵守"加披露键的三坑"规矩）。为假的情形＝跑完一段含自生成答案的回合计数仍为 0，
  或计数只活在台账文本里而不在件里。

## §3 守卫（两条，各自能为假）

* **G-N5q-1 赋值处唯一**：`"generated"` 这个字面量在产品码里被**写入侧**使用的位置必须＝1（本入口），
  其余出现只许是枚数定义与合同校验。判定＝按 AST 找出把该字面量作为实参传给写入路径的调用点并计数。
  为假的情形＝出现第二处（将来某处在不动入口的情况下随手改标签，读数会分不清是谁写的）。
  本守卫自己必须带负对照：喂一份含两处赋值的合成源码，计数必须为 2。
* **G-N5q-2 不许重抄生成链**：新入口不许自己构造皮层上下文或自己算 cue pattern——必须复用同一条
  `settle_action`→`memory.write` 链。判定＝入口实现体内不得出现对 `EpisodicField.write(` 的**直接**调用
  （只许经 `Taiji` 那条既有路径）。为假的情形＝出现直调，那"赋值被走到"测的就不是产品链而是我自己。

## §6 落笔即钉的三行

* **预期绿**：五支全绿；`test_episodic_field`／`test_n2_06`／`test_n5_28` 三册**零改动**仍绿（它们不接新入口）。
* **仍红时收回哪句**：若 `J-N5q-1` 红 ⇒ 收回"producer 已就位"，DEBT-G116 不许结清，批次 C 继续不可起跑；
  若 `J-N5q-3` 红 ⇒ 收回"默认中性"，本件回退（把入口接到自动链上是违反 §1.4 的实施错误，不是判据要放宽的信号）；
  若 `G-N5q-2` 红 ⇒ 收回"测的是产品链"这句，先把直调拆掉。
* **发表资格前置**：本件全绿之前，以下三句都不许说——「`generated` 已能长出权重」「批次 C 已可起跑」
  「自生成内容已与外部经验分开记账」；全绿之后也**只**许说"入口存在且默认不接线"，任何幅度主张仍要批次 C 的实测读数。

## §7 落地后的三条记录（2026-10-12 ㊵-736；上面原文一字不动）

* **`J-N5q-4` 的"载荷自述"未采纳**：计数落在运行时属性 `EpisodicField.generated_write_count`，**不进 `to_payload()`**。
  三条理由：payload 键受摘要键集约束；已有披露键被别线做精确相等比较；`load_payload` 若用 `payload.get(..., 0)`
  就等于把"件里没有的数"回填成 0。契约册 `test_the_counter_is_published_without_touching_the_payload` 反过来
  **断言 payload 不带它**，并断言"载入旧 payload 后计数仍为 0"——这是收紧而不是放松，且可为假。
* **`J-N5q-3` 的"前后两次摘要相等"落成两条机械半支**：产品码里 `record_generated_answer` 的**调用点数＝0**
  （AST，面＝`git ls-files` 的 `taiji/`＋`seed/`＋`api/`，现读 181 个文件）＋一段固定回合后
  `generated_write_count` 仍为 0 且 payload 键集未增。理由：本格没有"改码前"的基线件可比，硬造一份基线
  就是把未测说成已测；要把逐位中性钉成一条，得先用现有 HEAD 生成摘要件、下一格再做前后对照。
* **实施期发现（我第一版契约册因此四支全红，坏的不是产品码）**：情节写入在**下一次观察**才落账——
  `settle_action` 只把经验挂成 pending，`write_count` 要到 `observe(outcome)` 才自增。凡要测"某次结算是否被走到"，
  必须走到那枚观察，否则测的是 pending 而不是产品行为。


## §8 G-N5q-1 的改形记录（2026-10-12 ㊵-740；§3 原文一字不动）

* **为什么动**：六裁⑴ 选了甲——再开一条**无动作**入口 `Taiji.record_generated_prediction(...)`。于是产品码里把
  `"generated"` 当写入实参的合法位置从 1 处变成 2 处，§3 冻的「位置必须＝1」按字面为假——红的是判据的形状，
  不是行为。
* **不放松成什么**：不写成「≤2」，也不写「数一下就行」——那样任何数量都过，守卫失去能为假的性质。改钉的是
  **每一处的所在**：扫描面内全部命中数必须**等于**位于某个 `record_generated_*` 函数体内的命中数（载体
  `test_the_generated_label_lives_only_inside_the_producer_entries`，现读 2 对 2、入口枚数 2）。
* **它能红在哪**：将来任何人在入口之外（自动链里、跑器里、某个 helper 里）随手打这个标签 ⇒ 体内数小于总数 ⇒ 立刻红。
  册内负对照给的就是这一支：一处写在入口体内、一处写在外面 ⇒ 必须报 2 对 1，而不是 2 对 2。
* **这条改动没买到的**：入口枚数的**上界**不再被钉住。再加第三条入口需要一次新批文，本判据不会自动放行；
  现读两枚＝`record_generated_answer`（有动作）＋`record_generated_prediction`（无动作），两枚都在 `taiji/model.py`。
