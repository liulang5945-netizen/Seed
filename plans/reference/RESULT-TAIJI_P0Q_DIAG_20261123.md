# 结果卡：P0-Q CN 基座通道组传输探针（`p0q_char_space_only`；32:36/40:44 被抑制，0:4 传输）

> [结果卡·探索诊断] — 2026-11-23（D-20261123-353）。脚本 [diag_p0q_20261123.py](../../scripts/training/diag_p0q_20261123.py)；回执 [report](../../reports/taiji_p0q_diag_20261123.json)。**1 seed、147.44 CPU、零 check；探索诊断，不出能力结论。**

## 1. 设置

Subject72 仅训练 cn 块 800 步（正常中文 8 色任务）；向 4 个通道组注入 4 类 one-hot flag（固定 tick），在 CN 块状态上训练 MLP 探针（1500 步）测 flag 可解码性。

## 2. 读数

| 通道组 | 探针 train acc | 结论 |
|---|---|---|
| **0:4（字符空间，正对照）** | **1.000** | 传输 |
| **32:36** | **0.371** | 抑制（≤0.55）✅ |
| **40:44** | **0.363** | 抑制 ✅ |

## 3. 判读

1. **CN 基座与 p24 基座一致**：channels 32:36（及 40:44）在训练后被抑制，可作为「新证据来源通道」而不被旧表示读出。
2. 这为中文修订任务提供了正确设计：新来源 token 放 **32:36**（旧 CN 状态探针 ≤0.55 ⇒ 压力合格）；但旧基座不传输它，新生单元也无法经 base 特征读到 ⇒ **必须给单元级原始输入通路**（机制 B 的单元版）。
3. 与 P0-O 首试对照：P0-O 把 flag 放在 0:32 字符空间 → CN 探针 0.844（不压力）；P0-Q 确认 32:36 是正确位置。
