## 1. 本次主线决策

2026-09-16决定先推进R2整模型语言能力主线。P5.2d在线回写v2的仪器修正保留为并行债务，不删除、不改写、不继续占用当前主线；已有未提交实验文件不属于本文的修改范围。

这个决策不是认为在线适应失去意义，而是因为当前还没有足够可信的原生语言能力作为持续适应的载体。在线更新是否改善后续任务，必须建立在“确实存在一个能读入问题、保留上下文、生成答案并接受结果评价的模型”之上。否则，在线门禁会继续测到局部记录器、候选选择器或仪器行为，而不是用户真正会对话的模型。

R2当前只做四件事：

1. 把“模型存在”“能生成合法文本”“能回答条件问题”“能保持上下文”“能因结果改进”拆成不同证据层。
2. 把训练目标从单一裸字节预测，改造成能对齐回答边界、回答内容和上下文的候选目标体系。
3. 设计成熟发展训练、运行期原生适应、持久写回之间的状态和权限边界。
4. 建立从checkpoint保存恢复到L2/L3用户验收的连续晋级路径。

在第4项完成并获得相应训练授权前，不启动正式pilot。当前只允许预注册入口执行隔离的preflight、plumbing smoke和诊断性小规模过拟合；它们不改变默认入口、不覆盖保护checkpoint，也不构成Mini/L2/L3结论。

## 2. 已有证据：当前问题在哪里

### 2.1 现有训练到底学了什么

当前原生训练入口 scripts/training/train_seed_corpus.py 的训练循环是：

1. 逐个文档加边界；
2. 把文档编码为UTF-8字节流；
3. 对每个字节调用 model.observe(symbol, learn=True)；
4. 用在线surprise、在线准确率和一个固定字节探针写进度；
5. 周期性把模型checkpoint原子保存。

这条链能训练“在字节流中预测下一个符号”的能力，但没有把用户问题、上下文、回答边界、回答目标或结果评价作为独立监督。文件头部曾把语料中的问答标记描述为对话结构，但真实语料主要是多角色文本；语言监督诊断还发现，在抽样的2000行中同时出现问和答标记的行只有1行。不能把文本中存在几个问答字符，等同于已经存在可学习的指令回答任务。

P3b也明确保持了同一目标：scripts/training/train_p3b_aligned.py 记录的 objective_function_unchanged 仍是 observe(symbol, learn=True) 的字节级下一符号预测。它改变的是数据分布对照，不是回答目标、语言接口或信用分配。

### 2.2 当前运行链到底输出了什么

api/seed_runtime.py 的 chat 链路会把用户问题和历史序列化成文本，再调用 model.generate_input；返回值首先是原始字节，随后以UTF-8替换错误解码，再截断回合标记，最后交给表达计划和语言器官。

taiji/language_organ.py 的 readable surface 检查主要验证：

- 返回值是否为字符串；
- 是否非空；
- 是否没有替换字符；
- 是否没有控制字符；
- 是否至少包含字母或数字。

这可以防止把任意损坏字节直接伪装成可读文本，但它不能证明内容回答了问题。P3a的受限解码把合法UTF-8表层从0/4提高到4/4，说明编码约束是必要修复；CAP链上的C仍为0，D为0.0625，E为0.15，说明“可读”没有自动变成“相关、正确、保持上下文或完成指令”。

P3b的实验态在18M共同可观察点确实产生了训练后原始字符序列，但C=0、D=0.0625、E=0.10，B/G仍需人工复核，A/F/H未完成。这个结果证明：

- L0：存在训练状态和可执行生成链，已有局部证据；
- L1：模型输入确实会影响原始输出，已有待完整消融的初步证据；
- 编码层：需要合法UTF-8或等价的受限输出机制；
- 语义层：目前没有证据证明模型能回答基本问题；
- L2：尚未达到；
- L3：不能触发。

### 2.3 当前不能推出的结论

P3b只有一个共同检查点，不能判定对话密度与全语料分布之间没有差异。P3b负结果也不能单独证明Taiji架构已经失效，因为两臂使用的仍是同一个裸字节目标，而且回答信用没有进入训练。

同样，不能因为输出出现汉字、标点或重复片段，就说模型已经存在；也不能因为语言器官可以返回固定可读回退，就说模型会回答。后续所有结果必须同时保存原始生成、约束后生成、回退路径和评分来源。

## 3. 需要解决的真实架构问题

R2把当前语言能力链写成以下因果链：

输入和历史上下文 → 内部表示与工作记忆 → 预测或状态更新 → 语言读出 → 合法文本 → 条件回答结果 → 结果信用回传。

过去的训练只覆盖了其中一小段：在字节流上更新预测状态。现在必须分别验证以下四层：

| 层 | 要求 | 失败时只能说明什么 |
|---|---|---|
| S1 表层合法性 | 输出是合法、边界正确、可复现的文本，不靠替换字符或固定回退 | 编码器、读出或约束有问题；不能说明语义 |
| S2 条件回答 | 改变问题、材料或约束会使答案发生对应改变，并且内容满足题目 | 目标对齐、条件注入或输出读出有问题 |
| S3 上下文保持 | 能使用前文事实，经干扰后仍能回答；纠正、重置和跨会话边界明确 | 工作记忆、状态隔离或上下文信用有问题 |
| S4 结果改进 | 真实结果能改善未见任务，同时保持旧能力、可恢复、可撤销 | 结果信用、适应状态、持久写回或保护机制有问题 |

S1不是S2的替代，S2也不是S4的替代。任何只改善S1的解码修改，都必须继续接受S2/CAP评价；任何只改善代理surprise的训练，都不能直接宣称模型会对话。

## 4. 根因假设与可证伪顺序

当前按证据强度而不是按实现难度排序：

| 优先级 | 假设 | 当前证据 | 最小证伪实验 | 何时转向下一层 |
|---|---|---|---|---|
| H1 | 训练目标和回答任务不对齐 | 唯一监督是裸字节下一符号；对话标记稀疏；CAP语义低分 | 在相同核心和相近预算下加入明确prompt/context/response episode，比较未见C/D/E | 若回答目标对齐后仍只改善S1而S2不动，转H2/H3 |
| H2 | 字节级输出的信用分配过细且不适合回答任务 | UTF-8一个字符跨多个字节；错误发生在长回答末端时难回传到条件状态 | 保留字节动力学，同时加入合法序列、回答边界和序列级目标，观察边界、相关性和泛化 | 若序列目标仍不能改变条件行为，转H3 |
| H3 | 生成读出没有形成稳定的条件语言接口 | v2 prefix已让不同train episode进入不同native context，但20 epoch readout首选字节argmax仍不分离，最终train collision=0.5；dev/final sequence criterion=0 | 在同一checkpoint、同一native predictive owner上做条件margin和序列停止路径对照，保留greedy、原始bytes和恢复重复性 | 若读出对照仍不能把已分离context转成稳定回答，进入读出容量/上下文信用评审；若能，再做新题集泛化 |
| H3.1 | 候选序列路径没有把局部概率差异转成稳定回答 | bounded beam改变了候选序列，但只交换两个train样本的正确/错误归属，聚合collision、exact和sequence均未改善 | 同checkpoint、同owner的greedy/beam只读对照 | 不把搜索解码当作能力修复；转入条件表示泛化与课程/容量诊断 |
| H3.2 | 回答起点的首字节读出需要独立的边界相位 | 独立response-start candidate在20 epoch后train exact/sequence/top1均为1.0，但dev/final exact/sequence/top1均为0，paired delta=0；preflight和恢复为true | 候选首字节owner的独立学习、checkpoint、margin与跨split对照 | 仅证明已见条件拟合；不进入L2；需要新题族泛化和容量/课程诊断 |
| H4 | 工作记忆或状态隔离不足 | 当前D很低；旧状态、历史、重置和持续学习边界尚未作为主训练目标 | 做上下文置换、干扰、纠正、重置、跨会话泄漏和长度退化曲线 | 若短上下文达标而长上下文不达标，先扩记忆，不急于改核心 |
| H5 | 核心架构容量或归纳偏置不足 | P3b在原目标上未达标，但数据分布效应尚不可判 | 在H1-H4目标、链路和数据固定后做容量/状态消融 | 只有目标对齐后仍无条件改进，才进入核心架构替换评审 |

当前不应直接跳到H5。更高上限的做法不是把架构问题永久推迟，而是先让架构接受正确任务的压力；否则任何容量实验都无法区分“不会学回答”和“架构学不会回答”。

## 5. 推荐的高上限架构合同

### 5.1 总体选择

候选路线有三条：

| 路线 | 做法 | 优点 | 根本上限与风险 |
|---|---|---|---|
| A 继续裸字节训练 | 保持现有核心和目标，只扩大语料或预算 | 改动少、对照简单 | 不能直接解决回答信用；容易代理分改善而能力不动；不作为R2主线 |
| B 现有核心上的显式回答对齐 | 保留Taiji核心，在结构化episode上加入回答边界、语义结果和上下文目标 | 最快得到可证伪因果链，能复用现有状态与检查点纪律 | 如果内部状态容量不足，最终仍需升级读出或核心；作为R2首个pilot |
| C 成熟发展训练＋运行期原生持续适应 | 慢参数承担稳定能力，运行期快状态承担新经历，持久写回经过准入和回退 | 上限最高，能把首次能力、成长、适应和恢复放进同一架构合同 | 状态所有权、信用分配、保存恢复和安全边界复杂；必须分阶段落地，不能直接作为一次大改 |

推荐采用“C作为目标架构，B作为第一块可证伪实现”。B不是降低目标，而是为C建立第一条可测的语言因果链。第一块实现必须保留以下未来接口：慢参数、运行期短期状态、长期候选更新、事件来源、评价结果、回退父版本。这样以后加入成熟发展训练和原生持续适应时，不需要把第一版问答能力重新绑定到外部provider。

### 5.2 状态与功能所有权

| 状态/功能 | 负责什么 | 不能负责什么 | 保存与恢复要求 |
|---|---|---|---|
| 慢参数与基础预测状态 | 语言规律、常规表达、稳定的世界/任务结构 | 不直接吸收每次未审查的运行期反馈 | 有版本、来源、训练数据manifest和父checkpoint |
| 回答接口状态 | 接收问题、材料、历史和回答边界，形成条件生成状态 | 不用固定模板替代内容，也不绕过原生核心 | 记录接口版本、目标schema和解码约束 |
| 运行期快速状态 | 当前会话、短期经历、待评估的可塑变化 | 不自动改写父模型或跨会话泄漏 | 重启后按合同恢复或明确清空；区分会话与长期状态 |
| 长期候选更新 | 经结果确认、保持和预算检查后形成的新能力候选 | 不把“写入成功”当作“能力改善” | 事件ID、父lineage、前后摘要、拒绝/撤销记录齐全 |
| 原生语言读出 | 从Taiji状态生成实际文本，接受S1-S3评价 | 不调用外部模型冒充N模式 | 入口、参数、解码器、约束和权重绑定 |
| E/T辅助模式 | 外部表达或工具检索的产品能力 | 不计入N模式原生问答能力 | 单独标记provider、工具、数据和失败边界 |

这意味着“成熟发展训练＋运行期原生持续适应”不会只是新增一个训练脚本，它会改变以下核心功能的职责：

1. 训练器从单一字节流消费器，变成能理解episode边界、目标类型、阶段和保持约束的多目标训练器。
2. checkpoint从参数快照，变成包含慢参数、适应状态、事件账本、父子lineage、评价结果和恢复策略的bundle。
3. 生成器从裸字节采样器，变成带回答边界、合法输出、上下文和停止语义的原生读出。
4. 运行时从只生成一次结果，变成维护会话状态、记录反馈、分离候选更新与持久采用的闭环。
5. 评价器从surprise或短字节准确率，变成同时测编码、条件回答、上下文、结果改进、保持、安全和性能。
6. 回退从简单替换文件，变成参数、快状态、事件账本和环境副作用各自可撤销。

这些是架构合同的目标变化，不代表本次已经实施。

## 6. 结构化训练对象：从文本流到回答episode

### 6.1 最小episode字段

R2训练数据不能依赖原始文本里偶然出现的问号、问：或答：。每个结构化episode至少要有：

| 字段 | 含义 | 规则 |
|---|---|---|
| episode_id | 稳定样本标识 | 不含答案内容的随机或哈希ID，不能用顺序号掩盖重复 |
| task_family | 任务族 | 问候、事实、材料问答、比较、短指令、未知/安全等 |
| system_boundary | 允许的行为边界 | 是否允许使用历史、工具、外部资料和学习 |
| context | 给模型的事实、材料或历史 | 明确哪些内容可引用，哪些只是干扰 |
| user_input | 当前问题或指令 | 保存原始形式和必要的改写族关系 |
| response_boundary | 回答开始、结束和停止条件 | 不让模型靠猜测训练段落边界 |
| target | 参考答案或结构化判分目标 | 自由回答必须配评分标准，不把漂亮措辞当正确 |
| unknown_policy | 信息不足时的行为 | 允许不知道、澄清、拒答或说明依据不足 |
| required_terms / forbidden_terms | 可审计的必需内容与禁止内容 | 只作明确声明的序列级代理，不冒充开放语义理解 |
| unknown_markers | `say_unknown`时允许的未知表达 | 与required_terms分离，避免把未知策略和答案内容混成一项 |
| provenance | 来源、许可、清洗和版本 | 与manifest绑定，可追溯 |
| split | train、dev或final | final不可参与训练、调参或运行期反馈 |

当前simple_zh语料可以继续作为语言/世界文本的候选来源，但不能自动获得instruction或answer监督身份。结构化回答集、控制性合成集、人工审查小集和未见最终集必须分开登记。

### 6.2 数据分层

推荐的输入组合是：

1. 基础语言层：保留必要的原生文本预测，用于维持UTF-8、边界、局部句法和一般表达动力学。
2. 回答对齐层：使用结构化prompt/context/response episode，让模型在回答段承担明确目标。
3. 状态与保持层：包含上下文置换、纠正、干扰、重置和跨会话边界任务。
4. 安全与未知层：包含缺证据、矛盾条件、越权和伪造结果场景。
5. 结果信用层：只在具备真实 outcome、独立后测和旧能力保持时，进入运行期适应或长期候选更新。

训练集、开发集和最终集必须通过hash和episode族隔离。改写题、固定模板变量和同一答案的轻微变体不能被当成完全独立的最终样本。

## 7. 目标函数与信用分配

### 7.1 分层目标

R2不再把一个代理指标当作全部语言能力。候选目标写成：

总目标 = 字节/局部动力学目标 + 合法输出目标 + 回答内容目标 + 上下文目标 + 安全目标 + 保持目标

每一项必须登记：

- 计算在哪个时间点；
- 读取哪个状态；
- 更新哪些参数或快速状态；
- 是否能观察到最终答案；
- 与CAP哪一层对应；
- 如果这一项改善而整模型不改善，如何解释。

第一版pilot不要求一次实现所有复杂目标，但必须至少拥有“回答边界＋回答内容＋基础保持”三种与用户能力直接同构的信号；裸字节surprise只能作为辅助诊断。当前P2已经实现边界、required/forbidden/unknown的只读合同和原始生成回传，但尚未把序列结果信用写入fast/slow；只有在这一规则层先证明不泄漏、不混淆、能在已知正负样本上正确判分后，才允许设计结果信用更新。

### 7.2 四类信用

| 信用类型 | 典型信号 | 作用 | 不能单独推出 |
|---|---|---|---|
| 局部信用 | 下一字节、合法UTF-8、局部边界 | 修复编码、短程结构和读出稳定性 | 能回答问题 |
| 序列信用 | 完整回答是否结束、是否覆盖目标、是否满足约束 | 把回答末端错误传回条件状态 | 长期学习或真实有用 |
| episode信用 | 正确、部分正确、未知处理、依据与安全 | 衡量一次回答的内容结果 | 持续适应有效 |
| 延迟结果信用 | 未见后测收益、旧任务保持、用户/环境真实结果 | 决定快速状态是否进入长期候选 | 只要写入就成功 |

信用路径必须记录“状态版本—目标—更新—生成—评价—后测”的来源图。若最终答案错误，不能只报告字节loss变好；若后测变好，也必须检查是否由回显、模板、外部provider或测试泄漏造成。

### 7.3 运行期原生持续适应的边界

运行期适应建议分三层：

1. 会话层：当前对话中的上下文和短期状态，默认可重置，不自动成为长期能力。
2. 快速适应层：从真实反馈提取候选变化，作用于未见后续任务；必须有预算、保持和幂等。
3. 长期发展层：只有经过结果确认、数据来源审核、旧能力保持、恢复和撤销检查，才生成新的子checkpoint或长期状态。

当前P5.2d在线回写证据不能直接填充这三层，因为其v2门禁存在仪器不可判问题。R2先实现训练与回答的因果链，之后再把在线适应绑定到明确的模型状态和后测任务。

### 8.2 代理信号与能力信号分账

必须同时保存：

- 原始生成字节；
- 受限解码结果；
- 语言器官是否走回退；
- N、E、T模式标识；
- 输入、历史、checkpoint和状态摘要；
- 自动分、人工分、原始理由和失败类型；
- checkpoint前后、模型消融和外部provider关闭后的对照。

以下情况都不能晋级：

1. surprise改善，但C/D/E不改善；
2. 可读率改善，但回答与问题无关；
3. 固定问题成功，改写问题失败；
4. 只在旧题成功，最终未见集不改善；
5. 外部表达器成功，N模式原生读出失败；
6. 模型自报学习成功，但独立后测和旧能力保持没有证据。

## 9. 训练前checkpoint保存与恢复前置检查

按照项目规则，任何新训练前必须完成以下preflight；未完成不得以“先跑小预算”替代。

### 9.1 零步与全新进程

1. 从明确父checkpoint创建隔离副本，记录文件大小、hash、配置、tick、数据manifest和代码提交。
2. 不进行学习，直接保存一个零步子checkpoint。
3. 在全新进程加载零步checkpoint，用固定输入和固定解码设置生成，比较原始输出、状态摘要、tick和配置。
4. 缺件、版本不符、身份不符时必须显式失败，不能随机初始化或静默切换到外部模型。

### 9.2 一步更新与恢复

1. 用一个非最终集的固定episode执行一步受控更新。
2. 保存更新后checkpoint，记录参数或状态摘要、学习计数、随机状态、事件/待处理账本和父lineage。
3. 在新进程恢复，重复同一输入，比较输出和所有合同中声明的可恢复字段。
4. 再次执行同一更新，检查是否重复写入、重复计数或改变幂等语义。

### 9.3 文件与中断

1. 检查磁盘余量、最大checkpoint尺寸和并发写入限制。
2. 写临时文件完成并校验后再替换目标；模拟写入中断，确认旧父文件仍可恢复。
3. 确认生产入口checkpoint、P3b起点和历史报告使用的seed_beta.pt不被新pilot覆盖。
4. 保留父checkpoint、子checkpoint、manifest和失败日志；不能只留下最后一个文件。

preflight本身是R1/R2共同硬门。即使模型目标设计已经获得批准，只要保存/恢复不稳定，也不能进入正式训练。当前R2-P0已经通过；paired诊断显示zero→child的dev/final surprise平均下降0.3149、原题/改写题均改变原生输出，但exact response仍为0。static/slow/fast/fast_slow四臂均通过同一保存恢复与只读边界，且没有exact response收益。P2把raw bytes、generation stop reason、回答边界、required/forbidden/unknown和sequence criterion写入报告；G1 v2只增加运行时可提供的policy字段，20 epoch混合训练仍有50% train output collision、dev/final sequence criterion为0和paired改写敏感性为0。H2/H3审计显示prefix context与概率分布已经不同但argmax仍相同，且全量恢复重复性成立。H3.1的beam只改变候选归属，没有聚合收益；H3.2的response-start candidate把已见train首字节margin拟合到top1=1.0，但dev/final top1=0、exact/sequence=0。因此R2下一步不是继续扩大同质byte训练或堆叠解码器，而是进入条件表示泛化与课程/容量诊断。
