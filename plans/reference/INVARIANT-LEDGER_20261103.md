## 8. 证据文件保留与命名硬规则（后续包可直接引用）

**规则。** 任何重跑、改图后复测或仪器修订，**不得复用既有证据文件名**：必须写入带阶段变体后缀的新文件（`_r2_postfix_YYYYMMDD`、`_v2`、`_v3` 等），旧文件字节保持不变。旧文件的状态不在其 JSON 正文里追加字段，而是由旁挂 `<原文件名>.superseded.json` 声明 `status: superseded`、`superseded_by`、`superseded_at` 和一句原因；旁挂与清单（`plans/manifests/taiji_selection_routing_17_2r_supersession_20261103.json`）共同构成可引用的状态来源。报告、manifest 与 plans 引用旧数字时必须同时引用旁挂或标 `superseded`。

**格式/注释改动（2026-11-04）。** 仅格式或注释类改动**不得触发证据重跑**，条件是语义哈希 `candidate_sha_v2` 不变且零更新等价探针逐位一致（`max_abs_diff=0`：权重、720 步 gold 强制、selection logits、三臂 loss、游标状态）。只有行为相关要素（模块清单、配置常量、参数名/形状、路由与解码规则、输入白名单）变化，才需重新验证并按本节以新文件名重跑、重定价。字节哈希降为附属 `source_sha`，不再决定身份。

## 9. 语义候选身份（`candidate_sha_v2`）

## 10. 子继承父的两层保持判据（2026-11-04 owner 修订）

**适用范围。** 任何“子继承父”的包（09 生长出生、14–18 候选之间的继承、后续 19–22 经历写入）。本节只定义规则：**不改 18.1 本轮判据、不启动训练、不改任何阈值**；18.1 仍按 18.0 冻结预注册结算。

**0.85 的来源与敏感性。** 与现有 bootstrap 世界重采样噪声对齐：当前 dev 面 12–20 个 world，2000 次重采样下界对“同分布重测”的经验波动约 0.10–0.15；取 0.85 使“真实保持”不易被噪声误判，同时保留表征更新空间。不用 1.0：1.0 等于禁止任何表征更新（任何子都无法通过），与“继承后继续学习”的目标矛盾。敏感性：0.80 更宽松，偏向容忍更新、放过轻度退化；0.90 更严格，偏向“几乎不许动旧能力”，在 12–20 world 的噪声下容易把正常更新判成破坏。本轮冻结 0.85。

**必备对照臂（写入未来包设计，不在本轮）。** 每个继承包必须加一臂：**只学新任务、不混合旧任务**。用途是把“遗忘”与“新任务干扰”分开：若该臂与混合臂留存率接近 → 旧能力未被依赖，混合不是必需；若差异显著 → 混合是必要代价，必须写入成本账。缺该臂的继承包按 `retention_control_absent` 不予结案。

## 11. 字节空间合法性结论与逐字节门（18.1 四探针，2026-11-04 登记）

**结论（架构层，可引用）。** 当前解码端点 `decode_endpoint` 是纯 `argmax`，**没有 UTF-8 掩码、没有修复**；字节空间里不存在任何合法性约束。18.1 六格 step300 的 UTF-8 合法率在各格 0.010–1.000 之间大幅波动，正是“无约束”的直接读数，不是随机噪声或模型“乱码”。

**来源拆解（同一批 48 例/格、六格、0 更新）。**

| 条件 | 合法率 | 非法起点位置 | 含义 |
|---|---:|---|---|
| γ=1 纯生成 | 0/288 | 集中 6–16 | 生成通路没有合法性先验 |
| γ=0 复制主导（模型自身路由） | 0/288 | 从 0 起遍布全串 | 路由未锁导致复制到错误位置；且 γ=0 仍保留 `q_null·generated`，不是纯复制 |

### M1（否）“去掉 fresh 层的 α 就能消除耦合”

- **原文**：曾提议把 softmax(α·β/T) 改为 log-β 温度化，认为 fresh pointer 不再依赖 α，新旧候选即解耦。
- **否决理由（§3）**：最终 Q 恒为 `λ·m + (1−λΣm)·S`，并在全局 cursor 混合后重新条件化记录，旧 α 仍进入 η。`∂η_old/∂α_i = (c λ M_i / D_i²)(p_i − ν_i) ≠ 0`（一般情形），且存在可达反例改变位置 argmax。温度化只能去掉 fresh pointer **内部**的 α，不消除全局混合后的耦合。
- **适用范围**：在“记录先选、游标全局混合”的旧核下**无条件不成立**；只有在“先定记录、再读内容”的 OP2 record-first 语义下，“分离”才可定义。
- **依赖命中**：[账本 L4 第 20 行](#)（“内容与绑定分离…独立可控的内容保真通道”）、[L4 表第 39 行](#)（“记录选择 a 与记录内 eta 分别记录”）、[17 设计第 290 行](DESIGN-POST-N16_SELECTION_ROUTING_20261103.md)（“内容/绑定分离与联合信用”打分项）、[03 的 17.x 结论](#)（“内容/绑定分离…半保住”，现已改写为“无法真正分离（M1）”）。
- **处置**：`must_retract`（“分离/独立可控”表述）；`veto_if_reliance`（17 号若把它当结构性保证 → “17 的结构性主张被否”，不得写“部分保住”）。

### M2（否）“任意记录控制与原样继承续读可以同时保留”

- **原文**：17 的设计同时要求“对象/地点/模板可在合法记录间切换”与“切换后旧 cursor 质量可原样续读/逐位恢复”。
- **否决理由（§5.1）**：要让记录 i 的 Q 恰为 `a_i` 且保留旧续读 `λ_i·m_i`，对每条记录需 `a_i ≥ λ_i·M_i`。反例：`a_i=0.1, λ_i=0.8, M_i=0.5` → 续读需 0.4 而预算 0.1。**Q 锁定只保证未选记录为 0，不能保证被选记录同时拥有“任意控制”和“原样续读”**。17 设计第 70 行把“最终 Q 锁定”当作配套条件，只能锁住前者，锁不住后者。

### 16.1 D16-8 活性检查门（activity pre-check）

**规则。** 任何 loss 干预在开训之前，必须在**可训数据**上先做两项读数：

| 读数 | 口径 | 门槛 |
|---|---|---|
| 触发点数与占比 | 该项 loss 在训练样本上取到 >0 的点数 / 总点数 | **≥20%** |
| 梯度范数 | 该干预对应张量在首个批次上的梯度范数 | **必须非零** |

**任一不满足 → 禁止开训。** 只允许两条出路：改参数化方式（例如把 clamp 型边距换成参数化对齐）或换干预；**不得靠多跑更新去"等它触发"**。

**第一号实例（登记在案）。** [§15.7①](#157-192g-记录匹配对比边距2026-11-0430-adam1-存包0-confirm) 的边距项在训练集 128 个内容起点上激活 **0**（gold-decoy 边距最小 5.313、中位 8.08，而 `m=1.0`）。这不是代码错误，是**干预在可训数据上没有定义域**；30 Adam 只重训了 CE。此后再有 loss 型方案，必须先过本门再谈预算。

**参数化干预的读法。** 对不是 clamp 型、而是"新增结构/新增特征"的干预，"触发"读作 **目标行为需要修的样本占比**：19.2h 取新描述物件侧 route 错 **37/96 = 38.5%**（≥20% 通过），同时要求新增张量在首批次梯度非零。

### 16.2 D16-9 零干预对照臂（equal-dose control）

**规则。** 任何 **≤60 Adam** 的小验证，必须同时跑一条**等额 CE-only 对照轨迹**：同父包、同步数、同数据顺序、同损失口径（原损失），只有干预本身不同。否则任何增益都不可归因。

**依据。** 19.2g 的"前后漂移"是直接证据：在边距项恒零、实际只训 CE 的情况下，新描述 96 例整句仍从 0.2604 移动到 **0.2083**、`composite_start` 物件从 0.3854 到 **0.3646**。**"只多训 30 步"本身就会移动读数**，所以绝对读数不能当干预效应。

**报法。** 增益必须写成 **`Δ = 干预臂 − 对照臂`**（配对、逐例），并给 bootstrap 区间；只报绝对读数的结论一律视为未归因。

### 16.5 D16-11 / D16-12 登记（2026-11-04 owner 裁定，19.2j 起强制）

**D16-11（判据侧）：重复目标判定（duplicate_objective）。**

- **规则。** 任何"新损失/新 CE 变体"在报批之前，必须先与**训练里已在用的同一族损失**做一次 0 成本同构核查：写清两者的**公式、输入张量、归约方式**（哪一层取均值、哪些步被覆盖）、以及是否同一目标函数。判定为同一目标族（只差温度 τ 或步覆盖）→ 该提案**退役**，不花训练预算。
- **第一号实例（19.2i 退役）。** 19.2i 拟用"12 路 listwise CE、τ=0.1、只在两个内容起点求和"，与训练中实际在跑的 `selection_loss` 同构：

| 项 | 现有 `selection_loss`（19.2e 起在跑） | 19.2i 提案 |
|---|---|---|
| 公式 | `CE(softmax(scores), route_label)`，`scores` 长 R+1（12 记录 + null 行） | `CE(softmax(scores[:R]/τ), gold_record)`，τ=0.1 |

| 归约 | 每 stage 内对**全部**内容步取均值，再跨 stage 均值 | 只在 2 个内容起点求和 |
| 温度 | τ=1（`F.cross_entropy` 默认） | τ=0.1 |
| 目标 | gold 记录的 listwise NLL（null 行参与竞争） | 同一目标（去掉 null 竞争、只覆盖 1/9 的步） |

- **判定。** 同一目标族，且 19.2i 的两处差异（更低 τ、更少步）都是**更弱/更窄**的方向，不构成新信息 → 登记 `duplicate_objective`，**19.2i 退役**，省 1,089 CPU。

- **规则。** 在**已收敛父包**上做 **≤60 Adam** 的微调，只允许用于**行为校准**（门控、解码掩码、温度等不改图的量）；**不得**用于证实或证伪某个**结构性改动**（新增特征、新增通路、换打分形式）。架构类问题必须走 **同初始化、同数据顺序、从零训练、只差一个变量** 的对照（A/B），且两条臂共享初始化种子与非差异量的逐位拷贝。

### 16.8 D16-15 登记（2026-11-05 owner 裁定，强制）

**D16-15（记账侧）：读数即落盘；报告 write-then-rename；"只在内存里"的读数视为设计缺陷。**

- **规则一（读数即落盘）。** 每一个 50 步读点、每一次停包判定（触发与未触发都算）、每一段 CPU 计时，**产生的那一刻**就 `append` 一行到 `progress-*.jsonl`（append-only，逐行 flush+fsync）。**不许攒到收尾统一写**。
- **规则二（报告原子写）。** 报告必须 **write-then-rename**：先写 `*.tmp`，成功后再原子替换；写失败**不得覆盖**旧报告。
- **规则三（收尾不是唯一一道）。** 收尾写盘只是"最后一道保险"，**不是"唯一一道"**。任何"计算已完成但只存在于内存"的读数，**一律按设计缺陷处理**，不按运气解释。
- **规则四（崩溃路径试跑）。** 每轮开跑前必须有"**崩溃路径已试跑**"的证据：预跑必须覆盖**上一次崩溃发生的那一段**。19.2j 上一次只试跑了训练前段（计价结束 + 3 个 update + 中途闸回调），**没有试跑报告序列化**，所以第二次崩溃（`TypeError: keys must be str ... not tuple`）没有被拦住。
- **第二号实例证据（19.2j 正式运行，2026-11-05）。** **1,200 更新全部完成、4 个 step300 bundle 完整落盘**（28031-O/N、28032-O/N，02:10:20–02:13:49），随后报告序列化在 `training.first/last` 的 `(seed, arm)` 元组键上崩溃：**全部中途读数与 CPU 计时丢失**。修复：键改 `f"{seed}|{arm}"`、全量 `sanitize_keys()`、`write_json_safe()`、`serialization_precheck()` 进 `--dry-run-pricing` 与主训练前必过项。**分类：工程失败，不是实验失败**（训练成果有效）。
- **为什么是"强制"而不是"建议"。** 这是**连续第二次算完账没记上**：前一次为 19.5 的 `by_world` 丢失。两次都发生在"结果已在内存、收尾才写"，因此本条不再作为建议。
- **新增触发条件（计时器未落盘）。** "CPU 计时文件未落盘"本身即触发本条：19.2j 的 CPU **不可得**，只能按 bundle 文件时间戳记 wall **4,961 秒（≈82.7 分钟，00:51:08→02:13:49）**；CPU 登记为**仪器缺口**，不得估算。
- **落地形态（本脚本已实现）。** `progress_append()`（逐行 fsync）、`write_json_safe()`（tmp→replace）、`serialization_precheck()`（用假读数构造完整 report 骨架、含故意元组键，先序列化到临时文件并回读，失败即拒跑）；训练主线在每个 50 步读点、每次停包判定、每段 run CPU、计价段 CPU 都即时落盘。

**边界。** 本节不改任何阈值、不改 19.2j 判据；只约束"读数何时算存在"。

### 16.9 D16-16 登记（2026-11-05 owner 裁定，强制）

**D16-16（负样本侧）：若打分器输出只依赖记录字节多重集，则任意字节置换负样本的边距项梯度恒为 0；所有"加难负样本"提案必须先过这条结构读数，才允许花训练预算。**

- **命题（条件式，数学成立）。** 设负样本与 gold 的字节多重集、长度、字节种类完全相同，仅顺序不同。若打分器每一行的输入只是该记录字节多重集的函数，则 `score_gold ≡ score_decoy`，`max(0, m − (score_gold − score_decoy))` 对**任何**打分器参数的梯度精确为 0（不是"很小"，是恒等 0）。此时边距项是"激活但惰性"的，训练它等于白跑。
- **可操作判据（替代"按臂名假设"）。** 提案必须同时给两个读数：① `max|key_gold − key_decoy|`（关键向量是否逐元素相同）；② 该边距项对可训参数的梯度范数。**若 ① 为 0 → ② 必为 0（结构保证）；若 ① 非 0 → ② 可能非 0，必须实测，不得用臂名（"纯袋装臂"）代替测量。** 阈值沿用 19.2l：`≤1e-12` 记"结构零"，`>1e-6` 才允许进入训练。
- **实测对照（2026-11-05，19.2l-A，0 Adam / 21.9 CPU，128 起点 + 首批 16 起点）。** 冻结 transport（局部位置特征 + 因果 GRU）**本身对置换敏感**：`max|Δkey|` 中位 **1.491**（min 0.994 / max 1.838，128/128 全部不同）。
  - **O 臂（无 `W_align`/`offset_embed`）梯度范数 1.5965**（首批 2.1366）→ **不是 0**；
  - **N 臂 1.6015**（首批 2.1515）；新增块范数 **0.0089**（约占总范数 **0.56%**），主干 1.6015 → 该边距项几乎全部由主干承担，位置块近乎惰性；
  - N 首批梯度 **2.1515 > 1e-6** → 未触发 `gradient_cancels_at_source`；
  - N 初始化可辨识性 **log10 per-param RMS 比 −1.425（不可辨识）**，与 19.2j 价格闸的初始化读数一致（step300 才升到 −0.436）。
- **结论（必须原样引用）。** 命题成立，**但当前 pipeline 不实例化它的前提**；"O 臂是纯袋装打分器、其边距项梯度恒零"**被实测推翻**。因此任何"用 O 作对照没有信息量"的归因**不得再引用**；19.2l-B 的 N×边距项 vs N×CE-only 对照仍成立，但归因须改写为"主干承担、位置块近乎惰性"，不得写成"位置特征给了边距项梯度"。
- **边界。** 本节不改任何冻结阈值、不改 19.2l 判据、不放开 confirm；只为未来负样本提案提供"先测后训"的结构闸。

### 16.10 D16-17 登记（2026-11-05 owner 裁定，强制）

**D16-17（预算闸口径）：`CPU_BUDGET` 是量级闸，不是精度闸；预估 ≤ 2× 预算就必须直接跑，只有 > 2× 才允许停。**

- **阈值。** 本轮 19.2l-B 的 `CPU_BUDGET = 1,200`（不是 800，也不是 400）；**判定式 `预估 > 2 × 预算`（即 >2,400）才允许 `over_budget` 停并上报**。
- **禁止精度循环。** 不得为 **1%–10%** 的差距再停一次；不得"定价 → 超一点 → 改常量 → 再定价"。
- **同包定价只做一次。** 定价读数一旦落盘即为**终值**；若确需重测，必须等下一个包。开跑前测一次、收尾测一次（开/收盘单价对比）算同一次定价的两端，不属于重测。
- **本次证据（登记 `budget_gate_precision_churn`）。** 连续三次被 **1.5%–8%** 的差距拦停（400 口径底板 708.4、800 口径外推 812.1/813.6）；两次纯定价消耗 **77.75 CPU（≈本实验的 10%）**，未产生任何训练读数。
- **边界。** 本节只改预算闸口径，**不改**设计、判据、三读、互斥归因口径；`over_budget` 仍必须先报不跑（仅限 >2×）。

### 16.11 D16-18 登记（2026-11-05 owner 裁定，强制；第三次同类事故）

**D16-18（格式化纪律）：格式化只在收尾提交时跑一次，且必须带硬超时；跑不到就记"格式门未执行"，不得后台补跑。**

- **唯一时点。** 格式化**只在收尾提交时跑一次**；**禁止**在开跑前、运行中、或任何无人值守的后台环节跑。

- **边界。** 只约束格式化/格式门的执行方式，不改任何判据与阈值。
