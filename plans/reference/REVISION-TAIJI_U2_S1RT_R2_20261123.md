## 0. 一句话

S1-RT 证明的是「**任务名外控路由 + 固定分区参数隔离**下，三任务能在同一参数文件里共存并可恢复」。这是成立的，但它不能代表「同一主体在共享表征上学会多项能力并保持旧能力」。r2 保留 S1-RT 结论，给它加上范围标签，并补一级任务无关、非平凡保持的判据（S1-R2），作为 25-S 生长和后续「同主体」类声明的前置条件。

## 1. 修订关系

- S1-RT 合同、冻结哈希 `ffe584fe…`、D-271 读数**原样保留**，出口 `s1_rt_verified` 不撤销；
- 新增**范围标签**（§3），对 S1-RT 及沿用同一机制的 23-S / 24-S / 生长 A 等结论一并适用；
- 新增 **S1-R2 级判据**（§4）。S1-R2 不是 23-S 的回溯前置（不重判已追认结论），但它是以下事项的前置条件：
  1. 25-S 结构生长正式包；
  2. 任何「同主体共享表征」「自主路由」「非隔离保持」类能力声明；
- 依据：核心需求 CR-3（外控路由须显式标记，不计为自主路由）、CR-4（运行时不得读取 evaluator task ID 路由）、根需求 §3.0（新增单元须读写主路径）、MAINLINE §1.1 铁律 5/8（分辨率与等算力配平）。

## 3. 范围标签（对已签结论的重定性，不改出口）

所有沿用 RT 机制的结论在 MAINLINE、能力总账与结果卡中统一附加：

```text
scope: routing=external_task_id; protection=fixed_partition_grad_mask; heads=per_task; state=episode_reset; scenario=task_incremental
```

- **可以声明**：外控路由下的多任务共存、参数隔离保持、胶囊继承与跨进程恢复、P-D 探针因果消融；
- **不能声明**：自主 / 学习路由、共享表征上的保持、任务无关推断、认知状态跨情节连续、CR-2 协同。

## 4. S1-R2 级判据（新增）

### 4.1 场景声明（P 层约束）

- **评测为任务无关推断**：评测前向不接收任务名或任务索引。训练损失可以使用任务标签，因为监督本身合法；
- 路由与读出选择只能由输入（合法通道）和主体内部状态计算；
- 静态检查：主体前向签名中不得出现任务参数，加单测断言；禁止在主体外部按任务拼 gates。

### 4.2 主臂结构（X 层实验选择，探索期二选一后冻结）

| 候选 | 结构 | 保护方式 | 依据 |
|---|---|---|---|
| R2-A 共享 + 路由 | 共享块 S（≥1/3 单元，所有任务都更新）+ 路由块 R；路由器从输入学得（软门或 top-k），带负载均衡项 | 路由块按学得掩码保护；共享块用小回放或 L2 锚定 | DeepSeekMoE 式 shared/routed 分工（[研究对照](CONSOLIDATION-RESEARCH-20261122.md) §C.3） |
| R2-B 学习掩码 | 全部 72 单元；每任务掩码由输入嵌入经学习得到（HAT 式），使用累积掩码和稀疏正则 | 累积掩码对已用单元做梯度屏蔽 | HAT（§C.2），即当前固定分区的学习版 |

两种候选都使用**单一共享输出空间**（三任务标签并集），或由同一个学得路由器选择读出头。读出头权重与路由器参数必须进入 `capsule_v2`。

### 4.3 对照臂（同卡、同数据顺序、同步数、等 FLOPs 重跑，不引用历史读数）

| 臂 | 内容 | 用途 |
|---|---|---|
| C0 | 当前 S1-RT（固定分区 + 任务名路由 + 独立头） | 任务 ID 预言机参照；报告 r2 主臂与 C0 的差距作为「去掉外控的代价」 |
| C1 | 全共享、朴素顺序训练 | 遗忘下界 |
| C2 | 全共享 + 经验回放（缓冲 ≤2% 训练样本，样本预算与主臂相同） | 强 CL 基线 |
| C3 | 全共享 + L2 / EWC 锚定 | 强 CL 基线（24-S.F1b 已有 L2 锚定实现） |
| C4 | 三任务联合多任务训练（非顺序） | 上界参考，不进入顺序门 |
| C5 | 与主臂相同的协议，单元换成 GRU + `read_gate` | 检验 `SelectiveNeuralUnits` 本身的贡献；**必选**（D-20261123-329，见 §7） |

### 4.4 门（读前冻结；每 seed 判定，3 seed 全过为过）

| 门 | 指标 | 判据 |
|---|---|---|
| G1′ 任务无关共存 | 末态各任务准确率（评测前向无任务名） | CN ≥0.85、P-B ≥0.75、conflict ≥0.85、P-D ≥0.70，且任一任务 ≥0.50（沿用 owner 联合口径 D-284 §3） |
| G2′ 路由为主体学得 | 用随机 / 置换路由替换学得路由器 | 最低任务下降 ≥0.20 |
| G3′ 非平凡保持 | 各旧任务 BWT（末态 − 学完该任务时） | ≥ −0.05（owner 放宽口径，D-20261123-328 确认）；**且**共享块参数在 ≥2 个任务阶段收到非零梯度（记录梯度范数日志）；**且**主臂遗忘量 ≤ C1 遗忘量的 1/2 |
| G4′ 不劣于强基线 | 三任务平均 ACC | ≥ max(C2, C3) − 0.02 |
| G5′ 共享块被多任务使用 | 让共享块休眠 | ≥2 个任务各下降 ≥0.10 |
| G6′ 探针因果（沿用 G3） | P-D 拔除探针输入 | 下降 ≥0.20 |
| G7′ 恢复 | 胶囊（含头与路由器）前向差；恢复后三任务差 | ≤1e-6 / ≤1e-6 |
| G8′ 分辨率预检 | 冻结前用 C0 / C1 低价试跑（不计正式曝光） | 每个门既非天花板锁定也非地板锁定；每任务评测样本 ≥512；保持门使用同样本配对 bootstrap，记录 95% 区间 |
| G9′ 预算 | 3 seed、全部对照臂 | 实测报价后冻结帽（估算见 §5） |
| G10′ 纪律 | `criteria_sha256` 读前冻结；对照与主臂同次运行；记录 run conditions；不调阈 | 必须 |

报告指标统一为 ACC / BWT / FWT，给出 mean±std 和逐 seed 表。硬门取逐 seed，均值只用于报告；这一聚合方式写入合同正文。

### 4.5 状态声明

- 默认把 `state=episode_reset` 写入范围标签，S1-R2 不对跨情节状态连续性作声明；
- 如需声明，另设非阻塞门 G-state：设计一个必须依赖上一情节携带的 `z/a` 才能答对的任务；携带状态与重置状态的准确率差 ≥0.20。

### 4.6 出口

`s1_r2_verified` / `s1_r2_partial` / `presentation_failure`（G8′ 预检不通过，即任务或门设计不可判）/ `budget_stop` / `engineering_failure`。出口必须附上实际采用的主臂（R2-A 或 R2-B）和范围标签。

## 5. 执行分两段

1. **R2-X 探索段**（可丢弃，不出能力结论）：1 seed，≤300 CPU；R2-A 和 R2-B **两者都试**（D-20261123-328）各跑一个低价版本，加上 C0 / C1，选出主臂，同时完成 G8′ 预检；
   - **主臂选择规则（读前写定）**：先剔除 G1′ 任一任务 <0.50 或 G2′ 路由置换下降 <0.10 的候选；余者按「最低任务准确率」取高者，差 ≤0.02 时取 BWT（最坏旧任务）较好者，再平则取 FLOPs 较低者；两者均被剔除则出口 `presentation_failure`，不进 R2-F；
   - 探索段读数只作选择与预检，不写入能力总账、不作 R2-F 判据的经验阈值来源；
2. **R2-F 确认段**：冻结 `criteria_sha256` → 单卡 `training_authority` → 3 seed，主臂与 C0–C5 同次运行。估算：S1-RT 正式单臂 670.66 CPU / 3 seed，六臂按 4–5 倍计约 **2,700–3,400 CPU**。这只是估算，需按 §1.2 第 6 项批量实测报价，并留 ≥1.25 倍余裕。
