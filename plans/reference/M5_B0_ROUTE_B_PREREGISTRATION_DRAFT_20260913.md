## §1 研究问题（拆成三个不可互相替代的主张）

| 编号 | 主张 | 判别式 |
|---|---|---|
| **H1 路由** | 组合能覆盖比任何固定单体更广的任务面 | 统一参照下 `U(pair) > U(best deployable control)` |
| **H2 协作** | 组合在**同一任务**上超过全体单体 oracle | `mean(P − max_i S_i) > 0` 且经成员/连接 lesion 归因 |
| **H3 排序** | 模型能对未见组合**正确排序**，而非仅区分类别 | 独立排序验证 + 校准样本量达标 |

三者**分列验收**：H1 通过不授予 H2 主张，H2 通过不授予 H3 主张。

## §3 任务（前置：必须先过 B0 §6.3 上界预检）

### 3.1 任务六条（先验可检验，缺一不可）

非平凡、可满足、权限不放宽、需真实交接、lesion 使收益消失、不被脚本补答案。

### 3.2 候选（D2 决策项，未选定）

| 候选 | 结构 | lesion 判别 |
|---|---|---|
| T1 串联交接 | 两个有序状态变更，第二步依赖第一步的中间态 | 去成员 / 打乱顺序 ⇒ 增益消失 |
| T2 纠错交接 | 成员 B 依赖成员 A 的失败证据修复 | 断开证据通道 ⇒ 增益消失 |
| T3 共享状态约束 | 各成员满足子目标但组合违反全局不变量 | 去掉不变量检查 ⇒ 任务失效（说明不变量未被强制） |

### 3.3 上界预检（**训练前强制**，B0 出口条件）

1. 开发集上逐 context 计算 `max_i S_i` 与 `max_all cell`；
2. 要求 `oracle_all_cell − oracle_singleton` **显著大于**目标阈值；
3. 报告"margin 归零是否可达"；归零仍不可达 ⇒ 任务否决，不允许调 margin；
4. 报告区分面大小，以及 block/模板先验的来源与可见性；
5. **交接可行性探针**（条件 2，无法由 oracle 推出）：脚本化真实执行下必须出现交错轨迹。

**未通过预检的任务不进入 §4。**

## §10.2 参照口径更正与上限优先修订（2026-09-15）

> §10.1 原表不改；本节只补两条会改变冻结版写法的事实与排序。

1. **参照口径更正（影响 §10.1 第 1 项）**：审计面的 `best_pair_gain` 由 `dictionary.policy_mean_gain_vs_all_singleton_oracle` 计算（`audit_taiji_b0_m4_artifact.py:169`），因此实测 **`+2.000` 本来就是对最强参照 `all_singleton_oracle`（`reference_gain 1.5`、`required 1.65`）的增益**，不是对弱参照的增益。N1 报告逐格给出三种参照的 `reference_requirements_audited`，create 行三格在**三种参照下全部 `feasible: true`**、`ceiling_gain 2.0`、`max_clearable_reference 1.85`。据此，"取最强参照 ⇒ 主张不可达"的推断**不成立**：F2 的可证上界 ≤0 只约束**冻结规则**（其轨迹恒为单成员），M4 产生交错轨迹（`interleaved 4/4`）已逃出该上界。
2. **零余量代价**：`+2.000 = ceiling_gain 2.0`，即当前规模（每格 2 context / 3 种子）下增益正好贴天花板、**没有任何余量**；任一格退化就会跌破 `required 1.65`。⇒ WP-1.5 扩面（上限档每格 6 context / 7 种子）在取最强参照时**从可选并行升级为冻结前必过项**。
3. **排序原则修订**：用户明确"更倾向于上限更高的方案，而不是成本更低的"。据此本草案的取值建议改为：D1 = 主判据 `all_singleton_oracle`（另两种降为诊断列）；D2 = create 行**全部 3 条**语言路由；D3 = 逐格公布 `required`，不用单一全局阈值；D4 = 新测试面独立冻结且规模随 WP-1.5 上限档；D5 = **落地**；N2 = 落地前预注册且 `all_members_blocked` 定为一类终局结果；N1a = **开**，列为 WP-6（WP-3 之后、打 `binder_version` 标注）。对照表见[推进计划修订](M5_B0_CLOSEOUT_AND_PLAN_REVISION_20260914.md) §5。
