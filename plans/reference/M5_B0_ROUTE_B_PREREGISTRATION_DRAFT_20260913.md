## §1 研究问题（拆成三个不可互相替代的主张）

| 编号 | 主张 | 判别式 |
|---|---|---|
| **H1 路由** | 组合能覆盖比任何固定单体更广的任务面 | 统一参照下 `U(pair) > U(best deployable control)` |
| **H2 协作** | 组合在**同一任务**上超过全体单体 oracle | `mean(P − max_i S_i) > 0` 且经成员/连接 lesion 归因 |
| **H3 排序** | 模型能对未见组合**正确排序**，而非仅区分类别 | 独立排序验证 + 校准样本量达标 |

三者**分列验收**：H1 通过不授予 H2 主张，H2 通过不授予 H3 主张。

## §3 任务（前置：必须先过 B0 §6.3 上界预检）

### 3.1 任务六条（先验可检验，缺一不可）

非平凡、可满足、权限不放宽、需真实交接、lesion 使收益消失、不被脚本补答案。

### 3.2 候选（D2 决策项，未选定）

| 候选 | 结构 | lesion 判别 |
|---|---|---|
| T1 串联交接 | 两个有序状态变更，第二步依赖第一步的中间态 | 去成员 / 打乱顺序 ⇒ 增益消失 |
| T2 纠错交接 | 成员 B 依赖成员 A 的失败证据修复 | 断开证据通道 ⇒ 增益消失 |
| T3 共享状态约束 | 各成员满足子目标但组合违反全局不变量 | 去掉不变量检查 ⇒ 任务失效（说明不变量未被强制） |

### 3.3 上界预检（**训练前强制**，B0 出口条件）

1. 开发集上逐 context 计算 `max_i S_i` 与 `max_all cell`；
2. 要求 `oracle_all_cell − oracle_singleton` **显著大于**目标阈值；
3. 报告"margin 归零是否可达"；归零仍不可达 ⇒ 任务否决，不允许调 margin；
4. 报告区分面大小，以及 block/模板先验的来源与可见性。

**未通过预检的任务不进入 §4。**

### 3.4 数据隔离

- 旧 144/88 载体只作开发回归；新测试面独立冻结。
- 未见联合 cell 在 **train 全分区**移除（部分移除无效，已有回归测试钉住）。
- 按任务结构 / 项目文本 / 成员组合分组去重；同一结构事实的多个实例不算独立样本。
- 条件化输入只取预测时可见 observation；评分真值不得进入输入。
- 校准样本量 / seed / 阈值 / wall cap 在 development 阶段冻结，不依最终成绩反推。

## §5 门禁（分层，不得合并为一门）

| 层 | 门 | 内容 |
|---|---|---|
| G1 合同门 | 干预真实性 | 非 baseline cell 零步 ⇒ `interventions_happened=false`；承接 P5.2b 三层修复 |
| G2 数据门 | 隔离与去重 | train 全分区移除、分组去重、真值分接口、先验披露 |
| G3 排序门 | 独立排序验证 | tie-break / 重命名 / 编号置换下方向稳定；校准样本量 ≥ 下限 |
| G4 任务门 | H1 | 统一参照下优于可部署对照 |
| G5 协作门 | H2 | 超过公平单体 oracle 且 lesion 归因成立 |
| G6 预算门 | 成本与恢复 | 等预算、wall cap、中断恢复、拒绝路径 |

**出口**：G1–G3 失败 ⇒ 回实现/数据；G4 失败而 G5 通过 ⇒ 任务不可达，回 §3.3；G4 通过而 G5 失败 ⇒ **只作路由主张**，不得表述为协作；预测有效而执行受阻 ⇒ 回动作/组合机制，不在关系层无限调参。

## §6 三态结论（沿用并扩展既有分类）

| 三态 | 触发条件 | 允许的表述 |
|---|---|---|
| `representation_ineffective` | 特征仍不可区分候选 | 只支持"该表示下不可行" |
| `routing_only` | G4 过、G5 不过 | 只支持"覆盖更广"，**不支持协作** |
| `collaboration_supported` | G4、G5 均过且 lesion 归因成立 | 支持协作主张 |
| `task_unreachable` | §3.3 预检未过，或 G5 天花板 < 要求 | **不判为能力不足**；任务/目标须改 |

## §7 必报分账（不作门，禁止省略）

总体收益、逐任务差异、最坏类、安全违规、保持（retention）、成本（calls/steps/wall/recovery）、校准样本量与符号一致率、lesion 前后对照、拒绝与恢复路径、oracle 与可部署对照的全部分项。

## §8 停止点

1. §3.3 上界预检未过 ⇒ 不进入 B1。
2. 公平 oracle 无法超过门槛 ⇒ 停止，讨论任务/目标修改（**本轮已触发**）。
3. 改变任务定义、估计目标或冻结阈值 ⇒ **先审阅确认**，不得在实现中顺手改。
4. 收益保持不过 ⇒ 不得进入 P5.2d。

## §9 纪律

- 负结果如实落账，绝不改绿；失败报告独立保存。
- 报告对自身机制的描述必须与代码同步（P5.2b 曾有自述错误）。
- 回归测试双向钉住（能过 + 该拒绝的拒绝）。
- 临时探针用毕即删；预注册冻结后不改，新结论写新预注册。
- `growth_admitted=false`、`can_promote=false` 贯穿；研究通过不自动授权产品采用。
