# PLAN-R2-DIALOGUE-04：自然对话生成通路只读审计

**状态：已冻结，下一步执行；依据PLAN-R2-DIALOGUE-03R1结论立项。** 本审计不启动训练或模型生成。

## 目标

判断当前实际加载的Taiji原生语言模型是否具备继续训练自然中文对话的基础，并定位从OASST2文本到逐字节输出之间的关键结构与数据路径。重点区分：容量/初始化和预训练来源不足、训练目标或样本呈现不匹配、byte表征/结束标记配置问题、解码/UTF-8映射错误。只形成证据和下一个训练合同所需的技术事实，不从静态读数推断模型能力。

## 审计范围

- 检查父checkpoint、当前R2训练与生成checkpoint元信息；统计实际可训练参数量、模型层/状态维度、byte/输出表规模、优化器状态与训练历史长度。
- 从`LanguageEpisode`序列化、trainer目标构造、loss/梯度更新、checkpoint保存恢复，追踪到逐字节推理、停止标记及UTF-8重组；记录所有输入/输出字段和mask边界。
- 核对父档的来源说明、已有训练历史、报告与数据来源，区分有证据支持的初始化/预训练事实与仓库中没有记录的未知项。
- 将上述路径与R2-DIALOGUE-01、03R1的自由生成样例和格式统计对照，检视是否有输出解码错误、训练/推理不一致或表示能力疑点。样例使用已消费的报告副本，不发新生成查询。

## 边界与验收

- 只读代码和已存在的报告/checkpoint；CPU≤120秒。
- 0参数更新、0新生成、0dev/holdout访问、0新数据、0checkpoint写入、0模型晋升。
- 报告需给出实际参数量与可核验来源；按“已证实 / 尚未知 / 可能机制”区分结论，并指出继续沿当前byte-RNN/Native路径训练前必须通过的最小技术门。
- 若某项来源无法由仓库证据确认，明确写“未知”，不以checkpoint文件大小、训练loss或end-marker率代替语言能力证据。
