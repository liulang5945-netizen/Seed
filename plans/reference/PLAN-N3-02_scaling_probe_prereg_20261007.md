## 0. 第 0 点锚：平台是实测出来的，不是引用的

仪器＝[audit_taiji_n3_plateau_baseline.py](../../scripts/training/audit_taiji_n3_plateau_baseline.py)（只读、零跑），读数件＝`reports/taiji_n3_plateau_baseline_20261007.json`（rc=0）。取法＝每条 run 的 `progress.jsonl` 按 **ticks 五等分**取段均值，噪声带用该 run 自身的**相邻段最大跳幅**（不引外部阈值）：

**三条如实结论**：
1. **平台成立**——自答档斜率 +0.000233 远小于噪声带 0.005066；语料档 +0.006076 **恰好等于**自身噪声带上沿 0.006054 ⇒ 只能说"没有可检出的增长"，**不许声称仍在涨**，也不许声称严格为零。
2. **09 登记的"0.495→0.533 后平"与"0.5934→0.5941 全程平"两条读数同源已核对**：前者＝该件首行→末行的**单行值**（0.494986→0.533012），后者＝**末两段段均值**（0.593346→0.594120）。两句都对，但**口径不同**（单行 vs 段均值）——本件把两种口径都列出来，避免后来者拿段均值去比单行值（§16.1 锚点项的"分子分母同一集合"同族纪律）。
3. **新登记的负面形态**：两档的 holdout_surprise 都在**变差**（+0.041／+0.066 每首末段），即"平台"不是中性的原地，而是**原地＋泛化侧缓慢退**。⇒ ×10 探针若不先看住这个，可能读成"容量大了过拟合更多"而不是"容量解除"。

**本件的分母缺口（点名，不含糊）**：`progress.jsonl` 里没有 §8.7 要求的"语料可用量、实际唯一 episode、实际更新数、序列长度、独立测试覆盖"五项 ⇒ 甲线正式跑必须自带这五项的取数面（§2 判据的一部分），否则 ×10 的读数不可解释。

## 1. 假设

**H-N3a（容量封顶）**：两条 2M run 的平台来自**容量**而非暴露量或课程。若成立 ⇒ 参数×10（region/容量/数据同步扩，09 §2 N3 甲的原文形态）应把平台**解除**（斜率转为可检出为正）；若不成立（×10 仍在噪声带内）⇒ "约束在容量"这条被否证，N3 的容量路线关闭，按 09 §4 第五行保留旧内核并记质量—成本曲线，同时把压强/生长侧（乙）升为唯一扩容解释。

## 2. 判据（先于任何 ×10 读数冻结）

- **J-N3a（平台解除）**＝×10 档的 acc 末段−首段斜率 **> 该档自身相邻段最大跳幅**（噪声带自取，不引外部阈值），**且** acc 末段段均值 > **本件 §0 的两条基线末段均值中较大者 +0.02**（对照锚＝在库件，点名 `a31_onpolicy` 0.594120）。两条件缺一 ⇒ 判"容量不是封顶"。
- **J-N3a-保（泛化侧不退，合取项）**＝同档 holdout_surprise 末段−首段 **≤ +0.02**（对照 §0 两条基线的 +0.041／+0.066 均为"变差"，若 ×10 仍变差更多 ⇒ 判"扩容买到的是过拟合"，不算解除）。
- **五项报告（§8.7）**：语料可用量、实际唯一 episode/任务族、实际更新数、序列长度、独立测试覆盖——**缺任一项即整档读数只算"跑了"，不算"测了"**；等量不可达时给质量—成本曲线，不声称纯架构胜利（§13 变量控制原则）。
- **否证对照（预注册的"对照落在什么值算否定"）**：同 seed、同数据、**同 ×10 参数量但数据不扩**的第二臂 ⇒ 若两臂同分，说明增益来自容量；若只有数据扩臂涨，说明封顶在数据不在容量。两臂都算数，不许只报赢的那条。

## 3. 守卫与纪律

- **G-N3-1 §18.3 发展规模三件分开写**：本次扩的是"覆盖／容量／计算"中的哪一种，跑前写死，不许跑后用读数倒推（这三项在 09 里明确"不是相互替代项"）。
