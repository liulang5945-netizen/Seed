# E5 诊断卡：纠正率为 0 是"学不会"还是"被回滚＋剂量不足"

> 日期：2026-11-18｜性质：**零训练诊断**（本卡不含训练）｜上游：A.5（`correction_protocol_suppressed_learning`）、A.6（`0.333` 归因臂）
> 目标：在动任何训练之前，把 A.5 的 `纠正率 0.0` 归因到三个互斥原因之一。

## 1 原始读数（A.5，3 seed 全部逐位一致）

| 项 | 读数 | 门 |
|---|---|---|
| A 任务 fit 全应答精确 | **1.0（32/32）** | ≥0.80 ✅ |
| 任务 B 首过（无记录） | **0/24** | 分母 |
| 反馈释放 | 24 | — |
| 更新次数 | **24** | — |
| **回滚次数** | **24** | — |
| 纠正数 / 纠正率 | **0 / 0.0** | ≥0.80 ❌ |
| 反馈增益 | **0.0** | ≥0.05 ❌ |
| 反事实臂（释放相反答案） | **0/24** | 非门 |
| A.4 式归因臂（**192 更新**） | **0.333（8/24）** | 非门 |
| 旧能力损伤 | 0.0 | ≤0.02 ✅ **按构造不可失败，不得引用** |

## 2 三个候选原因与现有证据

| 原因 | 支持证据 | 反对证据 | 现状 |
|---|---|---|---|
| **① 写入被回滚** | 释放 24 次、更新 24 次、**回滚 24 次**——每次学完立刻被撤销 | 无 | **最强嫌疑**，A.5 卡自己也把 0 归到"协议条款" |
| **② 剂量不足** | 24 更新 → 0 纠正；**192 更新 → 0.333**（8/24，约为 0 的 3 倍以上） | 0.333 仍远低于 0.80 | **已部分证实**：剂量确实影响结果 |
| **③ 读出不可分** | 反事实臂 0/24（给相反答案也没用） | 反事实臂同样只有 24 更新，与 ① 混淆 | **未分离，不能判定** |

**结论（本卡）：`纠正率 0.0` 主要是 ①+② 的合成，不是"机制上不可能"。** 依据是 A.4 那臂在 192 更新下到 0.333：如果写入根本不可用，剂量不会带来任何提升。

但 ③ 还没被排除干净——反事实臂与主臂共用 24 更新，所以它同时被 ①、② 污染。要判定 ③，必须先把 ① 去掉。

## 3 检查 1 已结（读码，零运行）

`scripts/training/run_a5_22_5.py:454-482` 的协议是：

1. 对每个首错项 `snapshot(model, names)`；
2. **只做 1 次** `loss.backward()` + `optimizer.step()`；
3. 立刻重测该项；**仍错就 `restore(model, saved)` 并把优化器也重建**（注释明写"Adam 矩属于被拒的那一步"）；
4. 计一次 `rollbacks`。

读数 24 释放／24 更新／**24 回滚** ⇒ **每一次更新都被撤销**，模型回到初始权重。所以纠正率 0.0 是**协议的直接后果**，不是可学性证据。

对照同文件 `protocol_accumulated_a4`：**每个错误累积 8 次更新**再测，得 **0.333（8/24）**。

⇒ **检查 1 结论：① 成立，且是充分原因。** A.5 的 `0.0` 应重新标注为"单步学习不可行"，**不得再作为"纠正不可能"或"读出不可分"的证据**。

## 4 三个零训练检查（检查 1 已完成，见 §3）

**检查 1：回滚到底撤了什么。**
在 A.5 的一个 bundle 上重放"释放 → 更新 → 回滚"，逐步做状态 digest，确认回滚是否把 `H`/`F`/槽/记录全部恢复到来释放前。若**逐位恢复** ⇒ ① 成立，任何 24 更新都会被清空，纠正率必为 0，与模型能力无关。
判据：回滚后 digest == 释放前 digest（全字段），且更新后 ≠ 释放前。

**检查 2：释放的记录在读出时是否可寻址。**
零训练探针：对"有记录 vs 无记录"的状态，测 `record_read` 的 route_score 是否对目标实体与 distractor 可分（AUC 或 top-1）。
判据：可分（AUC ≥0.9）⇒ ③ 不成立，问题在写入/剂量；不可分 ⇒ ③ 成立，要先修寻址，训练再多也没用。

**检查 3：保持门是装饰吗。**
对 A.5 的"旧能力损伤 ≤0.02"做**红演练**：人为把父代参数扰动到损伤 >0.02，看该门是否转红。若仍绿 ⇒ **该门不可失败**，必须从判据里移除或重做，否则"纠正与保持同时成立"这句话无法被检验。

## 5 检查顺序与出口

1. 检查 1 → 若回滚逐位恢复，先记录"24 更新必被清空"，**A.5 的 0.0 不再作为可学性证据**；
2. 检查 3 → 若保持门不可失败，先修门，否则后续所有"保持"读数无效；
3. 检查 2 → 判定 ③。

三项全为只读/零训练，预计 <5 CPU。**三项完成后才谈训练**，训练方案按检查结果二选一：
- ① 成立 + ③ 不成立 ⇒ 直接做**剂量-反应曲线**（24/96/192/384 更新，关回滚，测纠正率与真实损伤）；
- ③ 成立 ⇒ 先修记录寻址（C 线的可寻址值＋路由选择），不训练。

## 5.1 更正（2026-11-18，实测）：A 侧 1.0 是**练出来的**，不是出生值

§1 表里"A 任务 fit 全应答精确 1.0（32/32）"读的是 A.5 **跑完 600 步之后**的状态，不是出生值。零训练实测（同一具主体、同一 codes，17.53 CPU）：

| 项 | 读数 |
|---|---|
| 出生 A fit | **0/32 = 0.0**（输出退化字节流 `5d 58 1f 11 11 …`） |
| `build_subject` 两次构建参数逐位相同 | **True**（所以"codes 取自另一具模型"不是原因，原假设被否证） |
| 两具模型的 codes 逐位相同 | **True** |
| A.5 报告的学习曲线 | 200 步 0.5 → **400 步 1.0** → 600 步 1.0 |

⇒ **推论**：从出生态起跑的剂量探针**没有旧能力可损伤**，它那一列 `damage` 恒为 0 是"没东西可损"，不是"保持被挣到"。§6 原来"从同一初始主体出发"的写法必须改成"先练出旧能力并快照，再从快照起跑每个剂量"。

**探针 v1 作废**：`reports/taiji_u2_e5_dose_20261118.json`（只跑 dose 8、`fit_before 0.0`）已移除，不修复、不引用。

**代价变化**：本卡**不再是零训练探针**——它含 600 步 A 训练（练旧能力）＋最多 2880 次反馈更新，属训练卡，须先精确定价再请训练授权。

## 6 剂量-反应实验的执行锚点（v2 已实现，未运行）

A.5 运行器是冻结的合约脚本，不能改它的 `feedback_updates_a4`（会破坏 `criteria_sha256` 与数据 digest 守卫）。要单独写探针，按 `run()` 的装配顺序复用：

| 步骤 | 锚点 |
|---|---|
| 载入合约 | `plans/manifests/taiji_u2_a5_protocol_20261116.json` |
| 载入数据 + digest 守卫 | `run_a5_22_5.py:989-1008` |
| 建主体 | `build_subject(contract)`（:317）、`set_trainable`（:339） |
| 生成 codes | `a2.code_by_id(base_model, head, prior, data["train"] + data["fit"], contract)`（:602） |
| task B 项与模板 | `task_b_examples`（:102）、`template_of`（:1017） |
| 单次记录损失 | `record_loss`（:410） |
| 累积更新协议 | `protocol_accumulated_a4`（:493），剂量来自 `contract["feedback_updates_a4"]`，探针里改成参数 |

v2 探针（`scripts/training/probe_e5_dose_20261118.py`）的四相，已按 §5.1 更正：

1. **装配**：与 `run_a5_22_5.run` 同序（主体→head→prior→codes→`set_trainable`）；
2. **练旧能力**：`train_step`（`a2.emission_loss(use_code=True)`、`positions` 缓存批、`contract["optimizer"]`）跑 600 步，在 200／400／600 记学习曲线；
3. **快照**：`state_dict` 逐位复制＝旧能力 bundle；
4. **每剂量**：从快照 `load_state_dict` 复原 → 对 24 个首错项各累积 `dose` 次 `record_loss` 更新（**不回滚**）→ 测纠正数（分母 24）与 A fit 的旧能力损伤。

两处实现要点（v1 缺陷已修）：模板号必须用**原始项序号**（子集重编号会让记录字节与题面错位）；smoke 用 `emission_loss`／`record_loss` 的 `backward()` 取梯度而**不调 `optimizer.step()`**，才配得上"0 优化器步"。

判据：纠正率 ≥0.80 且损伤 ≤0.02 同时成立才算 E5 有解；只有纠正率涨、损伤也涨 ⇒ 是权衡问题，不是剂量问题。
