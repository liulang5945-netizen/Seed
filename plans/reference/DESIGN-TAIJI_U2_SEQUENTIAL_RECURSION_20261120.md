# 设计草案：顺序计算式递归（22.X，零训练设计稿）

> 状态：[设计草案/待实现] — 2026-11-20。依据 D-20261119-102（重复输入迭代无深度收益，该定义收口）与 D-50（结构稀疏细化负）。**本设计改变问题表述**：任务改为**两步动作序列的最终位置预测**，单 tick 原则上无法完成（看不到第一步后的中间状态），只有「保留状态→再吃第二步」的迭代推理才可能做对。

## 1. 任务定义（顺序计算，非重复输入）

- 由动作后果数据（`build_partition` 行：起止位置桶 + 48 维感知/动作特征）构造**动作对**：`bin1 = r1.final_bin`；`bin2 = bin1 + (r2.final_bin − r2.current_bin)`（裁到合法桶）。
- 序列输入：tick1 = r1 特征（预测 `bin1`），tick2 = r2 特征（预测 `bin2`），**状态 `z/a` 跨 tick 保留**。
- 单 tick 基线：只看 r2 特征、把位置代理清零（不知道初始桶）→ 理论上只能靠增量先验，难以预测 `bin2`。
- 对照：shuffled 顺序（先 r2 后 r1）应显著变差；仅标签控制（预测 `bin2−bin1` 相对量）不构成顺序推理。

## 2. 门（预注册）

1. **顺序收益**：序列模型 `acc(bin2) ≥ 0.55`，且比单 tick 基线高 ≥0.10；
2. **顺序依赖**：shuffled 顺序的 `acc(bin2)` 比正确顺序低 ≥0.10；
3. **中间步骤信用**：tick1 的 `acc(bin1) ≥ 0.50`（状态必须携带第一步信息）；
4. **反馈依赖**：tick2 输入换成无关样本时最终准确率 ≤0.45（信息来自 tick2 输入而非仅状态）。

四门全过 ⇒ `sequential_recursion_ready`（有界：单主体、两步、合成动作对）；否则按失败子条件记 negative/partial。

## 3. 实现（不改核心模块）

- 复用 `RouteBGraph` 多 tick 前向（tick=batch 内序列位置，状态跨位置保留，见 D-102 实现说明）；
- 训练：对每个动作对拼成 `[B, 2]` 序列，损失 = `CE(tick1, bin1) + CE(tick2, bin2)`；
- 3 seed、零 check、**价 ≤200 CPU**；对照臂：单 tick（r2 特征+位置代理清零）、shuffled 顺序、无关 tick2。

## 4. 与既有负结果的区别

| 项 | D-102（重复输入） | D-50（结构细化） | 本设计 |
|---|---|---|---|
| 信息结构 | 每 tick 同一输入 | 单元分裂掩码 | **每 tick 新信息、需携带中间状态** |
| 深度是否有用 | 无（tick1 已够） | 无 | 是（单 tick 缺中间状态） |
| 结论 | negative 收口 | negative | 待测 |

## 5. 风险与出口

- 风险 1：两次输入拼接式模型也能做（若无位置记忆则不能）→ 单 tick 基线正是排除项。
- 风险 2：状态坍缩或跨样本泄漏（实现限制）→ 记录逐 tick 损失/活动；若泄漏严重则记 `engineering_limitation` 子条件。
- 风险 3：合成动作对分布过窄 → 记录 bin 覆盖率（每桶样本数 ≥8 才入评）。
- 出口：全过记有界 verified；仅 1/3 过记 partial；否则 negative，停止该形态。
