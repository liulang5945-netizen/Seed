# 机制算法与机制检验的通过标准，以及转入正式训练（N32）的放行条件

> 文档状态：[规范] — 2026-11-24（D-20261124-464 生效；§10 参数取当前值，owner 可回溯调整；N32 目标规模待定）。上位目标见 [统一目标（核心需求 §2.1）](TAIJI_CORE_REQUIREMENTS.md#21-统一目标与验收)，冲突时以目标为准。编号统一采用 N 体系（见 [编号对照表](../reference/ID_MAP_N.md)）。本文与 [阶段验收与停止规则](STAGE_GATES_AND_STOPPING.md) 配套：那份管「阶段怎么结束」，本文管「机制怎么结束」和「何时从检验转入正式训练」。不改 P 层边界，不撤销已签结论；零训练、零 check/final。

## 0. 核心原则

1. **机制检验不负责证明 Taiji 更先进。** 它只回答三个问题：要放进正式训练的每个组件，是否**实现正确**、是否**确实被需要**、是否**不劣于最强的标准替代**。「Taiji 机制优于标准方法」改在正式训练中用预注册的消融臂检验，不作为放行前提。这一条是结束无限验证的关键。
2. **每个机制最终只能落入 6 种终态之一**（§5），没有「继续验证」这一状态。
3. **已达到的级别长期有效**，除非后来查出 bug，使该级证据失效。
4. **探索卡（卡号 01–89）不能让机制升级**，只有确认运行（卡号 90–99）可以。确认运行的口径同阶段规则 §2.2：确认 seed、读前冻结、逐 seed 判定。
5. **目标规定的必需能力不能被剔除，也不能被替换为「没有这项能力」**（§5.1）。可以替换的是实现方式，不是能力本身。

## 1. 机制与机制卷宗

**机制**指架构中可以单独开关、单独损伤的一个组件，并带有一条可证伪的主张。例如：「选择性写门让末态保留早期信息」；「生长的新单元承载旧表示无法表达的功能」。

- **需要检验的机制**：每个对应一条研究线 `N31.<线>`，卷宗为 `plans/reference/DOSSIER-N31-<线>-<机制名>.md`。
- **标准组件与工程组件**：不开线，统一登记在 `plans/reference/DOSSIER-N31-0-REGISTRY.md`。
- 卷宗只增不改，依次记录：设计（级0）→ 各级预注册与结果（附卡号）→ 当前级别与终态 → 已耗预算。
- 不挂在卷宗下的卡，不计入任何机制的级别。

## 2. 级0：机制算法（设计）通过标准

设计稿满足以下全部要求，即级0 通过。这一级只做文本审查，不需要训练。

| 编号 | 要求 |
|---|---|
| 设计01 | 补齐 ARCHITECTURE §4.1 的十个字段：owner、input、state、update、output、downstream、resource、lesion、checkpoint、evidence |
| 设计02 | 给出精确的更新方程或伪代码，包括变量维度、时序、可训练参数清单 |
| 设计03 | 写出**一条**可证伪主张，以及与之对应的检验任务类型 |
| 设计04 | 预先列出**标准替代集**，即承担同一角色的成熟方法，供级3 对标（参考 §4.5） |
| 设计05 | 写出预期失败方式，以及每种失败在级2、级3 上的表现 |
| 设计06 | 资源估算：FLOPs、参数量、状态大小如何随规模变化 |
| 设计07 | 场景声明：是否任务无关；是否引入外控（任务名、脚本常数、手工路由）。引入外控的机制只能作为工程组件或对照臂，不能算认知机制 |

## 3. 机制检验阶梯：级1–级4

### 级1 工程正确（单测 PASS/FAIL，放入 `tests/` 并进 CI）

| 编号 | 不变量 |
|---|---|
| 不变量01 | 批内样本互不影响：样本间串扰最大值为 0 |
| 不变量02 | 出生中性：生长并完成全部手工改动后、开始训练前，旧部分前向输出的最大绝对差为 0 |
| 不变量03 | 胶囊往返：保存后恢复，前向差 ≤1e-6 |
| 不变量04 | 生命周期与训练一致：训练期掩码等于评估期掩码（已有回归测试） |
| 不变量05 | 评估确定性：同一模型评估两次结果逐位相同；所有读出头处于 eval 模式 |
| 不变量06 | 梯度归属：声明可训练的参数梯度非零，声明冻结的参数梯度为零 |
| 不变量07 | 无死参数：每个参数被扰动后输出都会变化；做不到的要么删除，要么在卷宗里说明 |
| 不变量08 | 声明任务无关的机制，前向签名中不含任务参数（用单测断言） |
| 不变量09 | 同一 seed 重跑，报告逐位相同 |

### 级2 必要性（在合格的压力任务上）

**压力预检**必须先通过，否则本次级2 无效，记为 `presentation_failure`。预检条件：用不含该机制的冻结表示做收敛的 logreg 探针，得分 ≤ 目标门 T − 0.20，且经 null 校准后 Δ ≤0.10。

**判定**（确认 seed 上逐 seed 成立）：
- 开启机制：达到 T（预注册时写定，默认 0.85）；
- 关闭机制，但算力相同、调参相同：≤ T − 0.15（反事实必要性）；
- 训练好的机制休眠或置零：准确率下降 ≥0.15；唤醒后逐位复原。

级2 证明的是这个机制被使用、而且被需要，**不证明**它比其他方法好。

### 级3 对标（与最强标准替代比较）

- **对照**：从设计04 列出的替代集中，取最强的一个。
- **公平性**：FLOPs 相差 ≤10%，同时报告参数量；所有臂使用同一个学习率网格（≥3 点），在 tune 划分上各自取最优；数据顺序、批次、步数完全相同。
- **天花板规则**：最强替代 ≥0.95 时，判为不可分辨，改用预注册难度梯度中的下一档，最多换 2 档。换 2 档后仍在天花板，结论记为「平」。
- **结论分类**：
  - **优**：每个 seed 差值 ≥ +0.05，或在替代 ≥0.85 时误差下降 ≥30%；同时配对 bootstrap 95% 下界 > 0；
  - **平**：每个 seed |差值| ≤0.02，或置信区间含 0 且 |均值| ≤0.02；
  - **劣**：每个 seed 差值 ≤ −0.02；
  - **不确定**：不属于以上三类。允许追加 1 次（换 seed 或扩大测试集）；仍不确定，按「平」处理。

### 级4 稳健性

- **重测范围**：在两个规模上重测级2（级3 为「优」时也重测级3）：容量 ×4；难度 ×2（时程更长、项目或类别更多）。另外在第二个任务族上测一次。学习率取 ×0.5 和 ×2，结论方向不能翻转。
- **判定**：
  - 所有被测条件下级2 都成立；
  - 级3 为「优」时，最大规模上方向不变，优势不少于小规模时的一半，且 95% 下界 > 0；
  - 最大被测规模 ≥ N32 目标规模的 **1/4**（目标规模在放行条件03 中声明）。

## 4. 统一检验规范（适用于级2–级4）

1. 使用 3 个确认 seed，逐 seed 判定；均值只报告，不参与判定。
2. 统一使用冻结的公共评估框架，测试集 ≥1024，报告二项分布标准误。
3. 门分三类（构造保证 / 工程回归 / 实验门），只有实验门决定结论。
4. 阈值、任务、对照集读前冻结，记录 `criteria_sha256`；读后放宽只在下一次确认运行生效。
5. **标准替代集参考**（每个机制在设计04 中定稿）：

| 机制角色 | 标准替代集 |
|---|---|
| 循环单元动力学 | GRU＋read_gate、LSTM＋read_gate，等 FLOPs |
| 结构生长 | 同最终容量预分配＋同回放＋同步数 |
| 路由 / 容量分配 | MoE top-k＋负载均衡、HAT 学得掩码、全共享＋回放 |
| 保持 / 抗遗忘 | 经验回放、EWC 或 L2 锚定 |
| 巩固 | 同步数继续常规训练 |
| 不确定度 | 读出集成分歧、温度校准 |
| 奖励适应 | 带基线的 REINFORCE（只训读出） |

## 5. 机制终态（每个机制必须落入其一）

| 终态 | 条件 | 如何进入 N32 |
|---|---|---|
| **ADOPT**（采纳为 Taiji 机制） | 级0–级2 通过，级3 为「优」，级4 通过 | 按原样进入；可声明优势，但须附范围标签 |
| **ADOPT-PARITY**（等效采纳） | 级0–级2 通过，级3 为「平」，级4 中的级2 部分通过 | 只有成本 ≤ 替代，或 P/E 层合同要求时才保留，否则按 REPLACE 处理；**不得声明优势**；进入训练前不再做新颖性检验 |
| **REPLACE-STANDARD**（替换为标准实现） | 级3 为「劣」；或为「平」但成本更高 | N32 配置改用标准替代 |
| **ENGINEERING**（工程组件） | 属于基础设施，如胶囊、生命周期 API、逐样本状态、评估框架 | 只需级1 |
| **REJECT**（剔除） | 级2 失败：不被需要，或未被使用 | 从训练配置中移除 |
| **DEFER**（暂缓） | N32 用不到 | N31 内不开卡；待使用它的阶段到来时重建卷宗 |

### 5.1 必需能力条款（依统一目标修订稿第一、二节）

**必需能力**：单位身份与生命周期（继承式出生、分化、整合、可逆休眠、退役/回收）、持续活动状态、可学习连接、持续可塑性（在线更新）、按需规模生长。

| 情形 | 终态 | 进入 N32 的方式 |
|---|---|---|
| 级1 不过 | 阻塞 | 必须修复；工程正确没有例外 |
| 级3 为「优」 | ADOPT | 照常进入，可签收益 |
| 级3 为「平」或「不确定」，或级2 显示「未被需要」 | **REQUIRED-INPLACE**（在位，收益未证） | 纳入配置；对应收益格记「未成立」；不得声明收益 |
| 级3 为「劣」（低于标准替代超过 0.02） | **REQUIRED-REVISE** | 允许 1 次设计修订（计入 §6）；仍劣则以保守触发纳入（默认不触发，仅当内部压力信号超过预注册阈值时启用），对应轴记 negative，修订方案列为下一阶段必做项 |

- REJECT、REPLACE-STANDARD、DEFER **不适用于必需能力本身**。可以替换的是**实现方式**，例如生长改用 Net2Net 式加宽、或渐进列加侧向连接；不得替换为「不生长」。
- 标准替代用于对标和标准基线臂（放行05），不进入主臂配置。
- 单元更新方程不属于必需能力本身。采用标准门控形式（如 GRU 式）即满足目标的结构要求，因此「单元动力学」这一机制仍按 §5 正常判定，可以判 REPLACE-STANDARD。

## 6. 每个机制的预算与尝试上限

- 级2–级4 合计 ≤8 张探索卡，且 ≤3,000 CPU；确认运行不计入。
- 每一级最多尝试 2 次：1 次修 bug，加 1 次设计修订（修订须回到级0，更新卷宗）。
- 预算用尽或尝试次数用尽时，按当时已达到的最高级别对照 §5 给出终态，**不得追加**。
- 卷宗的耗用同时计入 N31 时间盒。

## 7. 转入正式训练（N32）的放行条件

**N32（正式训练 T1）的定义**：用冻结的架构版本，在**声明的目标规模**和正式课程（原 23-S/24-S 合同的世界与分区）上训练；check 曝光 ≤2，final 保持封存。

以下 7 条**全部满足**才放行：

| 编号 | 条件 |
|---|---|
| 放行01 组件清单 | §5.1 所列必需能力全部在位，终态为 ADOPT / ADOPT-PARITY / REQUIRED-INPLACE / REQUIRED-REVISE 之一；其余组件终态属于 ADOPT / ADOPT-PARITY / REPLACE-STANDARD / ENGINEERING 之一；没有组件仍在检验中；REJECT 和 DEFER 的组件已移除 |
| 放行02 联合检验 | N31「通过」：格01–05 与格07 在确认 seed 上 3/3 通过 |
| 放行03 规模 | 声明 N32 目标规模（单元数、参数量、时程）；级4 的最大规模 ≥ 目标规模的 1/4；目标规模下做一次试运行（≤ 训练预算的 5%），确认不发散、损失下降，吞吐和内存实测与报价一致 |
| 放行04 训练合同 | 写明数据与分区、check/final 封存状态、评测套件（即 `SCORECARD-N32`，以九轴为骨架）、停止规则、实测定价，以及 owner 的 `training_authority` |
| 放行05 标准基线臂 | N32 内同时跑一组全标准配置的对照臂，预算 ≥ 主臂的 25%，用于解释训练结果 |
| 放行06 冻结 | 源码 pin、架构版本号、`criteria_sha256` 全部冻结 |
| 放行07 声明范围 | 训练结果按范围标签声明；ADOPT-PARITY 的组件不声明优势 |

## 8. 放行后的变更控制

1. 不在训练主体上做探索探针。
2. 架构变更走 MAINLINE §1.1 铁律 7，每个阶段 ≤2 次修订；每次修订都要重过受影响机制的级1，以及它改动到的各级。
3. 机制的新颖性研究改为 N32 内预注册的消融臂，不作为门控条件。
