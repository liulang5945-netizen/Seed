# 决策提示：P5.2c′ 归因后的下一步

> 日期：2026-09-13。基线：`1c0bf9cb`（P5.2c′ 已执行完毕，`transfer_no_gain`）。
> 依据：[P5.2c′ 结果报告](../../../reports/M5_P5_2C_PRIME_UNSEEN_COMBINATION_TRANSFER_RESULT_20260913.md) §6.2b / §7
> 用途：按预注册 §7 停止点，`transfer_no_gain` 需回归因并**另立新预注册**。本文给出可选路线，供决策后再冻结判据。

## 1. 归因结论（已确定，是决策的前提）

本 gate 的 `transfer_no_gain` **不是**「该 cohort 无联合增益潜力」。三条硬证据：

| 证据 | 事实 |
|---|---|
| 互补性真实存在 | `b+c` = `[0,6,6,0]` 与 `b+d` = `[6,6,0,0]` 均达 `12/24`，单体仅 `6/24` |
| 互补性由**能力面不重叠**决定 | `d` 与 `a` 能力面相同（均只覆盖 block-0）⇒「d 与 b 互补」≡「a 与 b 互补」 |
| learner **无特征**识别这一点 | 4 成员 `contribution` **全等 `0.5`**，即 learner 视 4 成员为不可区分 |

所以失败落在**表征层 + 设计层**，不在能力层。这决定了下一步该修什么。

## 2. 三条可选路线

### 路线 A：修 profile 表征（补「能力面」信息）

**做什么**：让 member profile 携带**能力面**信息（该成员在哪些 block/cell 类型上有效），而非仅有标量 `contribution`。然后检验：learner 能否据此判断两个成员是否互补，并正确预测未见组合的联合增益。

**理由**：直接命中归因结论。能力面「不重叠」是本 cohort 中联合增益的唯一来源，而它现在完全没有进入 learner 的输入。

**代价**：
- 需要定义「能力面」的可观测形式。**风险**：若直接把 block 标记喂给 learner，可能构成「把答案编码进特征」——必须论证能力面是**从 train 单体证据中可导出**的，而非外部注入的。
- 需新预注册；判据需重新设计（原 MARGIN 口径可能不再适用）。

**停止条件**：若能力面特征加入后 learner 仍无法在未见组合上产生正迁移 ⇒ 问题不在表征而在关系项形式，转路线 B。

### 路线 B：修 pair 关系项形式

**做什么**：当前 `_pair_features` 只能表达「成员身份组合」，无法表达「互补 vs 冗余」。改为显式建模成员间的**能力面关系**（重叠度）。

**理由**：§6.2b 显示「重叠度」才是决定联合增益的结构变量。身份组合是个糟糕的代理。

**代价**：
- 触及 `taiji/interaction_groups.py` 的 `_pair_features` —— 这是 P5.2b/P5.2c/P5.2c′ 共用的**冻结机制**。改动会同时影响既有报告的可比性。
- **必须**保留旧口径与旧报告，不能追溯改写。

**停止条件**：若新关系项在 train 上过拟合（train 增益涨、holdout 不涨）⇒ 回路线 A 或 C。

### 路线 C：修实验设计（未见组合的选取 + 提高功效）

**做什么**：三件事打包：
1. **未见组合数 ≥2**（当前为 1，导致门 8 校准只建在单样本上，检验力弱）；
2. 其中**至少 1 对具互补潜力**（当前按字典序索引选取，落到冗余 pair）；
3. 解决 **block-3 不可达**（`contract_intercepted:language_evidence_ambiguous`，1/4 context 对所有组合均 0）。

**理由**：这三项都是**已知的、可独立修复的设计缺陷**，修完再谈表征，能显著提高结论强度。

**代价**：
- 需要更大成员集配合**整体移除**才能造出 ≥2 个未见组合（预注册 §7 已注明成本更高）。
- block-3 涉及 P5.2a 任务定义，可能需独立预注册。
- 工程量大，且**不保证**修完就能证明迁移——但它让后续任何结论更可信。

**停止条件**：若更大成员集下 `train_only_candidates` 的行为再次塌缩（如所有 pair 仍被观测），回机制层重新分析。

## 3. 建议

**先 C 后 A，B 视 A 的结果再定。** 理由：

- **C 是「让实验值得做」的前置**。当前候选面基数为 1、block-3 全废、且未见 pair 落点由字典序决定——这三项使得**任何**表征改进都难以被可信地测量。先修好测量仪器。
- **A 是「针对归因」。** C 完成后，A 才有干净的场地检验「能力面特征能否预测未见组合的联合增益」。
- **B 是「若 A 不足」。** 关系项改动会污染与既有报告的可比性，应作为后手，除非 A 明确显示表征不是瓶颈。

**若只允许做一件事**：选 **C**。因为它不依赖任何新假设，且能改善所有后续实验的检验力；而 A/B 都押注在具体机制猜想上。

## 4. 三条路线共同的硬约束

1. **不得改动** P5.2c 原预注册、入场审计报告、P5.2b 报告、P5.2c′ 报告与预注册。
2. **不得**把本轮 `transfer_no_gain` 因归因结论追认为通过。
3. `growth_admitted=false`、`can_promote=false` 继续贯穿。
4. 任何路线都必须**新预注册**、先冻结判据再执行；阈值不得由实测反推。
5. **必须**保留 `zero_step = 0` 与「baseline 全 0」两个既得守卫（P5.2b 三层修复的成果）。
6. 临时脚本用毕即删；语义映射不得进入 learner/evaluator 输入。
7. 若能力面/重叠度等新特征被引入，**必须**在预注册中论证其可从 train 证据导出，并断言无 holdout 泄漏。

## 5. 需要你决策的点

- **路线选择**：C（设计先行）/ A（表征先行）/ B（关系项先行）/ 其他。
- **block-3 是否本轮处理**：若处理，需接受它触及 P5.2a 任务定义，可能引入一个独立预注册。
- **是否接受「先修测量仪器、本轮不产出迁移结论」**：选 C 意味着这一轮的产出是**更强的实验装置**，而非关于迁移能力的结论。这需要你明确认可，否则容易在 C 完成后被视为「没做出结果」。
