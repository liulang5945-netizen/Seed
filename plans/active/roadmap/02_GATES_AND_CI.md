## 1. 四种完成不得混写

| 完成层级 | 满足条件 | 可以宣布什么 |
|---|---|---|
| 实验完成 | 按冻结设计执行并记录成功/失败/阻塞 | 完成一次测量；负结果也可以结项 |
| 能力轴晋级 | 该轴范围/必达门冻结、证据齐备、保持/恢复/预算/安全通过，独立批准 | 只在批准范围内晋级 |
| 大阶段退出 | 01 中该阶段必达轴逐项结项，共同门通过；排除项获显式范围批准 | 该交付范围可以进入下一阶段，不等于长期愿景完成 |
| 产品采用/发布 | 实际依赖 artifact 准入、行为批准、端到端/正式 CI、恢复与发布 manifest | 指定行为采用或指定版本发布 |

`can_promote` 必须写明所属报告/轴，不设一个无范围的全项目布尔值。K 轴已晋级，其他报告 false 不撤销它；它的 true 不替其他轴授权。

## 2. 每次晋级评审的固定清单

### 2.1 统一认知闭环验收原则（2026-09-17用户确认）

**优先证明记忆、世界模型与规划在同一真实任务中共同改善行为，不以模块齐全、状态字段存在、局部gate通过或界面可用代替认知闭环成立。** 认知所有权、状态恢复与因果验证是必要底座，不是统一能力已经成立的充分证据；语言分数也不是整个认知架构的唯一能力出口。

本原则适用于后续“统一认知能力/闭环成立”的主张、相关CAP代表能力评审及M5退出/M6采用范围；不追改历史冻结实验阈值，不撤销K轴等已批准的限定成果，不要求每项局部实验同时调用全部机制。

| 验收要求 | 必须提供的证据 | 不可替代物 |
|---|---|---|
| 同一模型、同一入口 | 固定代码与checkpoint/bundle、真实任务入口、参数与运行模式；逐步追踪输入→记忆→后果预测→计划/选择→执行→实际反馈 | 拼接不同实验、换模型凑分、单列模块清单 |
| 任务确实需要三类机制 | 任务含需保留/更新的信息、需区分的行动后果及需选择的多步路径；依据来自当时可见信息 | 脚本强行调用三模块、无因果必要性的演示 |
| 行为而非表面表现 | 以隔离环境中实际执行后的可核验终态、约束满足、失败/恢复和成本评价；预测与真实结果分开 | 流畅回答、计划文本、内部奖励、工具返回成功标志单独充当完成 |
| 联合贡献与公平对照 | 完整系统对比可部署简单策略及分别禁用/替换记忆、世界预测、规划的对照；保持信息权限、任务、有效训练与推理预算公平并披露差异 | 损坏接口导致消融失败、无收益时宣称“撤销核心收益” |
| 迁移与连续性 | 未见任务实例、预先冻结的重复/种子要求、新进程恢复后的行为证据；学习型主张另验真实反馈后的新旧任务收益 | 同题复现、只证明checkpoint digest相同、把状态变化当持续学习 |
| 所有权与安全 | 工具只提供允许的执行/观测；模型选择、外部表达、宿主规则分别标明，真实高风险动作另授权 | 标签/绑定器暗藏答案、外部模型替代决策、越权执行 |

先证明各机制在声明范围内有贡献、组合有效且没有不可接受的相互抵消；**不预设必须出现超加成协同**。消融可能造成分布变化，须说明替换语义并用适当对照排除单纯接口破坏；未经验证不把性能下降直接当作机制因果证明。

运行时反馈用于下一次选择/重规划即可构成相应行为闭环；若进一步声称在线参数学习或持续适应，仍须独立通过更新、保持与回滚门，不能混称。

正式执行前，必须冻结单一任务范围、成功标准、比较方式、阈值/重复要求、资源上限及停止线；本原则不凭空指定数值，不授权启动实验。未集成、未测、协议偏差、未过门分别记录；失败先在原范围内结项，不自动追加模块或开启其他能力支线。

### 2.2 通用评审清单

1. **范围**：父阶段、能力轴、任务/数据/环境、允许的主张与明确排除项。
2. **冻结判据**：每门公式、参照、样本单位、预算、阈值来源；机器门与文字一致。
3. **能力证据**：独立测试、公平可部署对照、必要 lesion/归因，拒绝把 oracle 或模板先验当模型能力。
4. **保持与连续性**：旧任务、跨轮累积、正确 parent/lineage、无泄漏与可恢复继续。
5. **训练保存**：正式训练前零步完整保存、独立恢复、原子写入、容量/磁盘预检；失败则不启动。
6. **安全与运行**：权限、失败语义、拒绝、环境撤销与模型 rollback 分开验；相关工程检查实际通过。
7. **资源**：calls/updates/参数/wall/存储按冻结口径，预算超限不可隐藏。
8. **依赖**：逐项继承已批准资产，不以存在 checkpoint 代替准入。
9. **独立批准**：项目所有者审阅范围、机器门、未完成项与风险；批准或拒绝均落盘。
10. **同步结项**：报告/scorecard、01 轴状态、03 执行出口、plans 首页同一提交更新。

评审表字段：门 ID｜父阶段/轴｜判据版本｜证据路径/摘要｜pass/fail/blocked/not-applicable｜剩余动作｜批准记录。not-applicable 必须解释其范围依据，不等于通过；缺证据保持待核验。

### 2.3 分级规则如何进入验收

1. **接线、行为、学习、自主性分级**：字段/调用和恢复证明工程链；实际终态与有效对照证明行为贡献；反馈更新后新旧任务比较证明学习；内部选择时机/预算对照证明自主性。后一级不补发前一级，更不能把操作效力当自主调节。
2. **探索与确认分开**：探索只需明确假设、来源、权限、可撤销范围和资源上限；正式能力声明才要求完整冻结协议。不得因尚无能力证据而禁止隔离原型，也不得用探索成绩直接晋级。
3. **测量有效性先于解释**：消融接口有效、信息/预算可比、终态核验独立；模型差异、状态重置、失效缓存或仪器错误造成的落差先标不可判，不直接称机制因果贡献。
4. **硬边界与方法分开**：权限、无答案泄漏、证据诚信不能例外；残差出生、外控调度、局部/自动梯度等方法可另立协议比较。新容差/种子数依风险和测量冻结，不能事后改旧门或所有实验一刀切。
5. **机器通过与批准分开**：报告含判据公式、原始量、结论、适用范围与实际代码/模型/数据身份；文档design-only不计实现通过，implemented不计verified-scoped，后者也不等于adopted。
6. **失败不自动加门**：合同bug修相应实现；仪器失真撤回受影响判定；缺证据记未测/不可判；正确协议未过门则负结果结案。新增门说明漏检风险、影响范围与关闭条件，由所需权限层审阅。

本节调整以后如何组织工作和解读主张，不改变已有具体实验的样本数、阈值、停止线或final权限。

### 2.4 开发计划何时算写完整

当前用户要求补全计划，用于指导开发，而不是立即选择架构或训练。因此规划本身按下表审阅；它不是新模型门禁，不给历史实验追加要求，也不规定每次小改动都重新审批。

| 规划完整性 | 应能回答的问题 |
|---|---|
| 目标与范围 | 要形成什么能力，服务哪个阶段出口，当前不承诺什么？ |
| 事实与缺口 | 有何可继承证据，什么只是推测/未测，为什么值得做？ |
| 设计选择 | 有哪些实质不同的办法，各自上限/代价/适用条件是什么，什么证据会改变选择？ |
| 依赖与顺序 | 先需要哪些接口/能力，哪些工作可随当前包完成，哪些只是未来采用条件？ |
| 学习与数据 | 经历怎样产生，训练改变哪些参数，模型怎样在运行时使用学习成果？ |
| 开发交付 | 需要代码、数据、权重、原始输出、报告和恢复中的哪些实物，而不只是计划描述？ |
| 验证与退出 | 正/负/不可判怎样分别结束，何时扩大范围、切换方案或进入阶段评审？ |
| 资源与未知 | 已知约束是什么，未定数值怎样标定、何时冻结，谁负责相应开发/确认？ |
| 全局衔接 | 当前局部工作结束后怎样回到L2/L3、M5与M4/M6–M8，而不另起永久支线？ |

固定的是目标、证据诚信、所有权和安全边界；探索包先具备假设、隔离、来源、可恢复和资源上限，正式比较再冻结具体判据，产品采用再满足交付门。不能把正式确认的全部数值当作允许写规划/做隔离设计的前提。未定项显式保留并给出求取方法，比随意设定常数更可靠。

计划审阅完成只表示它能指导开发，不等于选择A–E、授予训练权限、批准晋级或发布。当前工作模式与后续入口以03为准。

### 2.5 局部实验的有条件准入（2026-09-18用户纠正）

**设定约束，不一概禁止追加局部实验。** 为定位可复现缺陷、区分竞争解释、估计稳定性/资源或确认必要机制，局部实验可以成为当前工作包或路线评审的组成部分；无需等所有架构方案完整评审后才允许取证。限制的是没有新判别价值、没有累计预算或不断移动出口的追加，不是实验规模小或次数多本身。

按风险使用一张简短准入卡，可直接写在03活动包下；不要求每个探针新建长文或满足正式晋级的全部统计门。至少说明：

| 约束 | 执行前必须明确 |
|---|---|
| 决策关联 | 当前哪个缺口阻塞了哪个决定；已有证据为何不足；结果将改变继续、修复、换设计或结案中的哪一项 |
| 可辨识性 | 主假设及至少一个替代解释；必要的同信息/预算对照；正、负、不可判各意味着什么，不能只写“希望分数提高” |
| 有界修改与权限 | 改什么、不改什么；所用split、权重/入口与写入范围；已批准范围如何覆盖本实验，是否涉及已停止方向 |
| 累计预算 | 父工作包内已花费与剩余的运行次数、数据暴露/更新、计算或墙钟及资源上限；需要重复测量或有限分支时一并登记，不凭空统一规定只能跑一次 |
| 停止与返回 | 预算耗尽、既定停止线触发或预定判别已完成时返回原决策；若不可判，只有预先约定的补测可在剩余预算内继续，不能自动加一个变体 |
| 记录与结论 | 真实配置/数据/权重身份、分母、原始输出或诊断量及失败记录；训练前实际保存/恢复检查；探索结果只支持相应诊断，不替代正式能力确认 |

**授权分层：**

1. 现有产物的只读分析与计划维护，可在任务范围内继续，不计作恢复训练。新模型运行、重新评分或可能写checkpoint的测试不冒充只读分析，按实际数据/资源/副作用检查权限。
2. 已授权包内、未触发停止线、符合预先约定的实验范围和累计预算，可自主执行必要的局部实验、补测或实现回归，不逐次要求用户重新审批。提前约定的条件分支也是授权范围，不等于自动开启全部备选路线。
3. 超出范围/预算、改变冻结判据或核心合同、读取封存final、改变默认行为，或重开已触发停止条款的方向，先作对应层级裁决。可以只批准一个有界诊断子包，不必先完成全架构选型；但不能靠重命名为“诊断”绕过原停止线。

**防止局部实验无限延长：**预算按父问题/工作包累计，不因换名、换seed或拆小包清零。重复试验若用于消除预先声明的随机性/测量不确定性，可以有价值；已达到所需判别精度后，不继续同质复现。正结果同样要及时返回能力路径，不因有积极信号而无限扩面。诊断不可判只关闭其判别范围，不证明整类架构无效。

本条是后续实验组织规则，不追改旧合同或补发运行授权。D2/P1已触发的停止条款继续有效，新增实验须按第3类边界处理；当前卡片与唯一活动入口仍在03。

### 2.6 多模态与自主学习的信息准入（设计补充，2026-09-18）

具体方案见[VISION §20–21](../../reference/VISION_FUTURE_TECHNOLOGY.md)。本条适用于后续新增媒体/外部输入、持久记忆、在线更新和相关采用声明，不追改旧实验门，也不要求静态R2完成全部多模态与红队平台。

- **权威、事实和许可分开**：外部文字/图片/音频及派生OCR/ASR/摘要可作为证据，不因此获得指令或学习权限；来源完整性不等于事实正确。模型不能通过普通学习修改宿主授权/安全策略。
- **按新增风险分层验收**：新输入验来源/权限/推理隔离；持久记忆验用途、污染/撤销与跨会话；快参数验反馈准入、影响范围/预算、新旧任务和回退；慢巩固验parent-child、独立采用及血缘。未进入的层不一概提前加门。
- **不能靠全部拒绝取高分**：同时报告攻击行为、正常任务与合法纠错/学习收益、误拒和审核成本。硬越权/隐私事件阻止对应采用；测试零事件仍须披露样本量、攻击范围及残余风险，不能称绝对安全。
- **多模态能力需实际干预**：同bundle比较单模态、打乱配对、关键区域/时段替换和共同输入；有文字捷径/OCR代答时收紧主张。缺失/冲突模态、旧语言保持和来源继承不可由接口成功替代。
- **恢复不是一句删除**：记忆/缓存撤销、快参数恢复、慢核心回退/重训分别验证；缺可靠干净基线则限制采用。参数回滚不撤销已发生的外部动作或信息泄露。

正式包在执行前冻结与范围匹配的攻击预算、来源/媒体组划分、主要行为门、保持与资源界。低风险且已获准的学习可按规则自主进行；扩大用途、敏感数据、权限或高影响采用再升级裁决，不逐条人工审批所有普通信息。
