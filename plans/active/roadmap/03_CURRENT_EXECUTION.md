## 3. 本轮复审的四项约束

### 3.1 表征非恒定不等于排序正确

A 的预测分两档：冗余 a+d 为 −0.02459，其他五对为 −0.11680；select 偏好更大的 predicted_interaction。只能说“能够区分两类”，不能说“已学会避开冗余”。两个未见对仍同分；集合列线性相关，单个系数也不能独立解释。

B 应检验位置敏感、任务条件化的关系表示，保留 A、旧标量和简单模型对照，而不是继续只加覆盖计数。

### 3.2 评分参照必须统一

object 使用组合减“该对内最强单体”，C2 使用“全体最强单体减 baseline”，却放进同一 mean_gain_vs_strongest_single 字段比较。−0.5 与 1.5 并非同参照收益。预注册 collaboration 子项与实现的正 factorial interaction 条件也不相同。

历史状态原样保存，不追认通过。新研究必须版本化定义估计目标、参照、分母、权重、成本及代码断言；“预测 interaction”“选择高效策略”“创造超过单体的协作”分开测量。

### 3.3 跨任务覆盖互补不等于同任务协作

b+c、b+d 总成功 12/24，高于任一固定单体 6/24，证明组合覆盖更广。但当前矩阵中没有 pair 在同一 block 超过全体最强单体；前三类已有单体拿到奖励上限，第四类全部失败。

更好的表示可能改善路由或排序，但不能凭空制造当前矩阵没有的同任务协作增量。若只能测到路由收益，就只作路由主张；若目标是协作，需新复合依赖任务与 lesion 证据，不能通过降低旧阈值解决。

### 3.4 已看过的 holdout 转为开发诊断

c′、c″、c‴ 在同一任务面反复归因，两个留出组合与结果已知。旧 144/88 载体保留作机制回归，不能继续当作未接触的最终泛化测试。block = task_index % 4 是模板先验，B 须披露来源与可见性，不把数字身份称为语义理解。

### 5.1 统一测量字典（**已交付 v1 草案**）

对同一 context 记录原始 outcome：空白 B、单体 S_i、组合 P_ij。以下为建议口径，须审阅冻结：

- 主任务表现：各策略在相同任务、预算、权重下的 mean outcome 或终态成功率。
- 同参照增益：所有可部署策略均使用 U(policy) − U(common reference)，不按各自 pair 更换参照。
- 因果 interaction：P_ij − S_i − S_j + B，独立报告，不自动作为任务效用。
- 全体单体 oracle：逐任务 max_i S_i，仅作评分时诊断上界，不冒充可部署策略。
- 可部署单体对照：仅凭 train 学出的固定/条件化单体选择器，在预测前冻结。
- 成本：调用数、步数、wall、恢复成本分账；折为 utility 时，权重须提前冻结。

交付手算用例：完全冗余、覆盖互补但不协同、联合必需、全部失败、同结果不同成本。每例给公式、预期值及自动测试要求。旧 1.65 判据不静默替换，也不无解释继承。

5. block-3 缺证据时按安全拒绝评分；若新任务提供合法证据，另列版本，不把旧拒绝判为能力不足。

> 因此**不进入 B1 训练**；当前动作改为完成设计包 §11 的 D1–D4 决策，并据此冻结路线 B 预注册。

## 6. B1：关系表示实施与对照

推荐位置敏感、任务条件化关系，目标是表达“谁在当前观察下提供何种贡献、联合如何改变结果”，不止识别四类模板。

1. 审计 profile/record/candidate 的输入、拟合目标和排序效用，列数据责任表。
2. 从 train 单体证据构建能力描述；per-block 向量作可解释诊断基线，正式表示须说明新 context 泛化方式。
3. 比较 A 计数表示、位置敏感简单模型与候选关系模型；复杂度增长须有额外预测/任务收益。
4. 生成、排序、执行均绑定 parent digest 和 observation；排序目标与主任务效用一致，interaction 另报。
5. 旧 checkpoint 读取/拒绝策略版本化；显式迁移，不能静默把缺失 surface 当空能力。

对照包含无学习、A、train-only 简单模型、特征 lesion、固定/随机组合、可部署单体路由。成员重命名与 task 编号置换应不改变非语义判断，防字典序或编号泄漏。

**验收**：目标不同的候选能被表达，独立验证排序方向，拒绝/恢复通过。非零系数和秩改善不是单独的完成条件。

**上界约束（B0 续篇新增，必须先读）**：仲裁类机制的上界恒 ≤ 0，故 B1 的表示改进**最多只能回收冻结规则的 headroom（实测 ≤ +0.5）**，
**永远不能单独支撑 H2 协作主张**。B1 不得把"预测区分度提升"或"秩提升"报告为协作证据；
H2 必须先由任务改造（续篇 §5）提供组合专属可解 context。

## 7. B2：离线选择到真实收益

- 预测先于评分；模型决定动作/组合，参数绑定逐字段披露，失败不得替换为 oracle。
- 对照同初始世界、预算、审批合同、评分；执行后独立验证文件/语言/撤销终态。
- 报告总体收益、逐任务差异、最坏类、安全、保持、成本和校准样本量。
- 先证明优于可部署对照；协作主张还需超过公平单体并经成员/连接 lesion 归因。
- 排序变好而执行不变，检查可达性、交接与动作生成，不直接归咎关系模型。
- P5.2a 失败场景保留回归，不因新指标容易过而移除。

**出口**：合同失败回实现；上界不成立回 B0；表示不足回 B1；预测有效但执行受阻回动作/组合机制；收益保持均过才进入 d。新失败报告独立保存。

## 8. 在线、真实语料与采用

P5.2d 只消费合格 train outcome，测试仅评分；多轮比较冻结父代、等预算更新和 child，同时验新旧任务、stale parent、重复 feedback/token、中断恢复。
