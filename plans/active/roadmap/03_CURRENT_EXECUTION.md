## 1. 核心问题与本轮解法

当前最关键缺口不是“模块数量不足”或“必须先找到另一种算法”，而是：

1. **语义没有统一消费证据**：感知、记忆、世界信念、目标/计划可能同时存在，却未证实在同一模型、任务和时间状态下共同参与决策。
2. **行为与学习没有统一证据**：输出变化、loss下降、局部gate通过，不能证明实际任务改善，也不能证明任务错误已有效分配到负责表示/预测/选择的状态或参数。
3. **规则没有正确分层**：长期能力目标、当前工程合同、实验方法与冻结阈值混写，产生“原型先满足成熟目标”和“历史实现永远不可改”的循环前置；实际接口与失败处理反而缺定义。

本轮已完成的治理/设计修复：

| 问题 | 本次落地 | 尚未完成、不可冒称 |
|---|---|---|
| 核心目标分散 | 以同任务的记忆→世界预测→规划→实际反馈作为统一能力主张的验收链；语言仍是必达能力 | 统一模型能力本身尚未获证 |
| 接口/学习责任含糊 | 架构§4.6–4.7与§6.3明确共同状态、消费/失效、执行生命周期和学习权限 | 默认 chat 尚未据此完成集成；新字段/迁移未自动实现 |
| 规则僵硬与缺失 | 根需求区分成熟目标与原型；架构§0.2/§8.5建立P/C/E/X层级、例外、状态、复审与责任 | 不是放宽已冻结门，也不是所有规则都已有机器守卫 |
| 执行指令互相覆盖 | 旧逐轮“下一步”移出活动页，保留本页唯一队首与条件出口 | 不删除历史证据，不恢复暂停 |

## 3. 主线如何收敛，而不是再开几条支线

**能力主线目标：Taiji自己的状态和参数在同一实际任务中形成可用内容、作出选择、承受结果并改进后续行为。** R2基本语言缺口仍保留，不能被动作ID或宿主模板替代；但也不能把“先通过全部语言门”作为验证记忆/世界/规划能否协同的先决条件。

原R0–R6是责任分类，不是七条同时开工的主线：

| 分类 | 在单一工作包中的职责 | 何时才成为实施前置 |
|---|---|---|
| R0 结案/证据 | 关闭存量身份、协议和结果解释 | §4已记录后继报告和归因限制；不重复全仓审计、不再占设计队首 |
| R1 可信底座 | 加载、保存、数据隔离、实际相关CI | 确实阻塞该包且有复现时；不先清完全部技术债 |
| R2 内容与语言 | 条件内容、共同表示、跨时间信用、原生表达 | 选定同任务切片后共同设计；L2仍是语言完成出口 |
| R3 持续适应 | 真实反馈后的合格更新、新旧任务与恢复 | 参数学习层开工时；行为状态反馈不冒称参数学习 |
| R4 同入口集成 | 同bundle消费链、真实执行、代表能力 | 应在隔离切片早期验证，不再全部拖到语言训练之后 |
| R5 扩面/缺口 | 知识准入、独立结构、身体全生命周期 | 当前切片结案后，按M5退出缺口逐个选；不同时打开 |
| R6 阶段/产品 | 轴评审、L3、M5退出、M6/M7采用发布 | 相应必达证据齐备后独立批准；包完成不等于阶段完成 |
| V 未来架构 | 长期高上限候选及替代方案 | 独立批准后才实施；不作为绕开当前负结果的入口 |

**本次设计选择**：复用已有Taiji状态/恢复/执行资产，围绕共同任务信念建立可训练纵切片；不再单独串接另一个byte读出补丁，也不全面推倒重建。前者容易继续只改善表层代理指标，后者同时引入太多无法归因的变化。所选方向让表示、预测、选择与表达能够获得同任务信用，同时保留替换内部算法的空间。它是下一合同的设计约束，不是新训练授权或默认迁移。

### 5.1 最小代表任务及选择依据

首选候选为**隔离Workbench内的受约束多步工件组装与修复任务族**，先缩成“早期条件—干扰—两步选择—新问题回答”的可学微任务，再增加同族难度；不是立即做聊天演示：

1. 早期给定需保留的目标/保护约束及部分环境经验，随后插入无关事件；决策时不再次免费提供全部历史答案。
2. 当前状态提供合法观察与可用操作，存在不同后果、前置条件和成本的候选路径；对象名称、关系组合和环境变化不能靠固定模板答案决定。
3. Taiji依据记忆和当前信念预测后果、选择多步路径，执行发生真实沙箱状态变化；中途可遇到新观察，必须核对旧计划是否仍有效。
4. 用独立环境检查核验终态内容、约束、成本和遗留副作用；脚本只负责环境/评分，不替Taiji选路线。
5. 将实际反馈用于下一次选择，再单独比较允许参数更新与冻结参数的表现。最终让同一bundle表达依据、结果或未知；宿主回执文字不计语言能力。

选择理由：可复用已有Workbench合同、后状态核验和规划资产，且能同时检验记忆的时间作用、世界预测的反事实作用与规划的选择作用。它不是对现有binder已具备这些能力的断言：先做消费映射，必要的最小接口补齐属于该包，跨域/多工具泛化不随之开工。

任务必须排除三种假需求：环境已重复给出全部约束却声称需要记忆；工具schema直接提供最优后果却声称学会世界模型；唯一合法动作却声称需要规划。简单策略拥有同等合法信息与预算，不能靠禁止基线读取历史人为造增益。参考计划、最优终态、隐藏环境状态仅评分使用。

## 6. 防止规则再次变成僵硬闸门

- P层边界不能豁免；C层只约束相应能力声明；E层允许有迁移/回退的版本替换；X层在新实验中可更换方法。完整规则见架构§0.2/§8.5。
- 路由/睡眠/成长先证明操作效力，再证明学习策略与自主触发；固定控制可作公开原型/基线，不把原型叫成熟能力，也不禁止先研究机制。
- 基础联合有效性与更强协作涌现分级；恢复一致性、行为保持与参数位级不变分账。旧精确门不追改，新主张依风险冻结容差。
- 失败先定位到合同实现、仪器、证据不足或机制负结果，不把每个失败变成更大的新门。新增硬门必须写具体风险和可关闭条件。
- 结案报告区分事实/假设/因果结论/资源决策；“停止某候选”不需要证明整类理论不可能。
- 外部动作结果未知时先对账，不盲重试；模型恢复不等于环境撤销。低风险缺信息可澄清/降级，高风险权限不明拒绝相关动作。
- 新数据通过显式warm-start新血缘进入，不绕过现有corpus校验；当前尚无相关迁移实现时标待实现。
- 本次已核对代码允许backward；保留所有权与现有禁止外部认知检查，不再以过时AST禁令阻塞方法讨论。
