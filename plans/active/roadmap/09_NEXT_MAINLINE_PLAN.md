## 1. 阶段结构（P 痛点 → S 正解 → N 阶段）

### N1 P1 接口修复（最优先；一切机制失败的总根源）

- **痛点 P1**：复制电路把锁定事件经位置注意力池化成 257 维分布加进 logits（`copy_circuit.evidence()`→`_pool_into`），无终点信号、无顺序保证。
- **第 0 步 S5（便宜证伪，零训练、可与 N2/N3 并行）**：内容末字节 → 证据让位＋轨迹演到终点（终点检测器）。判据先冻：若 never-LF 显著缓解 ⇒ P1 诊断坐实；若否 ⇒ 病在更深（基底），同样是真知识。
- **正解 S1（再激活式读取）**：情景召回**驱动 fabric 沿存储轨迹重放**（走现成 `episodic_feedback` 通道进皮层），生成从被再激活的状态继续——"说完"成为重放走完的副产品，不需要终点检测。这同时是 P2 的正解（读取与计算同基底，脑的回忆是再激活，不是贴摘要）。
- **开工前置**：S5 判读入库后再落 S1 的实施规格与判据。

### N2 P5 离线重放→巩固通电（能力与窗口解耦）

- **正解 S2**：真实长跑后用 `sleep_pass` 的 **organs/learn 路径**做离线重放巩固（管线在产品里活着，㊵-P5 澄清；通电即得"重放不受睡眠窗口限制"这个机器加速点）。材料扩容＝**C6 六决策点**（原 PLAN-M6-01 §8 提取；该件已按蒸馏政策删除、原文见 git 历史；待 owner 批）：① kind 白名单——(a) 扩语料侧行内字面集加 `workbench_artifact`（EVOLUTION_CONTRACT_VERSION 维持 1）／(b) 复用 verified_domain_material（须放弃 snapshot_id/revision 生命周期与增量去重）／(c) 不接（C6 只留诊断）；② 渲染模板与语言——(a) 作者一张中文能力表（唯一能把 CJK 推到中文主导且保住信息量，但属新写语料作者工作）／(b) no_prose 只投结构化字段（CJK 0.503，零作者成本）／(c) id_only（0.63 最高但信息量趋零）／(d) 接受 literal 0.243 分布外行（不建议）；③ 值不值得现在做——16 条≈名册 207 万行的 0.00077%，作训练权重可忽略；现实定位＝(a) 为「数据环第四块补齐＋留接口」而做，不是为训练效果；④ 生产者落点——sleep_pass 的 project 段（推荐）；⑤ 消费者同批（推荐，否则只补一端）；⑥ P4 面板行要不要（只读、最小）。
