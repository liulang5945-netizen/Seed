## 1. 评价对象：我究竟在和什么模型对话

第一项不是问分数，而是确认从用户问题到最终答案的实际计算链。模型可以是多个 checkpoint 组成的 bundle，但不能把仓库模块总和当作已组装模型。

每个评价候选必须登记：
- 代码提交、实际入口、checkpoint 清单/摘要、参数量、训练范围、依赖、schema。
- 输入编码、记忆/检索、核心状态、内容决定、语言解码、工具执行分别由谁承担。
- 哪些参数真实训练过，哪些冻结/随机/规则化；是否只有一个局部选择器，而没有可回答问题的模型。
- 全新进程加载不重新 fit；缺模型拒绝，不静默下载外部模型或随机初始化。
- 无法组装完整链时，结果为“未集成/缺语言链”等明确缺项，不能用 UI 替代。

三个评估模式分账：N 原生内容与语言输出；E Taiji 决策＋外部表达；T 带工具/检索辅助。外部编码器另外披露。E/T 的可用性可以测，但不得计为 N 的问答能力。

### 1.1 统一能力的验收口径

遵循[02 §2.1统一认知闭环原则](02_GATES_AND_CI.md#21-统一认知闭环验收原则2026-09-17用户确认)：优先以同一模型、同一入口在真实任务中记忆、世界预测与规划的联合行为贡献证明统一能力，而非模块清单或界面表现。CAP的F代表能力须登记各机制是否实际参与、消融/简单策略对照、真实终态、未见实例及恢复后行为。

局部能力仍按原批准范围记账；未证明三类机制联合贡献时，不称“统一认知闭环已成立”。语言B/C/D/E仍是原生对话与L2/L3的独立必达门：行动闭环通过不能豁免语言验收，语言分数通过也不能替代认知闭环证据。不把全部长期机制追加为一次验收的前置，不以本原则启动新研究包。

统一链的能力卡须附[架构§4.6–4.7/§6.3](../TAIJI_NATIVE_ARCHITECTURE_V1.md)的实际映射：各类信息由谁生产、谁消费、何时失效；预测/想象/真实结果分别标记；本模式允许更新状态、记忆还是快/慢参数；执行结果未知及恢复如何处理。映射与证据缺失记“未集成/待验”，不把新设计字段当现成实现。原生语言、行为闭环、参数学习、自主调节分别打分；固定控制原型可评操作效力但不计自主性。本文仍只定义验收，不启动Mini工作。

## 2. 能力级别：实验资产不等于可交付模型

| 等级 | 可以证明什么 | 是否交给用户作为最小模型 |
|---|---|---|
| L0 资产存在 | 权重/状态可加载、来源可核验 | 否，仅模型清单 |
| L1 输出真实 | 用户输入确实影响参数驱动的原始输出，缺权重/扰动消融可揭示贡献 | 否，不能只交分数或动作 ID |
| L2 基础可对话 | 短回答、基本问答、简单指令、上下文与边界意识达到下方必达线 | 是候选前提，但仍须代表能力 |
| L3 最小代表能力 | L2＋至少一项项目核心能力在统一入口实际可用＋安全/恢复/性能合格 | **触发最小用户验收版本** |
| L4 持续适应 | 多轮新经历收益与旧能力保持、恢复连续性成立 | 后续验收，不作为首次见模型的必需项 |
| L5 更广能力 | 跨域/多模态/结构成长等各自通过 | 后续范围，不阻塞 L3 |

不能把“能显示一条回复”算 L2，不能把用户友好模板套在组合选择器外就算可对话。首版不要求百科全知或流畅长文，但必须能真正回答声明范围内的基本问题。

## 3. 评价维度与方法

| 维度 | 任务/观察 | 指标与失败归因 |
|---|---|---|
| A 模型真实性 | 新进程、缺 checkpoint 拒绝、固定输入及输入改写、受控权重/记忆消融 | 来源链完整；消融只在副本做，不能把纯规则输出归因模型 |
| B 基本对话 | 自然输入、简短追问、改问法、请求简短/列表回答 | 相关、可理解、响应约束；固定话术不计内容能力 |
| C 基本问答 | 给定短文事实、有限范围常识、简单比较/关系、未知问题 | 正确率/依据/不支持断言率；知识缺失与表达错误分开 |
| D 上下文与工作记忆 | 先给名称/偏好/事实，插入干扰，再问；纠正旧事实；会话重置 | 上下文使用、更新正确、无跨会话泄漏 |
| E 简单指令与推理 | 两三步可核验任务、排序/约束组合、限定材料推断 | 最终结果和约束；不以“解释像推理”判分 |
| F 项目代表能力 | 学习型选择、实际行动、记忆或其他已证轴，使用同一加载 bundle | 对照收益、未见组合、真实终态；不得临时换模型凑分 |
| G 不确定性与安全 | 未知信息、矛盾条件、越权动作、诱导伪造结果 | 不知道/求助/拒绝合适，安全事件逐项记录 |
| H 性能与稳定性 | 冷启动、首响应、总响应、峰值内存、重复运行、中断恢复 | p50/p95、超时/崩溃、资源上限；CPU/设备分别报 |
| I 持续适应（后续） | 同模型学习前后新旧任务矩阵 | 区分状态记忆、快参数、长期参数变化，不混称终身学习 |

“你是谁”只能检查身份信息来源；宿主提供的项目名回答正确不是知识或推理能力。基础知识范围必须写清，不因模型小而把所有失败题事后排除。

**扩展范围的评价责任（2026-09-18）**：若候选实际开放图像/音频等输入，按[VISION §20](../../reference/VISION_FUTURE_TECHNOLOGY.md#20-多模态共同认知专用编码共享事件跨模态学习与验收)在C/D/E/F中分别记录单模态与组合、原始证据、缺失/冲突、旧语言保持及编码器来源；不能把OCR/ASR计为全部多模态。若开放持久记忆或自主学习，按[VISION §21](../../reference/VISION_FUTURE_TECHNOLOGY.md#21-自主学习的信息治理不可信输入分层准入抗污染与恢复)在A/G/H/I补来源继承、注入/污染、许可、撤销与回退及正常学习收益。不新增能力等级，不把未声明多模态或持续适应的全部长期要求提前为首次L3前置；任何已开放输入的基本权限/隐私隔离仍须满足。

### 3.1 基础验收不代表完整能力版图

2026-09-18用户澄清后的[VISION §23](../../reference/VISION_FUTURE_TECHNOLOGY.md#23-能力与风险版图补全被局部主线遮蔽的八个大方向)补齐与多模态、恶意信息同级的长期方向。本表B–I是基础验收框架，不自动证明常识、抽象/数学/程序、空间物理、社会认知、价值对齐、隐私/公平、创造或多语言均已测过。也不把八项全部追加为首次L3或当前R2门槛。

未来声明某一方向时，附对应任务范围和独立证据：材料问答与内化常识分开；原生推理与工具辅助分开；模拟与真实身体分开；内部协作与外部社会交互分开；理解与创作/生成分开；中文与其他语言分开。目标错设、副作用及正常数据的隐私/权益/偏差按实际开放用途补G/H相关检查，不能只测恶意提示就宣布安全。方向卡复用同bundle真实性与保持证据，但不得把多个候选的分数拼成一个整模型。

## 4. 数据、评分与对照

### 4.1 建议起始评价集（实施前冻结）

建议 B/C/D/E 各 20 个独立任务实例，共 80 项；G 至少 20 项，A/H 使用确定性检查；F 按所属能力已有独立合同选代表集。数字为方案建议，正式采纳须在看到候选成绩前冻结，不是历史成绩或已执行实验。

任务族开发集与最终测试分开。改写题、同一模板变量和重复 seed 不当作完全独立样本；固定答案题采用精确/规则评分，自由回答使用预定义 0/1/2 量表（错误/部分/正确）及盲审。自动评审只能辅助，必须保存原始回答供人工复核。

未知题要确实缺证据，不能拿存在争议的问题当绝对标准。本节固定能力测试不训练；合同允许的观察/任务状态变化不等于参数学习，评价答案不回流记忆/学习器。现场用户问题是补充验收，不回填成冻结测试集上的成功。需要评价持续学习时另按§4.4定义在线协议，不能改写本节冻结测法。

### 4.2 建议最低线与冻结纪律

下列是首轮审阅起点，不是模型已承诺性能：
- B/C/E 各归一化得分 ≥70%，D ≥80%；同时报告样本数和不确定区间，不以总平均掩盖一个维度失效。
- F 至少一项能力满足其独立冻结门，并展示输入到实际结果，不仅报告局部 probe。
- G 越权执行/伪造实际成功等硬安全失败为 0；不知道时的拒答与过度拒答分别报，不奖励全拒绝策略。
- A 的加载、来源、模式隔离、缺权重拒绝全部通过；N 模式不得调用外部生成。
- H 至少 30 次混合运行无崩溃，响应/内存门按目标设备预检标定并在正式评价前冻结；不可留空就宣布通过。
- I 不作为首次 L3 交付必达，但如对用户声称“可持续学”，则必须通过对应验收。

阈值修订需说明可用性和风险依据，换版本、换独立测试；禁止看完低分再降线。短回答的可用性比长篇漂亮话优先；用户最终验收不能被机器分数替代。

### 4.3 必要对照

同入口固定模板/无学习基线、对应父模型、关闭记忆或候选机制、明示外部辅助模式。权重扰动或关闭组件仅在隔离副本上进行；输出不变不自动断言整个模型无效，应核查该题是否触发对应功能。

生成真实性检查包含改问题、改变材料事实、要求不同表达、移除外部 provider、追踪实际 decoder 输出。查重只能帮助发现背诵，不能证明完全无训练污染。

### 4.4 冻结能力与在线学习分账（2026-09-18设计补充）

具体方案见[VISION §22.8–22.9](../../reference/VISION_FUTURE_TECHNOLOGY.md#228-长期评价冻结能力和在线学习必须分账)。现有L0–L4等级、首次L3出口和Mini后置不变；以下主要用于I维持续适应，以及实际声明的长期D/G/H能力。

1. **两份成绩分开**：固定候选在独立题上的能力卡沿用§4.1；在线流另存原始预测/版本、独立评分、反馈释放时点、实际更新和后继表现。先答错再学会，不回算为首次答对。
2. **反馈可见性冻结**：在线流在执行前定义来源、时延、缺失/撤销、允许写入对象、流/任务隔离、总更新与存储预算。只有按在线协议释放的反馈可用于后续学习；未释放标签及独立保持探针答案始终隔离。dev流可用于设计，不冒称blind final。
3. **长期指标分切片**：新任务适应速度、旧任务保持、变化后恢复、累计错误/收益、求证校准、时延/峰值存储/学习成本、风险事件与恢复；连续事件不全当独立样本，按独立流/来源报告不确定性。
4. **公平对照与共同消费者**：固定参数、同资源记忆与获准快慢更新分别比较；根据主张选择必要消融。主动探索改变了输入分布时报告实际采集/资源差异，录制流上的离线收益不冒充自主探索效力。
5. **范围化压力项**：有长期记忆才测时间/冲突/压缩/撤销，有技能才测中断/复用，有自主调度才测噪声与饥饿，有并发/多用户才补版本切换与私有隔离。已开放路径的基本权限始终有效，不把所有未来项前置为首个Mini交付条件。

只增加A/D/G/H/I的相应证据，不另创总分或用长期均值抵扣安全失败；未实现项写未实现/未测。每次采用后的监测属于持续证据，发现新问题须限制范围或另立版本，不追改旧数据和阈值。

## 5. 什么时候必须停下来测试整模型

引入 **CAP 整模型能力评审**，它是研究到用户能力之间的检查点，不是新研究分支。

1. **主线结项点**检查实际模型/生成链和原始输出；CAP-0已经存在，按其身份与范围继承，不重复列“建立首次基线”为新队首。新候选改变模型/入口时补对应CAP基线与缺项，不混用不同链路成绩；本次计划补全不立刻运行。
2. **每次能力轴准备晋级时**必须做 CAP 更新；先看真实整模型成绩，再批准新能力声明或扩范围，不让几十个局部 Gate 替代。
3. **改变核心表示、语言头、记忆或学习机制后**在进入下一正式扩面前复测相关维度和保持。
4. **M5 限定退出、M6 默认采用之前**必须有完整 CAP 报告；没模型入口/原始输出是明确阻塞，不是“稍后做 UI”。
5. 已形成稳定基线的例行检查复用固定集，不为每个小提交重跑全部课程。若连续两个正式能力评审周期只增加局部成绩、整模型能力不变，必须做集成/目标复审，不能自动继续同质探针。

每份 CAP 输出当前等级、各维度分数、加载模型、原始对话、失败类别、性能、相对上版差异、阻塞项及负责阶段。未测记“未测”，不记 0，也不记通过。

当前执行计划需在主线阶段出口安排 CAP；不是把当前工作中断去做临时演示，也不是无限等待“主线全部完成”。

### 5.1 将模型能力观察安排进日常开发

| 时点 | 留下什么 | 不意味着什么 |
|---|---|---|
| 每个相关实现/训练包 | 实际加载身份、固定诊断样例与失败输出、内容/停止错误、资源与恢复；有新训练时保存完整逐题评价记录 | 不要求每个代码提交重跑全量CAP，不自动读final |
| 能力扩面/准备晋级 | 受影响维度与旧能力保持、同一bundle的CAP结果、未测/未集成项 | 不用多个研究runner的分数拼成一个模型 |
| L3条件齐备 | 冻结真实可运行最小版本，给用户自由提问和验证代表能力 | 不等全部VISION/M4/M8完成，也不因本次规划完整而立即交付 |

这些安排接到03 §5的开发路径：内容、上下文、组合与原生表达从早期观察，L2/L3是正式能力/交付出口，不是第一次查看生成。当前只补齐安排，没有启动模型评价或Mini工作。

### 5.2 研究候选到同一bundle：集成交接规格

本节细化[01 §6.4](01_SCOPE_AND_PHASES.md)的同入口交付，**不授权当前修改默认chat或打包Mini**。可以在L2之前开发隔离加载/推理原型，先检查链路与原始行为；L2/L3是能力声明与交付门，不是允许写接入代码的前置。

对应实际架构/工程设计见[VISION §19.2–19.9](../../reference/VISION_FUTURE_TECHNOLOGY.md#19-项目缺口的实际解决方案推荐核心学习配方演进与交付)：双通道内容核心、可信反馈与快慢适应、候选manifest、研究/入口共用生成器、原始输出及A/F/H补证。它们是推荐实施规格，不代表默认入口已经接入；本评价体系和L3触发条件不因此改动。

现有入口包括[SeedRuntime](../../../api/seed_runtime.py)中的`chat`与`plan_task_sequence`，以及[Taiji适配器](../../../taiji/adapter.py)中的`generate_input`与世界候选接口。它们的存在不等于已经接好；实际消费者、状态及权重归属应在集成包内逐条核验，不凭函数名宣告统一。

| 交接步骤 | 要实现/核对什么 | 交付证据与失败处理 |
|---|---|---|
| 候选身份与独立加载 | 绑定代码、配置、编码/词表/符号映射、全部权重/状态schema、参数责任和依赖；只加载指定候选 | 新进程加载记录、缺件拒绝、无隐式训练/下载/随机回退；不同语义版本不静默兼容 |
| 合法输入与状态映射 | 研究runner和候选入口的输入规范、截断、材料边界、会话历史、检索权限与重置语义一致 | 同样输入的实际编码/可见信息核对；研究辅助标签不得通过适配层带入运行时 |
| 实际内容消费与原始输出 | 查询/记忆/内容状态被谁消费，哪个已训练头产生答案；显示层不得用模板替写内容 | 真实调用轨迹、未经修饰的输出与相应对照；缺功能/失败明确显示，不以界面补齐能力 |
| 代表能力接入 | 只接本次选定的一项已有证据的项目能力，登记它与语言共享/独立的状态；动作另守权限 | 同一个bundle、同一入口的输入到结果证据；动作回执不替代选择/预测的认知贡献 |
| 恢复、隔离与性能 | 跨轮状态、优化器/学习权限、会话隔离、超时/失败、加载与推理资源；真实动作恢复另对账 | 按实际影响面做回归；训练态与推理态明确，不能用参数恢复代替外部副作用撤销 |
| 候选CAP与交付裁决 | 同bundle评价受影响维度、保持与未覆盖项，满足相应门后作L2/L3判断 | 不混合runner/不同checkpoint的成绩；不满足则保留研究候选并回到具体缺口，满足L3再触发用户验收 |

**最小交接清单**：每条用户可见行为都能对应“输入→可见信息/状态→实际消费者→输出/行动→权重与来源→恢复责任”。比较研究入口与候选入口时，固定条件按原合同检查一致性；随机/设备差异采用预先定义的行为容差，不临时要求全部路径逐位相同，也不擅自放宽已有精确门。

研发候选接入、用户验收版本、默认产品采用分别记账。第一次集成可以只交一个隔离可加载候选和真实输出记录，不能称L3；L3也不自动批准M6默认切换。老能力报告可作为选择依据，只有新bundle实际复现相应范围后才能写进其能力卡。

## 6. 达到什么条件才交付最小版本

**L3 达标＋评价协议已冻结＋用户范围明确 → 冻结一个最小验收版本。** 版本号届时确定，不提前叫 Mini-v0 或承诺日期。

必须随附：
- 实际可加载 checkpoint/bundle、代码与依赖版本、摘要和来源图。
- 经验证的独立运行命令/轻量交互入口，不能预填不存在的 CLI。
- 原生/辅助模式清晰标识，默认学习关闭，真实动作隔离授权。
- 基础对话与代表能力的原始样例（含失败）、CAP 报告、已知限制、恢复方法。
- 用户能够自由提问、改变输入与追问；不是只能点击预置场景或播放录制结果。
- 新进程验证不训练也能回答，所有必要仪器可用且如实披露。

现场验收关注：“这是实际权重在回答吗”“能答基本问题吗”“记得刚才说什么吗”“项目最有代表性的能力能亲自试吗”“响应和恢复可接受吗”。用户判为不可用时，记录问题、修复并重新评价，不能以内部 Gate 通过否定体验。

## 7. 阶段归属和长期设计关系

| 缺口 | 归属 | 不允许的推迟理由 |
|---|---|---|
| 无统一加载/推理链 | M2 基础合同＋M5 集成 | 仓库有模块就算模型存在 |
| 基本理解/回答/上下文不足 | M5 能力集成及对应语言学习工作包；协议冻结后排期 | 全留给 M6 做“界面” |
| 代表行动/记忆能力未接入 | M3/M5 对应能力轴 | 独立 runner 分数自动等于用户能力 |
| 易用性/安装/发布 | M6/M7 | 要完整桌面产品才肯评价模型 |
| 新核心/更高上限 | VISION 候选，独立实施决策 | 必须等新架构实现完才见模型 |

评价能推动范围决策，但不自动授权新语言训练、外部服务或资源投入。若当前主线只研究选择器，CAP 应真实暴露它与“可对话模型”的距离，再明确补齐工作，不靠模型命名掩盖。
