## 2. 每个训练实验必须交付架构归因

用户规则：**每一次训练的归因的重点之一是其是否是架构的问题。** 以一份训练实验/配方及其有限结案为单位执行，不把每个epoch变成全架构重审。架构不能默认因更多数据、更多步数或训练loss下降而通过。

| 必交内容 | 判断要求 |
|---|---|
| 架构假设与适用任务 | 指明可能限制任务的状态、表示、读取/更新机制，以及数据、剂量、目标、优化与评价的竞争解释；独立切片披露未接入器官 |
| 信息与连续性路径 | 记录生产者→实际状态值→消费者→原始行为、来源/时间及reset边界；相关交换、无关交换、切断与救援分别裁决可达、进入计算和正确使用 |
| 学习责任 | 追踪合法反馈/任务误差→允许更新的状态或参数→隔离query收益与旧能力保持；按机制选择梯度、资格迹或实际更新证据，不要求合法冻结/离散分支强造非零梯度 |
| 结构反证 | 争议用有固定出口的最小因果对照；记录初始化、数据、更新量、参数/计算、实际成本差异，禁止把整包收益单归因给课程或规模 |
| 明确结案 | 使用“结构缺陷已确认”“架构瓶颈有因果支持”“架构嫌疑未证实”或“本轮证据主要支持其他原因”，附任务范围、剩余不确定性与唯一后继动作 |

结案固定包含`architecture_verdict`、`task_scope`、`suspected_mechanism`、`information_path`、`credit_path`、`causal_evidence_refs`、`competing_causes`和`next_action`。历史报告不回填改写，新增归因链接原证据。若必要信息已确认不可达、所需差异被表示混同或反馈到不了负责模块，先补接或重构相关主链，阻止该任务继续同质训练；“架构嫌疑未证实”也必须在一次有界验证后结束，不能无限续训。

## 3. 整合依赖与逐阶段有限出口

主链为：**N176原包一次结案＋N177接口/静态工程并行准备 → 共同状态/来源/时间/重置 → 所需记忆选择与行动条件世界预测/短规划 → 同一状态的语言/行动和合法反馈信用 → 同一候选内F0–F2、学习责任与保持 → F3自然连续任务/跨会话 → 按实际瓶颈研究时间尺度、学习机制或算力 → 07同bundle验收。**

前一阶段的接口/恢复条件是依赖，能力分数不自动成为后一阶段所有工程的前置。N176负结果不阻塞已知共同链欠账的修复；N177也不反过来延长N176。每阶段按所选范围一次固定输入、对照、分母、批次、资源和停止线，支持、负结果、不可判、partial或工程失败均可有限结束。

3.2–3.5按N177的T1→T2→T3逐任务纵向执行：当前子任务所需状态、消费者、信用和恢复具备后即可做其固定课程包，不等待所有任务全部模块完成。扩展任务继续同候选家族迁移及旧保持；前级负结果不阻断已知必要接口的静态工程，但不得用无限加轮跨过失败。
