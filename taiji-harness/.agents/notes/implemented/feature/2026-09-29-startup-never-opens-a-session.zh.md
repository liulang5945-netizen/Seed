# Agent Note: Startup never opens a Session

Status: implemented

[English](2026-09-29-startup-never-opens-a-session.md) | 中文

## Problem

启动恢复会替用户选中一条会话，于是每个安装的首屏都是已经打开的会话，而不是 Hero 提供的选择点。任何想观察"空状态"的东西都得先压掉这次创建；而通过网络请求压掉它，会改变装配后真正渲染出来的内容，所以比对渲染结果的 lane 用不了这种手段。

## Decision

启动只恢复已经存在的东西。它等工作区与会话两份基线齐了，在没有登记工作区时准备默认工作区，并在持久化的选中项指向一条仍然符合条件的空白会话时把它复用回来。它从不新建会话：第一条会话来自用户手势——在 Hero 里发送、New Session、或打开某个工作区。[首用默认工作区](2026-09-20-default-workspace.zh.md) 继续拥有"准备与资格判定"，这一点未被本次改动改变，包括它那条唯一的失败提示；空白会话复用的理由仍由 [会话作用域与供给通道](../architecture/2026-07-25-web-client-session-scope-and-provide-channel.zh.md) 拥有。

复用已保存的空白会话是刻意保留的，因此刷新后仍停在用户原来那条会话上。启动期的失败上报（`initial Session restoration failed`）现在只覆盖这条复用路径，并且仍然只进 console：工作区存在并不是启动失败，所以不弹提示，也不多出会话行。

## Alternatives considered

- **保留启动创建，在测试里钉住空状态。** 拒绝 `session/create` 请求确实让几何 lane 变确定了，但它同时移除了产品本来会打开的那条会话，于是同一个前提不能用在任何比对渲染输出的 lane 上；而且它没有改变实际交付的首屏形态，而那正是这些反馈指向的地方。
- **只拒绝"客户端自己建的那块工作区"里的创建。** 改动更小，默认工作区那条路确实安静了，但已存在的工作区仍会替用户打开一条会话，首屏和侧栏里的行仍然是没人请求过的。
- **连已保存的空白会话也不复用。** 侧栏就再也不会出现用户没要过的会话，但刷新会把用户从正在阅读的那条会话上甩下来——而这正是无手势路径唯一的可取之处。
- **改在第一次按键时创建会话，而不是第一次发送时。** 需要一条草稿会话、一次向真实会话的迁移，以及和首次提交的协调；而一旦会话存在，Hero 走的就是普通输入框管线。

## Consequences

新安装的首屏是带着已准备工作区、等待发送的 Hero，Sessions 树里恰好只有被创建过的那些会话。比对型 lane 改为陈述自己的前提而不是拦截它：几何 lane 现在冷启动并断言没有当前会话，路径里没有任何被拒绝的请求。

代价：启动时"没有当前会话"成了每个读取它的界面都能到达的状态，于是头部几何、输入框屏蔽、工作区选择都要把它当常态，而不是一瞬间的空档。录制下来的启动形态行为随之改写：客户端服务规格把契约写成"prepares the default Workspace without opening a Session"，首用浏览器场景覆盖准备、Hero 发送、以及刷新后恢复。
