# Agent Note: 退役包名留在 Session 格式转换器里

Status: implemented

[English](2026-09-29-retired-plugin-identity-in-v3-migration.md) | 中文

## 问题

给一方包改名之后，Session 格式转换器读不到改名前录下的 Session。`session-format-v3-to-v4` 靠一张历史身份表把记录里的 `plugin` 来源解析成产出方的当前 kind，而这张表在改名后只剩下新标识符。于是每一条系统消息记着退役标识符的 v3 Session 都被解析成不透明的 `plugin:<退役名>`，而 `packages/core/session/src/index.ts` 的回放准入检查要求 `system/message` 的来源 kind 必须是 `system-prompt`，整条 Session 因此装载失败。在本检出面的录制语料上实测：375 份非 expected 的 JSONL 夹具共含 213 条系统消息，其中 192 条带退役标识符，且这 192 条全部落在 `*.v3.jsonl` 里。

## 裁定

历史身份表两种拼写都认。`sources.ts` 把两个系统提示产出方标识符放进同一条冻结列表：`system` 角色都解析成 `system-prompt`，其余角色都解析成 `runtime-context`，于是改名前录的 Session 与改名后录的走同一条转换。`sources.spec.ts` 里两条断言分别钉住退役标识符的那一只手臂，因为只给当前标识符钉过的角色敏感映射，下一次改名会静默退化。

这张表是只读历史，不跟随当前包列表。一个已经不再作为包存在的标识符仍然必须能被解析，因为叫它的那份数据比包活得更久。改一方包的名字因此要把格式转换器里的产出方表当作独立一步来扫，而不是混进机械的标识符替换里。

## 考虑过的替代方案

- **重录语料。** 录制需要模型，而且要为了读侧的一个解析缺陷重写每一份场景夹具。它也救不了已经持有改名前 Session 日志的用户，而那正是转换器存在的理由。
- **在记录的夹具里改写退役标识符。** 否决：记录下来的系统消息与用户消息是模型可见文本，本仓把这段文本按原样钉死。改它等于伪造模型实际收到的内容，同时让读侧看起来是对的。
- **让系统消息接受不透明 kind。** 否决：准入检查的意义是回放的系统消息必须归属到提示产出方。放宽会让真正外来的系统消息通过，也改变了回放保证的含义。

## 后果

改名前录的 Session 重新可装载，格式 v3 夹具不再在回放它们的浏览器套件里停在装载期。改动只限于转换器的身份解析，没有任何上线格式、记录载荷或事件词表发生变化。

后续代价是一条规则而非代码：今后任何一方包改名都必须把退役标识符加进产出方表，并为每一只角色敏感的手臂钉一条断言。`verify-session-format-catalog` 只查目录形状，查不出丢掉退役名的表 ⇒ 这一步扫描尚未被机器守住。
