## 前端语言 vs 开源 Harness 采用 —— 决策简报落档

- 触发：所有者提问「是否把前端改用 TypeScript，或改用 DeepSeek Harness / ZCode 做 taiji 化改造」。
- 取证（10:30 GMT+8）：
  - ZCode（智谱 ADE）：`zai-org/ZCode` 于 2026-09-20 20:01 开源，Apache-2.0，TS 97.6%，**仅 2 条提交、无 release**，正处工作区快照静默上传 OSS 的安全事故整改期 ⇒ 不可作为 fork 基座。
  - dsh（DeepSeek Harness）：MIT，TS + Cordis 插件内核，v0.1 预览并明言破坏性变更；四档 preset（Standard / PTC Code Mode / **Minimal 裸 harness** / Create）。
  - 反例：Aider / OpenHands / AutoGen 为 Python ⇒ **实现语言与 agent 效果无因果关系**。
- 前端实测：`frontend/src` 124 文件 / 21,117 行；`.vue` 45 且**全部 `<script>` 为 js**；`.js` 69；**无 tsconfig**，仅有 `jsconfig.json`（仅 `@/*` 别名）。
- **关键发现**：`src/composables/nativeApi.js` 已是类型化边界门面的雏形（冻结 `nativeApiPaths` 路径表，注释明言 payload 保持 plain object 且仅在此边界序列化）⇒ 契约单点化已做完，**前端是「TS 形状的 JS」，缺的只是类型层**，迁移是补类型层而非重写。
- 结论：**采纳**「前端增量 TS 化」；**否决**「采用 dsh/ZCode 做内核替换」（层次错位 + 架构倒置 + v0.1 破坏性变更 + ZCode 不可 fork + 与 R2/M5 主线冲突）。
- 落档：`plans/reference/FRONTEND_TS_VS_HARNESS_ADOPTION_DECISION_BRIEF_20260921.md`（状态：待所有者裁定，未裁定前不产生代码改动）。
- 待批准后唯一下一步：前端 TS 地基（`typescript` + `vue-tsc` + `openapi-typescript`；`tsconfig.json` 开 `allowJs`、`checkJs:false`；由 api OpenAPI 快照生成 `src/api/schema.d.ts`；`nativeApi.js` → `nativeApi.ts`；CI 加 `vue-tsc --noEmit` 仅限新增/改动文件）。零 `.vue` 改动、零回归、可逆。
- 可借用思想（借架构不借代码）：append-only session log + trajectory；Code Mode / PTC 收敛 workbench 端点；**dsh 的 Minimal 裸 harness 形态 = R2 所需裸环境对照臂**。
