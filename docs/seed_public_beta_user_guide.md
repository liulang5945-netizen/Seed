# Seed 公测版用户指南

> 适用版本：公测（Public Beta）打包版（`Seed.exe` 双入口，约 1.1GB）
> 完整验收证据见 `reports/seed_public_beta_release_20260823.md`

## 1. 安装与启动

- **免安装**：解压发布包到任意目录（建议路径不含中文与空格），双击 `Seed.exe`。
- 启动约 3 秒出界面（判据 ≤15 秒）。启动过程：后端工作进程（`SeedBackend.exe`）
  就绪 → Seed 原生运行时激活 → WebSocket 8765 → 前端加载。
- 数据均位于程序目录内：

| 目录/文件 | 用途 |
|---|---|
| `checkpoints/` | 模型检查点（训练产物） |
| `data/` | 用户数据（会话、知识库等） |
| `logs/desktop_main.log` | 主进程日志（启动排障首选） |
| `logs/desktop_backend.log` | 后端日志（API/推理排障首选） |

- 关闭主窗口即同时退出后端进程；如残留，可在任务管理器结束 `SeedBackend.exe`。

## 2. 对话使用

- 打开即进入聊天页，输入问题回车或点击发送。
- **启动即激活模型**（运行环境偏好自动恢复），冷启动后首问首字节实测约 27ms，无需等待激活。
- 多轮会话自动保存，侧栏可切换历史会话；会话切换不丢上下文。
- 模型切换（Seed 原生 ↔ Cortex）：设置 → 运行环境；选择会被持久化，重启自动恢复。
- 实时状态：生命状态页（`/life`）与顶部横幅由 WebSocket 8765 推送，
  连接失败时自动降级为 10 秒轮询，功能不受影响。

## 3. 训练与续训

- 训练页（`/train`）：查看检查点列表（`/api/train/checkpoints`）、发起续训
  （`/api/train/resume_checkpoint`，SSE 流式进度；关闭页面即停止，避免无人值守耗算力）。
- 命令行方式（大预算语料须显式指定 `--corpus`，缺省会落到脚本默认的对话小语料）：

```bash
python scripts/training/train_seed_corpus.py \
  --resume checkpoints/seed_beta.pt \
  --corpus data/simple_zh/simple_zh_texts.jsonl \
  --max-symbols <增量>
```

- 语料防漂移：检查点元数据含 `corpus_fingerprint`（语料文件名+字节数），
  续训时若语料被换会自动在元数据中反映，可据此核对。

- 检查点采用原子落盘：进程崩溃/断电不会损坏已有检查点（10/10 故障注入演练验证）。
- 注意：大预算训练长时间占用 CPU，建议空闲时段运行。

## 4. 环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `SEED_PORT` | `8000` | Web/对话服务端口 |
| `SEED_HOST` | `127.0.0.1` | 监听地址；设 `0.0.0.0` 开放局域网访问（手机浏览器访问 `http://<主机IP>:8000`） |
| `SEED_RUNTIME` | 未设 | 设 `1` 时启动即激活 Seed 原生运行时 |

> ⚠️ 当前无鉴权。开放局域网仅限可信网络；请勿将 `0.0.0.0` 直接暴露公网。

## 5. 已知限制

1. **回复质量**：当前为早期检查点（4M ticks），回复可能为乱码或不连贯文字——
   这是模型训练阶段的预期表现，不是故障；工程链路（发送/推理/渲染）已全量验证。
2. **包体体积**：约 1.1GB（含 PyTorch CPU 运行时与数据资产），未做裁剪。
3. **首问冷启动**：见 §2；后续提问首字节延迟 ≤0.13 秒、吞吐 ≥350 字节/秒。
4. **跨进程实时事件**：个别生命事件可能有至多 10 秒延迟（轮询兜底窗口）。
5. **平台**：公测版面向 Windows（x64）；开发模式源码运行支持主流平台。

## 6. 常见问题

- **双击没反应**：查 `logs/desktop_main.log`；确认 8000 端口未被其他程序占用
  （可改 `SEED_PORT`）。
- **界面白屏**：查 `logs/desktop_backend.log` 是否有启动错误；确认 `_internal` 目录完整。
- **回复乱码**：见已知限制 1，属预期。
- **续训后进度看起来"重复"**：进度统计以模型自身累计量为基线，不会重复计入；
  若怀疑异常，对照 `logs/` 中的训练日志。
