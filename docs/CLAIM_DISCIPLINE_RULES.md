# 判定纪律（2026-11-18 立，因当日反复自我推翻）

> 用途：约束"什么时候可以说结论"，以及"用哪个主体说"。每条都对应当日一次具体事故。

## 1 三级判定

| 级 | 允许的说法 | 前提 |
|---|---|---|
| **读数** | "本次运行得到 X" | 一次运行，须标种子数、样本数、预算 |
| **推断** | "在 A 对照下 X 大于 Y，方向为 Z" | **至少一个对照臂**，机制可命名 |
| **结论** | "X 成立／不成立" | 预注册判据 + **≥2 个独立见证** + 红向演练能失败 |

**禁止**：拿读数当结论。单次运行不得使用「成立／越过／证明／不可能」。

## 2 四条硬规则

1. **先穷尽零更新路径**：说"必须训练才能改善"之前，先证明"不训练做不到"。
2. **归因必须带对照**：说"瓶颈在 X"时，必须给出"去掉 X"的读数，否则只写"读数分布"。
3. **换道前先做等价性分析**：能证明两种改法等价时，不要花预算去跑。
4. **反转必须落账**：每次推翻自己，写「原判 → 新判 → 依据」，不得静默改写历史卡。

## 3 主体标定（机器强制）

训练后主体**必须按注册表取名加载**，不得直接写 bundle 路径：

```python
from scripts.training.subject_registry import load_subject
model, subject = load_subject("a5-pre-seed20261110")
```

- 注册表 `plans/manifests/subject_registry_20261118.json`：**手工声明**，不做 glob 自动发现——自动发现会把 c2／p4_1 的 bundle 混进来，等于重造主体混用；
- 加载校验 **sha256 + update + revision**，任一不符抛 `SubjectError`（fail closed）；
- 报告必须写 `subject`、`bundle_sha256`、`bundle_update`；
- 红向演练：`--drill` 必须两条都响（未知 key、被篡改摘要），当日已验。

**未登记主体不得引用**；`output/` 下的检查点属瞬态实验臂，只作过程记录。

## 4 校准仪式

**任何探针在出结论前，必须先复现一个已发布的数字。** 复现不上就报 `bundle_does_not_reproduce` 并结束当轮，不得继续解读。
